# 일반 페이지의 제목과 첫 콘텐츠

## 메인·서비스 소개 통합 (2026-11-19, 현행)

### 메인 콘텐츠 최대 너비 — 2026-11-19 후속 승인

메인 `[data-marketing-page="home"]` 안의 `.site-marketing-container`는 공통 `--site-content-max`(100rem, 기본1600px)와 기존 gutter를 사용해 중앙 정렬한다. 히어로 제목·설명·진행 막대, 기기 소개 문구, 서비스 프레임의 콘텐츠, 운영·기능 그리드와 요금·CTA가 헤더·푸터의 콘텐츠 경계와 맞는다. 화면이1600px보다 좁으면 기존 폭·여백을 유지한다.

배경 사진·배경색과 전체 화면 stage는 제한하지 않는다. 사진의 높이 기준 카메라·목업 위치/배율·외곽 블러/페이드·시연·스크롤은 그대로다. 최상위 page/main이나 배경에 최대 폭을 걸지 않고 콘텐츠 래퍼에만 적용한다. 헤더·푸터, 다른 경로와 고객 렌더러는 변경하지 않는다. 아래의2026-11-17 본문 최대 폭 제거는 과거 기준이며 메인에는 더 이상 적용하지 않는다.

베이직·다이닝·디스플레이 소개는 메인 `/`의 검정·와인·네이비 서비스 프레임에서만 제공한다. 헤더 PC/모바일 메뉴, 푸터, 홈 플랜 소개와 신청 화면의 서비스 소개 링크는 `SERVICE_HOME_HREFS`의 `/#service-basic`, `/#service-dining`, `/#service-display`를 공유한다. 기존 `/services/basic`, `/services/dining`, `/services/display` 및 메뉴/시그니처/스크린/풀옵션/테이블씬 프로 별칭은 해당 앵커로308 영구 이동한다. 고객 메뉴판·편집/신청 흐름은 이 통합의 대상이 아니다.

스크롤 기준점은 sticky 프레임 바로 앞의 높이0인 일반 흐름 앵커다. 이미 다른 프레임에 덮인 sticky 요소의 현재 좌표를 목적지로 사용하지 않는다. 앵커가 뷰포트 위 끝에 도착하면 프레임의 기존 헤더 높이+섹션 여백이 제목을 가리지 않도록 한다. 기존 프레임 색·레이아웃·스크롤 커버 모션은 유지한다.

메인 안의 서비스 링크는 부드럽게 이동하며 같은 메뉴를 다시 눌러도 프레임 시작으로 돌아간다. 모바일은 메뉴를 닫고 이동하고, 다른 페이지/직접 주소 접근은 Next Link의 해시 탐색을 사용한다. 공통 ScrollToTopOnPathChange는 해시 목적지가 있으면 맨 위로 초기화하지 않는다. iframe 준비나 DOM 변화를 감시해 나중에 다시 스크롤하는 복원 동작은 제거한다. 명시적 링크 입력만 한 번 이동시키고, 실행 전에 새 휠·터치·포인터·키 입력이나 뒤로가기가 발생하면 취소한다. 새 창·키보드·뒤로가기와 모션 감소 설정을 유지한다. 현재 위치 표시는 URL 해시가 아닌 실제 흐름 앵커 위치로 판단하며, 서비스 스택 밖에서는 해제한다. 서비스 스택의 시작이 뷰포트 상단에 닿으면 헤더를 투명 배경과 흰색 글자·아이콘으로 표시한다. 브라우저의 앵커 이동에서 생기는 1 CSS px 미만의 소수점 차이는 도착으로 간주한다. 스택 하단이 헤더 아래 경계에 닿으면 기본 흰색 헤더로 돌아간다. 아래 네 페이지를 별도 소개로 다루는 과거 규칙은 통합 전 기록이다.

박스 안쪽·본문 묶음·폼과 버튼 정렬은 [본문 구성 계약](site-content-layout-contract.md)을 함께 따른다. 페이지 도입부의 간격과 박스 내부 간격은 소유자가 다르며 중복하지 않는다.

2026-10-29 사용자 요청. 공통 서체만 적용하고 페이지마다 상단 패딩·margin을 추가하던 구성을 대체한다.

- 베이직·다이닝·디스플레이 소개·약관·템플릿 목록·FAQ·공지 목록·이용가이드·신청·요금·마이페이지·운영의 일반 제목은 components/layout/SitePageHeader.tsx를 사용한다.
- 헤더 아래 제목 시작은 --site-page-heading-top, 즉 공통 compact 페이지 여백이다. 기본40–64px, 기존 와이드 보정에서는 최대72px이다. 같은 뷰포트에서 일반 페이지 H1 시작 높이는 같다.
- 제목과 설명은 --site-page-title-description-gap=12px. 설명을 포함한 제목 그룹에서 첫 콘텐츠는 --site-page-intro-content-gap, 모바일32px·768px 이상40px다. 여러 줄 설명은 자연스럽게 높이가 늘어난다.
- 공개 일반 페이지는 가운데, 관리 페이지는 시작 정렬이다. 문자 정렬을 바꾸어도 수직 간격은 동일하다. 홈의 홍보 히어로·상품 상세의 별도 구성 역할과 고객 메뉴판 렌더러는 분리한다. 인증 폼의 좁은 가로 폭은 유지하되 위아래 바깥 여백은 일반 페이지의 공통 토큰을 따른다.
- 공통 `SitePage`를 사용하는 매장 운영은 `typography="management"`를 지정한다. 본문과 페이지 제목이 같은 관리 화면 글자 기준을 상속한다. 수치는 [최종 사이트 폰트 기준](site-typography-final.md#관리-화면의-밀도)을 따른다.
- 제목 그룹에 mt/pb/mb를 페이지마다 중복으로 더하지 않는다. 보조 설명은 그룹 안의12px 간격, 알림 박스·검색·탭·폼은 그룹 다음의 첫 콘텐츠 간격을 사용한다.
- 템플릿 목록의 서비스 탭과 영역 탭은 명시적인32px 그룹 간격이다. 기본 Tabs gap과 별도 margin을 중복으로 더하지 않는다.
- 템플릿 종류 탭과 배경 없는 검색·필터 콘텐츠는 `site-stack-group`의24px 간격으로 분리한다. 영역형 Tabs의 연결용 gap0을 페이지의 서로 다른 묶음 사이까지 적용하지 않으며 탭 자체의 디자인·높이는 유지한다.

## 메인·세 서비스 소개의 본문 경계 (2026-11-17, 통합 전 기록)

메인·베이직·다이닝·디스플레이의 첫 제목도 SitePageHeader를 공유하고 헤더 spacer 다음 --site-page-heading-top을 적용한다. 같은 viewport에서 네 페이지의 제목 시작 간격은 같다. 홈의 별도48–112px hero 상단 여백은 폐기한다. 이 네 페이지 본문만 site-marketing-container로 화면 가장자리의 공통 gutter를 사용하며1600px max-width와 내부 주요 그리드의 중첩 cap을 제거한다. 헤더/푸터와 다른 페이지는 기존 최대 폭을 유지한다. 일반 페이지 제목과 메인 스크롤 장면·서비스 섹션 제목은 모바일28px·태블릿32px·PC36px 및 공통 와이드 보정을 따르며, 확대 히어로는 별도 역할로 정의한다. 자세한 역할은 [최종 사이트 폰트 기준](site-typography-final.md)을 따른다.

## 탭

선택한 최상위 탭은 3px 밑줄과 글자 굵기600을 사용한다. PC에서 글자 기본16px이며 탭 크기별 최소 높이는 탭 역할 계약을 따른다. 밑줄은 클릭 영역 하단에서4px 위로 올려 글자와 가깝게 배치한다. 비선택 글자만 --ui-tab-inactive-text=#969696으로 더 연하게 표시한다.

영역 탭은 연결형 사각 버튼이며 바깥 네 모서리만8px다. 선택은 검정 바탕·흰 글자, 비선택은 흰 바탕·보조 글자색이다. sm/md/lg의 최소 높이는40/44/48px, 상하 여백은8px, 좌우 여백은16/20/24px이다. equal 분배는 최대36rem에서 같은 폭을 나누며 모바일도 한 줄로 맞춘다. 긴 콘텐츠형 목록은 내부 가로 스크롤을 유지한다. 템플릿 검색·필터·결과·페이지네이션은 배경 없는 연속 콘텐츠이며 페이지 콘텐츠 경계까지 사용한다. 이전 회색 래퍼와 그 안쪽 여백을 재사용하지 않는다.

추가 가능한 룸·문서 작업 영역에는 `Tabs purpose="section" appearance="document"`를 사용할 수 있다. 흰 선택 탭이 아래 기준선에 연결되며 생성 행동은 탭 옆의 TabsAction으로 구분한다. 기존 section 영역형의 기본 디자인과 다른 탭 역할은 유지한다. 크기·색·포커스·비활성은 공통 문서형 계약을 따른다.

## 고객지원

헤더 고객센터는 마우스오버·클릭·키보드로 열리는 공통 Popover다. 자주 묻는 질문 /faq, 공지사항 /faq/notices, 이용가이드 /guides의 세 페이지로 연결한다. 모바일 메뉴는 고객센터를 서비스와 같은 대분류의 펼침 버튼으로 두고 이 세 페이지를 하위에 표시한다. 푸터도 같은 페이지들을 제공한다. FAQ 아래 공지 목록을 혼합하지 않는다. 기존 FAQ5개·공지10개 페이지 나눔과 공지 상세 경로, AI 상담과1:1 문의는 유지한다.


새 페이지 기본 틀·자동 검사·레거시 이전 원칙은 [자동 적용과 회귀 방지](site-system-enforcement.md)를 따른다. 공지사항은 큰 FAQ 검색 영역 대신 공통 BoardList와 목록 상단의 작은 검색 도구를 사용한다.


## 모바일 본문·푸터 간격 (2026-11-01)

`styles/site-spacing.css`의 의미 기반 토큰을 사용한다. 767px 이하에서는 관련 문구8px, 제목/설명12px, 작은 블록16px, 콘텐츠 묶음24px, 주요 콘텐츠32px, 독립 카드48px, 새 섹션64px, 표면 안쪽20px다. 제목 위치40px·제목 그룹/첫 콘텐츠32px는 기존 계약을 유지한다. 숫자는 16px 기본 rem 환산이며 뷰포트별 글자 배율로 보정하지 않는다.

본문 묶음은 `site-stack-copy`, `site-stack-block`, `site-stack-group`, `site-stack-content`, `site-stack-section`을 사용한다. 이 묶음은 자식의 수직 margin을 없애 gap 한 곳에서 간격을 소유한다. SitePageHeader 경계에 stack 여백을 중복으로 더하지 않는다. 같은 역할의 간격 변경은 공통 토큰에서 하고 페이지 CSS에서 `--site-space-*`를 재정의하지 않는다.

모바일 템플릿 목록은 탭 안내 위아래24px, 별도 박스 안쪽 여백 없이 페이지 gutter 사용, 필터/결과32px, 도구/목록24px, 이미지/카드 정보16px, 카드 사이48px, 페이지네이션 위32px, 별도 상담 영역까지64px다. 좁은 폭의 도구는 기존 순서를 지키고 자연스럽게 줄바꿈한다. 버튼 크기나 기존 기능 위치를 간격 수정으로 바꾸지 않는다.

모바일 푸터의 최신 기준(2026-11-19)은 위·좌우24px, 소개→접이식 메뉴24px, 열린 메뉴 위4px·아래12px이다. 서비스·이용 안내·사업자 정보의3개 묶음은 기본 접힘이며 요약 행·펼친 링크·연락처·정책은 이전44px 높이로 복구한다. 직전32px 조정은 취소한다. 서비스·이용 안내의 링크는 각각1열·세로 gap0이다. 이전2열 배치는 폐기하며 링크의 원래 순서를 세로로 유지한다. 별도 고객지원 묶음은 제거하되1:1 문의는 이용 안내에, 전화·이메일은 사업자 정보 안에 보존한다. 모바일 이용 안내의 마이 메뉴는 제외한다. 사업자 정보 행 사이8px·연락처 앞8px, 정책 앞16px이다. 768px 이상은 기존 펼친 구성과 연락처·너비를 유지한다. 서비스·이용 안내·고객지원 제목은 기본16px, 메뉴·연락처는 보조 본문14px이다. 모바일 서비스·이용 안내 제목과 메뉴·연락처도 기본14px이다. 글자 크기는 공통 와이드 보정을 따른다. 둥근 회색 면·투명 바깥 배경·내부에서 잘리는 워드마크는 보존하며 장식 테두리를 추가하지 않는다.

서비스 소개·홈의 일반 섹션 제목/설명12px·첫 콘텐츠32px, 카드 묶음24px, 주요 섹션64px를 같은 역할 토큰에 연결한다. 이용가이드의 영상/설명24px·문서 사이64px도 동일하다. PC/태블릿 기존 간격과 고객 메뉴판의 독립 모바일 규칙은 변경하지 않는다.

실측과 적용 범위는 [모바일 간격 검수](mobile-site-spacing-qa.md)를 참고한다.


## 설명·도움말 최소화 (2026-11-06)

제목만 기본으로 표시하고 필요한 조건은 공통 도움말에 둡니다. 사용자 요청·박스 내부·상태·데이터·필수 주의사항의 보존 기준과 `descriptionPurpose` 계약은 [디자인 시스템](site-design-system.md#설명도움말-최소화-2026-11-06)을 따릅니다. 코드 전수 점검 범위는 [설명 정리 기록](site-copy-audit.md)에 기록합니다.


룸처럼 독립 선택 버튼이 필요한 영역은 `Tabs purpose="section" appearance="rooms"`를 사용한다. 왼쪽 고정 추가 행동과 스크롤되는 룸 선택, 조건부 오른쪽 페이드와 룸 관리 패널의 최신 계약은 [디자인 시스템의 룸 선택·관리 도구](site-design-system.md#룸-선택관리-도구-2026-11-10-이전-룸-탭-내-이름-편집오른쪽-삭제-배치-대체)를 따른다. `site-content-heading-row data-layout="toolbar"`는 제목과 보기 선택을 모바일에서도 한 행에 두는 공통 변형이다.


운영 메뉴의 제목은 `SectionHeader`의 `type-section-title`로 통일한다. 현재 선택 메뉴판명·소개 문구를 본문 제목에 반복하지 않고, 선택기가 있는 경우 같은 헤더 오른쪽의 공통 `ViewStyleSelect`를 쓴다. 필수 조건은 기존 InfoTooltip, 실제 기간·개수·오류는 원래 위치를 유지한다.


## 아티메뉴 인증 페이지의 바깥 여백 (2026-11-11)

로그인·가입·계정 찾기·비밀번호 복구는 가로 폼 폭만 별도로 유지한다. `.site-auth-page`의 위는 `--site-page-heading-top`, 아래는 일반 compact 페이지와 같은 `--site-page-space-compact`다. 화면 높이 기반 최소 높이와 세로 중앙 정렬을 제거해 제목과 마지막 콘텐츠가 불필요한 빈 공간 안에 떠 있지 않도록 한다. 제목에서 폼까지는 `--site-page-intro-content-gap`을 공유한다. 폼 내부 간격·입력 크기·인증 동작은 유지한다. 매장 운영·마이페이지 등 별도 작업 레이아웃은 변경하지 않는다.

## 2026-11-18 홈 사진 hero 헤더 예외

이전 일반 도입부 규칙은 베이직·다이닝·디스플레이 및 다른 일반 페이지에 유지한다. 홈의 사진 시퀀스만 헤더 spacer를 0으로 하고 `100svh` 장면을 `top:0`에 고정해 사진이 헤더 뒤까지 이어진다. 첫 제목도 다른 장면과 같은 마케팅 section-title 역할을 사용한다. 공통 큰 hero 타이포 역할 자체는 보존한다.

홈에서만 hero의 실제 아래 경계가 헤더 아래 경계에 도달할 때까지 헤더를 투명·흰 글자/아이콘으로 표시한다. 사진의 상단 음영이 대비를 보장하고 만들기는 공통 secondary를 사용한다. 이후에는 기존 흰 헤더·검정 글자와 primary CTA로 복원한다. 역방향 스크롤과 크기 변경에도 같은 실제 경계를 다시 측정한다. 다이닝 소개의 정적 검정 헤더 규칙, 다른 경로의 24px 스크롤 규칙, 모바일 흰 메뉴 시트·팝오버·알림 및 메뉴판 렌더러에는 전파하지 않는다.

## 헤더 로고의 메인 시작 동작 — 2026-11-19

헤더와 모바일 전체 메뉴의 ArtiMenu 로고는 공통 `HomeStartLink`를 사용한다. 일반 클릭·키보드 실행은 현재 서비스 hash/query를 남기지 않고 `/`의 scrollY=0으로 즉시 이동해 스크롤 기반 히어로를 첫 장면으로 되돌린다. 다른 페이지에서 눌러도 홈이 표시되기 전에 같은 위치로 이동한다. PC 헤더와 모바일 전체 메뉴의 베이직·다이닝·디스플레이 링크도 각 서비스 프레임 위치로 즉시 이동한다. 푸터와 본문 안의 서비스 링크는 기존 이동 동작을 따른다. 초기 렌더링·브라우저 뒤로가기에 무조건 초기화를 붙이지 않는다. 수정 키를 이용한 새 탭 열기와 링크의 기본 의미는 보존한다.

`lib/service-home-scroll.ts`는 서비스 위치 이동과 로고의 맨 위 이동을 하나의 최신 탐색 의도로 관리한다. 로고를 누르면 이전 서비스 예약을 취소하고, 그 명시적 시작 의도에만 scroll 가드를 유지해 늦은 프로그램/포커스 이동이 맨 위를 되돌리지 못하게 한다. 메뉴 시연 준비나 DOM 변화를 감시하지 않는다. 이후 wheel/touch/pointer/key/popstate 입력이나 새 서비스 이동은 그 예약을 종료한다. 명시적 로고 이동에만 홈 첫 장면과 문구를 전환 없이 표시한다. 일반 스크롤과 다른 서비스 링크의 본문 모션은 기존 동작을 따른다.


## 관리 화면 경로와 내 메뉴판 카드 — 2026-11-27 현행

마이페이지/직원 관리/매장 운영과 하위 화면은 SitePageHeader의 breadcrumbs API를 사용한다. 경로는 현재 화면 h1 바로 위에 같은 시작 정렬선과 공통12px title rhythm으로 표시한다. 마이페이지/매장 운영 같은 영역명은 경로에서 전달하고 h1은 현재 기능명이다. 내부의 중복된 기능 제목은 제거하되 SectionHeader titleHidden으로 기존 도움말·보기 선택·aria-labelledby 대상은 보존한다. 편집기는 고유한 상태/공개 주소/저장 도구를 유지하며 그 제목 위의 목록 이동을 공통 SiteBreadcrumb으로 표현한다. 일반 공개/마케팅/고객 메뉴판은 이 관리 화면 이전과 구분한다.

내 메뉴판의 이용 중·이용 만료/보관·종료됨은 같은 ContentPanel 세로 카드를 사용한다. 썸네일16:9 프레임 → 이름/주소/상태 → 기간 정보 → 기존 실행 순서다. 고객 메뉴 렌더러/이미지 원본 비율은 변경하지 않는다. 본문 컨테이너42rem 이상2열,72rem 이상3열, 미만1열이며 카드 사이24px, 내부16px와 기존 panel inset을 사용한다. 기존 버튼/권한/비활성 사유/미리보기/QR/복구/결제내역과 종료 사유를 보존한다. 종료 카드에 편집/공개/QR을 추가하지 않는다.

MENU_CARDS_PER_PAGE=12이며 선택한 탭 전체(권한 허용된 직원 참여 포함)를 이름 검색한 뒤 페이지를 자른다. 검색 변경과 탭 전환은1페이지로 초기화한다. 결과12개 이하에서는 페이지 번호를 숨긴다. 페이지 선택 후 결과 시작으로 스크롤/키보드 초점을 옮기고 공통 SitePagination의 현재 페이지/처음/이전/다음/마지막 접근성을 유지한다.

기존 디자인 템플릿 상세의 독자 breadcrumb도 같은 SiteBreadcrumb과 site-stack-title12px 경계로 이전한다. 상세의 설명/갤러리/신청/도킹 구조·글자 역할은 유지한다. 브레드크럼이 없던 공개/마케팅 화면에 경로를 일괄 추가하지 않는다.
