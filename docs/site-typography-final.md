> 버튼·필드 라벨·드롭다운 옵션 내부의 글자·높이·간격은 [컴포넌트 크기·간격 기준](site-component-density.md)을 우선한다. 기본 조작14px, 필드32/40/44/48px, 옵션32px·gap0·안쪽8px이며 터치 기준은 별도로 유지한다. GNB·계정/사이드바 탐색·페이지/섹션/콘텐츠 제목·설명·본문은 컴포넌트 밀도 조정에서 제외하며 기존 크기와 와이드 보정을 유지한다.

# 최종 사이트 폰트 기준

공식 사이트는 메인과 일반 페이지의 제목 크기를 구분하고 본문 글자 위계를 공유한다. 역할별 크기·굵기·행간·자간은 아래 표와 디자인 시스템에서 확인할 수 있다.

## 공식 사이트 대표 서체 (2026-11-19)

- 영문 알파벳 A–Z/a–z는 Tenor Sans, 한글·숫자·기호는 Pretendard다. 혼합 문장도 공통 `--font-family-site-ui: "ArtiMenu Site Latin", "Pretendard", "Noto Sans KR", system-ui, sans-serif` 스택으로 문자별 적용한다. `styles/fonts.css`의 사이트 전용 Tenor Sans 별칭은 `unicode-range: U+0041-005A, U+0061-007A`로 알파벳만 담당한다. 숫자·문장부호·통화·백분율 기호는 다음 Pretendard에서 표시한다. 글리프가 없는 문자는 기존 대체 서체 순서를 따른다.
- 공식 사이트 본문·제목·탐색·버튼·입력·공통 팝업은 이 스택을 상속한다. 기존 역할별 크기·굵기·행간·자간은 유지한다.
- 고객 메뉴판 디자인·저장된 서체·스타터·실제 렌더러·미리보기/시연 안의 메뉴판 글자에는 적용하지 않는다. 원본 `Tenor Sans`의 문자 범위와 메뉴판의 `--menu-font-ko`/`--menu-font-en`, Tailwind 기초 `--font-sans`는 독립적으로 유지한다. 메뉴판 뷰어/렌더러가 참조하는 기존 `--font-family-site` 스택도 그대로 보존하며 사이트 UI는 새 `--font-family-site-ui`만 사용한다. 로고·서체 선택기의 서체 견본·코드 식별자용 고정폭 서체는 기존 그래픽/의미 역할을 보존한다.
- 변경 시 `node scripts/qa-site-fonts.mjs`로 실제 렌더링 서체를 문자 종류별로 확인하고, 메뉴판 미리보기의 원본 Tenor Sans 숫자·기호도 함께 확인한다. 메뉴판은 PC·태블릿·모바일에서 변경 전후 서체·크기·굵기를 비교한다.

## 푸터 하단 장식 글자 서체 (2026-11-12)

공통 푸터 하단의 큰 ArtiMenu 텍스트도 `--font-family-site-ui`를 사용해 영문 Tenor Sans를 적용한다. 기존 Pretendard 고정 예외는 제거한다. 장식의 크기·굵기·행간·자간·색상과 회색 표면 안에서 하단이 잘리는 구성은 유지한다. 별도 로고 자산과 고객 메뉴판 서체에는 적용하지 않는다.

## 헤더 주메뉴 굵기 (2026-11-11)

공식 공통 헤더의 주메뉴와 고객센터 트리거, 모바일·태블릿 전체 메뉴의 상위 탐색 항목은 기존500에서600(`--font-weight-semibold`)으로 한 단계 강조한다. 공통 Navbar에서만 적용하며 일반 `type-nav`·계정 링크·하위 메뉴의 기존 굵기는 유지한다. 글자 크기·행간·자간·헤더 높이·배치·서체 정책과 고객 메뉴판 디자인은 변경하지 않는다.

## 공식 사이트의 글자 위계 (2026-11-19)

메인 스크롤 장면·서비스 소개 제목은28/32/36px이다. 일반 페이지 제목은28/28/32px, 일반 섹션 제목은24/24/28px이다. 주요 제목은700/1.28이다. 자간은 모바일-.04em, 태블릿·PC-.05em이다. 기존 설명은 페이지 제목 아래 `type-page-description`, 섹션의 짧은 소개에는 `type-body-lg`를 사용하며 두 역할 모두18/18/20px·500·1.55·-.03em이다. 자세한 본문16px은400·1.65·-.02em, 보조 설명14px은400·1.6·-.02em이다.

하위 구역 제목20/20/24px은500·1.35·-.04em, 콘텐츠 제목18px은500·1.4·-.03em이다. 소제목은 실제 구획을 나타낼 때 사용한다. 메뉴판 자체의 글자·편집 설정·미리보기와 시연 안의 메뉴판 이미지는 독립된 규칙을 따른다. 확대 히어로 역할은 필요 시 메인에만 사용할 수 있으며 현재 장면 제목은 메인의 섹션 크기를 사용한다.

## 관리 화면의 밀도

마이페이지, 메뉴 편집기, 매장 운영의 `.site-management-scope`는 PC에서도 한 화면에 작업 정보가 읽히도록 페이지 제목28/28/32px·700, 페이지 설명16px·400·1.5를 적용한다. 내부 구역 제목24px·700, 폼 구역 제목20px·700, 콘텐츠 제목18px·600, 항목 제목16px·500, 기본 본문16px·400, 보조 설명14px·400, 라벨14px·500, 메타13px·400을 사용한다. 본문 행간은1.5, 보조 설명은1.45다. 통계와 작은 결제 금액은24px·700이다. 제목 자간은-.04em을 사용한다. 크기와 굵기는 `SITE_MANAGEMENT_INTRO`와 `SITE_MANAGEMENT_TYPE_ROLES`가 디자인 시스템에 표시한다.

마이페이지의 안내 문단은400, 상태·메타 강조와 폼 라벨은500, 실행 조작 문구는600을 사용한다. 관리 화면에서 열리는 결제·구독·계정·편집 확인창도 같은 범위를 상속하되, 공통 팝업 제목18px과 본문14px 기준은 유지한다.

로그인·가입·복구뿐 아니라 베이직·다이닝·디스플레이·고객센터·신청·요금·템플릿 목록에서 H1 바로 아래 페이지 소개는 `type-page-description`을 사용한다. 비밀번호 찾기, 이메일 찾기, 회원가입, 로그인 복귀 같은 계정 보조 이동은 `type-body-sm`을 사용해 페이지 설명보다 작게 표시한다. 섹션에서 메시지를 요약하는 짧은 소개에는 `type-body-lg`를 사용한다.

베이직·다이닝·디스플레이처럼 화면을 전환하는 글자는 본문이 아니다. 탭·세그먼트의 컨트롤 라벨이며 주요 화면 탭은lg18px·md16px, 독립 영역 탭은md16px, 일반 md는15px, 조밀한 sm은14px을 사용한다. 같은 역할과 크기는 페이지마다 동일하며 자세한 모양·색·굵기는 최종 탭 역할 계약을 따른다. 템플릿 상세의 디자인명 아래 템플릿 설명과 개별 기능 소개문은 기본 본문16px·400을 쓴다. 기능 카드 요약과 상세 기능 설명도 기본 본문이다. 페이지 전체 개요에는 강조 본문18/18/20px을 사용한다. 오른쪽의 포함 기능 요약·디자인 교체 안내·구독 및 결제 안내는 보조 본문14px·400을 쓰고 이미지 캡션·분류는 메타13px이다. 제목과 설명은 공통 제목 묶음, 개요의 이미지·텍스트·기능 목록은 공통 콘텐츠 간격, 개별 기능의 이미지·설명·목록은 공통 그룹 간격으로 맞춘다.

## 적용 범위와 경계

메인·서비스·가격·상품·템플릿 목록과 상세·고객센터와 공지·가이드·로그인/가입/계정복구·신청·마이페이지·문의·결제·알림·계정·직원·운영·편집·관리자·약관/개인정보/오류 화면의 읽는 UI를 포함한다. 공통 Dialog·Popover·Toast·폼과 카드도 같은 기준을 따른다. 탭·알림창의 형태, 색상, 배치, 서비스 동작은 이번 폰트 정리에서 바꾸지 않는다.

고객이 제작하는 메뉴판과 Display/Pickup 등 손님용 엔진, 메뉴판 미리보기/제품 시연 그림 안의 글자, 로고는 별도 그래픽 경계다. 푸터 장식 글자는 서체만 공통 사이트 스택을 따르며 별도 크기·잘림 구성은 유지한다. 메뉴판 기초 `--font-size-*`, 저장된 글자 설정·실제 렌더러·모바일 읽기 비율은 변경하지 않는다. 사이트 전용 `--site-type-*`만 사용한다.

공지의 저장 데이터와 편집 기능은 유지하고, 공개 화면은 기존 허용 크기를 공통 단계 변수에 연결한다. 실제 데이터 저장·결제·AI 질의·동의는 폰트 검수에 포함하지 않는다.

## 2026-10-29 와이드 화면 보정

사용자의 와이드 화면 요청이 이전의 모든 폭 고정 크기 규칙을 대체한다. 기준은 제품 해상도나 devicePixelRatio가 아니라 실제 브라우저 CSS viewport 너비다. 1,600px까지 기본 역할 크기를 유지한다. 1,600–2,600px에서는 모든 `--site-type-*`에 동일한 비율(1 → 1.125)을 적용하고 이후 12.5%에서 제한한다. 1,920px는 +4%, 2,560px는 +12%다. CSS는 `clamp(base rem, base × .8 rem + base px / 80 vw, base × 1.125 rem)`이며 16px root 기준이다. 기준 rem·브라우저 확대를 유지하며 html font-size나 메뉴판의 `--font-size-*`는 변경하지 않는다. 공개 페이지와 관리 화면은 각 역할의 기본 크기에 같은 와이드 보정을 적용한다. 라이브러리 표는 기본값이고 실제 샘플은 공통 보정을 받는다.

폭·간격은 전부 글자와 같은 배율로 확대하지 않는다. 사이트 콘텐츠 바깥 최대 폭은 100rem을 유지하며 와이드 gutter는 40–48px, 페이지·구역 간격과 그리드 gap은 기존 최대값의 최대 12.5%까지 제한한다. 단일 인증 폼은 폭 26–29.25rem, 인증 main은 화면 높이 기반 최소 높이와 세로 중앙 정렬을 사용하지 않는다. 위아래 여백과 제목→폼 간격은 일반 페이지의 공통 토큰을 따른다(`site-page-layout-contract.md`, 2026-11-11). 마이페이지는 기존 여러 열의 자연 흐름을 유지한다. 미리보기는 아래 문서의 가용 공간 맞춤 정책으로 독립 처리한다.

## 새 페이지·수정 화면 자동 적용

공통 스타일은 루트 layout에서 로드한다. 새 페이지는 `type-page-title`, `type-page-description`, `type-body` 등의 의미 역할과 공통 버튼, `site-gutter`, `site-page-spacing`/compact, `site-section-spacing`, `site-card-grid`를 사용한다. 별도 화면별 미디어 쿼리 없이 같은 와이드 보정을 자동 상속한다. 기준·토큰과 컴포넌트 라이브러리는 공통 `WideScreenRules`와 `SITE_WIDE_TYPE_POLICY`를 사용해 동일한 표를 표시한다. 역할·배율·전역 로딩·새 파일의 사설 폰트 크기를 계약 검사로 확인하며 공통 기초 토큰의 지역 재정의를 금지한다. 일반·turbo·debug 빌드는 `check:site-ui`를 먼저 실행해 새 파일에도 같은 계약 검사를 자동 적용한다.

미리보기의 상단 도구는 보조 조작 역할이다. 14px/600 기본 문구·36px 높이, 모바일 터치 높이44px을 사용하고 공통 글자 보정만 따른다. 기본 막대는480–576px, 주문·호출이 있으면 최대688px, 묶음형·채움형도 있으면 최대848px 안에서 가용 폭을 넘지 않으며 좁을 때 줄바꿈한다. 주문·호출·배치 전환은 상단에 유지하고 보기 옵션으로 옮기지 않는다. 목업 표시 크기는 글자 보정과 독립적이다. 최신2026-10-31 기준으로 태블릿·모바일 목업은 페이지 전체의 중앙에서 가용 영역을 채우되 최대1.25배다. 옵션 패널/상단 도구는 레이어이며 공간을 예약하지 않는다. PC는 테두리 없이 실제 뷰포트를 채운다. 모바일 브라우저의 PC 선택은1440×900 PC 구성을 축소해 전체를 보여준다. 고객 메뉴 렌더러의 글자·내용·fit 알고리즘은 변경하지 않는다.

크기·여백 조정은 기능이나 버튼 위치 변경을 포함하지 않으며 사용자 요청 없이 옮기거나 숨기지 않는다. 실제 계산과 두 라이브러리 표는 같은 정책 데이터를 사용한다.

## 2026-11-03 행간·자간·굵기 정리

[코오롱몰 ACC](https://www.kolonmall.com/View/ACC)의 Pretendard와 작은 음수 자간을 참고하되, 아티메뉴의 기존 글자 크기·반응형 단계·와이드 배율과 버튼 높이·색상·위치·기능은 유지한다. 공식 사이트 UI에만 적용하며 고객 메뉴판 렌더러, 스타터데이터, 메뉴판의 실제 서체·굵기·행간·자간은 수정하지 않는다. body, html, 메뉴판의 --font-size-*와 --menu-* 토큰 및 일반 Tailwind 글자 크기·굵기 유틸리티도 바꾸지 않는다.
