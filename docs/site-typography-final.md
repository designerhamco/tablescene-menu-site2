# 최종 사이트 폰트 기준

2026-10-26 사용자가 첨부한 홈 플랜 화면의 전체 비율을 기준으로 한다. PC에서 페이지 제목36px/700, 큰 구역 제목28px/700, 하위 구역 제목24px/700, 대표 가격44px/900, 페이지 설명·일반 본문16px/400, 버튼16px/600, 보조 설명14px, 하단 작은 안내13px로 역할을 고정한다.

## 단일 기준

- 기준 데이터는 `lib/site-typography.ts`의 `SITE_TYPE_STEPS`와 `SITE_TYPE_ROLES`다. 실제 CSS는 `styles/typography.css`, 라이브러리의 역할 표는 같은 데이터를 직접 표시한다. 단위·계약 검사가 CSS와 데이터의 일치를 확인한다.
- 사이트 전용 단계는 13·14·15·16·18·20·24·28·32·36·44px다. 일반 읽기 문구는 13·14·16·18·20px 다섯 단계만 사용한다. 15px은 모바일·태블릿 컨트롤 문구와 중간 탭에만 사용하고, 24px 이상은 큰 구역 제목·페이지 제목·가격·핵심 수치에만 사용한다. 페이지나 컴포넌트에서 임의 크기·fluid clamp를 추가하지 않는다. 아래 와이드 보정만 공통 기초 토큰에서 적용한다.
- 모바일은 768px 미만, 태블릿은 768–1023px, PC는 1024px 이상이다. 기기별 기본 단계를 사용하며 rem과 브라우저 글자 확대는 존중한다. 표의 px 수치는 기본값이다.

## 관리 화면의 밀도

마이페이지, 메뉴 편집기, 매장 운영 화면의 **페이지 제목은 일반 페이지와 같은 기준**을 쓴다. 페이지 제목은 모바일28px·태블릿32px·PC36px/700이다. 제목 바로 아래 문구는 마케팅 문구가 아니라 기능 설명이므로 모든 기기에서16px/400의 `type-page-description`을 사용한다. `.site-management-scope`의 조밀한 역할 체계는 그 아래의 실제 작업 영역에만 적용한다. 큰 구역 제목24px/700, 폼 구역 제목20px/700, 콘텐츠 제목18px/600, 항목 제목16px/600, 일반 본문16px/400, 보조 설명14px/400, 라벨14px/600, 메타13px/500로 고정한다. 통계와 작은 결제 금액은24px/700이다. 같은 역할이 페이지마다 달라지지 않게 하고, 카드·폼·내역의 밀도만 페이지 도입부보다 낮춘다.

마이페이지의 안내 문단은400, 상태·메타 강조는500, 폼 라벨과 조작 문구는600을 사용한다. 관리 화면에서 열리는 결제·구독·계정·편집 확인창도 같은 범위를 상속하되, 공통 팝업 제목18px과 본문14px 기준은 유지한다.

로그인·가입·복구뿐 아니라 베이직·다이닝·디스플레이·고객센터·신청·요금·템플릿 목록과 상세 화면에서 H1 바로 아래 설명은 모두 `type-page-description`을 사용한다. 비밀번호 찾기, 이메일 찾기, 회원가입, 로그인 복귀 같은 계정 보조 이동은 `type-body-sm`을 사용해 페이지 설명보다 작게 표시한다. `type-body-lg`는 페이지 상단의 별도 크기가 아니라 섹션 안에서 기본 본문보다 강조할 짧은 문장에만 사용한다.

베이직·다이닝·디스플레이처럼 화면을 전환하는 글자는 본문이 아니다. 탭·세그먼트의 컨트롤 라벨이며 주요 화면 탭은lg18px·md16px, 독립 영역 탭은md16px, 일반 md는15px, 조밀한 sm은14px을 사용한다. 같은 역할과 크기는 페이지마다 동일하며 자세한 모양·색·굵기는 최종 탭 역할 계약을 따른다. 템플릿 상세에서는 디자인명 아래 문구와 기능 섹션의 설명이 기본 본문16px, 기능 카드 요약이 보조 본문14px, 날짜·과금 주석이 메타13px이다.

## 적용 범위와 경계

메인·서비스·가격·상품·템플릿 목록과 상세·고객센터와 공지·가이드·로그인/가입/계정복구·신청·마이페이지·문의·결제·알림·계정·직원·운영·편집·관리자·약관/개인정보/오류 화면의 읽는 UI를 포함한다. 공통 Dialog·Popover·Toast·폼과 카드도 같은 기준을 따른다. 탭·알림창의 형태, 색상, 배치, 서비스 동작은 이번 폰트 정리에서 바꾸지 않는다.

고객이 제작하는 메뉴판과 Display/Pickup 등 손님용 엔진, 메뉴판 미리보기/제품 시연 그림 안의 글자, 로고와 사용자가 따로 승인한 푸터 장식 워드마크는 별도 그래픽 경계다. 메뉴판 기초 `--font-size-*`, 저장된 글자 설정·실제 렌더러·모바일 읽기 비율은 변경하지 않는다. 사이트 전용 `--site-type-*`만 사용한다.

공지의 저장 데이터와 편집 기능은 유지하고, 공개 화면은 기존 허용 크기를 공통 단계 변수에 연결한다. 실제 데이터 저장·결제·AI 질의·동의는 폰트 검수에 포함하지 않는다.

## 2026-10-29 와이드 화면 보정

사용자의 와이드 화면 요청이 이전의 모든 폭 고정 크기 규칙을 대체한다. 기준은 제품 해상도나 devicePixelRatio가 아니라 실제 브라우저 CSS viewport 너비다. 1,600px까지 기본 역할 크기를 유지한다. 1,600–2,600px에서는 모든 `--site-type-*`에 동일한 비율(1 → 1.125)을 적용하고 이후 12.5%에서 제한한다. 1,920px는 +4%, 2,560px는 +12%다. CSS는 `clamp(base rem, base × .8 rem + base px / 80 vw, base × 1.125 rem)`이며 16px root 기준이다. 기준 rem·브라우저 확대를 유지하며 html font-size나 메뉴판의 `--font-size-*`는 변경하지 않는다. 로그인·마이페이지·서비스·템플릿에서 같은 역할의 크기는 동일하다. 라이브러리 표는 기본값이고 실제 샘플은 공통 보정을 받는다.

폭·간격은 전부 글자와 같은 배율로 확대하지 않는다. 사이트 콘텐츠 바깥 최대 폭은 100rem을 유지하며 와이드 gutter는 40–48px, 페이지·구역 간격과 그리드 gap은 기존 최대값의 최대 12.5%까지 제한한다. 단일 인증 폼은 폭 26–29.25rem, 인증 main의 최소 높이는 화면 가용 높이와 56rem 중 작은 값으로 제한한다. 마이페이지는 기존 여러 열의 자연 흐름을 유지한다. 미리보기는 아래 문서의 가용 공간 맞춤 정책으로 독립 처리한다.

## 새 페이지·수정 화면 자동 적용

공통 스타일은 루트 layout에서 로드한다. 새 페이지는 `type-page-title`, `type-page-description`, `type-body` 등의 의미 역할과 공통 버튼, `site-gutter`, `site-page-spacing`/compact, `site-section-spacing`, `site-card-grid`를 사용한다. 별도 화면별 미디어 쿼리 없이 같은 와이드 보정을 자동 상속한다. 기준·토큰과 컴포넌트 라이브러리는 공통 `WideScreenRules`와 `SITE_WIDE_TYPE_POLICY`를 사용해 동일한 표를 표시한다. 역할·배율·전역 로딩·새 파일의 사설 폰트 크기를 계약 검사로 확인하며 공통 기초 토큰의 지역 재정의를 금지한다. 일반·turbo·debug 빌드는 `check:site-ui`를 먼저 실행해 새 파일에도 같은 계약 검사를 자동 적용한다.

미리보기의 상단 도구는 보조 조작 역할이다. 14px/600 기본 문구·36px 높이, 모바일 터치 높이44px을 사용하고 공통 글자 보정만 따른다. 기본 막대는480–576px, 주문·호출이 있으면 최대688px, 묶음형·채움형도 있으면 최대848px 안에서 가용 폭을 넘지 않으며 좁을 때 줄바꿈한다. 주문·호출·배치 전환은 상단에 유지하고 보기 옵션으로 옮기지 않는다. 목업 표시 크기는 글자 보정과 독립적이다. PC는 canvas 가용 공간100%에서 비율을 유지해 최대 크기로, 태블릿은 가로·세로90%에서 표시한다. 두 기기의 과거1.25배/1배 상한은 제거하고 가용 공간 자체가 상한이 된다. 모바일 목업은 기존90%/84%·최대1.25배를 유지한다. 실제 내부 기기 뷰포트와 고객 메뉴 글자 크기는 유지한다.

일반 페이지 제목과 영역 탭 여백, 고객지원 경로의 현재 기준은 [페이지 간격 계약](site-page-layout-contract.md)을 따른다.

바깥 브라우저가768px 미만일 때는 PC·모바일의 가용 폭·높이100%/최대1배를 유지하되 태블릿은 가용 폭90%·높이90%/최대1배로 구분한다. 화면이 좁다는 이유로 두 기기를 모두 같은 가로100%에 맞추지 않는다. 크기·여백 조정은 기능이나 버튼 위치 변경을 포함하지 않으며 사용자 요청 없이 옮기거나 숨기지 않는다. 실제 계산과 두 라이브러리 표는 같은 정책 데이터를 사용한다.
