# 알림 표시와 데이터 보관 정책

2026-11-03. 공식 사이트 알림만 해당한다. 고객 메뉴판·주문·호출 렌더러와 별도다.

## 승인 및 적용: 최근90일 표시

- 공통 `NOTIFICATION_DISPLAY_DAYS`와 `getNotificationDisplaySince`가 기준이다. 조회 시각에서90×24시간 전을 UTC ISO로 계산하며 경계 시각을 포함한다. 읽지 않은 알림도 동일하게 만료된다. 한국 시간은 표시용 날짜에만 적용한다.
- 헤더 목록/배지, `/notifications` 목록/배지, 마이페이지 목록/배지와 모두 읽기가 같은 범위를 사용한다. 한 요청의 목록과 개수는 한 번 계산한 기준 시각을 공유한다. 모두 읽기는 처리 시각 이후 새 알림과90일보다 오래된 기록을 변경하지 않는다.
- 기존 조회 상한은 헤더10개, 전용/마이페이지 최신50개다. 모두 읽기는 이 상한과 무관하게 최근90일 전체 미확인 알림을 처리한다. 현재 페이지네이션 확장은 이번 범위가 아니다.
- 헤더: “최근 90일의 알림 중 최대 10개를 표시합니다.”
- 내역: “최근 90일 동안 받은 알림을 확인할 수 있습니다. 결제·구독 및 문의 내역은 각 메뉴에서 확인해주세요.”
- 원본 행·발송 기록·결제/구독/문의 내역은 삭제하지 않는다. 기존 인증/RLS/계정 격리/채널·상태 필터를 유지한다. 공통 패널의 기능/탭/버튼 위치는 바꾸지 않는다.

## 제안만: 실제 데이터 보관·삭제

아래는 운영 검토용 제안이다. 아직 승인된 파기 정책이나 실행된 자동 삭제 작업이 아니다. 문구 노출만으로 데이터 삭제를 약속하지 않는다.

| 데이터 | 제안 | 도입 조건 |
| --- | --- | --- |
| 알림 제목·본문·고객 표시용 메타데이터 | 생성 후1년까지 운영 문의 대응용으로 제한 보관하고 이후 삭제 | 문의 대응 범위·기존 개인정보 처리방침과 맞는지 검토 후 확정 |
| 이메일 재시도/대기·실패 정보 | 처리 중인 기록은 단순 날짜로 삭제하지 않음 | 미완료 작업·재시도 종결 기준 확정 |
| 중복 발송 방지용 최소 기록 | 본문과 분리하고 이벤트 유형·대상·발송 식별키·결과 등 필요한 필드만 관리 | 현재 생성 경로가 `notification_events`의 `metadata.period_key` 존재 여부로 중복을 방지하므로 분리 이전에 원본 삭제 금지. 최소 기록의 기간과 계정 종료 처리도 이벤트별로 확정 |
| 결제·구독·문의 원본 | 알림 표시/삭제와 별도로 기존 정책 적용 | 이 문서로 원본 보관 기간을 새로 정하거나 변경하지 않음 |

도입 순서: 데이터 용도/최소 필드/보관 기산점 확정 → 중복 방지 기록 분리 및 재발송 회귀 검증 → 읽기 전용 dry-run으로 삭제 후보·제외 사유 확인 → 실제 삭제 범위 승인 → 배치 삭제·실패 관측. 백업의 별도 만료와 회원 탈퇴 시 처리는 기존 정책과 함께 검토한다. 이번 변경에는 마이그레이션·삭제 SQL·삭제 cron이 없다.
