# 관리 표의 디자인 시스템 정리

2026-11-05. 기존 Table 기본 부품은 있었지만 직전 관리 표에 정식 라이브러리 예시·열 너비 API가 없었고, Tabs 기본8px 간격이 탭·추가·목록 사이에도 적용되고 있었다. 이번에는 작업 간격과 표의 역할을 공통 시스템으로 정리했다.

- 보기 전환 → 추가 버튼 → 목록 묶음은 공통24px, 제목 → 표는16px를 사용한다. 중첩된 stack에서 표 너비가 페이지를 밀지 않도록 공통 스크롤 영역이 inline-size를 소유한다.
- 헤더는 위아래12px·좌우16px와 최소56px, 본문은16px 안쪽과 최소64px 행을 사용한다.44px Switch가 있으면 행이76px 이상으로 커지고 긴 이름도 여러 줄로 확장된다. 이름은 기존16px 항목 역할을 사용하며 와이드 공통 보정만 따른다.
- 업무별 data-column 퍼센트를 제거하고 compact/text/detail/control/actions 공통 열 역할을 추가했다. 선택한 역할 합계로 최소 너비를 정하며 읽기 전용 일반 표에는 고정 최소 너비를 강제하지 않는다. 기존 default Table의 외형은 유지한다.
- /design-system#management-tables에 규칙·실제 조작·긴 이름·읽기 전용·저장 대기·도움말·숫자 끝 정렬 예시를 등록했다. 공통 데이터와 CSS 값을 계약 검사로 비교하며 모든 빌드 모드의 기존 UI 검사에도 포함했다.

## 검증

- 라이브러리를 실제 DOM viewport320×780·390×844·820×1180·1440×900·1920×1080·2600×1200에서 실측했다. 페이지 가로 넘침0px, 셀 내용 넘침0건, 헤더12/16px·본문16px가 일치했다. 이름은16px → 16.64px → 18px로 기존 공통 와이드 정책을 따랐다. Switch와 버튼의 조작 크기는 유지됐다.
- 실제 MenuTableManager를 렌더링한 임시 예시 화면에서도320/390/820/1440/1920px의 간격24/24/16px, 페이지 넘침0px을 확인했다. 좁은 표 영역의 키보드 가로 이동, 보기 전환 중 등록 초안 보존, 이름 수정 Enter/Escape를 확인했다. 실제 등록·저장·연결·보관·삭제는 제출하지 않았다. 브라우저 오류·경고0건이었다. 임시 경로는 빌드 전에 제거했다.
- 전체 테스트1,069건, 사이트 UI 계약114건, TypeScript·변경 파일 ESLint와 프로덕션 빌드를 확인했다. 새 DB/기기/결제 동작 변경은 없다.
