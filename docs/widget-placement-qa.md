# 위젯 배치·열 분리선 검수 — 2026-11-10

## 수정 원인과 범위

활성 Basic PC·태블릿 읽기 엔진은 위젯의 저장된 `bottom` 값을 일반 콘텐츠처럼 분배했다. 구성 페이지 역시 배치 방식과 상관없이 이동을 허용했다. 다이닝 렌더러는 위젯을 모든 카테고리 뒤에 한꺼번에 출력해 혼합 순서를 무시했다. 추가로 구성 페이지 위/아래 버튼이 교환 후의 배열에서 이동 대상을 읽어 자기 자신을 대상으로 넘기는 기존 오류를 수정했다.

`lib/menu-widget-placement.ts`가 Basic/Dining의 배치 의미와 순서 정규화를 담당한다. 편집 초기값, 로컬 반영, 최종 직렬화와 기존 권한 검사 뒤의 저장 계획이 같은 정책을 사용한다. DB 스키마·권한·업로드·고객 데이터는 변경하지 않았다.

Basic 하단 위젯은 마지막 실제 메뉴 열에서 안내 바로 위에 정렬하고, 안내가 없으면 바닥에 정렬한다. 안내는 해당 열의 실제 내부 바닥에 놓인다. 기존 상단행/대표영역 안내 위치는 유지한다. 모바일은 마지막 메뉴 다음 자연 흐름이다. Dining은 기존 bottom도 혼합 순서형으로 읽으며 배치 선택을 표시하지 않는다. Display/Brew/Noir는 기존 위젯 미지원 상태다. 이미지 비율·색상·모바일 읽기 크기는 유지한다.

MELLOW 메뉴 열 사이 세로선의 양쪽 여백은 각각 페이지 안쪽 여백이다. 전체 열 간격은 `2 × inset + 1px`이며 가시 배치와 측정 후보에 같은 계산을 사용한다. 대표영역 경계·헤더 간격·페이지 패딩은 바꾸지 않았다.
