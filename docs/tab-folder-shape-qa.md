# 파일형 탭 윤곽 통일

## 기준

- 라이브러리의 ‘탭·세그먼트의 역할과 크기’에서 연결형(`contained`)은 파일형(`folder`)과 같은 버튼 윤곽·패딩·선택색·상태·rail 경계를 공유한다. 공통 CSS 선언을 함께 사용하며 파일형 스타일을 따로 복제하지 않는다.
- 연결형의 문구 기반 폭, 흰 목록 패널과 12px 하단 모서리, Radix 선택/패널 연결을 유지한다. 상위 밑줄 탐색과 보기 전환 세그먼트의 역할은 유지한다.
- 라운드 연결형(`flow`)은 기존 흰 선택면·짧은 밑줄·둥근 외곽 패널을 유지한다. 오목한 radial-gradient 연결부를 제거하고 동일한 `tab-folder-mask.svg`의 사선 옆면과 둥근 모서리를 사용한다. hover/pressed 표면도 같은 마스크 안에서 그린다.
- sm/md/lg 40/44/48px rail, 14/15/16px 글자, 비활성 건너뛰기와 방향키/Home/End는 기존 공통 규격이다. 좁은 화면은 rail 안에서만 가로 스크롤한다.

## 검증

기존 계약 테스트·변경 TSX lint·최적화 빌드, 실제 320/390/820/1440px의 세 크기와 세 변형을 확인한다. 연결형/파일형의 실제 스타일 일치, flow의 공통 mask·오목한 장식 부재·밑줄, 패널 연결과 선택/키보드/비활성 상태를 비교한다. 실제 `/faq`와 `/templates`에서 목록 탭·문구 기반 폭·가로 넘침을 확인하며 고객 메뉴판 렌더러는 변경하지 않는다.

## 결과

- 기존 계약/단위 854건, 변경 TSX 4개 lint, 타입 검사를 포함한 최적화 빌드와 diff 공백 검사를 통과했다.
- 최적화 빌드의 실제 320×1000, 390×1000, 820×1000, 1440×1000에서 세 크기×세 변형 36개 조건을 비교했다. contained/folder의 글자·굵기·색·패딩·최소 높이·mask·선택 표면이 같았고 5개 상태 표의 선택색·표면·포커스·비활성도 일치했다.
- flow는 같은 mask와 흰 선택 표면, 3px 짧은 밑줄을 확인했다. 의사 요소에 오목한 radial-gradient가 없으며 세 크기에서 목록 패널과 틈 없이 연결된다.
- 각 변형의 클릭·방향키·Home/End·비활성 건너뛰기와 `/faq`, 현재 템플릿 목록 `/templates`의 실제 선택 전환을 확인했다. 모든 폭에서 페이지 가로 넘침·브라우저 실행 오류 0건이다.
- 배포 완료는 병합 커밋의 Vercel 성공과 공개 `/design-system`, `/faq`, `/templates`에서 별도로 확인한다.
