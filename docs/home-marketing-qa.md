# 홈 마케팅 화면과 서비스 이동 검증

검증일: 2026-10-16

## 변경

- Next Link로 변경된 주소를 `OriginalApp`의 화면 선택과 스크롤 복원에도 사용한다. 별도 BrowserRouter의 이전 주소가 남아 다이닝·디스플레이 본문이 어긋나던 경로를 제거했다.
- 홈·다이닝의 히어로를 후속 제공 이미지 `모니터·태블릿·스마트폰 쇼케이스.png`로 교체했다. 투명도를 보존한 1672×941 WebP는 `public/assets/artimenu-home-showcase.webp`이며 약 105KB다. 새 파일 주소를 사용해 이전 히어로 이미지 캐시와 구분한다.
- 히어로 문구는 `디지털 메뉴판의` / `새로운 경험` 두 줄로 바꿨다. 작은 소개 문구와 기존 영문 문구를 제거하고 제목을 이미지 박스 밖에 배치한다.
- 1280px 이상은 제목→이미지, 1280px 미만은 이미지→제목 순서다. 모바일 640px 미만은 세로형 0.95 비율 박스와 확대된 기기 이미지, 태블릿은 2:1 박스, PC는 2.3:1 박스를 사용한다. 기기 그룹을 보존하면서 배경과 카운터 가장자리를 크롭한다.
- 히어로 프레임은 밝은 회색 `#f4f4f5`, 최대 너비 1520px, 32~48px 모서리로 제한한다. 제목과 이미지는 겹치지 않으며 이미지 기하 비율을 왜곡하지 않는다.
- 최신 요청에 따라 디자이너 템플릿 갤러리는 흰 바탕·어두운 글자를 유지한다. 바로 다음 간편한 메뉴 제작부터 반응형 메뉴판까지는 검정 바탕·밝은 글자, AI와 매장 활용 영역은 흰 바탕·어두운 글자로 전환했다. 홈의 가이드 CTA는 계속 렌더링하지 않는다.
- 공통 헤더와 푸터는 흰 바탕·어두운 글자를 사용한다. 이번 히어로 요청에서는 헤더 파일을 변경하지 않았다. 디스플레이 소개 본문의 기존 섹션 색상은 유지한다.

## 실제 브라우저 결과

히어로는 개발 서버와 로컬 Production 빌드에서 각각 10개 실제 화면 폭을 검사했다. 메뉴 이동 검사는 PC·모바일 왕복과 별칭 3개를 포함한 5개 묶음으로 별도 통과했다.

- PC 1440×1000, 모바일 390×844에서 다이닝→디스플레이→다이닝 3회 반복, 뒤로/앞으로 가기, 새로고침, 디스플레이 직접 진입 후 다이닝 이동이 모두 주소와 본문을 함께 전환했다.
- `/services/basic`, `/services/menu`, `/services/screen`의 직접 진입과 기존 리디렉션을 확인했다.
- 실제 DOM viewport를 아래 치수와 대조했다. 모든 폭에서 가로 넘침 0px, 두 줄 제목, 이미지 박스 밖 제목 배치, 기기별 제목/이미지 순서, 최대 너비, 히어로 다음 섹션의 겹침 없음을 확인했다. PC·태블릿·모바일 스크린샷으로 세 기기가 박스 안에 보이는 것도 확인했다.

로컬 Production 홈의 공개 회귀 검사는 PC 1440×900·모바일 390×844에서 2/2 통과했다. 깨진 이미지, 가로 넘침, console/page error, 같은 출처 요청 실패 및 axe WCAG critical/serious 위반은 0건이었다.

이번 배포 소스의 `npm test` 618/618, `npx tsc --noEmit`, `npm run lint`, `npm run build`, 변경 파일의 `git diff --check`가 통과했다. 공유 작업공간에서 진행 중인 다른 작업과 구분하기 위해 최신 운영 기준 소스를 별도 임시 디렉터리에서 검증했다.
