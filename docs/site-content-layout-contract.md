# 사이트 본문·작업 영역 구성 기준

2026-11-03. 공식 사이트·마이페이지·매장 운영·메뉴 편집기의 사이트 UI에 적용한다. 고객이 제작하는 메뉴판과 공개 주문 화면은 독립된 디자인 경계다. 페이지 제목은 `SitePage`/`SitePageHeader`, 글자는 `site-typography-final.md`, 버튼·입력은 `site-control-contract.md`가 계속 소유한다.

## 확인된 적용 공백

- 폰트 역할·기본 색·버튼·입력·페이지 제목 경계와 모바일 본문 간격은 이미 정의돼 있었다.
- `site-section`/`site-card`는 표면 외형만 정하며 안쪽 padding과 자식 간격은 정하지 않았다. `p-5`, `p-6`, `mt-2`, `mt-3`, `mt-5` 등을 화면에서 선택해 같은 작업 박스의 밀도가 달라졌다. 기존 검사 통과는 본문 구성까지 같다는 증거가 아니었다.
- 이번 테이블 관리에도 20/24px 안쪽 여백 혼용, 16px 폼 라벨, 8/12px 제목-설명 혼용, 공통 필드 padding 덮어쓰기와 미정의 `type-meta`가 있었다. 공통 구성으로 이전했다. 이전 조각의 레거시 허용 기록 3건도 삭제했다.
- `site-control-contract.md`에 남아 있던 버튼 전 기기15px 및 인증 제목30–40px 문구는 최신 타이포 계약과 달라 정정했다.
- 기존의 모든 편집기·관리자·마이페이지 박스가 이번에 이전된 것은 아니다. 기존 화면의 수치형 배치는 해당 영역을 수정할 때 순차 이전한다. 기존 기능·순서·버튼 위치는 디자인 정리만으로 재구성하지 않는다.

## 박스의 역할

| 역할 | 공통 구현 | 표면·경계·모서리 | 안쪽 여백 |
| --- | --- | --- | --- |
| 작업·입력·설정 묶음 | `ContentPanel` | 흰색, 필요한 구분용 공통1px 경계, 12px, 그림자 없음 | 767px 이하20px / 768px 이상24px |
| 보조 정보 묶음 | `ContentPanel surface="muted"` | 옅은 회색, 경계 없음, 12px, 그림자 없음 | 동일 |
| 안내·작업 전제·결과 메시지 | `ContentPanel surface="notice" density="compact"` | 공통 밝은 노랑, 경계 없음, 6px, 그림자 없음 | 모든 기기16px |
| 박스가 필요 없는 연속 콘텐츠 | `site-stack-*` | 배경·외곽선 추가 없음 | 부모의 콘텐츠 경계 사용 |

안쪽 여백은 `--site-panel-inset`, `--site-panel-inset-wide`, `--site-panel-inset-compact`로 관리한다. 작업 박스 모서리는 기존 `--ui-radius-surface`를 사용하며 히어로·이미지·상품 카드의 별도 역할 모서리를 바꾸지 않는다. 회색·유색 박스에 장식 경계를 추가하지 않는다. 카드 안에 필드마다 새 카드를 겹치지 않는다. `ContentPanel`은 className/style로 외형이나 간격을 바꾸는 API를 제공하지 않는다.

## 간격의 소유자

| 관계 | 공통 구성 | 기본 간격 |
| --- | --- | --- |
| 페이지 제목 → 첫 콘텐츠 | `SitePage`/`SitePageHeader` | 모바일32px / 그 이상40px |
| 독립 작업 묶음 사이·박스 안의 제목 묶음 → 폼 | `site-stack-group` / `ContentPanel` | 24px |
| 작업 헤더 → 다음 주요 영역 | `site-stack-content` | 32px |
| 박스·섹션 제목 → 설명 | `site-stack-title` | 12px |
| 필드 사이·연결된 작은 블록 사이 | `site-form-row` / `site-stack-block` | 16px |
| 라벨 → 입력, 이름 → 날짜, 연관 설명 | `site-field-stack` / `site-stack-copy` | 8px |
| 버튼 사이 | `site-action-row` | 8px |
| 구분선 → 다음 내용 | `site-content-divider` | 16px |

숫자는16px rem 기준이다. 바깥 stack이 간격을 소유하면 자식 margin을 더하지 않는다. 제목과 설명을 하나의 `site-stack-title`로 묶고 이 그룹과 폼 사이에24px를 준다. 제목과 설명을 박스 직계 자식으로 나열해24px씩 벌리지 않는다. 구분선 위 간격은 부모 stack, 아래 간격은 divider가 각각 소유한다. 페이지 제목 경계와 카드 안 간격을 혼동하지 않는다.

## 정렬과 반응형

- 관리 화면의 제목·설명·입력·목록은 시작 정렬이다. 페이지·본문·박스·입력의 왼쪽 경계가 각 부모 경계에 맞아야 한다. 숫자 열은 비교가 필요할 때만 끝 정렬한다.
- `site-form-row`는640px 이상에서 라벨을 포함한 폼 열의 하단을 맞추고16px 간격을 준다. 입력·선택 박스 자체와 버튼을 나란히 놓을 때는 `data-alignment="center"`로 실제 컨트롤의 높이 중심을 맞춘다. 이 행 안에는 컨트롤과 숨김 라벨만 두며, 보이는 라벨·도움말은 `site-field-stack`으로 행 바깥에 둔다. 라벨 전체 높이를 포함해 가운데 정렬하지 않는다. 버튼을 필드 높이에 맞춰 늘리거나 개별 margin/translate로 보정하지 않는다. 그 미만에서는 DOM 순서를 유지해 한 열로 쌓으며 공통 높이·전체 폭 동작을 유지한다. 길이가 짧은 상태 필드만 `data-field-width="short"`를 사용한다.
- `site-action-row`는 시작 정렬·내용 너비·8px 간격·자연 줄바꿈이다. 버튼 수에 따라 임의의 균등 폭을 주지 않는다. 전체 폭 완료 행동은 기존의 명시적 폼/편집기 액션 역할을 사용한다.
- 같은 줄의 보조 이동과 상태 스위치는 `site-action-row data-distribution="between"`으로 양 끝 정렬한다. 이동 행동이 없는 단독 스위치는 `data-distribution="end"`를 사용한다. 페이지에서 margin이나 justify 유틸리티로 의미 클래스의 정렬을 덮어쓰지 않는다.
- 제목과 상태는 `site-content-heading-row`로 구분한다.640px 이상에서는 양 끝, 그 미만에서는 제목 다음 상태를 유지한다. 긴 제목은 줄바꿈하고 컨트롤과 겹치지 않아야 한다.
- 표시 아이콘의 colored 래퍼는 SVG 자체 크기만 차지한다.40/48px 타일을 투명하게 남기지 않는다. SVG 크기·잉크와 공통 아이콘→문구 간격은 유지한다. 버튼 hit area는 별도다.

## 폰트와 설명

관리 작업 영역의 큰 제목24px/700, 폼 제목20px/700, 콘텐츠 제목18px/600, 항목 제목16px/600, 본문16px/400, 보조 설명14px/400, 라벨14px/600, 메타13px/500를 기존 역할로 사용한다. `type-meta` 같은 미등록 이름을 만들지 않고 날짜에는 `type-caption`, 하단 도움말에는 `type-footnote`를 쓴다. 입력값은16px/400이며, 폼 라벨의14px를 상속해 축소하지 않는다. font/leading/tracking 유틸리티로 역할을 덮어쓰지 않는다. 일반 본문과 보조 설명은 역할의 줄높이1.625를 따른다. 색은 `site-copy-muted`/`site-copy-subtle`을 사용한다. 페이지 제목과 공통 와이드 배율은 기존 계약을 유지한다.

## 적용과 검사

`styles/site-spacing.css`가 구현을, `lib/site-spacing.ts`가 표시용 역할 표를 소유한다. `/design-system#content-composition`의 실제 `ContentPanel`·폼·안내 예시에서 확인한다. 새/수정 작업 박스에는 `ContentPanel`과 의미별 구성 클래스를 사용한다.

등록 항목의 기본 조회와 편집은 `EditableList`/`EditableListItem`으로 구분한다. 목록 전체에 ContentPanel 하나를 사용하고, 각 행은 이름·상태·공통 compact outline ‘편집’ 버튼만 표시한다. 행 사이는 공통 divider와 block 간격으로 구분하며 개별 행에 카드를 중첩하지 않는다. 제목은 공통 `site-editable-list-title`의12ch 최소 너비를 사용하며, 좁은 화면에서는 상태·편집 묶음이 다음 줄로 내려가 이름을 지나치게 좁히지 않는다. ‘편집’으로 펼친 영역에 입력·연결 상태·보관·삭제를 둔다. 공통 Collapsible의 키보드·aria-expanded/controls 연결을 유지하고, 접어도 작성 중인 입력값은 보존한다. 보관 목록처럼 상세 편집이 필요한 목록에 사용한다. 테이블·키오스크의 운영 목록은 아래의 관리 표를 사용한다.


### 관리 표

한 번에 항목을 비교하고 상태·관리를 바로 실행하는 목록은 공통 `Table variant="management"`를 사용한다. 회색 헤더, 흰 행, 가로 구분선만 사용하고 카드·개별 행 테두리를 중첩하지 않는다. 헤더는 위아래12px·좌우16px와 최소56px, 본문은 상하좌우16px와 행 최소64px를 사용한다. 큰 조작이나 긴 이름이 있으면 행이 자연스럽게 확장된다. 본문14px·주요 이름16px의 기존 글자 역할과 공통 compact 버튼·Switch를 사용한다. 이름은 줄바꿈하고 명시적인 nowrap 조작 묶음만 한 줄로 유지한다. 일반 표는 내용 너비를 사용하며 조작 표는 공통 열 역할의 너비 합계로 최소 너비를 계산한다. 작은 화면에서는 표 영역 안에서만 가로 스크롤하며 region 이름·키보드 포커스·열 제목을 유지한다. 페이지별 셀 여백·글자·스위치 크기를 덮어쓰지 않는다. 정식 치수·예시·열 역할은 `lib/site-table.ts`와 `/design-system#management-tables`가 공유한다.

테이블·키오스크 관리의 순서는 보기 전환 → 추가 버튼 → 운영 목록 제목 → 표다. 종류·이름·공용 태블릿 연결 여부·상태·관리를 열로 표시한다. 이름 수정은 이름 옆 연필 버튼에서 공통 Dialog로 연다. 미연결 테이블은 ‘미사용’, 키오스크는 ‘연결 필요’로 구분하고 실제 연결 정보 조회 실패는 ‘확인 불가’로 표시한다. 상세 기기 정보·연결 필요 조건과 보관/삭제 범위는 공통 InfoTooltip을 사용한다. 상태 스위치는 저장 중 spinner를 표시하고 성공한 서버 상태만 반영한다. 이름 수정과 상태 전환은 각각 필요한 필드만 저장한다.

`check:site-system`은 미등록 type 역할, 별칭으로 가져온 ContentPanel 안의 수치형 여백·글자 덮어쓰기, 의미 구성 클래스의 자체 padding/gap 및 지역 CSS 덮어쓰기, panel 토큰 재정의를 검사한다. 표시 아이콘의 크기를 페이지 CSS에서 다시 키우는 것도 차단한다. 기존 코드 전체의 배치 의미를 자동 추론하는 검사는 아니므로 실제 브라우저에서 경계·간격·글자·아이콘 래퍼 치수·줄바꿈·overflow를 측정해야 한다. 새 예외를 레거시 목록에 추가해 검사를 우회하지 않는다.

## 이번 적용의 검수

- 테이블 생성·운영·보관 목록, 운영 대시보드 제목, 테이블 준비 안내와 공용 단말 안내를 공통 구성으로 이전했다. 생성/복원 서버 동작과 기존 기능 순서는 유지했다.
- 실제 공통 컴포넌트를 렌더링한 임시 로컬 화면에서 DOM viewport320×780,390×844,640×900,820×1180,1440×900,1920×1080,2600×1200을 확인했다. 가로 넘침0px,20/24px 기본 안쪽 여백,16px 조밀 안내,12/16/8px 간격, 폼 하단 정렬과 와이드 타이포 배율이 일치했다.
- 회색 현황 아이콘의 wrapper/SVG가 모두20×20px, 회색 빈 상태는 모두28×28px였다. 흰 현황 카드의 래퍼40×40px와 SVG20×20px는 유지됐다. 검수 화면의 실제 문구 목록도 불필요한 선 없이 원래 목록 형식을 유지했다.
- 디자인 시스템 실제 구성 표와 예시, 생성/복원 대기와 중복 클릭 차단을 별도로 확인했다. 임시 검수 경로는 제거했다. 실제 매장 데이터 변경 요청은 차단했다.
- 사이트 UI 계약106건과 관련 기능/권한 테스트34건, TypeScript·변경 파일 ESLint·별도 출력 경로의 프로덕션 빌드를 통과했다. 기존 컴포넌트 전체의 시각 통일이나 실제 매장 생성·복원을 실행했다는 의미는 아니다.
- 출시 전 전체 테스트1004건도 통과했다. 이전 대시보드 안내 순서와 인라인 피드백의 과거 CSS 클래스를 고정하던 두 검사는 새 배치와 공통 안내 컴포넌트의 계약에 맞게 갱신했다.


## 캔버스와 중복 박스 (2026-11-06)

룸 문서형 탭 아래의 안내·배치 도구·캔버스는 site-stack-group의 연속 콘텐츠로 구성한다. FloorPlanCanvas가 경계와 비율을 소유하므로 동일 영역을 흰 ContentPanel로 다시 감싸지 않는다. 테이블 관리 편집기와 주문·호출 읽기 화면·디자인 시스템 예시에 함께 적용한다. 별도 경고·빈 상태·다른 룸 이동의 보조 영역과 기존 액션 순서는 유지한다. 공통 stack 간격과 실제 캔버스의 포인터·키보드·상대 좌표 처리는 바꾸지 않는다.


## 운영 내역·QR의 표 경계 (2026-11-06)

테이블 관리·주문·호출·QR 리스트는 Table variant=management의 표 경계와 내부 가로 스크롤을 사용한다. 표를 둘러싸는 장식 ContentPanel은 추가하지 않는다. 표 헤더는 빈 결과에서도 유지하며 등록 항목·룸과 실제 내역의 유무를 구분한다. 보기 전환과 룸 탭 이후의 콘텐츠는 site-stack-group24px, 제목과 설명은 site-stack-title12px를 따른다. 공통 Tabs의 기본 gap 유틸리티를 해당 콘텐츠 간격으로 오인하지 않는다.


## 인접 컨트롤 정렬 검수 (2026-11-06)

공통 중앙 정렬 행을 룸 배치도의 선택 박스·바로 배치에 적용했다. 로컬1512px PC,820px 태블릿,390px 모바일에서 입력/선택 예시와 실제 FloorPlanEditor 예시의 정렬·기존 줄바꿈을 확인했다. 당시에는 탭 연필·추가 아이콘을16px로 적용했으나, 같은 날 후속 요청으로 일괄 축소를 취소했다. 현재는 편집 연필만 위치와 관계없이 EditIcon16px를 쓰고 기존 조작 영역은 유지하며, 추가 등 다른 아이콘은 각 컨트롤의 기본 크기를 따른다. 라이브러리 예시에서 연필로 편집 진입 후 Escape 취소·초점 복귀를 확인했다. 전체 테스트1085건, 사이트 UI 계약118건, 변경 파일 ESLint와 Production 빌드를 통과했다. 실제 매장 데이터는 변경하지 않았다.



## 연결형 배치도 편집 작업 영역 (2026-11-06 최종 시안)

- 최신 승인 시안이 기존 배치도 무패널 기록보다 우선한다. 룸 선택·이름 수정·룸 추가와 등록/룸 삭제는 작업 영역 위의 기존 진입을 유지한다. 그 아래 `FloorPlanWorkspace`가 배치 현황/도구 → 캔버스 → 하단 이동·보관·처음으로 되돌리기·저장을 하나의 흰 작업 영역으로 묶는다.
- `ContentPanel layout="canvas"`의 공통 경계·모서리를 사용하며 안쪽 캔버스에는 중복 경계를 두지 않는다. 도구·하단 영역은 공통20/24px panel inset과16px 간격을 사용한다. 하단은 회색 면과 위쪽 구분선으로 연결하고 룸 이동은 왼쪽, 보관/처음으로 되돌리기/저장은 오른쪽에 둔다. 선택 칸과 버튼의 높이 중심을 맞춘다. 별도의 모바일 재설계는 추가하지 않는다.
- 기존4:3 캔버스·상대 좌표·룸 추가/즉시 이름 저장·바로 배치·드래그/크기 조절/방향키·저장/충돌/취소/이탈 보호를 유지한다. 사각형 안 X는 해당 배치 초안만 해제하며 등록·QR·운영 이력은 지우지 않는다. 공통 Tooltip/접근성 이름으로 ‘배치 해제’를 설명한다. X는 사각형 선택 영역의 형제 제어로 두어 드래그/선택/키보드 이동과 중첩하지 않고 해제 후 배치 선택 칸으로 초점을 돌린다. 읽기 전용 운영 배치도에는 X를 추가하지 않는다.
- 테이블·키오스크 관리에 모바일(767px 이하)로 처음 진입하면 공통 Dialog로 PC 편집 권장 안내를 표시한다. 모바일 확인/편집을 제한하지 않으며, 닫은 뒤에는 같은 탭 세션에서 반복하지 않는다. 브라우저 저장 공간이 제한되어도 닫기·편집은 동작한다. 확인·X·Escape로 닫고 보기 유형 탭으로 초점을 돌린다. PC·태블릿에는 자동 표시하지 않는다. 라이브러리는 같은 Dialog와 실제 편집기 예시를 제공한다.

- 선택한 테이블·키오스크 정보 줄은 배치 도구와 캔버스 사이에 일정한 높이로 표시한다. 주문과 호출은 각각 태블릿·모바일 허용 스위치를 사용하며 키오스크에는 매장 기기만 표시한다. 리스트형과 같은 컨트롤·연결 팝업을 공유한다. 보관은 하단으로 분리한다. 등록·보관·허용·기기 연결은 즉시 반영되며 처음으로 되돌리기는 마지막 저장 배치로 돌아간다.


## 2026-11-06 최신 등록·토글·넘침 계약

최신 사용자 지시는 `site-design-system.md`의 ‘상시 등록·한 줄 토글·표 넘침 안내’와 AGENTS.md를 따른다. 등록 폼은 두 보기에서 항상 열려 있고 종류·이름·만들기를 공유하며 취소 버튼은 두지 않는다. 저장된 룸이 있어야 등록할 수 있고 첫 룸은 추가 시 즉시 저장한다. 화면과 서버 모두 룸 없음/조회 실패 시 등록을 막는다. 기존 룸 없는 항목은 리스트에 유지한다. 룸 탭·추가와 맨 오른쪽 삭제 아이콘은 두 보기에 표시한다. 리스트의 룸 열은 제거한다. 선택 정보 전체와 기기별 라벨+소형 Switch는 한 줄이며 ON/OFF 상태 문구를 붙이지 않는다. 리스트형은 ‘저장’만 표시하며 되돌리기 아이콘을 두지 않는다. 배치도형은 ‘배치도 저장’을 사용하고 되돌리기는 캔버스 오른쪽 위, 보관은 선택 사각형 안, 크기조절은16px 아이콘/32px 조작 영역이다. 표 오른쪽에 숨겨진 내용이 남을 때만 공통32px 투명 마스크로 실제 표면색에 맞는 페이드를 표시하고 끝에서는 해제한다. 기존 권한·저장·비활성·실패 처리와 명시되지 않은 기능은 유지한다.

상시 등록의 `site-registration-row`는 PC/태블릿에서 종류 묶음·남은 폭을 쓰는 이름 묶음·공통 행동을 나란히 정렬한다. 각 라벨과 필드는 `--site-space-copy`, 묶음은 `--site-space-block` 간격이며640px 미만은 DOM 순서대로 쌓는다. 개인적인 글자·필드·버튼 크기를 만들지 않는다.

## 마이페이지 정보·선택·내역 (2026-11-06)

- 직원 관리와 마이페이지의 공통 외곽은 `AccountPageContent`가 소유한다. `site-container`가 가로 여백을 한 번 적용하고 `SitePageHeader`가 제목 경계를 소유한다. 직원 관리는 본문 제목을 사용하며 별도 페이지 제목 여백을 중복하지 않는다.
- 로그인·사업자·담당자 정보와 결제 내역은 `ContentPanel` 안의 `DetailGrid` / `DetailField`를 사용한다. 정보 값마다 회색 카드·테두리를 중첩하지 않는다. 라벨은 `type-label`, 값은 `type-body`, 라벨→값8px, 정보 필드 사이24px다. 이메일·주소·ID를 자르지 않고 줄바꿈한다. 기본1열,640px 이상2열,1280px 이상에서 명시적으로 요청한3/4열을 사용한다.
- 직원 초대 메뉴판·권한은 `CheckboxFieldGroup` / `CheckboxField`로 선택한다. 기본 컨트롤 높이 이상의 클릭 영역,12px 안쪽,8px 항목/관련 문구 간격과 기본 테두리·포커스를 사용한다. 선택된 항목은 진한 경계로 구분한다. 네이티브 `name`, `value`, `defaultChecked`, disabled fieldset과 폼 제출을 보존한다. 초대 메뉴판2열, 권한은1280px 이상3열이며640px 미만1열이다.
- 결제 필터는 `site-field-grid`와 `site-field-stack`을 사용한다. 필드 사이16px, 라벨→필드8px이며 기본1열·640px 이상2열·1280px 이상 최대4열이다. 결제 작업 내역에 카탈로그용 `site-record-card`를 사용하지 않는다. 그 클래스가14px 카드 본문/13px 메타 크기를 덮어썼기 때문이다. 결제·계정의 실제 값은 관리 본문16px와 공통 와이드 배율을 유지한다.
- 직원 내역의 신원·역할 폼·접근 회수는 `site-record-heading`의 기존 순서로 배치하고1024px 이상3개 슬롯으로 표시한다. `site-data-row`의24px 안쪽과 행 사이 구분선을 사용한다. 결제 액션은 기존 우측 슬롯, 좋아요 제목→목록은 `site-stack-group`24px다. 빈 status 요소로 공백을 만들지 않는다.

- `/design-system#content-composition`에 실제 정보·체크박스·위험 표면 예시를 추가했다. 이번 검증 범위는 소스 계약, 서버 렌더링 회귀 검사, 타입·lint·빌드다. 사용자의 요청에 따라 브라우저 시각 검수는 수행하지 않는다. 다른 레거시 화면까지 이전 완료됐다는 의미가 아니다.
