# 아티메뉴 메인 히어로 이미지 외곽 처리

2026-11-19 사용자 최종 지시: **확장 사진을 사용하고, 상하좌우 가장자리만 자연스럽게 흐리거나 페이드한다.** 좌우가 주 처리 대상이고 위아래는 얼굴이 살짝 드러나지 않게 하는 얕은 보험이다. 특정 신체 부위를 골라 가리던 v3 마스크·중앙 구멍·내부 사각형 처리는 폐기한다. 공식 사이트 메인 첫 사진 시퀀스만 대상이다.

## 현행 시각 규칙

- 네 장면 모두 동일한 연속 외곽 그라디언트를 쓴다. 사진마다 얼굴·팔 좌표를 등록하거나 내부를 부분적으로 지우지 않는다.
- 좌우는 넓고 완만하게 블러·페이드하여 확장 배경에서 주변 여백으로 연결한다. 와이드는 가로 여유가 많으므로 이 흐린 영역이 더 넓게 보여도 된다. 사진을 가로로 늘려 남는 폭을 채우지 않는다.
- 위아래는 일반 구도에서 대부분 화면 밖이다. 얼굴 등이 끝에서 드러날 경우를 막는 정도로만 얕게 연결한다. 좌우와 같은 강도/범위를 적용하지 않는다.
- 정상 손·목업·실제 메뉴 UI는 선명하게 유지한다. 원본 사진과 손가락 오버레이에는 blur를 적용하지 않고 실제 사진 테두리만 좌우6%·상하3%로 살짝 페이드한다. 위치 기준 프레임의 별도 가림/잘라내기는 제거한다.
- 중앙 영역은 온전히 남긴다. 두꺼운 내부 띠·직사각형·특정 신체 마스크·중앙 투명 구멍은 금지한다.
- 중앙까지 부자연스러운 부분이 들어온 새 사진은 외곽 효과로 억지로 가리거나 정상 손을 덮지 않는다. 문제를 알리고 사진 자체 수정/교체를 검토한다.

## 사진·기기 구도 보존

기존1536×1024 원본/메뉴 좌표와 높이 기준16:10 노트북 카메라를 유지한다. 확장 생성본의 중앙 절반에 원본 구도가 있으므로 배경은 기존 `matrix(2,0,0,2,-768,-512)`로 맞추고 같은 카메라를 사용한다. 이 좌표는 사진 합성 정렬용이며 개별 인물을 가리는 규칙이 아니다. 전체 스테이지가100svh 화면 경계를 소유한다.

두 번째 장면은 원래 `hero-cafe-v1/counter.webp`로 유지한다. 모바일(<768px) 마지막 QR 장면은 사진·손·휴대폰·메뉴·배경을 함께 아래로 창 높이의2.5%(최대24px, 실제 제목 여유 내) 이동한 승인 상태를 유지한다. 기기 크기·가로 위치·타임라인·진행 막대·입력·native 앱 로딩 제한은 바꾸지 않는다.

## 공통 외곽 자산

실제 배경은 `public/assets/hero-cafe-v4/{venue,counter,dining,phone}-surroundings.svg`다. 원본 생성 사진을 그대로 포함하고 네 사진 모두 같은 외곽 블러층과 중앙 선명층을 합성한다. 개별 부위 좌표/클립 경로는 없다. 흐려진 바깥 영역은 인물 없는 기존 매장 블러와 연결한다. v3 특정 부위 마스크 파일은 공개 자산에서도 제거한다.

`profiles`와32px 배경 블러는 `scripts/build-hero-surroundings.mjs` 한 곳에 있고 `provenance.json`에도 기록한다. 상하 프로필은 좌우보다 짧은 전환 폭을 사용한다. 사진을 새로 생성하거나 목업을 다시 그리지 않는다. 원본은 이전 #669 내장 image_gen 결과가 저장된 `f0cc63774aef405c007c2f22e1356a4e194e54bc` 커밋에서 읽으며 source SHA256과 정렬 매핑을 보존한다.

## 검증

`scripts/qa-hero-backgrounds.mjs`는 실제 브라우저가 해석한 외곽 알파가 양옆에서 중앙으로 연속 증가하고, 네 사진의 프로필이 같으며, 중앙에는 구멍이 없고, 위아래가 좌우보다 얕은지 확인한다. 검수용 외곽 얼굴/팔 판독점은 결과 확인에만 쓰며 렌더링 규칙을 만들지 않는다.

원본 사진은 filter:none이고 위치 프레임에는 가림이 없어야 한다. 실제 손·기기 선명도, 목업 위치/배율, 가로 넘침, 확대·역방향 이동·모바일 스와이프를 함께 확인한다. 창 크기만 바꿔 선언하지 않고 실제 표시 치수와 브라우저 화면을 검수한다.
