# 아티메뉴 메인 히어로 사진과 외곽 처리

2026-11-19 현행: **사용자가 제공한 완성 사진을 그대로 사용하고, 전체 사진의 실제 외곽만 부드럽게 연결한다.** 이전 원본 삽입·접합 방식은 폐기한다. 공식 사이트 메인 첫 사진 시퀀스만 대상이다.

## 확정 사진

사용자가 Firefly Upscaler2x로 처리해 전달한 네 JPG를 `assets/hero-photo-sources-v7/`에 그대로 보관한다. 모두4344×1448(3:1)이며, 이전 v6의2172×724 사진을 대체한다.

| 장면 | 확정 소스 | 기준 |
| --- | --- | --- |
| 매장 전체 | venue.jpg | `01-venue Firefly Upscaler 2x 비율.jpg` |
| 카운터 태블릿 | counter.jpg | `02-counter-hand-v2 Firefly Upscaler 2x 비율.jpg` — 최신 손 수정본 기반 |
| 서버·테이블 태블릿 | dining.jpg | `rere_03-dining-server Firefly Upscaler 2x 비율.jpg` |
| QR·휴대폰 | phone.jpg | `rere_04-phone-qr Firefly Upscaler 2x 비율.jpg` |

사용자가 업스케일을 직접 수행했다. 에이전트는 추가 Photoshop/이미지 생성이나 사진 접합을 하지 않는다. 소스 JPG는 전달 바이트 그대로 보관하고 화면용 WebP95 인코딩에서도4344×1448 픽셀을 유지한다. 소스 폴더의 `source-provenance.json`과 배포 자산 `provenance.json`에 출처·SHA256을 기록한다. 소스와 HTML 전용 화면 마스크는 v7을 유지하고, 현재 전체 사진 출력은 반응형 외곽 프로필을 포함한 v8이다. v6는 과거 원본 보관용이다.

### 원본 해상도와 후속 업스케일

이전2172×724 사진은1512×762 브라우저의 카운터 시작 장면에서 전체 사진이 약3950px 너비로 표시되어 과도하게 확대됐다. 현행4344×1448은 가로·세로가 각각2배이며 같은 카메라 배치에서 더 높은 픽셀 밀도를 제공한다. 아래 SVG의4608×1536은 배치용 논리 좌표이며 원본 디테일이 늘어난다는 뜻이 아니다. 선명층 알파255 검사도 추가 블러가 없음을 확인할 뿐 모든 배율·Retina 화면의 디테일을 보증하지 않는다.

초기에4배8688×2896을 제안했으나 사용자가 전달한 최종 파일은2배4344×1448이다. 파일명이나 제안값으로 해상도를 추정하지 않고 실제 메타데이터를 기록한다. 최종 사진에서 화면 좌표와 HTML 전용 가림 마스크를 다시 측정한다. 일반 이미지 재생성으로 장면을 바꾸거나 단순 리사이즈를 화질 복원이라고 보고하지 않는다. 사진에 메뉴 화면이나 외곽 효과를 미리 합치지 않는다.

## 사진 합성과 실제 화면의 구분

- 장면당 **완성 사진 한 장**만 SVG에 내장한다. 예전 원본 사각형이나 손가락 사진을 다시 덧붙이지 않는다. 따라서 브라우저에서 새 사진과 옛 사진을 접합하는 경계가 없다.
- 화면 출력용 WebP95 인코딩만 적용하며 실제4344×1448 크기를 유지한다. 사진을 자르거나 변형하거나 다시 그리지 않는다.
- `scripts/measure-hero-screens.mjs`가 확정 사진의 빈 화면을 측정하여 `lib/hero-photo-geometry.json`에 화면 모서리를 기록한다. 실제 HTML 메뉴와 시연 포인터는 같은 좌표를 사용한다. QR 종이는 중앙30–70%의 겹치는 직선 경계로 모서리를 측정한다. 강조 테두리는 사진 좌표에서 네 모서리를 공통 중심 기준1.4배로 확대한 뒤 투영하여 각 변의 각도와 사각형 모양을 그대로 유지하고3px 흰 선을 사용한다. 원근 변형 안쪽의 음수 inset으로 테두리를 확장하지 않는다. 같은 깜빡임 구간을 유지한다.
- `*-screen-mask.png`는 빈 화면의 모서리와 손가락 가림을 따라 **투영된 HTML에만** 적용한다. 사진 자체를 가리는 마스크나 손가락 사진 합성이 아니다.

## 외곽 효과와 카메라

완성 사진은4608×1536 논리 좌표에 배치한다. 기존1536×1024 카메라 평면은 그 안의(1536,256)에 있다. 이 좌표 변환은 기존 높이 기준16:10 카메라를 유지하기 위한 것이며, 사진을 가로 화면에 억지로 늘리지 않는다.

2026-11-19 후속 승인에 따라 와이드와 초와이드의 좌우를 이전보다 더 넓고 강하게 가린다. 정본은 `lib/hero-photo-edge-profiles.json`이다. 단일 기본 프로필을 모든 화면에 강하게 바꾸지 않고, 브라우저의 실제 너비와 가로/세로 비율로 전체 사진 출력 프로필을 선택한다.

| 프로필 | 조건 | 완전 선명한 좌우 범위 | 선명층 전환 | 블러층 전환 | 블러 |
| --- | --- | --- | --- | --- | --- |
| normal | 아래 조건 외 전체 | 29–71% | 22–29% / 71–78% | 12–26% / 74–88% | 48px |
| wide | 너비2560px 이상·비율11:5 이상 | 31–69% | 26–31% / 69–74% | 20–29% / 71–80% | 64px |
| ultrawide | 너비3840px 이상·비율3:1 이상 | 33–67% | 29–33% / 67–71% | 24–31% / 69–76% | 80px |

비율은 전체4608×1536 사진의 좌표 기준이고 블러 값도 이 논리 좌표 기준이다. `picture`의 `source`는 ultrawide→wide 순서로 등록하여 겹치는 조건에서는 더 넓은 화면용을 선택한다. 그 외에는 normal을 사용한다. normal 외곽 프로필은 이전 v7과 동일하며 일반 노트북·16:9 화면의 외곽을 더 가리지 않는다. 매장·카운터 normal SVG는 이전 v7과 바이트까지 같고, 서버·QR 사진은 사용자의 최신 rere_03·rere_04 교체 요청을 반영한다. 뷰포트 크기를 바꾸면 브라우저가 해당 한 사진을 다시 선택한다.

- 상하 효과는 모든 프로필에서 그대로다. 선명층16–84%, 전환12–16%·84–88%, 블러층 전환8–14%·86–92%다.
- 같은 화면 조건의 네 장면은 같은 대칭 프로필을 쓴다. 실제 화면에서 보이는 좌우 너비는 기존 카메라 위치·배율에 따라 달라진다. 시작 구도에서3440×1440은 한쪽 약8–12%,5120×1440은 약25–27% 너비가 선명층 밖의 전환 구간이다.
- 특정 신체를 가리는 내부 띠, 중앙 구멍, 위치 프레임 클리핑은 없다. 사진 전체의 실제 외곽에서만 부드럽게 연결한다.
- 일반 노트북에서 보이는 중앙은 기존 선명층 안에 둔다. 와이드 효과를 강화하려고 노트북의 선명층을 함께 줄이지 않는다.
- 주변에 필요한 바탕은 기존 사람 없는 매장 사진의 흐린 레이어다. 인물 사진을 가로로 확대하여 바탕을 채우지 않는다.

기기 크기·높이 기준 위치·스크롤 타임라인·진행 막대·입력·native 앱 로딩 제한은 유지한다. 모바일(<768px) 마지막 QR 장면의 하향 이동도 창 높이2.5%(최대24px, 실제 제목 여유 내)를 유지한다.

PC 첫 매장 장면은 천장형 스크린 세 대의 투영 경계 전체를 기준으로 가로 중앙을 맞춘다. 너비 1024px 이상에서만 적용하며, 세로로 긴 창에서는 좌우 여백 안에 세 대가 모두 들어오도록 배율을 제한한다. 사진과 메뉴 화면은 함께 움직인다. 중앙을 맞추면서 오른쪽 사진 외곽이 드러날 경우 기존 외곽 효과로 이어진다.

## 생성과 검증

재현 순서:

1. `node scripts/measure-hero-screens.mjs` — 화면 좌표 및 HTML 전용 화면 마스크.
2. `node scripts/build-hero-surroundings.mjs` — v7 소스에서 `public/assets/hero-cafe-v8/`의 normal/wide/ultrawide SVG와 출처 기록을 만든다. 각 SVG에는 한 사진만 내장하고 픽셀·카메라 좌표는 같다.
3. `QA_EDGES_ONLY=1 node --import tsx scripts/qa-hero-backgrounds.mjs` —1512×762·2560×1440의 선명층 유지와3440×1440·5120×1440의 강화된 외곽을 검사한다. `QA_WIDE_ONLY=1`은 와이드 두 크기만 실행한다.

자동 검수는 `img.currentSrc`가 가리키는 실제 선택 SVG의 선명층 알파 맵과 프로필, 단일 사진 여부, DOM 카메라/화면 좌표, 가로 넘침, 장면 전환·역방향 이동, 최대2개 iframe, API 쓰기 없음을 확인한다. 초와이드→와이드→노트북→초와이드 크기 변경 때의 소스 선택과 디코드도 확인한다. 전체 크기 검수 모드에는 기존 모바일 동작 검사도 남겨둔다.

이번 전달의 최종 시각 검수는 사용자의 요청에 따라 **AI는 와이드만**, **사용자는 일반 노트북·모바일**을 담당한다. 코드·좌표 검사만으로 사용자의 기기별 시각 검수가 끝났다고 보고하지 않는다. 추후 사진 수정이 필요하면 오래 걸리는 보정에 착수하기 전에 필요한 소스를 사용자에게 구체적으로 요청한다.
