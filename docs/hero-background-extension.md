# 아티메뉴 메인 히어로 이미지 외곽 처리

2026-11-19 최종 수정: **확장 사진을 사용하되 완성된 사진의 실제 상하좌우 끝만 자연스럽게 흐리거나 페이드한다. 일반 노트북에서는 그 끝이 화면 밖이므로 흐린 띠가 보이지 않아야 한다.** 공식 사이트 메인 첫 사진 시퀀스만 대상이다.

## 현행 시각 규칙

- 원본 경계에 항상 적용하던 좌우6%·상하3% 페이드는 제거한다.16:10 위치 프레임에도 가림/클리핑을 두지 않는다.
- 네 장면 모두 완성된 확장 사진의 실제 끝에서 시작하는 동일한 대칭 효과를 쓴다. 중앙 구멍, 내부 띠, 개별 얼굴/팔을 가리는 효과는 없다.
- 좌우 선명층은 전체 확장 사진의15–85%, 위아래는5–95%에서 완전히 불투명하다. 좌우 전환은5–15%와85–95%, 위아래 전환은1–5%와95–99%다. 가장 바깥 블러층은 좌우4%, 위아래1%에서 주변 배경으로 연결된다. 위아래 처리는 좌우보다 얕다.
- 노트북·일반 모니터의 실제 보이는 영역은 전부 선명층 안에 있어야 한다. 첨부 화면 비율1512×762를 필수 검수 크기로 포함한다. 와이드에서만 실제 사진의 더 먼 좌우 끝과 효과가 점차 드러난다. 사진을 가로로 늘리지 않는다.
- 확장부의 잘못된 신체/얼굴이 안쪽에 있으면 사진 자체를 정리한다. 이를 가리려고 효과 범위를 중앙으로 당기거나 정상 손을 흐리게 하지 않는다.

## 사진과 기기 구도

기존1536×1024 메뉴 좌표와 높이 기준16:10 카메라를 유지한다. 완성 사진은3072×2048이며 원본 평면을(768,512)에 배치한다. 같은 단일 카메라 아래 사진과 실제 메뉴 화면을 둔다. 이는 합성 정렬용이며 개별 인물을 가리는 규칙이 아니다. 스테이지는100svh다.

두 번째 장면의 핵심 사진은 원래 `hero-cafe-v1/counter.webp`다. 모바일(<768px) 마지막 QR 장면의 하향 이동은 창 높이2.5%(최대24px, 실제 제목 여유 내)를 유지한다. 기기 크기·가로 위치·타임라인·진행 막대·입력·native 앱 로딩 제한은 바꾸지 않는다.

원본과 선명한 확장부 사이에는 색/질감 연결용1% 합성 이음만 사용한다. 그 뒤에는 동일한 선명 사진이 있으므로 주변 블러층을 드러내는 원본 페이드가 아니다. 다이닝은 복원한 원본의 잘린 몸통을 정리한 배경에 다시 붙이지 않도록 정확한 태블릿 영역만 원본으로 합성한다. 정상 손의 자세와 기존 화면 투영은 유지한다. 이런 자산 합성 범위를 브라우저의 신체 가림 효과로 사용하지 않는다.

## 자산과 재생성

- 실제 사용: `public/assets/hero-cafe-v5/{venue,counter,dining,phone}-composition.svg`.
- 공통 생성기: `scripts/build-hero-surroundings.mjs`. 효과 프로필·48px 블러(3072px 합성 좌표)·원본 삽입 영역·SHA256은 `provenance.json`에 기록한다.
- 매장 확장 원본은 #669의 `f0cc63774aef405c007c2f22e1356a4e194e54bc`에서 읽는다. 매장은 사람 없는 확장 사진을 유지한다.
- 나머지 확장 사진은 내장 image_gen 편집으로 정리한 `assets/hero-photo-sources-v5/{counter,dining,phone}.webp`다. 카운터는 끊긴 소매를 자연스럽게 구부러져 화면 밖으로 이어지게 수정했다. 다이닝/휴대폰은 확장부에 새로 생긴 얼굴·불필요한 몸통을 제거하고 정상 손과 기기를 유지했다.
- 선택한 편집의 입력과 프롬프트 세트는 `assets/hero-photo-sources-v5/prompts.json`에 저장한다. 기존 원본 사진은 덮어쓰지 않는다. v4 자산과 원본6%/3% 규칙은 현행이 아니다.

## 검증

`scripts/qa-hero-backgrounds.mjs`는 실제 SVG에서 선명층만 흰색으로 렌더링해 선명도 맵을 만든다. 총 알파(블러층 포함)만 확인해서는 선명함을 증명할 수 없다. 실제 DOM 카메라로 화면 모서리와 내부99개 판독점을 이 맵에 대응시키고,1440·1512·1920·2560px 일반 화면에서는 모든 점이255인지 검사한다. 장면 시작과 확대 상태 모두 검사한다. 와이드는 실제 사진 끝의 전환이 드러나는지 확인한다.

모바일320/390/430px, 세로 태블릿820×1180, 일반/와이드3440/5120px를 확인한다. 정상 손·기기, 실제 메뉴 정렬, 카메라 비율/위치 보존, 가로 넘침, 역방향 이동·모바일 스와이프, iframe 최대2개, API 쓰기 없음을 함께 확인한다. 자동 검사와 별도로 실제 스크린샷에서 옷/배경의 합성 절단선과 잘못된 신체 노출을 확인한다.
