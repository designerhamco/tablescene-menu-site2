# 매장 운영 배치도

2026-11-04. 테이블·키오스크 통합 관리의 ‘운영 테이블·키오스크’ 안에서 공통 state 탭으로 리스트형/지도형을 전환한다. 신규 등록·기존 리스트 편집·보관 목록과 서버 기능은 원래 순서를 유지한다. 주문관리 지도형은 후속 범위다.

## 화면과 조작

- 한 메뉴판의 같은 룸·지도에서 테이블과 키오스크를 함께 표시한다. 보기 유형은 ‘리스트형 / 배치도형’이며 두 유형의 항목을 항상 함께 표시한다. 룸 이름은 1~40자, 중복 불가, 최대 30개다.
- 등록된 활성·비활성 항목만 선택해 배치한다. 항목 이름·상태는 현재 등록 정보를 따라간다. 같은 항목을 두 곳에 중복 배치하지 않는다. 전체 등록 정책(테이블·키오스크 각각100개)은 기존 정책을 따른다.
- ‘룸 추가’, 이름 수정, 룸 모양 선택, 룸만 삭제를 제공한다. 삭제 확인에는 등록 항목·주문 기록을 유지한다는 안내를 표시한다. 룸 삭제와 배치 해제는 저장 전 ‘변경 취소’로 되돌릴 수 있다.
- 편집 모드에서 ‘바로 배치’ 또는 빈 영역 드래그로 사각형을 그린다. 사각형 드래그로 이동하고 오른쪽 아래 모서리를 잡아 크기를 바꾼다. 다른 룸으로 이동도 제공한다. 위치/크기 숫자 입력은 제공하지 않는다. 방향키는1%, Shift+방향키는10% 이동한다.
- 좌표는 룸 대비0~100%, 최소 가로·세로8%다. 룸 밖으로 나가지 않게 제한한다. 룸 비율은0.5~2 범위이며 UI는4:3,16:9,1:1,3:4 프리셋을 제공한다. 자동 겹침 방지는 바로 배치의 빈 위치 탐색에만 적용한다. 수동 배치의 겹침은 사용자가 조정한다.
- 리스트형·배치도형 전환 중 편집 초안을 유지한다. 명시적인 ‘배치도 저장’으로 저장한다. 저장 중 중복 요청과 편집을 막고 실패 시 초안을 유지한다. 저장하지 않은 페이지 이탈/새로고침에는 브라우저 확인을 사용한다.
- 보관·삭제된 항목은 지도에서 제외하며 다음 배치도 저장 시 제외된 위치를 정리한다. 배치 해제는 테이블/키오스크 등록 정보, QR, 기기 연결, 주문·호출 기록을 변경하지 않는다.

## 공통 컴포넌트

`app/components/ui/floor-plan-canvas.tsx`의 `FloorPlanCanvas`/`FloorPlanObject`가 캔버스와 사각형 표시를 소유한다. 공식 사이트 공통 UI이며 후속 주문 지도에서도 재사용한다. 바깥 작업 영역은 ContentPanel, 제목·폼·행동·글자와 탭은 기존 의미 API를 사용한다. 캔버스는 부모 너비와 화면 높이70svh 안에서 룸 비율을 유지한다. 사각형 좌표만 동적 inline geometry를 사용한다. 회색 사각형에는 장식 테두리를 두지 않고 선택/포커스의 안쪽 outline을 유지한다. 방향키와 Shift+방향키 이동을 함께 제공한다. `/design-system` 컴포넌트 예시에 실제 공통 캔버스를 연결한다.

## 저장·보안

- `public.menu_floor_plans`: 메뉴판별 한 행. `menu_site_id` PK/FK, `revision` 양의 정수, `document` JSONB(`rooms`, `placements`), 변경자·변경일을 저장한다. 주문·기존 테이블 스키마/데이터는 변경하지 않는다. 좌표에는 이름/개인정보/QR 토큰을 복사하지 않는다.
- 서버에서 기존 `requireMenuTableReadAccess`/`requireMenuTableWriteAccess`를 공유한다. 로그인, `table.manage`, 이용권 수명주기, 제품·기능 런타임 제한과 직원 변경 감사 경계를 그대로 적용한다. 클라이언트의 사용자 ID나 권한 표시는 신뢰하지 않는다.
- 테이블은 RLS를 켜고 public/anon/authenticated 직접 접근을 회수한다. 서버 service_role만 사용한다. 공개 메뉴/QR/고객 렌더러로 배치도를 전달하지 않는다. service_role 키는 기존 서버 전용 클라이언트에서만 사용한다.
- 저장 직전 현재 메뉴판의 활성/비활성 테이블 ID를 검증한다. 다른 메뉴판·삭제·보관된 ID나 없는 룸·중복 배치는 거부한다. 문서 정규화는 허용한 속성만 반환한다.
- 최초 저장은 PK 충돌을, 수정은 `menu_site_id`+`revision` 조건의 단일 UPDATE를 사용해 동시 수정을 감지한다. 충돌 시 자동 덮어쓰기/재시도를 하지 않는다. 새로고침 후 사용자가 최신 배치도를 확인한다.
- DB는 문서 구조·건수·최대128KiB와 revision을 추가 제한한다. 테이블을 아직 적용하지 않았거나 배치도를 읽지 못한 경우 지도에 안내하고 기존 리스트 관리는 유지한다.

## 최종 등록·배치 흐름

- QR만 사용하는 운영자를 위해 리스트/지도 모두 룸 없이 등록할 수 있다. 룸을 필수로 만드는 데이터 제약이나 등록 제한은 추가하지 않는다.
- 지도는 ‘공간과 항목 준비’ → 룸 선택·이름/모양 → ‘지도에 배치’ → 사각형 직접 조작 → 저장 순서로 구성한다. 룸 또는 등록 항목이 없으면 배치 도구만 비활성화하며 필요한 조건을 바로 설명한다. 별도 ‘배치 편집’ 진입 없이 직접 조작한다.
- 등록 버튼은 룸 추가 옆에 유지하며 등록 폼과 배치 편집의 위계를 구분한다. 선택 항목이 있을 때만 룸 이동·배치 해제 도구를 노출한다. 상/하단 배치도 저장과 저장하지 않은 이탈 확인을 유지한다.

- 항상 직접 편집 가능한 지도에서 빈 공간은 모바일 페이지 스크롤을 허용한다. 그리기 모드의 캔버스와 사각형 이동/크기 조절에서만 touch-action:none을 사용한다. 유형 필터를 바꾸면 그리기 모드를 해제하고 숨겨진 유형의 배치는 그대로 보존한다.
