# 매장 운영 배치도

2026-11-04. 테이블·키오스크 관리의 ‘운영 테이블/운영 키오스크’ 안에서 공통 state 탭으로 리스트형/지도형을 전환한다. 신규 등록·기존 리스트 편집·보관 목록과 서버 기능은 원래 순서를 유지한다. 주문관리 지도형은 후속 범위다.

## 화면과 조작

- 한 메뉴판의 룸 구성을 테이블·키오스크 탭이 공유한다. 각 탭의 지도에는 해당 구분만 표시한다. 룸 이름은 1~40자, 중복 불가, 최대 30개다.
- 등록된 활성·비활성 항목만 선택해 배치한다. 항목 이름·상태는 현재 등록 정보를 따라간다. 같은 항목을 두 곳에 중복 배치하지 않는다. 전체 등록 정책(테이블·키오스크 각각100개)은 기존 정책을 따른다.
- ‘룸 추가’, 이름 수정, 룸 모양 선택, 룸만 삭제를 제공한다. 삭제 확인에는 등록 항목·주문 기록을 유지한다는 안내를 표시한다. 룸 삭제와 배치 해제는 저장 전 ‘변경 취소’로 되돌릴 수 있다.
- 편집 모드에서 ‘바로 배치’ 또는 빈 영역 드래그로 사각형을 그린다. 사각형 드래그로 이동하고 오른쪽 아래 모서리를 잡아 크기를 바꾼다. 위치/크기(%) 입력과 다른 룸으로 이동도 제공한다. 방향키는1%, Shift+방향키는10% 이동한다.
- 좌표는 룸 대비0~100%, 최소 가로·세로8%다. 룸 밖으로 나가지 않게 제한한다. 룸 비율은0.5~2 범위이며 UI는4:3,16:9,1:1,3:4 프리셋을 제공한다. 자동 겹침 방지는 바로 배치의 빈 위치 탐색에만 적용한다. 수동 배치의 겹침은 사용자가 조정한다.
- 지도·리스트 및 테이블·키오스크 전환 중 편집 초안을 유지한다. 명시적인 ‘배치도 저장’으로 저장한다. 저장 중 중복 요청과 편집을 막고 실패 시 초안을 유지한다. 저장하지 않은 페이지 이탈/새로고침에는 브라우저 확인을 사용한다.
- 보관·삭제된 항목은 지도에서 제외하며 다음 배치도 저장 시 제외된 위치를 정리한다. 배치 해제는 테이블/키오스크 등록 정보, QR, 기기 연결, 주문·호출 기록을 변경하지 않는다.

## 공통 컴포넌트

`app/components/ui/floor-plan-canvas.tsx`의 `FloorPlanCanvas`/`FloorPlanObject`가 캔버스와 사각형 표시를 소유한다. 공식 사이트 공통 UI이며 후속 주문 지도에서도 재사용한다. 바깥 작업 영역은 ContentPanel, 제목·폼·행동·글자와 탭은 기존 의미 API를 사용한다. 캔버스는 부모 너비와 화면 높이70svh 안에서 룸 비율을 유지한다. 사각형 좌표만 동적 inline geometry를 사용한다. 회색 사각형에는 장식 테두리를 두지 않고 선택/포커스의 안쪽 outline을 유지한다. 모서리 조절 외에 숫자 입력을 동등한 대체 수단으로 제공한다. `/design-system` 컴포넌트 예시에 실제 공통 캔버스를 연결한다.

## 저장·보안

- `public.menu_floor_plans`: 메뉴판별 한 행. `menu_site_id` PK/FK, `revision` 양의 정수, `document` JSONB(`rooms`, `placements`), 변경자·변경일을 저장한다. 주문·기존 테이블 스키마/데이터는 변경하지 않는다. 좌표에는 이름/개인정보/QR 토큰을 복사하지 않는다.
- 서버에서 기존 `requireMenuTableReadAccess`/`requireMenuTableWriteAccess`를 공유한다. 로그인, `table.manage`, 이용권 수명주기, 제품·기능 런타임 제한과 직원 변경 감사 경계를 그대로 적용한다. 클라이언트의 사용자 ID나 권한 표시는 신뢰하지 않는다.
- 테이블은 RLS를 켜고 public/anon/authenticated 직접 접근을 회수한다. 서버 service_role만 사용한다. 공개 메뉴/QR/고객 렌더러로 배치도를 전달하지 않는다. service_role 키는 기존 서버 전용 클라이언트에서만 사용한다.
- 저장 직전 현재 메뉴판의 활성/비활성 테이블 ID를 검증한다. 다른 메뉴판·삭제·보관된 ID나 없는 룸·중복 배치는 거부한다. 문서 정규화는 허용한 속성만 반환한다.
- 최초 저장은 PK 충돌을, 수정은 `menu_site_id`+`revision` 조건의 단일 UPDATE를 사용해 동시 수정을 감지한다. 충돌 시 자동 덮어쓰기/재시도를 하지 않는다. 새로고침 후 사용자가 최신 배치도를 확인한다.
- DB는 문서 구조·건수·최대128KiB와 revision을 추가 제한한다. 테이블을 아직 적용하지 않았거나 배치도를 읽지 못한 경우 지도에 안내하고 기존 리스트 관리는 유지한다.

## 배포·검증

마이그레이션: `supabase/migrations/20261104082127_add_menu_floor_plans.sql`. 신규 내부 테이블과 정책·인덱스만 추가한다. 기존 데이터를 수정·삭제하지 않는다. 운영 적용 전 SQL과 UI를 검토하고, 적용 후 테이블·RLS·직접 접근 차단 및 보안 advisor를 확인한다. 배포를 되돌릴 때는 기존 애플리케이션으로 복귀하고 새 배치도 행은 보존한다. 사용자 배치도가 생긴 테이블을 자동 DROP하지 않는다.

격리 SQL 검증은 `PGLITE_MODULE=<installed module path> node scripts/qa-floor-plan-sql.mjs`, 모델·서비스 검증은 `lib/menu-floor-plan.test.ts`를 사용한다. 실제 매장 자료를 생성/수정하지 않고 격리 예시로 룸 CRUD, 그리기·이동·크기 조절, 키보드·터치, 초안 유지, 저장·새로고침과 동시 수정 오류를 검증한다. 320~2600px 실제 DOM viewport에서 넘침과 사각형 경계를 확인한다. 임시 검수 경로는 배포 전 제거한다.
