# 모바일 공식 사이트 간격 정리

2026-11-01 사용자 요청. 공식 사이트의 모바일 간격을 공통 역할로 연결했다. 고객 메뉴판 렌더러와 독립 모바일 규칙은 변경하지 않았다.

## 기준

| 역할 | 모바일 값 | 적용 위치 |
| --- | --- | --- |
| 관련 문구 | 8px | 분류/설명, 푸터 펼친 본문 위 |
| 제목/설명 | 12px | 페이지·서비스 섹션·가이드 |
| 작은 블록 | 16px | 이미지/정보, 약관/저작권 |
| 콘텐츠 묶음 | 24px | 탭 안내, 도구/목록, 영상/설명 |
| 주요 콘텐츠 | 32px | 제목 그룹/첫 콘텐츠, 필터/결과, 페이지네이션 |
| 독립 카드 | 48px | 템플릿 카드 사이 |
| 새 섹션 | 64px | 별도 상담 영역, 서비스 섹션, 가이드 문서 사이 |
| 표면 내부 | 20px | 회색 목록·설명 박스 |

제목 위40px·제목/설명12px·첫 콘텐츠32px는 이미 공통이므로 유지했다. 템플릿 회색 면 안쪽16→20px, 필터/결과24→32px, 도구/목록20→24px, 이미지/정보12→16px, 카드 사이40→48px로 조정했다. 페이지네이션 위40→32px, 별도 상담 영역80→64px로 불필요한 빈 공간도 줄였다. 좁은 폭의 도구는 기존 순서로 자연스럽게 줄바꿈한다.

푸터 소개/접이식 메뉴 간격은 실측0→32px로 수정했다. 안쪽 위32px·좌우24px, 펼친 본문 위8px/아래24px, 사업자 정보 행12px, 약관/저작권16px다. 모바일 접이식은 사이트 구분과 같은767px까지 사용한다. 기본 접힘·링크44px·요약 행56px·회색 면 내부 워드마크 잘림을 유지한다. 외곽 테두리는 추가하지 않았다.

## 시스템

styles/site-spacing.css가 간격 소유자다. lib/site-spacing.ts 역할 표를 디자인 기준·컴포넌트 라이브러리 양쪽에서 표시한다. check:site-ui는 CSS/표 일치, SitePage 연결, stack 중복 margin 제거와 푸터 연결을 검증하며, 페이지에서 공통 spacing 토큰을 덮어쓰면 자동 감사가 차단한다. 기존 예외 목록은 확대하지 않았다.

새 페이지는 SitePage와 site-stack-copy/block/group/content/section으로 구성한다. 제목 경계와 본문 gap을 중복으로 더하지 않는다. AGENTS.md와 공통 페이지/시스템 문서도 같은 기준을 명시한다. 정적 검사는 모든 동적 배치를 증명하지 않으므로 실제 모바일 줄바꿈도 검수한다.

## 브라우저 실측

폰트 loaded 후 CSS viewport를 확인했다. 320×780·390×844에서 /templates, /faq, /faq/notices, /guides, /apply, /services/basic, /services/dining, /services/display를 확인했다. 8개 모두 가로 넘침0px, 제목 시작 y=104px(헤더64+위40), 제목/설명12px, 제목 그룹 아래32px다.

| 실제 viewport | 목록 안쪽 | 카드 간격 | 열 수 | 푸터 |
| --- | --- | --- | --- | --- |
| 320×780 | 20px | 48px | 1 | 접이식 |
| 390×844 | 20px | 48px | 1 | 접이식 |
| 640×960 | 20px | 48px | 2 | 접이식 |
| 767×960 | 20px | 48px | 2 | 접이식 |
| 820×1000 | 16.4px 기존 | 40px 기존 | 2 | 기존 펼침 |
| 1280×720 | 24px 기존 | 40px 기존 | 3 | 기존 펼침 |

위 모든 폭에서 넘침0px. 320px 푸터 사업자 정보 펼침도 넘침0px, 본문 위8/아래24px·행12px·바깥 테두리0px다. 템플릿 다음 페이지의 ROSY ORANGE 표시를 확인했다. 기능/콘텐츠 순서·탭/버튼 크기와 좋아요/링크 동작은 변경하지 않았다.

검수 범위는 위 공개 페이지와 공유 푸터다. 계정 데이터·결제·구독·운영 기능은 실행하지 않았다. PC/태블릿 기존 간격, 메뉴판 디자인과 이미지 자체는 유지한다.

## 검증

공통 UI 계약95건, TypeScript, 수정 TS/TSX ESLint 통과. 별도 출력 경로의 Production 빌드 통과(84개 정적 페이지 생성). 운영 반영은 연결 PR의 Vercel 배포 상태와 최종 보고에서 확인한다.
