# 모바일 알림 진입

2026-10-28 사용자 요청: 모바일 벨은 마이페이지 > 알림 내역이 아니라 PC·태블릿 레이어와 같은 알림 중심의 별도 화면을 연다.

- 768px 미만 헤더 벨은 /notifications 링크다. 768px 이상은 기존 공통 알림 레이어다. 헤더의 다른 메뉴·아이콘·배치는 유지한다.
- 전용 화면은 공통 헤더, 알림 제목, 뒤로가기, 전체/읽지 않음 밑줄 탭과 목록만 표시한다. 계정 카드·마이페이지 메뉴·푸터·상담 런처는 넣지 않는다.
- NotificationHistorySection의 공통 NotificationPanel과 기존 읽음 API를 재사용한다. 마이페이지에서는 기존 제목·설명을 유지하고, 전용 화면에서는 중복 소개를 생략한다. 대상 없는 알림은 현재 전용 화면에 남는다.
- 서버에서 기존 세션의 getUser를 확인한다. 미로그인은 /sign-in?next=%2Fnotifications로 이동한다. 세션 클라이언트와 본인 user_id 조건·기존 RLS를 사용하고 관리자 키·새 권한을 추가하지 않는다.
- 기존 in_app/email 채널, skipped 제외, 최신50개 조회 기준을 따른다. 조회 실패를 빈 목록으로 표시하지 않는다.
- 뒤로가기는 직전 방문 화면으로 돌아가며 방문 기록이 없으면 홈으로 이동한다.

검수: 타입·변경 파일 lint·내비게이션/알림 계약 검사, 미로그인 진입의 next 유지, Production 로그인 세션에서 모바일 벨 → 전용 화면 → 전체/읽지 않음 → 뒤로가기, 기존 마이페이지 알림 내역을 확인한다. 인증 화면 QA 스크립트에도 /notifications와 390/820/1440px 진입·레이어 검사를 추가한다. 실행 결과는 배포 PR과 완료 보고에 기록한다.

배포 전 검수: 전체 테스트890개, 관련 계약17개, TypeScript·변경 파일 ESLint·Production 빌드 통과. 미로그인 320/390/820/1440px 진입에서 로그인 리다이렉트와 next=/notifications 및 가로 넘침0px를 확인했다. 기존 로그인 세션의 실제 화면 검수는 배포 후 PR에 기록한다.
