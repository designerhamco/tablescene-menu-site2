# 개인 기기·공용 단말 주문 설정

## 적용 상태와 범위

2026-10-29: 구현 및 로컬 검수 완료. 운영 SQL 적용·타입 재생성·운영 배포는 아직 실행하지 않았다. NICE AppPOS, 온라인 결제 승인, 카카오 연결 및 알림톡 발송은 포함하지 않는다.

이번 변경은 **주문 권한**, **미주문 장바구니**, **단말 연결**의 수명을 구분한다. 계산이 끝나 테이블 이용을 종료하는 업무 처리는 이 타이머들과 별개다. 실제 결제 결과에 따른 테이블 이용 종료·다음 손님 내역 초기화는 NICE 연동 단계에서 연결해야 한다. 현재 공용 단말 연결을 결제 완료에 따라 자동 종료하거나, 장바구니 초기화를 계산 완료로 처리하지 않는다. 기존 직원의 외부 결제 완료 기록 기능도 그대로 유지한다.

## 설정과 고객 동작

| 구분 | 동작 |
| --- | --- |
| 개인 기기 결제 방식 | 주문 OFF / 후결제 / 선결제 / 둘 다. 실제 선결제는 기존과 같이 준비 중이다. 선결제만 선택하면 후결제 주문을 받지 않으며 설정 화면에 이를 안내한다. |
| 개인 기기 주문 권한 | QR 진입부터 1시간, 5분 전 명시적인 연장 안내. 확인할 때 1시간 연장한다. 새로고침·조회·자동 요청은 연장하지 않는다. 완전히 만료되면 QR 재스캔이 필요하다. |
| 개인 기기 내역·장바구니 | 주문 권한 만료로 삭제하지 않는다. 24시간 방문 쿠키가 유효한 동안 동일 브라우저의 QR 재진입은 같은 방문을 재사용한다. 다른 브라우저·다른 방문의 내역을 포함하지 않는다. 쿠키 삭제·24시간 방문 만료 후 복구를 보장하지 않는다. |
| 전화번호 | 개인 기기에서만 필수/선택/숨김 설정. 기본은 필수. 주문마다 수정할 수 있고 이전 성공 주문의 번호를 해당 브라우저 탭에 자동 입력한다. 주문 당시 번호를 별도로 저장하며 과거 주문의 번호는 바꾸지 않는다. 공용 단말은 입력란과 번호 저장 모두 제외한다. 번호 인증·실제 발송은 없다. |
| 공용 단말 | 테이블 관리에서 권한 있는 직원이 **이 기기를 공용 단말로 연결**한다. 해당 브라우저가 지정 테이블에 연결되며 후결제만 제공한다. 연결 유효기간은 30일이고 해제·테이블 중지·QR 교체로 폐기할 수 있다. |
| 공용 장바구니 | 미주문 상품이 있는 상태로 10분간 조작하지 않으면 비운다. 1분 전에 안내하며 계속 이용하면 타이머를 다시 시작한다. 접수된 주문·미결제 기록은 유지한다. 전송 중이거나 통신 결과를 확인하지 못한 주문은 임의로 비우지 않는다. |
| 동일 주문 확인 | 같은 방문의 마지막 비취소 주문과 메뉴·선택 옵션·수량이 같으면 재주문 확인. 확인하면 새 주문을 만든다. 줄 순서나 같은 상품을 나눠 담은 형태는 비교 결과를 바꾸지 않는다. |
| 통신 재시도 | 같은 요청 ID는 기존 주문을 반환한다. 응답을 잃은 뒤 새로고침해도 동일 장바구니의 요청 ID를 복원하여 재시도한다. |
| 일반 메뉴판 | 주문 기능을 사용하지 않으면 주문 타이머·연장 창을 만들지 않는다. 메뉴판 보기는 유지한다. 호출 권한의 기존 테이블·방문 검사는 유지한다. |
| 알림톡 | 조리 완료 메시지 예시와 비활성 설정 화면만 제공한다. 연동 준비 중임을 표시하며 API·발송 작업은 만들지 않는다. |

개인/공용 구분은 서버에 등록된 방문 채널로 결정한다. 폴더블·태블릿·PC, 화면 폭·회전, IP, `?mode=terminal` 값으로 권한을 바꾸지 않는다. 일반 고객용 링크를 PC에서 열어도 자동으로 공용 단말 권한을 얻지 않는다. 같은 메뉴판에서 개인 고객과 등록 공용 단말을 함께 사용할 수 있다.

정적 QR 주소를 다시 여는 것도 QR 재진입으로 처리한다. 웹에서 실제 카메라 스캔이나 매장 안에 있는 사실을 이 링크만으로 증명하지는 않는다.

## SQL·보안 계약

승인 대상은 `supabase/migrations/20261029001153_add_order_session_settings.sql` 한 건이다.

- 방문에 서버 지정 채널·별도 주문 만료 시각을 추가하고 기존 방문 만료 상한을 개인 24시간/공용 30일로 구분한다. 기존 행의 만료 시각을 일괄 늘리지 않는다.
- 주문에 연락처 스냅샷·동일 주문 비교값과 방문 내 최근 주문 조회 인덱스를 추가한다. 고객 내역 조회 응답에는 전화번호를 내보내지 않는다.
- 등록·조회·연장·주문 V3 RPC는 service_role만 실행한다. security invoker/빈 search_path, 기존 RLS와 운영 대상 목록을 유지한다. 단말 등록은 서버에서 `table.manage` 쓰기 권한·이용권·공개 상태를 먼저 검사한다.
- 등록 완료 후 이 브라우저의 관리자 로그인만 `signOut({scope: 'local'})`로 해제한 뒤 공용 메뉴판으로 이동한다. 다른 기기의 로그인에는 영향을 주지 않는다. 로그아웃 실패 시 공용 진입을 완료하지 않는다.
- 기존 V2 주문 진입점에도 새 주문 만료·채널 결제 설정을 적용하는 INSERT 가드를 둔다. 신규 UI가 주문을 막는 것과 별도로 DB에서 검사한다.
- 방문 잠금으로 같은 방문의 요청을 직렬화하고, 동일 요청 재전송은 추가 주문 없이 기존 결과를 반환한다. 이 멱등 처리와 재주문 확인은 별개다.
- 개인/공용 쿠키는 난수 토큰의 해시를 DB에 저장하는 기존 방식과 Secure/HttpOnly/SameSite=Lax 정책을 유지한다. User-Agent 검사는 추가 바인딩이며 IP나 실제 휴대폰 식별자로 사용하지 않는다.
- 원문 번호를 로그나 테스트 보고서에 쓰지 않는다. 운영 사용 전 연락처 보관·삭제 정책은 별도 운영 정책과 함께 확정해야 한다.

## 운영 적용 순서와 복구

운영 SQL 변경은 기존에 정한 별도 명시 승인 대상이다. 구현 요청만으로 운영 DB에 적용하지 않는다.

1. 승인 직전 운영 스키마·기존 주문/결제/방문 건수와 기존 데이터 지문, 새 컬럼/RPC 부재를 읽기 전용으로 확인한다. 현재 운영 대상 목록은 변경하지 않는다.
2. 승인한 위 SQL 원문 한 건만 1회 적용한다. 과거 migration 재실행·일괄 `db push`를 하지 않는다. 기존 주문/결제/방문 행 보존, 제약·RLS·함수 권한·본문을 확인한다.
3. `npm run supabase:types`로 운영 스키마 타입을 생성하고 `lib/server/order-session-rpc.ts`의 임시 계약 어댑터를 생성 타입으로 바꾼다. 실제 환경변수 값을 출력하지 않는다.
4. 타입·주문 통합 검수를 다시 통과한 코드만 병합·배포한다. **SQL보다 코드를 먼저 운영 배포하지 않는다.** 새 RPC가 없으면 방문 확인은 실패하도록 되어 있다.
5. 배포 Ready와 공개 메뉴, 쿠키 없는/다른 출처 요청 차단, 실제 기기 설정 화면을 확인한다. 별도 승인 없는 실주문·전화번호·결제·알림톡을 만들지 않는다.

복구 시 기존 주문·연락처·결제 행을 삭제하지 않는다. 가드가 남아 있으면 이전 코드에도 1시간 주문 제한이 적용되므로 단순 코드 롤백을 기능 복구 완료로 보지 않는다. 필요 시 신규 주문을 OFF하고, 승인된 범위에서 SQL 가드와 코드의 호환성을 함께 복구한다. 이미 접수한 주문과 결제 기록은 유지한다.
