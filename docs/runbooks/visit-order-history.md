## 고객 화면

공통 장바구니의 기존 디자인을 재사용한다. 빈 장바구니 팝업은 상단 탭 없이 유지하고 주문내역 보기로 전환한다. 상품이 있는 장바구니 또는 주문내역 화면은 장바구니/주문내역 탭을 사용한다. 실제 주문 성공 후 주문내역 탭을 연다. 미리보기의 예시 주문·sessionStorage는 실제 주문과 분리한다.

실제 내역은 현재 서명된 방문 쿠키의 주문만 표시한다. 같은 테이블의 다른 방문·다른 테이블·다른 매장의 내역은 포함하지 않는다. 이름·선택 옵션·가격·수량은 주문 당시 불변 스냅샷을 사용한다. 주문 시각은 서울 시간이며, 주문 접수 → 조리 준비 → 조리 중 → 서빙 준비 → 서빙 완료를 표시한다. 결제 전/결제 완료/결제 취소/환불 상태도 별도로 표시한다. 직원 관리와 고객 화면은 같은 주문 상태 이름을 사용한다.

화면이 열리고 주문내역 탭이 보일 때만 약 5초마다 새로 읽는다. 탭·창 숨김·닫힘에서는 멈추고, 통신 실패는 간격을 늘린다. 만료/차단 세션은 이전 내역을 숨기고 다시 QR을 읽도록 안내한다. 최근 100건 제한에 도달하면 직원에게 이전 내역을 문의할 수 있도록 명시한다. 한 방문이 끝나면 다음 방문의 쿠키로 이전 내역을 볼 수 없다.

## 고객 취소와 직원 처리

고객은 `received` + `unpaid` 주문만 전체 취소한다. 조리 준비부터 또는 결제 완료된 주문은 직원에게 문의한다. 확인 버튼과 전송 중 중복 클릭 차단을 유지한다. 서버는 클라이언트가 보낸 테이블·방문 ID·주문 상태·가격을 취소 권한으로 사용하지 않는다.

새 취소 RPC는 테이블 → 방문 → 주문 순서로 잠그고 현재 활성 테이블·공개 메뉴·폐기되지 않은 방문과 만료 시각을 다시 확인한다. 주문 잠금 후 `received/unpaid`를 재확인하며 만료 시각도 다시 검사한다. 고객 취소는 상태/시각/고객 요청 사유만 기록하고 결제 행이나 금액을 변경하지 않는다. 이미 취소한 동일 방문의 주문을 다시 취소해도 추가 변경은 없다. 직원의 기존 조건부 상태/수동 결제 갱신과 충돌하면 실패하고 최신 상태를 다시 표시한다. 실제 카드 결제·환불 API는 호출하지 않는다.

신규 주문을 OFF해도 기존 방문의 받은 주문을 없애거나 접수 전 취소를 막지는 않는다. 조회·취소에는 기존 사이트별 후불 운영 연결, 사업자 이용권·공개 상태, 지원 템플릿과 유효한 방문이 필요하다. 기존 매장별 운영 대상 목록은 확대하지 않는다.

## SQL 범위와 복구

두 서버 전용 RPC만 추가한다. 기존 테이블·행·RLS·구독 계약·금액·실행 설정을 이관하거나 변경하지 않는다. 기존 방문 인덱스를 재사용하며 새 대형 인덱스나 backfill은 없다. 함수는 security invoker/빈 search_path이며 service_role만 실행한다. anon/authenticated에 테이블·함수 권한을 추가하지 않는다.

1. 승인 직전 운영의 menu_customer_orders/items/options, 테이블·방문, 호출·구독·결제의 건수/지문과 기존 두 함수 부재를 읽기 전용으로 확인한다.
2. 승인한 파일 원문 한 건만 한 번 적용한다. 과거 migration 재실행·일괄 db push를 하지 않는다.
3. 함수 본문·권한·RLS·Security Advisor 및 기존 행 보존을 확인한다. 공식 도구로 타입을 재생성하고 임시 계약 어댑터를 제거한다.
4. 같은 검증 커밋을 병합·배포한 후 Production Ready와 공개 도메인, 비인증/다른 출처 API 차단을 확인한다. 실제 고객 주문·취소·결제·세션을 검수로 만들거나 바꾸지 않는다.
5. 코드 롤백 시 새 RPC는 서버 전용으로 남겨도 기존 기능을 바꾸지 않는다. 주문 기록을 지우거나 결제·구독 상태를 임의 복구하지 않는다.
