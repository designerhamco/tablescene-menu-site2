# 기본 디자인 구매 표시·스타터 분리

## 원인과 변경

기본 디자인 10종은 기존 렌더러를 공유한다. 구독에는 정확한 `initial_design_id`와 이용권이 저장됐지만 신규 스타터 생성에는 렌더러 키만 전달돼 원래 디자이너 샘플이 저장됐다. 이후 초기화는 중립 서체·색상만 적용했다. 마이페이지/완료 화면도 렌더러 표시명을 사용해 기본 디자인을 REAL MATCHA 등으로 표시했다.

- 생성·결제 재시도/복구는 구매한 디자인 ID를 스타터 생성까지 전달한다. 기본 디자인 전용 샘플은 미리보기와 공유한 중립 문구·자리 이미지·카테고리/가격 예시를 저장한다. 원래 디자이너 샘플은 유지한다.
- 매장명·연락처·주소 등 기존 입력값은 보존한다. 중립 샘플 번역은 렌더러의 매장명/안내 문구를 복원하지 않으며 매장명은 고객 입력값으로 대체된다.
- 마이페이지의 이름/썸네일, 생성 완료, 편집, 가져오기, 전환 화면은 저장된 디자인 ID를 사용한다. 직원 목록에는 디자인 ID만 추가해 계약/결제 설정을 노출하지 않는다. 저장 ID가 없는 기존 메뉴판은 종전 표시를 유지한다.
- 커버 샘플 초기화와 빈 메뉴 복구도 현재 저장된 디자인을 따른다. 일반 디자인 교체는 기존 내용·사진·메뉴/페이지 ID·주문을 보존하며 재시딩하지 않는다.
- 렌더러 배치·서체 크기·모바일 간격/스크롤 정책은 변경하지 않는다.

## 검증과 운영 교정

- 기본 10종의 실제 생성·중복 생성 방지, 디자이너 샘플 보존, 구매 복구 경로, 고객 입력값 보존을 검사한다. 카테고리 가격 열·대표상품 참조·번역·베이커리 이미지 예외도 확인한다.
- 기존 실제 디자인 서비스/API와 계약 DB 가드를 격리 PostgreSQL에서 91건 재검증했다. 디자인 전환은 고객 내용·금액·주문을 변경하지 않는다.
- 사용자가 정확한 교정을 승인한 신규 draft 메뉴판 **한 개**만 백업 후 원자적으로 교정했다. 기존 샘플과 다른 변경이 있으면 전체 중단하며 같은 교정을 재실행해도 중단한다. 같은 SQL을 복제 DB에서 검증했고 동시 편집 보존·중복 실행 중단 포함 1,016개 대조를 통과했다.
- 수정 대상은 잘못 혼입된 샘플 설명/사진/카테고리/상품/번역과 기본 가격 열 예시다. 기존 상품/페이지 ID, 매장 입력정보, 공개 상태, 계약·요금·주문·결제·이용권은 보존한다. 일반 고객 전체에 자동 데이터 보정을 실행하지 않는다. 별도 DB 스키마/Auth/Storage/권한/자동 청구 설정 변경은 없다.
- 운영 사후 2,384개 필드 대조로 승인한 교정 외 변경이 없음을 확인했다. 매장 입력정보·draft 상태·기존 모든 ID·할인 시간·계약/주문/결제/이용권이 일치하며 실제 태블릿 미리보기에도 중립 이미지/문구가 반영됐다.
- 단위 756건, 디자인 서비스/API 91건, 타입/변경 파일 린트/운영 빌드 통과. 개인 식별자·백업·교정 SQL은 저장소에 포함하지 않는다. 배포 뒤 표시 이름/썸네일과 실제 메뉴판을 재확인한다.
