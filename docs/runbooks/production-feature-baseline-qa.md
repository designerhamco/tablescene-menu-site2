# Production 기능 기준선 QA

확인일: 2026-09-14 (KST)

## 범위와 안전 기준

- Production의 공개 화면, 관리자 화면, 기존 테스트 이력과 데이터 상태를 교차 확인했다.
- 실제 결제, 구독, 환불, 환경변수, 비밀키는 변경하지 않았다.
- 새 Production 주문·메뉴판·대기번호 데이터는 만들지 않았다.

## 스마트호출과 테이블 QR

- `오브 테이블 QA` 메뉴판이 게시 상태이며 멀티페이지 템플릿과 스마트호출 기능이 연결되어 있음을 확인했다.
- 매장 운영 대시보드에서 호출 관리와 테이블·QR 관리가 활성화되고, 대기번호 기능은 비활성으로 구분되는 것을 확인했다.
- 호출 관리 화면에서 `물 요청`, `식기 요청`, `테이블 정리`, `직원 호출` 4개 선택 항목과 완료 이력 3건의 테이블 번호·시간·상태를 확인했다.
- 테이블 관리 화면에서 활성 테이블 1개와 영구 공개 주소를 확인했다.
- 대표 메뉴 QR과 테이블별 QR 다운로드를 각각 실행해 현재 화면에 성공 토스트가 노출되는 것을 확인했다.
- Production DB에서 호출 이력 3건이 모두 완료 상태이고, 대기 중인 호출이 0건임을 재확인했다.

## Display 대기번호

- 공개 대기번호 API와 화면이 모두 HTTP 200으로 응답하고 Summer Blue 테마를 사용하는 것을 확인했다.
- Production DB에 완료된 대기번호 이력 1건, 현재 활성 이력 0건이 있음을 확인했다.
- 현재 로그인한 QA 계정에는 Display 메뉴판이 없어 새 대기번호 등록·픽업·수령 쓰기 흐름은 실행하지 않았다. 실제 결제·구독 데이터를 우회해 QA 메뉴판을 새로 만드는 작업도 수행하지 않았다.

## 메뉴 제작 AI와 크레딧

- Production의 기존 QA 메뉴판에서 설명 생성 `-1`, 메뉴 정리 `-3`, 다국어 부분 번역 `-1` 크레딧 거래를 확인했다.
- 최근 설명 생성과 메뉴 정리의 연속 거래에서 잔액이 `13 -> 12 -> 9`로 정확히 감소해 총 4크레딧이 원자적으로 차감된 것을 확인했다.
- 실제 메뉴 콘텐츠를 임의로 변경하지 않고 API 응답·거래 기록·잔액을 교차 확인했다.
- 신규 계정의 첫 메뉴 6크레딧 평생 1회 지급과 추가 메뉴 미지급은 신규 결제·무료체험 E2E에서 별도로 확인한다.

## 직원 권한

- Production 직원 관리 화면에서 `매니저`, `편집자`, `운영 직원`, `조회 전용` 역할 프리셋이 정상 노출됨을 확인했다.
- 현재 QA 계정에 활성 직원이 없어 직원별 덮어쓰기 체크박스의 저장 동작은 운영 화면에서 변경하지 않았다.
- `permission_overrides` 스키마, 검증 제약, service-role 전용 RPC 권한과 자동 테스트로 저장·권한 계산 기준을 확인했다.

## 남은 실제 QA

1. 현재 QA 사용자가 소유한 격리 Display 메뉴판을 준비한 뒤 대기번호 등록·픽업·수령을 새 데이터로 한 번 완주한다.
2. 신규 결제수단으로 30일 무료체험, 첫 메뉴 6크레딧, 추가 메뉴 미지급, 해지 예약·복구를 함께 검증한다.
3. 활성 직원이 있는 격리 메뉴판에서 역할 프리셋과 직원별 허용·차단 덮어쓰기를 실제 저장·재로그인으로 검증한다.
