# 전체 카탈로그 생성·디자인 정합성 점검

## 범위

현재 선택 가능한 기본 디자인 10종, 디자인 템플릿 9종, 독립 Display 1종을 대조한다. 구매 선택/가격·디자인 ID/표시명, 실제 신규 스타터 저장, 중복 생성 방지, 대표상품/이미지/가격 열/위젯/번역, 디자인 교체 후 고객 내용 보존을 검사한다. 실제 결제를 실행하거나 운영에 검수용 메뉴판을 생성하지 않는다.

## 발견 및 보완

1. 신규 메뉴의 가게 설명을 적용하는 조건이 프리셋 객체 자체의 동일성을 사용했다. 보조명을 채우기 위해 복제한 모카·루프는 조건에서 탈락했고 반고흐·온유·다이닝도 등록된 샘플 설명이 저장되지 않았다. 이제 등록된 템플릿 키를 기준으로 적용하며 이미 입력한 가게 설명은 보존한다.
2. 신규 베이직 번역 행에 샘플 가게명을 저장해 언어 전환 때 고객 매장명을 덮었다. 초기 번역의 매장명/소개 타이틀/커버 타이틀은 비워 고객이 입력한 원문을 사용한다. 메뉴/설명 번역은 유지하며 카탈로그 샘플의 원래 브랜드는 바꾸지 않는다.
3. 등록된 위젯 샘플이 신규 스타터의 실제 저장에서 누락됐다. 기존 `menu_widgets` 표·파서·권한을 재사용해 페이지와 설정을 함께 저장한다. 모카만 기존 이미지 전용 3:1/contain/bottom-right 위젯 ON, 나머지 OFF다. 기존 메뉴가 있으면 생성 함수가 먼저 반환하므로 고객 위젯을 채우거나 덮지 않는다.
4. 기본 다이닝 좌측형의 신규 생성이 확정된 미리보기와 다른 메종 마레 샘플을 사용했다. 기본 다이닝 2종/앨범은 원래 동일한 메뉴 예시(185,000원 시그니처 코스)를 사용한다. 공유 원본 선택을 한 정책으로 묶어 실제 카탈로그 서버 경로·신규 생성·번역을 동일하게 맞췄다. 원래 메종 마레/오브 테이블 스킨은 각자의 데이터와 서체·구조를 유지한다.

## 검증

- 전체 생성 20종: 입력 매장명/주소/전화/설명 보존, 페이지·아이템 수·대표 연결·실제 이미지 파일·가격/계약·디자인 이름·번역 원문 fallback·위젯 파싱/설정/기본 표시·재실행 무변경을 확인했다. Display는 전용 생성기 결과와 비교한다.
- 기본 다이닝 좌측형/앨범 4언어 8조합과 실제 카탈로그 서버 경로의 기본 다이닝 외국어 12조합을 확인했다. 구매 생성과 미리보기의 실제 페이지/카테고리/상품 이름·가격을 20종 모두 직접 대조한다. 수작업으로 구성한 원본 가정만으로 정합성을 판정하지 않는다.
- 격리 PostgreSQL의 실제 서비스/API/계약 DB 가드: 19개 구매 가격 선택과 136개 허용 교체 조합 및 원래 디자인 복귀를 포함해 1,185건 통과. 다른 서비스/이용권/소유자 차단, 동시 편집 보존, 고객 메뉴·주문·결제 불변을 포함한다.
- 전체 단위 786건, 타입·변경 파일 린트·운영 빌드 통과.
- 운영 읽기 감사: 신규 디자인 계약 1건의 저장 디자인/렌더러/이용권 불일치 0건. 운영 고객 데이터·계약·결제·권한·환경변수·DB 스키마는 이번 작업에서 변경하지 않는다.
- 실제 운영 미리보기 58개 고유 조합: Basic/Dining 19종 × PC/태블릿/모바일 및 독립 Display 1종. 실제 source viewport PC 1512×762, 태블릿 1180×820, 모바일 390×844를 기록했다. 가로 넘침·깨진 이미지 0, 원래 스킨 제목 유지. 메종의 첫 폰트 로딩 상태는 별도 재관찰해 loaded를 확인했다. 데이터/번역 변경 조합은 배포 후 다시 확인한다. 추가 모바일 320/430px 38조합에서도 가로 넘침·깨진 이미지 0건을 확인했다.

검수 결과와 운영 읽기 원본은 `/private/tmp/catalog-*`에 보관하며 고객 식별자와 비밀키는 저장소에 포함하지 않는다. 기존 고객 데이터를 일괄 초기화하는 기능은 추가하지 않는다. 템플릿 배치·서체 크기·모바일 20/24/48 간격과 독립 Display 엔진은 변경하지 않는다.
