# 전체 메뉴판 통합 운영

2026-11-18 사용자 요청. `운영할 메뉴판`에 **전체 메뉴판**을 추가하고, 기능을 지원하며 사용자가 접근 가능한 베이직·다이닝의 주문·호출을 통합 조회·처리한다. 홈페이지 통합과 애니메이션은 별도 후속 작업이다.

- 통합 대시보드: `/mypage/operations?site=all`
- 통합 현재 주문/주문 이력: `/mypage/operations/orders`, `?tab=history`
- 통합 호출: `/mypage/operations/calls`
- 통합 목록과 상세에는 메뉴판 이름을 표시한다. 개별 메뉴판 목록/상세에는 새 이름 열을 추가하지 않는다. 영수증은 해당 주문의 실제 메뉴판 이름을 사용한다.
- 주문·호출에 이미 연결된 메뉴판 식별자를 사용한다. 새 DB 컬럼·데이터 이동·스키마/권한 변경은 없다.
- 메뉴판별 기존 서버 조회와 상태 변경 경로를 재사용한다. 주문 조회와 주문 처리/미결제 취소/외부 결제 기록 권한은 각 메뉴판별로 따로 적용한다. `all`을 실제 메뉴판 식별자로 쓰거나 직원 권한을 합집합으로 확대하지 않는다.
- 디스플레이·미지원 템플릿·권한 없는 메뉴판은 통합 대상에서 제외한다. 접수 사용 설정과 구독 상태를 자동 변경하지 않는다.
- 테이블 이름과 주문/호출 번호가 같아도 내역을 합치지 않는다. 통합 화면은 메뉴판 이름·룸·테이블을 포함하는 공통 리스트를 사용하고, 개별 메뉴판의 기존 리스트/배치도 선택은 유지한다. 테이블·QR·매출·대기번호·접수 설정은 개별 메뉴판에서 관리한다.
- 현재 주문은 기존의 날짜와 무관한 진행 중/미결제 조회를 유지한다. 주문 이력은 같은 필터/복합 커서를 메뉴판별로 적용한 뒤 전역 시간·ID 순서에서 50건을 선택한다. 필터된 전체 건수를 합산하고 앞/뒤 페이지 커서를 다시 계산한다. 테이블 선택에는 메뉴판 이름을 함께 표시한다.
- 호출은 기존 기준대로 메뉴판별 최근 100건을 합쳐 최신순으로 표시한다. 도움말에 조회 범위를 명시한다.
- 현재 내역은 15초마다 갱신한다. 개별/통합 화면은 같은 메뉴판별 알림 설정·확인한 ID 기록을 공유한다. 알림을 새로 켜거나 화면 전환으로 기존 내역을 새 접수로 재알림하지 않는다. 브라우저 알림 본문은 기존의 일반 건수 안내를 유지한다.
- 한 메뉴판 조회가 실패해도 다른 메뉴판은 표시하되 실패 메뉴판과 집계 누락을 명시한다. 전체 실패는 빈 내역으로 표시하지 않는다. 동시 조회는 최대 네 메뉴판으로 제한한다.

## 검증

`lib/all-menu-operations.test.ts`는 기능별 대상 필터, 권한 없는 메뉴판 조회 차단, 부분 실패, 조회 동시성, 동일 이름/번호의 출처·처리 권한 보존, 전역 양방향 이력 페이지 경계, 호출 병합, 통합/개별 메뉴판 이름 열을 검증한다. 공통 사이트 UI 검사와 실제 브라우저의 PC/태블릿/모바일 리스트·상세·출처별 폼 대상을 함께 확인한다. 검수용 주문/호출은 합성 데이터만 사용하며 운영 접수/결제/설정 쓰기는 하지 않는다.

이 변경은 기능 추가이므로 일반 소규모 UI 자동 릴리스 정책과 구분한다. Production 배포 전 사용자 승인을 받는다.

### 통합·개별 운영 화면 일관성 보완 (2026-11-18)

사용자 승인에 따라 왼쪽 상단의 `운영할 메뉴판` 선택기를 유지하고, 통합 대시보드에도 개별 화면과 같은 공통 OverviewCard 4개를 같은 순서(공개 상태, 테이블·키오스크 등록, 전체 주문 상태, 전체 호출 상태)로 제공한다. 최근 주문·호출은 개별 화면과 같은 공통 리스트를 사용하며 통합 화면에서만 메뉴판 이름을 덧붙인다.

- 통합 카드에는 공개/등록/접수 중인 메뉴판 수와 진행 중 주문·대기 호출 수를 표시한다. 바로 아래 `메뉴판별 상태·설정`에서 각 메뉴판의 상태, 기존 사장 전용 주문·호출 스위치, 개별 설정/운영 진입을 제공한다. 전체 메뉴판을 동시에 변경하는 마스터 스위치는 추가하지 않는다.
- 등록 정보는 `table.manage`와 테이블 이용 가능 여부를 모두 만족할 때만 조회한다. 사장은 기존 전체 설정 로더, 직원은 허용된 주문·호출 접수 요약 로더를 사용한다. 지원 템플릿만 집계하고 최대 4개 메뉴판씩 조회한다. 조회 실패는 `상태 확인 불가`와 경고로 구분하며 등록 0개/미사용으로 숨기지 않는다.
- 통합 모드의 테이블·키오스크/QR/매출/대기번호 메뉴는 이용 가능한 대상이 있을 때 메뉴판 선택 창을 연다. 카드의 공개/등록 설정 및 주문·호출 화면의 설정 버튼도 같은 창을 사용한다. 사용자가 대상을 고른 후 기존 개별 경로로 이동한다. 대상이 없으면 이용 불가 상태를 유지한다.
- 선택 대상은 메뉴판별 기존 권한과 기능 이용 여부로 제한한다. 호출 항목은 `call.manage`가 있는 대상만 제공한다. 선택 창은 권한을 부여하지 않으며 도착 페이지·변경 액션의 기존 서버 검증을 유지한다. DB 스키마/접수/알림 설정을 자동 변경하지 않는다.
- 추가 검증: `lib/operation-overview.test.ts`에서 대상별 권한, 기존 설정 진입, 집계/부분 실패, 사장·직원 조회 경계, 공통 카드 순서 및 메뉴판별 스위치를 검증한다. 합성 데이터의 320/390/820/1440px 실제 DOM viewport에서 가로 넘침 0px, 공통 카드 순서, 사장별 스위치/직원 읽기 전용, 선택 전 이동 비활성, 권한 없는 대상 제외, 선택한 개별 메뉴판 경로와 로그인 후 복귀 경로, Escape 닫기와 포커스 복귀를 확인했다. 검수용 라우트는 삭제하며 운영 설정 쓰기는 실행하지 않는다.
- 보완 변경 검증: TypeScript, 변경 파일 ESLint, 사이트 UI 167건 통과. 전체 1,314건 중 1,313건 통과하며 남은 1건은 위에 기록한 기존 DialogOverlay 문자열 검사다. 해당 테스트와 Dialog 소스는 기준 배포 커밋과 동일하다.
