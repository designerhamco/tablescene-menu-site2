# 원페이지 채움형 배치 감사 — 2026-10-16

## 직접 확인하는 환경

- 개발 서버: `http://localhost:3000/qa/ordered-layout`
- 활성 원페이지 8종의 공개 스타터를 실제 미리보기 renderer로 표시한다.
- PC 1512×762 / 1920×1080, 태블릿 1180×820 / 1024×768 / 820×1180, 모바일 390×844를 선택한다.
- iframe의 실제 viewport는 선택한 값이다. 바깥 화면에 맞춘 CSS 축소는 메뉴의 fit 입력을 바꾸지 않는다.
- 채움형/묶음형 비교, 호출 ON/OFF, 한국어/영어/중국어/일본어, 새 창 열기를 제공한다.
- 계정·결제·주문·실제 고객 메뉴 데이터에 쓰지 않는다. 스타터 편집/저장 기능은 제공하지 않는다.
- 개발 모드에서만 접근한다. 로컬 Production 빌드의 같은 경로는 HTTP 404를 확인했다.

## 감사 범위와 결과 해석

PC/태블릿 128개 조합을 순회했다: 8종 × (한국어 5개 viewport × 호출 ON/OFF + 영어/중국어/일본어 × PC/태블릿 각 1개 viewport × 호출 ON).

감사 도중 확인된 공통 오류를 수정하고 재현 조건을 다시 검사했다. 마지막 공통 변경 이후에는 8종 × PC 1512×762 / 태블릿 1180×820 / 820×1180 × 한국어 호출 ON의 **24개 대표 사례를 모두 재검사해 통과**했다. 리얼맛차 중문 경계도 PC/태블릿에서 별도로 재검사했다. 이는 **전체 128개 조합이 최종 수정본에서 전부 무오류였다는 뜻은 아니다.** 아래 미해결 조건이 남아 있다.

### 미해결: 선데이 로스터스

1024×768 한국어에서 대표 이미지가 차지하는 왼쪽 영역과 상단 행을 제외하면 메뉴 열의 폭/높이가 제한된다. 호출 ON은 마지막 호출/언어 블록이 추가 CSS 열로 밀려나는 사례, OFF는 마지막 상품과 하단 언어 dock의 안전 영역이 겹치는 사례가 남는다. `reload` 상태이며 정상으로 통과시키지 않는다. 읽기 글자 하한을 낮추거나 내용을 숨기지 않았다.

### 미해결: ROSY ORANGE

1024×768 한국어 및 1180×820 영어에서 중앙 브랜드 열 양옆의 카테고리 묶음 중 일부가 세로 공간을 넘는다. 현재 중앙열은 저장 모드가 채움형이어도 `CenterRailMenuGrid`의 카테고리 단위 분할 경로를 사용한다. 다른 셸의 상품 단위 CSS 다단 흐름과 동일하지 않다. 후보 열 너비와 실패한 partition 재사용은 보완했지만, 이 조건의 실제 넘침은 해소되지 않았다. 상품 단위 이어짐/중앙열 구조의 별도 보완이 필요하며 이번 감사에서 완료로 처리하지 않는다.

1180×820 일본어의 후보 `data-fit-overflow=true`는 실제 잘림과 구분한다. 최종 상태가 ready이고 실제 DOM의 메뉴 overflow·클리핑·겹침이 없으면 후보 추정값만으로 실패시키지 않는다. 최종 안전 판정은 계속 유지한다.

### 미해결: 공통 채움형 푸터의 하단 앵커

최종 PC/가로 태블릿 스크린샷 8종을 각각 비교하면, 일반 CSS 다단 채움형의 호출/안내 블록은 `.cafe-a-ordered-menu-flow > .cafe-a-footer-info`의 static 흐름을 따른다. 따라서 항상 페이지 맨 아래에 고정되는 것은 아니다. LOOP BAGEL 1180×820에서는 호출/안내만 다음 메뉴 열 상단에 넘어가는 빈 열 사례도 보인다. REAL MATCHA·KOHI·Mocha 등도 호출/안내가 메뉴 바로 뒤의 중간 높이에 머물 수 있다. ONUE는 별도 측정되는 바깥 하단 푸터를 이미 사용한다.

이것은 텍스트 겹침/잘림 검사 통과와 별개의 **디자인 앵커 미준수**이며, 이번 감사에서 정상 하단 고정으로 간주하지 않는다. 공통 ordered 푸터의 실제 공간 예약과 마지막 열 하단 앵커를 함께 보완해야 한다. 전역 글자 하한/간격을 낮춰서 숨기거나 템플릿마다 별도 숫자를 더하지 않았다.

## 이번에 수정한 공통 문제

1. 간격 적용이 다음 블록을 다음 열로 이동시켰다는 이유로 그 간격을 다시 제거하지 않는다. 채움형의 등록된 다음 블록이 간격 판정의 기준이며, 열별 fragment는 장식/물리적 위치 판정에 사용한다. 카테고리→위젯 등 블록 유형은 보존한다.
2. 최종 안전 배율·실제 copy 측정·선택적 5% 강조·행 높이 변화 뒤에도 경계를 갱신한다. 컨테이너 크기가 그대로인 경우도 포함한다.
3. 768–1023px 태블릿 canvas에 동일한 경계 토큰을 연결한다. 옛 좁은 화면의 sibling 위 여백과 마지막 상품 아래 여백이 중복되지 않게 한다. 기존 분리선/KOHI 여백 및 모바일 규칙은 유지한다.
4. 상단 행은 이미 잘린 설명/안내의 현재 사각형만 읽지 않고 `scrollHeight`까지 포함한다. 기존 공통 8–14% 범위는 유지한다.
5. 중앙 브랜드 셸의 후보 너비가 확정된 `data-fit-columns`가 아니라 탐색 중 `--fit-columns`에 반응하게 한다. 실제 실패한 partition/허용되지 않는 열 후보를 settled-state 유지 경로에서 다시 재사용하지 않는다.

## 반복 실행

```sh
node --import tsx scripts/qa-one-page-ordered.mjs
node --import tsx scripts/qa-one-page-ordered.mjs --mobile
ORDERED_QA_MODE=orderedBalancedFit ORDERED_QA_CALL=on ORDERED_QA_WIDTHS=820 ORDERED_QA_LOCALES=ko node --import tsx scripts/qa-one-page-ordered.mjs
```

- `ORDERED_QA_KEYS`: 템플릿 키 쉼표 목록.
- `ORDERED_QA_WIDTHS`: 한국어 검사 viewport 너비 필터.
- `ORDERED_QA_LOCALES`: 추가 번역 언어. `ko`만 지정하면 추가 번역 사례를 생략한다.
- `ORDERED_QA_CALL`: `on`/`off` 또는 생략해 둘 다 검사.
- `ORDERED_QA_BASE`, `ORDERED_QA_OUTPUT`: 서버 주소와 결과/스크린샷 디렉터리.
- 기본 출력: `/private/tmp/ordered-layout-qa/report.json`과 실제 화면 PNG.

검사는 폰트와 실제 행 위치 및 로딩 덮개가 안정된 뒤 실제 viewport, 상품 누락/중복, 상품/가격 정렬, 열별 카테고리 경계, 실제 잘림·겹침, 상품 분할, 호출/안내 충돌, 스크롤 및 깨진 이미지를 확인한다. 숨긴 모바일 메뉴 영역을 PC 검사 대상으로 사용하지 않는다. 추정 fit overflow 플래그만으로 실제 안전 검사를 대체하지 않는다. 원페이지 검수 목록이 활성 공통 셸 목록에서 빠지면 단위 테스트가 실패한다.

최종 회귀: 대표 채움형 24개 / 세로 태블릿 묶음형 8개 / 모바일 320·430px 16개 통과. 645개 단위 테스트, TypeScript, 변경 파일 ESLint, Production build 통과. 검수 화면의 8개 선택 버튼·실제 iframe viewport·배치/언어/호출 전환도 브라우저로 확인했다. 이 통과 숫자에는 위 미해결 viewport/언어 조합과 푸터 앵커의 시각 판정을 포함하지 않는다.

브라우저 증거는 로컬 임시 디렉터리에 보관한다. `ordered-layout-final-a/b`는 128개 1차 감사, `ordered-layout-final-regression`은 최종 대표 24개, `ordered-layout-boundary-final`은 리얼맛차 경계 재현, `ordered-layout-header-fix`는 반고흐 상단 높이, `ordered-layout-center-fix`는 중앙열 보완 후 남은 실패 조건을 기록한다. 화면이 ready라는 이유만으로 모든 고객 입력의 무오류를 보장하지 않는다.
