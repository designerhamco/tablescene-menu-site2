# 매장 운영 테이블 우선 흐름 검수

## 동작

- 현재 이용 가능한 메뉴판만 왼쪽 고정 영역의 셀렉트에서 선택한다. 현재 기능/설정 화면을 가능한 범위에서 유지하며 권한이 없으면 대시보드로 이동한다. 상단 메뉴판 탭은 제거한다.
- 종료·취소로 이용권이 끝난 메뉴판은 제외한다. 설정 진입이 가능한 사장 메뉴판도 동일한 이용기간 검사를 통과해야 한다. 이용기간이 남은 해지 예약과 유료 이용 중인 작성중 메뉴판은 보존한다.
- 테이블·QR을 주문/호출보다 위에 표시한다. 테이블 준비 여부와 기능 연결 상태·조회 실패를 구분해 안내한다. 대표 QR은 테이블 없이 메뉴판 공유에 사용한다.
- ON 저장 직전에 서버에서 해당 메뉴판의 활성 테이블을 재확인한다. 빈 목록·조회 실패·기존 runtime 미연결에서 ON을 거절하며 OFF 저장은 테이블 조회 없이 계속 가능하다. 다른 기능의 저장값은 보존한다.
- 기존 주문/호출 내역 접근을 테이블 개수나 기능 ON/OFF로 막지 않는다. 테이블을 활성화해도 주문·호출 저장값을 자동 변경하지 않는다. 테이블 변경 뒤 운영 대시보드·주문/호출/설정 화면을 갱신한다.
- 상품별 주문 허용 스위치·상품 데이터·품절 정책은 이번 변경 대상이 아니다.

## 검증

- 전체 단위·계약 890건 통과. 활성 테이블 0개/조회 실패/runtime-off의 ON 차단, OFF 보존, 주문·호출 독립 저장, 메뉴판 범위/상태 제한, 종료·완전 취소 제외와 기간이 남은 해지 예약 보존, QR 전용 권한 경계 포함.
- TypeScript 포함 최적화 빌드, 변경 파일 lint, diff check 통과.
- 실제 로그인된 로컬 사장 계정에서 기존 16개 선택 목록이 현재 이용 가능한 7개로 제한됨을 확인했다. 셀렉트로 다른 메뉴판을 선택하면 URL·운영 대상·QR 관리 주소가 함께 바뀐다.
- 실제 주문 설정 화면에서 활성 테이블이 없는 경우 주문 ON 체크박스 비활성·테이블 준비 안내를 확인했다. 1280×720·390×844·820×1180의 선택 상자 경계와 가로 넘침 없음 확인.
- 실제 저장/테이블 생성·상태 변경은 실행하지 않았다. 운영 검수와 배포 확인 결과는 출시 PR에 기록한다.

## 보존 경계

운영 DB/Auth/Storage, 고객 메뉴판 디자인·기존 QR, 구독/결제와 runtime 허용 대상은 변경하지 않는다. 테이블 준비 상태는 인증된 운영 대상에 한정해 최대 1행씩 조회하며 직원에게 테이블 ID나 QR을 추가 노출하지 않는다.

## 운영 안내와 보관 테이블 (2026-11-03)

- 테이블 관리의 QR 관리 바로가기·다운로드 안내를 제거한다. QR 관리는 왼쪽 운영 메뉴에서 진입한다.
- 테이블 준비 안내는 대시보드 운영 현황·스위치보다 먼저 표시한다. 공통 `site-notice-warning` 표면과 colored 표시 아이콘을 사용하며, 테이블이 없어 표시되는 이유와 다음 행동을 안내한다. 조회 실패·기능 미연결·권한 없음 문맥은 유지한다.
- 태블릿 연결 안내와 연결 해제는 테이블 관리에 둔다. 각 테이블의 ‘현재 태블릿을 테이블에 연결’ 바로 옆에 ‘테이블 연결 해제’를 표시한다. 현재 기기가 실제로 연결된 테이블에서만 해제와 메뉴판 다시 열기가 활성화된다. 대시보드에는 이 안내/행동을 표시하지 않는다.
- 생성 중에는 공통 `LoadingState`와 `aria-busy`, 비활성 제출 버튼으로 진행 상태를 알린다.
- 보관 테이블은 테이블 관리에서만 명시적으로 포함해 조회하고 운영 목록과 별도로 표시한다. 기존 QR 관리·대시보드 집계에는 섞지 않는다. 복원은 기존 `table.manage` 읽기/쓰기 권한과 이용권/runtime 가드를 통과한 뒤 해당 메뉴판의 보관된 행만 갱신한다. 비활성으로 복원하며 QR·종료된 세션·기존 주문을 변경하지 않는다. 이름 중복은 복원 이름 입력에서 수정할 수 있고 기존 100개 제한도 유지한다.
- 관련 기능 테스트 29개, 사이트 UI 계약 104개, 변경 파일 ESLint와 TypeScript, 프로덕션 빌드 통과. 복원 조회 범위·권한·중복 이름·100개 제한·이미 복원된 상태의 오류를 가짜 DB 질의로 확인했다.
- 실제 컴포넌트를 사용하는 임시 로컬 검수 화면에서 DOM viewport 320×780, 390×844, 820×1180, 1440×900, 1920×1080을 확인했다. 가로 넘침 0px, 안내가 스위치보다 앞에 표시됨, 무테 연노랑 안내/추가 바탕 없는 아이콘, 보관 목록·복원 입력, 생성/복원 대기 상태를 확인했다. 데이터 변경 요청은 모두 차단했으며 실매장 생성·복원·단말 연결 해제는 실행하지 않았다. 임시 라우트는 검수 후 제거했다.

## 테이블별 태블릿 연결과 주소 안내 후속

- 연결은 현재 기기를 해당 테이블의 손님용으로 지정하는 기능이다. 사용자가 요청을 정정한 최종 동작은 **연결 버튼에서 관리자 로그아웃 후 손님용 메뉴판 자동 열기**다. 연결만 저장하고 별도 열기를 요구하는 단계는 도입하지 않는다. 관리 화면으로 돌아온 연결 기기는 ‘메뉴판 열기’에서 동일한 로그아웃 보호를 적용해 다시 열 수 있다.
- 현재 기기의 연결 상태는 권한·메뉴판·token hash·user agent hash·terminal channel·만료·해제 여부를 확인하는 읽기 전용 조회로 표시한다. 조회 실패는 미연결과 구분해 안내하고 연결/해제를 막는다. 관리 페이지 조회로 세션 갱신/쓰기 작업을 하지 않는다.
- 해제는 서버에서도 선택한 테이블 ID와 현재 기기의 유효 terminal 연결을 함께 제한한다. 다른 테이블·다른 기기·손님 QR 세션·만료/이미 해제된 세션을 해제하거나 현재 쿠키를 지우지 않는다. 기존 주문은 보존한다.
- 테이블별 영구 주소는 이미 생성된 `qrPath`를 사용해 표시·복사한다. 주소는 기존 QR 관리 권한이 있는 계정에만 전달하고, 테이블 관리만 가능한 직원의 QR 조회 권한을 확대하지 않는다. QR 다운로드는 QR 관리에 유지한다. 공개 주소의 origin 설정은 QR 관리와 같은 공통 함수로 읽는다.
- 실제 사용 예시와 ‘연결하면 메뉴판 자동 열기’, 같은 태블릿에서 관리자 재로그인 후 해제하는 방법을 짧게 표시한다. 보관은 매장에서 치운 테이블의 과거 주문을 남기며 운영 목록에서 빼두는 기능, 일시 중지는 비활성이라는 설명을 추가한다.
- 연결/미연결/조회 실패/비공개/QR 권한 없음의 실제 컴포넌트를 320×780,390×844,820×1180,1440×1000에서 검수했다. 20개 화면에서 가로 넘침0px, 선택 테이블에만 해제·다시 열기 활성, 주소 복사와 기존 QR 다운로드 미노출을 확인했다. 연결/해제/다시 열기 대기 상태3건도 변경 요청을 차단하고 검수했다.
- 서버 동작 검사는 자동 메뉴판 이동·로그아웃 실패 차단, 테이블별 해제 범위와 실패 시 쿠키 보존을 포함한다. 실제 운영 데이터/Auth 설정·DB 구조는 변경하지 않았다.
- 배포 전 최신 운영 브랜치의 타이포 규칙을 반영했다. 전체 테스트 1,012개·사이트 UI 계약 108개·TypeScript·변경 파일 ESLint·프로덕션 빌드를 통과했고 위 브라우저 23건도 다시 통과했다. 최신 타이포 계약 테스트의 선택적 문자열 검증은 명시적인 타입 좁히기로 보완했다. 검수용 임시 라우트는 제거했다.
