## 동작

- 현재 이용 가능한 메뉴판만 왼쪽 고정 영역의 셀렉트에서 선택한다. 현재 기능/설정 화면을 가능한 범위에서 유지하며 권한이 없으면 대시보드로 이동한다. 상단 메뉴판 탭은 제거한다.
- 종료·취소로 이용권이 끝난 메뉴판은 제외한다. 설정 진입이 가능한 사장 메뉴판도 동일한 이용기간 검사를 통과해야 한다. 이용기간이 남은 해지 예약과 유료 이용 중인 작성중 메뉴판은 보존한다.
- 테이블·QR을 주문/호출보다 위에 표시한다. 테이블 준비 여부와 기능 연결 상태·조회 실패를 구분해 안내한다. 대표 QR은 테이블 없이 메뉴판 공유에 사용한다.
- ON 저장 직전에 서버에서 해당 메뉴판의 활성 테이블을 재확인한다. 빈 목록·조회 실패·기존 runtime 미연결에서 ON을 거절하며 OFF 저장은 테이블 조회 없이 계속 가능하다. 다른 기능의 저장값은 보존한다.

## 테이블별 연결 기기 표시·다른 기기에서 해제 (2026-11-03)

- 사용자 후속 시안의 `태블릿 사용 / 손님 휴대폰·QR`을 공통 상태 탭으로 제공한다. 현재 접속 기기는 운영 테이블 제목 아래에 한 번 표시한다. OS·모델·브라우저를 보여주고, 상세 정보를 브라우저가 제공하지 않으면 확인되지 않은 모델을 만들지 않는다. OS·모델명은 연결 전에 직접 보완할 수 있다. 닉네임 방식으로 대체하지 않는다.
- 각 테이블은 연결된 매장 기기 목록과 현재/다른 기기, 연결일, ‘기기 연결됨’ 상태를 보여준다. 여러 기기는 목록으로 구분한다. 개별 ‘기기 연결 해제’는 대상 확인 후 선택한 terminal 한 건만 종료한다. 연결됨은 등록된 유효 연결 상태이며 실시간 온라인/전원 상태를 뜻하지 않는다. 기기/테이블 미연결·조회 실패·기기 정보 없는 과거 연결을 구분한다.
- 현재 기기 연결은 기존 관리자 로그아웃과 메뉴판 자동 열기를 유지한다. 대시보드의 현재 기기 빠른 연결 패널도 유지하고 다른 기기 관리 진입은 테이블 관리로 안내한다. 테이블별 기존 편집·보관·복원은 보존하며 탭을 바꿔도 입력 중인 이름/상태를 잃지 않는다. 테이블 메뉴판 주소 옆에 열기/복사를 둔다. 현재 terminal의 메뉴판 열기는 서버 확인·관리자 로그아웃을 거치고, 다른 테이블에 연결된 현재 기기가 잘못된 테이블 주소를 여는 경우는 차단한다. QR 권한이 없더라도 기존의 현재 terminal 메뉴판 열기는 남긴다.
- 목록/해제 서비스는 유효 이용권·지원 템플릿·runtime·table.manage를 검증한다. 다른 매장·테이블·손님 QR 세션·만료/이미 해제된 연결은 거절한다. 선택한 다른 기기를 해제해도 호출자의 쿠키/관리자 로그인·다른 연결·접수 주문은 보존한다. 목록에 토큰/UA hash를 전달하지 않고 기기 설명은 표시용으로만 사용한다.
- 전체 테스트1,029건·사이트 UI 계약108건·TypeScript·변경 파일 lint가 통과했다. 별도 메모리 PostgreSQL에서 실제 기존 등록 SQL과 추가 마이그레이션을 실행해 기기 정보·JSON/크기 제약·교체 원자성·다른 기기 보존·비활성 차단과 RPC 실행 권한을 검증했다. 운영 DB는 접속/변경하지 않았다.
- 실제 컴포넌트의 현재 연결/다른 기기/미연결/조회 실패/비공개/비활성/이전 연결/복수 기기/긴 모델명/QR 권한 없음/빈 테이블 11상태를 DOM viewport320·390·820·1280·1440·1920·2600px에서 검수했다. 두 탭154조건에서 가로 넘침·카드 내부 넘침·page error·실데이터 쓰기는0이며 공통20/24px 패널·16px 안내 여백과 흰/유색 경계를 실측했다. 해제 확인/취소·정보 제출·현재 메뉴판 열기·다시 확인·주소 복사6건과 두 탭의 WCAG2A/AA·2.1AA axe 검사도 통과했다. 연결된 현재 기기의 메뉴판 열기 버튼이 중복되지 않음을 별도 확인했다. 검수용 임시 라우트는 제거했다.
- 기기 정보 저장용 SQL 한 건은 준비만 했으며 운영 적용과 배포는 아직 하지 않았다. 상세 정보 저장은 SQL 적용 후 새 연결부터 가능하고, 기존 hash에서 모델명을 복원하지 않는다. 기존 스키마에서도 목록/해제/기존 등록은 호환한다. 출시 순서와 격리 DB 검수 재실행은 `docs/runbooks/table-terminal-device-info-migration.md`를 따른다.
- 임시 라우트 제거 후 별도 출력 경로의 프로덕션 빌드도 통과했다. 타입 검사는 빌드 설정의 생략 여부와 별개로 `tsc --noEmit`을 실행해 통과했고, 검증용 Next 생성 설정 변경은 복원했다.

## 대시보드 형제 key 충돌 수정

- 현재 기기 패널과 운영 상태 카드가 같은 부모에서 같은 메뉴판 ID를 key로 사용해 로그인된 대시보드 조합에서 React 중복 key 오류가 발생했다. 각각 `tablet-connection:${menuId}`, `operation-status:${menuId}`로 구분해 충돌을 없애고 메뉴판 변경 시 각 영역의 상태 초기화는 유지한다.
- 실제 서버 페이지 함수를 인증/조회 스텁으로 실행하는 회귀 테스트를 추가했다. 수정 전 동일 메뉴판 key 중복으로 실패하고 수정 후 두 메뉴판 모두 통과했다. 실제 두 컴포넌트를 같은 부모에 렌더링하는 임시 로컬 화면에서도 오류를 먼저 재현한 뒤 두 메뉴판을 번갈아3회 열어 console error·page error가0임을 확인했다. 이 검수는 실제 운영 계정/데이터 저장을 사용하지 않았으며 임시 경로는 제거했다.

## 공개 검사 안내의 의미 확인

- 현재 공개 검사는 저장된 매장명·주소·필수 메뉴 데이터 유무와 다이닝 구조를 확인한다. 기본 예시 데이터도 존재하는 데이터에 포함되며, 실제 매장 정보로 수정했는지 또는 내용의 정확성까지 자동 판별하지 않는다. 조건을 충족하면 별도 사전 확인창 없이 공개하고, 부족할 때만 오류를 안내한다.
- 공개 서비스/대시보드 action 관련10개 테스트를 다시 통과했다. 실제 공개 토글 컴포넌트에 매장명 누락·메뉴 누락의 action 응답을 모의하는 로컬 브라우저 검사에서 해당 안내가 표시되고 토글은OFF를 유지했다. 실제 공개 요청은 차단했고, 운영 상태는 변경하지 않았다. 임시 검수 경로는 제거했다.

## 미사용/사용 불가와 카드 밖 저장 피드백 후속

- 사용자 요청에 따라 준비된 상태의OFF만 ‘주문 미사용 / 호출 미사용’으로 표현한다. 비공개·테이블 미등록·전체 비활성·기능 제한은 ‘주문 사용 불가 / 호출 사용 불가’와 원인 칩으로 표시한다. 조회 실패와 권한 부족의 확인 불가 표현은 유지한다. 저장된 플래그가ON이어도 사용 조건이 없으면 사용 불가이며, 비공개가 확실하면 부가 조회 실패와 별개로 해당 제약을 안내한다.
- 공개·주문·호출의 저장 결과 문단을 카드에서 제거했다. 공통 `OperationActionFeedback`이 실패를 공통 Dialog로, 성공을 기존 공통 토스트로 표시한다. 공개 실패의 편집 이동은 편집 권한이 있을 때만 제공한다. 서버의 공개 검사/권한/동시 변경 보호와 기존OFF 확인은 유지한다. 사전 공개 확인창을 추가하거나 오류를 성공으로 처리하지 않는다.
- 공통 `Switch loading`은 저장 전 위치와48×44px 크기를 보존하고 손잡이 안에 스피너를 표시한다. 행 밖/옆의 로딩 때문에 좁은 카드가 늘어나는 문제를 피한다. 결과 레이어창은 비동기 처리가 끝난 뒤 열어 닫기 직후 토글에 포커스가 정상 복귀하도록 한다. 비활성화된 토글이면 같은 카드의 가능한 이동 행동으로 복귀한다. 닫기 버튼과 긴 제목은 공통 `DialogHeader reserveCloseButton` 영역으로 구분한다.
- 전체 테스트1,033건·사이트 UI 계약110건·별도 TypeScript·변경 파일 lint와 최적화 빌드가 통과했다. 실제 상태 카드의11상태 × 7너비(320·390·820·1280·1440·1920·2600px) 77화면에서 표시값·스위치·원인·공통 여백·무테·넘침 없음을 확인했다. 공개/주문/호출의 실패·성공·긴 오류·통신 오류45조건에서 토글의 저장 전 상태 보존, 레이어/토스트, 닫기와 포커스 복귀, 처리 중/후 카드 높이 보존을 확인했다.
- 실제 레이어창을320·390·820·1440px에서 axe WCAG2A/AA·2.1AA와 제목/닫기 글리프 비겹침으로 검수했다. 흰/회색/어두운 표면의 로딩ON/OFF를 일반·강제 색상·동작 감소로 확인해 스위치48×44px·CSS스피너12px·손잡이 내부 포함과 reduced-motion 정지를 검증했다. 저장 응답은 로컬 모의 응답으로 대체해 운영 공개/주문/호출 설정을 변경하지 않았다.
- 검수용 임시 라우트/컴포넌트는 제거했고, 검증 빌드가 변경한 Next 타입 설정은 복원했다. 로컬 반영 상태이며 운영 배포·SQL 적용은 실행하지 않았다.
