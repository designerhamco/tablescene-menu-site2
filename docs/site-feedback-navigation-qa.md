# 보조 안내·로딩·모바일 전체 메뉴 검증 — 2026-11-02

## 적용 범위

- 이용가이드의 Chrome 권장 안내는 기존 공통 말풍선을 사용하는 `InfoTooltip`으로 이동했다. 마우스오버·클릭·키보드를 지원한다.
- 조회 상태에는 공통 `LoadingState`를 사용한다. 스피너와 불확정 막대를 제공하며, 실제 진행률이 있는 작업만 `ProgressBar.value`를 사용한다. 컴포넌트 디자인에 예시와 모션 감소 동작을 등록했다.
- 템플릿 상세는 승인된 세 묶음(메뉴 표현 / 콘텐츠·프로모션 / 매장 서비스)에서 기존 여덟 상세로 연결한다. 지원 여부 설명과 만들기·미리보기·갤러리·도킹은 유지한다.
- 모바일 전체 메뉴는 흰 왼쪽 시트, 같은 단계의 서비스와 고객센터 펼침 메뉴, 계정 영역과 하단 문의·로그아웃으로 구성한다. 로그인/회원가입, 알림, 만들기와 로그인 후 마이 메뉴·매장 운영·계정 역할을 제공한다. PC 헤더 배치는 유지한다.

- 새 메뉴 Dialog·도움말 Dialog·공지 로딩 영역의 axe WCAG 2 A/AA 및 2.1 AA 검사: critical/serious 위반 0. 이용가이드 전체 페이지 검사에서는 기존 비활성 디스플레이 탭의 대비 경고가 남아 있으므로 전체 사이트 접근성 통과로 해석하지 않는다.

화면 검증은 실제 DOM 뷰포트 320/390/820/1180/1440px 중 해당 화면의 조건을 사용한다. 이용가이드 말풍선의 클릭·Enter·Escape·호버와 화면 경계, 모바일 계정 3상태, 같은 단계 메뉴의 타이포그래피, 고객센터 펼침, 포커스 제한과 복원, 공지 로딩 종료, 상세 3개 바로가기와 8개 설명, 실제 진행률의 ARIA 값, 모션 감소를 확인한다. 익명 계정 조회는 실제 서버의 401·private/no-store를 확인한다.

사장·직원 화면은 브라우저의 인증 응답과 계정 요약을 격리된 고정 데이터로 대체한다. 유효한 실제 로그인 토큰을 만들거나 Production 계정·공지·DB를 변경하지 않는다. 역할의 서버 판정은 기존 접근 검증 서비스의 소유/직원 결과를 사용하며, 표시 정보로만 사용한다. 실제 계정 로그아웃 대신 디자인 시스템 예시의 상태 전환을 검사한다.

추가 상세페이지 검사인 `scripts/qa-template-details.mjs`는 기존 `aria-hidden` 장식용 푸터 워드마크만 대비 검사에서 제외한다. 도킹 직전 좌표는 실제 스크롤 적용을 기다리며, 버튼 위치의 연속성은 버튼 경계가 도킹 시점을 결정하는 경우에 검사한다. 높은 화면에서 헤더 경계가 우선인 경우에도 버튼의 화면 내 노출·클릭 가능 여부와 갤러리 복원은 계속 검사한다.

디스플레이의 신청 버튼은 현재 Production 정책대로 비활성인 출시 준비 상태를 검사한다. 이 작업에서 신청을 활성화하지 않는다.

## 유지할 규칙

새 로딩 UI에는 실제 조회 상태와 상태 문구를 함께 연결한다. 빈 결과·실패를 로딩으로 표시하거나 임의의 진행률을 만들지 않는다. 새 보조 안내와 모바일 탐색은 공통 컴포넌트·색·타입·간격을 재사용한다. 고객 메뉴판의 타이포그래피·템플릿 엔진과 공식 사이트의 로딩/탐색 시스템은 독립적이다.
