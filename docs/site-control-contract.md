# 최종 폰트 기준 우선 적용

글자 크기의 현재 기준은 [최종 사이트 폰트 기준](site-typography-final.md)이다. 이전 기록의 40–60px 제목이나 fluid 글자 크기보다 이 기준이 우선한다.

# 사이트 버튼·탭 공통 기준

공식 사이트와 마이페이지·운영·편집·관리자 화면은 `styles/ui-system.css`, `styles/site-design.css`와 `app/components/ui/button.tsx`, `tabs.tsx`, `navigation-tabs.tsx`를 사용한다. `/design-system`의 기준·토큰과 컴포넌트 라이브러리는 같은 구현을 표시한다.

## 버튼

### 버튼 모양이 달라지는 경계 (2026-11-06)

같은 작업 행에서 서로 붙어 있는 버튼의 모양이 달라지면 그 경계에만 공통 `ButtonGroupDivider`를 사용한다. 예: **사각형 텍스트 버튼 | 원형 아이콘 · 원형 아이콘**. 같은 모양은 기존 순서대로 8px 간격을 유지하고 버튼마다 선을 반복하지 않는다. 색상·활성/비활성 차이만으로는 구분선을 넣지 않는다. 기존 행동의 순서·위치·모양·작동은 유지한다.

구분선은 공통 `--ui-border`의 옅은 회색, 1px 너비, `--ui-button-group-divider-height` 24px 높이이며 버튼 높이의 중앙에 맞춘다. 양옆은 `site-action-row`의 기존 8px 간격을 따른다. 선은 `aria-hidden`인 장식이며 클릭·포커스·키보드 탐색 대상이 아니다. 구분선과 뒤쪽 버튼들을 `site-action-row data-wrap="nowrap"` 한 묶음 안에 두어 좁은 화면에서도 선만 따로 줄바꿈되지 않게 한다. 바깥 작업 행은 기존 자연 줄바꿈을 유지한다.

이 규칙은 인접한 버튼 묶음에만 적용한다. 탭, 입력 필드, 단독 도움말, 서로 떨어진 작업 영역, 고객 메뉴판 렌더러에 자동 삽입하지 않는다. 새 버튼 묶음을 만들 때 모양별 경계를 확인하며, 페이지마다 별도의 선 색·높이·여백을 만들지 않는다. 배치도 편집기의 ‘바로 배치 | 사각형 그리기 · 배치 해제’와 컴포넌트 라이브러리가 같은 구분선을 공유한다.


| 용도 | 공통 변형 | 규격 |
| --- | --- | --- |
| 저장·시작·확인 | primary | 검정 표면, 흰 문구 |
| 미리보기·취소·다운로드·로그아웃 | outline | 흰 표면, 회색 테두리 |
| 초기화·보조 행동 | secondary | 옅은 회색 표면·공통 1px 경계 |
| 아이콘 도구 | ghost + icon | 투명 표면, 명시적인 원형 |
| 삭제 요청 / 삭제 확정 | outline-danger / danger | 빨강 의미 유지 |
| 문구형 보조 이동 | link | hover 때만 밑줄 |
| AI 실행 | ai | 일반 40px, 보라·파랑 공통 그라데이션·흰 문구 |
| 고객지원 퀵 버튼 | ai + 지원 전용 형태 | 56px 정사각형·20px 모서리·30px 말풍선 |

버튼 높이는 compact 32px, default 40px, header 44px, large 48px 네 단계뿐이다. 텍스트 버튼은 최신 타이포 계약의 공통 control 역할(모바일·태블릿15px / PC16px·600)을 사용한다. 기본 모서리는 8px, 좌우 패딩은 default 16px·large 20px, 내부·버튼 간 간격은 8px이다. 내용이 긴 문구는 필요한 높이를 확보한다. 폭은 문구를 따르며, 폼의 전체 폭이나 모바일 액션 행 배치는 호출 화면에서 결정한다. 같은 버튼을 페이지마다 다른 크기로 보이게 하던 `sm`·`xl`·`rounded`·`square` 별칭은 사용하지 않는다.

compact는 표·편집기 안의 밀도 높은 짧은 도구, default는 일반 실행, header는 헤더 CTA, large는 로그인·가입·결제·신청처럼 흐름을 끝내는 주요 행동에 쓴다. 원형 아이콘은 40px이며 compact 아이콘은 32px다. 기기 미리보기의 어두운 도구는 `site-preview-control` 36px 전용 변형을 사용한다. 색상 스와치도 공통 포커스·hover·누름·비활성 규칙을 사용한다. 카카오 로그인은 제공자 색만 명시적인 변형으로 보존한다.

알림의 ‘모두 읽기’는 사용자 첨부 시안의 전용 떠 있는 역할(`site-button-notification-read-all`)이다. 기존 compact 최소32px·공통 글자/상태를 유지하고152px 너비·12px 모서리·어두운 회색 선·짧은 그림자를 사용한다. 아이콘 없이 알림 목록 하단 중앙에 두며 이 표현을 일반 실행 버튼에 재사용하지 않는다.

라운드는 역할로 정한다. 일반 실행은 8px, 헤더·떠 있는 짧은 CTA·명시적인 pill 그룹만 완전한 pill, 아이콘 단독 제어는 원형이다. 고객지원 런처는 56px·20px 모서리의 전용 둥근 정사각형이다. 크기나 라운드를 문구 길이, 페이지 이름, 개인 취향에 따라 바꾸지 않는다.

secondary는 중간 회색 표면·공통 1px 경계를 사용한다. 비활성 실행 버튼은 더 옅은 표면·낮은 문구 대비와 공통 1px 경계를 유지한다. outline은 취소·미리보기·다운로드·로그아웃 등 보조 실행에 사용하며 흰색과 회색·유색 배경 모두에서 버튼 형태를 구분한다. 회색·유색 패널 자체에는 장식 경계를 추가하지 않는다. 비활성은 역할 색을 모두 제거하며 hover·누름 반응이 없다. 투명 아이콘 도구와 본문 링크는 기존 역할을 유지한다.

페이지의 `text-xs`, `px-*`, `py-*`, `rounded-*`, `disabled:bg-*` 등으로 공통 버튼을 다시 꾸미지 않는다. 반복된 실행 버튼에 고정 최소 폭을 추가하지 않는다. 편집기의 pending/dirty 로직은 원래 역할 클래스를 유지하며 native `disabled`로 공통 비활성 표현을 선택한다.

모든 실행 변형은 기본·hover·누름·키보드 포커스·비활성을 구분한다. hover/active는 native disabled와 aria-disabled를 모두 제외한다. Ghost의 비활성 표면은 투명하게 유지한다. 포커스는 2px 파랑 선으로 표시한다. 라이브러리의 `data-ui-state` 비교표는 실제 의사 클래스와 동일한 CSS 선언을 사용하며, 별도 색상표를 복제하지 않는다. 비상태 칩(역할·서비스·일반 라벨)은 진한 중립 배경·흰 글자·무테, 상태 칩만 성공·주의·오류·정보의 의미색을 사용한다.

## 탭과 선택

[최종 역할 계약](tab-hierarchy-contract.md)을 따른다. 고정 단계와 URL 변경 여부로 모양을 정하지 않는다. 주요 화면은 lg18px·md16px, 선택600·비선택500과 공통 중성 회색을 사용한다. 고객센터는 FAQ·공지·이용가이드를 독립 페이지로 연결하며 FAQ/공지 전환 탭은 사용하지 않는다.

| 역할 | 공통 구현 | 표현·적용 |
| --- | --- | --- |
| 주요 화면 전환 | Tabs/NavigationTabs purpose="page" | 배경 없는 텍스트·문구 너비의 검정 밑줄. 서비스, 가이드, 편집 설정 |
| 독립 콘텐츠 전환 | Tabs/NavigationTabs purpose="section" | 연결형 사각 버튼·검정 선택 면. 템플릿 종류, 결제/AI 내역, 미리보기, 요금 상품 유형 |
| 목록 분류 | CategoryFilter, Tabs purpose="category" | 별도 영역 없는 밑줄. 고객센터·새 메뉴판 주제, 전체/읽지 않은 알림 |
| 목록 조건·본문 이동 | site-filter, ChoiceTile, 링크 | 작은 필터·아이콘. 업종·구성·문서 위치 |
| 상태·보기 값 | Tabs/NavigationTabs purpose="state" | 회색 레일의 둥근 흰 선택 면. 이용 상태·언어·보기 방식 |

템플릿은 page → section → 필터 → 결과, 고객센터는 page → category → 결과다. 영역형은 특정 단계에 고정하지 않는다. 최상위 버튼은 PC·태블릿 내용 폭+좌우 각각24px, 모바일 기존 폭·영역 내 스크롤을 사용한다. 크기는 lg48px/16px, md44px/15px, sm40px/14px다. 선택600·비선택500의 공통 토큰을 쓰고 페이지 CSS로 덮어쓰지 않는다.

영역형은 연결된 사각 버튼이며 바깥 네 모서리만8px다. 검정 바탕·흰 글자 선택 면, 흰 비선택 면과1px 공통 경계를 사용한다. 콘텐츠로 이어지는 긴 기준선이나 둘레 테두리는 넣지 않는다. 최상위 탭의3px 밑줄은 클릭 영역 하단에서4px 위로 올리며 기존 클릭 높이를 유지한다. 제품 Tabs는 purpose를 반드시 선언한다. 저수준 variant는 라이브러리 상태 비교표에서만 쓴다. 패널은 Radix 선택·ARIA·방향키·Home/End, 링크는 URL 이동, CategoryFilter는 버튼/aria-pressed·기존 목록 필터링 동작을 유지한다.

스위치·체크박스·날짜·페이지 번호·캐러셀·드래그·아코디언·썸네일은 각 기능을 유지한다. 헤더·사이드바·마이페이지 메뉴 레일은 사이트 내비게이션이다. 고객 메뉴판·공개 주문/호출·수령 제품은 사이트 탭과 분리한다.

## ON/OFF 스위치

ON/OFF 스위치는 [디자인 시스템의 스위치 계약](site-design-system.md#onoff-스위치-2026-11-03)을 따른다. `Switch`/`SwitchField`의 공통 `--ui-switch-*` 토큰만 사용하며 흰색·밝은 회색은 light, 어두운 배경은 dark 팔레트를 사용한다. 비활성에 전체 opacity를 적용하지 않고, 상태 위치·윤곽·인접 안내를 보존한다. 회색 표면 무테 원칙은 스위치를 식별하는 기능적 윤곽을 제거하라는 뜻이 아니다.

## 셀렉트

기본 HTML select와 Radix SelectTrigger는 동일한 chevron 경로, 20px 크기, 2.25 선 굵기와 16px 우측 여백을 사용한다. 문구 끝에 48px 공간을 예약한다. 커스텀 셀렉트는 열리면 화살표를 회전하고 긴 문구를 잘라 표시한다. native select의 폼·선택·키보드 동작을 보존하며 multiple/size>1 목록에는 화살표를 추가하지 않는다. 강제 색상 모드는 native 화살표를 복원한다. hover·포커스·비활성은 공통 필드 규칙을 상속하고, 비활성에서도 화살표를 유지한다. 고객 메뉴판 렌더러에는 적용하지 않는다.

## 표시 아이콘

설명·빈 상태·현황·알림용 표시는 [표시 아이콘의 표면 계약](site-design-system.md#표시-아이콘의-바탕과-실제-주변-표면-2026-11-03)을 따른다. `site-indicator-icon`은 실제 인접 표면을 `data-icon-surface`로 구분한다. 흰 영역의 필요한 옅은 바탕은 유지하고, 회색·유색 영역에서는 바탕뿐 아니라 타일의 고정/최소 크기·padding·margin도 제거해 실제 SVG 크기만 차지하게 한다. 아이콘 버튼의 동작·클릭 영역·포커스와 알림 점은 이 규칙으로 제거하지 않는다.

## 적용 범위와 검증

- 사이트 UI 전체 TSX와 page 소스를 대조한다. 공통 버튼의 개별 크기·패딩·비활성 색상 덮어쓰기와 폐기된 크기·형태 별칭은 자동 검사에서 실패하며, 별도 탭·선택·도구 구현은 공통 역할에 연결한다.
- 홈·서비스·상품·요금·신청·디자인 템플릿·상세·가이드·고객센터·인증·초대·오류 화면, 마이페이지·구독·결제·계정·문의·직원·운영·메뉴 편집·미리보기·관리자 화면이 같은 스타일 진입점을 사용한다.
- 고객이 제작하는 메뉴판의 `.menu-typography`, `.aube-table-root`, `[data-template-artwork]`와 `components/menu-templates`, `components/public-menu`는 별도 디자인 경계다. 메뉴판의 폰트·배치·모바일 읽기 규칙은 변경하지 않는다.
- `lib/site-control-states.test.ts`는 공통 규격, disabled 상태 우선순위, 동일 상태표 사용, 페이지별 오버라이드 재발과 탭 역할을 검사한다. 기존 헤더 순서·아이콘 크기·접근성 대비 계약도 유지한다.
- 브라우저 검증은 실제 DOM 뷰포트를 기록하고 native 키보드/포인터 입력으로 수행한다. 저장·결제·환불·초대·주문·호출·권한 등 실제 데이터를 바꾸는 동작은 실행하지 않는다. 접근 권한이나 데이터 조건으로 열리지 않는 상태는 소스·공통 컴포넌트 검증 범위를 구분한다.

### 2026-10-26 선택 요소 위계·셀렉트 검수

- `/design-system` 실제 320×850, 820×1180, 1440×1100; `/guides` 390×844, 820×1180, 1440×1000; `/apply` 390×844, 820×1180, 1440×1000에서 로드된 본문과 실제 치수를 확인했다. 페이지 가로 넘침은 0px이다.

## 고객지원 홈과 AI 진입 (2026-10-26)

사이트 퀵 메뉴에는 56×56px/20px 모서리/30px 채팅 말풍선 아이콘의 고객지원 버튼 하나를 둔다. 기존 사용가이드 퀵 링크는 홈 안의 서비스 가이드로 옮긴다. 런처와 고객센터 AI 상담 버튼은 `site-button-ai`의 공통 보라·파랑 그라데이션·흰 문구와 hover/active/포커스를 사용한다. 맨 위로 버튼은 런처보다 16px 위에 놓고 safe-area를 반영한다.

### AI 상담 웰컴 화면과 공통 컴포넌트 (2026-10-26)

선택된 웰컴형을 실제 상담 폼에 적용한다. 상단에는 단일 4방향 반짝임과 ‘AI 상담’ 제목만 표시한다. 영문 텍스트 칩과 캐릭터는 없다. 인사말은 `type-subsection-title`, 본문은 공통 의미 역할, 추천 질문은 실제 `Button`의 outline, 전송은 `Button`의 ai/icon, 입력은 `Input`의 md를 사용한다. 흰 배경에서 CSS Module은 배치·스크롤·대화 말풍선만 맡고 버튼의 모서리·패딩·색상·상태와 입력의 경계·높이·포커스를 별도로 덮어쓰지 않는다. 추천 질문은 기존 상담 API로 이어지며 FAQ 자동 응답 기능을 추가하지 않는다.

채팅 하단의 상시 사용가이드·1:1 문의 링크는 지원 홈과 겹치므로 표시하지 않는다. 실패 상태의 1:1 문의 연결과 개인정보 처리방침 링크는 유지한다. 체크 전 국외 이전 안내 전문·체크 후 요약, 명시적 동의 검증, 계정 DB 미저장과 기존 runtime gate는 보존한다. 고객지원 홈의 채널·FAQ·링크와 런처 형태는 그대로이며, AI 진입점·전송 버튼과 라이브러리 예시는 `--site-ai-gradient`/`--site-ai-foreground` 및 공통 상태 규칙을 공유한다.

## 흰 배경의 독립 보조 행동 (2026-11-06)

- 취소·변경 취소·로그아웃·독립 안내 CTA는 기존 outline을 사용한다. 흰 바탕에 공통 밝은 회색1px 경계로 구분한다. 삭제 요청은 outline-danger의 의미색을 유지한다. 새로운 버튼 크기·색·모서리 변형은 추가하지 않는다.
- ghost/danger-ghost는 아이콘 도구에 사용한다. 독립 텍스트 실행을 투명 버튼으로 표시하지 않는다. 본문 이동 링크·동의 상세·이름 옆 연필과 결합한 인라인 편집 진입은 각각 기존 link/인라인 패턴을 유지한다.
- disabled는 기존 공통의 옅은 회색 표면·흐린 문구·반응 없음으로 표시한다. 회색·유색 패널에 장식 테두리를 추가하지 않는다. 아이콘 도구의 클릭 영역·포커스·hover는 유지한다.
- /design-system의 ‘흰 배경의 보조 행동’ 예시는 실제 Button outline·outline-danger·ghost/icon과 비활성을 표시한다. 상태 표의 ghost는 텍스트가 아닌 실제 아이콘 도구로 비교한다. 자동 검사 action-affordance는 네이티브 버튼/링크·별칭 Button의 ghost 텍스트 오용을 차단한다.

## 배경과 실행 버튼의 경계 (2026-11-06)

- 버튼 색상은 실제 인접 배경에서 판단한다. 같은 계열의 회색 면이 이어져 문구만 떠 보이게 하지 않는다. 일반 실행은 기존 primary/outline/secondary 역할을 유지하며 새 로컬 색상·그림자·크기를 만들지 않는다.
- 회색 secondary와 불투명 비활성 실행 버튼은 `--ui-button-boundary`의 공통1px 회색 경계를 유지한다. 비활성은 옅은 표면·흐린 문구·반응 없음으로 표현하며, 경계를 지워 형태를 없애지 않는다. native disabled, 부모 fieldset의 disabled, aria-disabled 모두 같은 경계 규칙을 사용한다.
- 이 경계는 조작 영역 식별을 위한 기능적 윤곽이다. 회색·유색 패널 자체의 무테 규칙과 구분한다. ghost/danger-ghost 아이콘 도구·문맥 안의 link는 기존 투명/링크 역할을 유지한다. 버튼 위치·기능·비활성 조건은 바꾸지 않는다.
- 컴포넌트 라이브러리 `#button-surface-boundaries`에서 흰색/회색 배경, 활성 secondary/outline, 부모 fieldset으로 비활성인 이동 버튼을 비교한다.

검수: 로컬1512px PC·820px 태블릿·390px 모바일에서 흰색/회색 예시의 경계와 줄바꿈을 확인했다. 부모 fieldset으로 비활성인 이동 버튼은 접근성 트리에서도 disabled로 유지된다. 사이트 UI 계약119건·전체 테스트1086건·변경 파일 ESLint·Production 빌드가 통과했다. 실제 매장 데이터는 변경하지 않았다.


## 연결형 배치도 편집 작업 영역 (2026-11-06 최종 시안)

- 최신 승인 시안이 기존 배치도 무패널 기록보다 우선한다. 룸 선택·이름 수정·룸 추가와 등록/룸 삭제는 작업 영역 위의 기존 진입을 유지한다. 그 아래 `FloorPlanWorkspace`가 배치 현황/도구 → 캔버스 → 하단 이동·변경 취소·저장을 하나의 흰 작업 영역으로 묶는다.
- `ContentPanel layout="canvas"`의 공통 경계·모서리를 사용하며 안쪽 캔버스에는 중복 경계를 두지 않는다. 도구·하단 영역은 공통20/24px panel inset과16px 간격을 사용한다. 하단은 회색 면과 위쪽 구분선으로 연결하고 룸 이동은 왼쪽, 변경 취소/저장은 오른쪽에 둔다. 선택 칸과 버튼의 높이 중심을 맞춘다. 별도의 모바일 재설계는 추가하지 않는다.
- 기존4:3 캔버스·상대 좌표·룸 추가/즉시 이름 저장·그리기/바로 배치·드래그/크기 조절/방향키·저장/충돌/취소/이탈 보호를 유지한다. 사각형 안 X는 해당 배치 초안만 해제하며 등록·QR·운영 이력은 지우지 않는다. 공통 Tooltip/접근성 이름으로 ‘배치 해제’를 설명한다. X는 사각형 선택 영역의 형제 제어로 두어 드래그/선택/키보드 이동과 중첩하지 않고 해제 후 배치 선택 칸으로 초점을 돌린다. 읽기 전용 운영 배치도에는 X를 추가하지 않는다.
- 테이블·키오스크 관리에 모바일(767px 이하)로 처음 진입하면 공통 Dialog로 PC 편집 권장 안내를 표시한다. 모바일 확인/편집을 제한하지 않으며, 닫은 뒤에는 같은 탭 세션에서 반복하지 않는다. 브라우저 저장 공간이 제한되어도 닫기·편집은 동작한다. 확인·X·Escape로 닫고 보기 유형 탭으로 초점을 돌린다. PC·태블릿에는 자동 표시하지 않는다. 라이브러리는 같은 Dialog와 실제 편집기 예시를 제공한다.

### 2026-11-06 · 주문·호출 개별 허용과 보관으로 단순화

- 테이블·키오스크 자체의 사용 ON/OFF 스위치는 제거한다. 잠깐 멈추는 기능은 기존 주문·호출 설정의 방식별 허용 ON/OFF가 담당하고, 보관은 운영 목록·배치도에서 제외하되 등록·주문·호출 기록을 유지하는 관리 동작이다.
- 배치도 선택 정보는 도구 아래·캔버스 위에 표시한다. `OrderPointReceptionSummary`와 `OrderPointConnectionControl`을 리스트형과 공유하며 개별 허용값·기기 도움말·설정 목적지가 같다. 전체 기능·공개 상태·연결 조건이 포함된 실제 접수 상태로 오해하지 않도록 개별 허용임을 안내한다. 보관은 선택 정보 줄 오른쪽의 별도 관리 행동이며 X 배치 해제와 구분한다.
- 선택 전후 같은 높이를 확보하고 좁은 화면은 가로 스크롤한다. 정보 표시 때문에 캔버스의 드래그·그리기 기준점이 이동해서는 안 된다.
- 기존 disabled 데이터는 자동 활성화하지 않는다. 해당 항목에만 호환용 ‘운영 재개’를 제공하며 주문·호출 4개 방식 모두 OFF와 active를 한 요청으로 저장한다. 보관 복원도 같은 OFF 원칙을 적용한다. QR 식별자·배치 저장·과거 기록·종료된 세션은 변경하지 않는다. 서버 권한·현재 상태 조건을 검사하고 일괄 데이터 전환은 하지 않는다.
