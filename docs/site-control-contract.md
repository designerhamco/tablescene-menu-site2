# 사이트 버튼·탭 공통 기준

공식 사이트와 마이페이지·운영·편집·관리자 화면은 `styles/ui-system.css`, `styles/site-design.css`와 `app/components/ui/button.tsx`, `tabs.tsx`, `navigation-tabs.tsx`를 사용한다. `/design-system`의 기준·토큰과 컴포넌트 라이브러리는 같은 구현을 표시한다.

## 버튼

| 용도 | 공통 변형 | 규격 |
| --- | --- | --- |
| 저장·시작·확인 | primary | 검정 표면, 흰 문구 |
| 미리보기·취소·다운로드·로그아웃 | outline | 흰 표면, 회색 테두리 |
| 초기화·보조 행동 | secondary | 옅은 회색 표면 |
| 아이콘 도구 | ghost + icon | 투명 표면, 명시적인 원형 |
| 삭제 요청 / 삭제 확정 | outline-danger / danger | 빨강 의미 유지 |
| 문구형 보조 이동 | link | hover 때만 밑줄 |
| AI 실행 | ai | 일반 40px, 보라·파랑 공통 그라데이션 |
| 고객지원 퀵 버튼 | ai + 지원 전용 형태 | 56px 정사각형·20px 모서리·30px 말풍선 |

일반 버튼은 높이 40px, 모서리 8px, 글자 14px, 좌우 패딩 16px, 내부·버튼 간 간격 8px이다. 강조는 48px/16px/20px, 주요 시작은 56px/16px/24px이다. 내용이 긴 문구는 필요한 높이를 확보한다. 폭은 문구를 따르며, 폼의 전체 폭이나 모바일 액션 행 배치는 호출 화면에서 결정한다.

편집용 compact는 32px/13px, 헤더 CTA는 기존 44px를 명시적으로 사용한다. 기존 square API도 8px로 표시한다. 원형 아이콘은 40px이며 compact 아이콘은 32px다. 기기 미리보기의 어두운 도구는 `site-preview-control` 36px 전용 변형을 사용한다. 색상 스와치도 공통 포커스·hover·누름·비활성 규칙을 사용한다. 카카오 로그인은 제공자 색만 명시적인 변형으로 보존한다.

페이지의 `text-xs`, `px-*`, `py-*`, `rounded-*`, `disabled:bg-*` 등으로 공통 버튼을 다시 꾸미지 않는다. 반복된 실행 버튼에 고정 최소 폭을 추가하지 않는다. 편집기의 pending/dirty 로직은 원래 역할 클래스를 유지하며 native `disabled`로 공통 비활성 표현을 선택한다.

모든 실행 변형은 기본·hover·누름·키보드 포커스·비활성을 구분한다. hover/active는 native disabled와 aria-disabled를 모두 제외한다. Ghost의 비활성 표면은 투명하게 유지한다. 포커스는 2px 파랑 선으로 표시한다. 라이브러리의 `data-ui-state` 비교표는 실제 의사 클래스와 동일한 CSS 선언을 사용하며, 별도 색상표를 복제하지 않는다.

## 탭과 선택

| 역할 | 공통 구현 | 적용 예 |
| --- | --- | --- |
| 콘텐츠·서비스·상태 탐색 | underline / NavigationTabs | 서비스 선택, 마이페이지, 알림, 운영, 가이드 |
| 목록 종류 전환 | contained | 디자인/기본 템플릿, 공지사항/FAQ |
| 보기·설정 방식 전환 | outline | 이미지/목록 보기, 미리보기 기능/디자인 옵션 |
| 하위 조건·본문 바로가기 | site-filter / ChoiceTile | 고객센터 주제, 가이드 본문 바로가기, 서체 분류, 업종 |
| 설명을 가진 선택 | site-choice-control | 편집기 레이아웃·가격 입력·위젯 종류 |

모양은 용도, 크기는 정보 단계로 정한다. `TabsList`와 `NavigationTabs`는 `size="lg" | "md" | "sm"`을 사용한다. 생략하면 md, 이전 default는 md의 호환 별칭이다. 페이지에서 CSS로 크기를 덮어쓰지 않는다.

| 단계 | 밑줄·연결형 탭 높이 / 글자 | 세그먼트 전체 높이 / 글자 / 내부 버튼 | 적용 |
| --- | --- | --- | --- |
| 대 lg | 56px / 18px | 56px / 16px / 48px | 서비스 선택, 가이드·디자인 시스템의 주요 분류 |
| 중 md | 48px / 16px | 48px / 14px / 40px | 마이페이지 목록, 편집 메뉴, 호출 화면, 알림·요금 패널, 보기·설정 방식 |
| 소 sm | 40px / 14px | 40px / 14px / 32px | 섹션 안의 번역 대상 등 세부 선택 |

보기 전환의 기본 표현은 밝은 outline이다. 이전 segmented API의 검정 선택 표면은 호환 변형으로 보존하며 상위 콘텐츠 분류나 필터에 임의로 사용하지 않는다. 홈의 업종은 작은 필터, 배치 방식 데모는 소 outline 세그먼트를 사용한다.

탭은 문구에 맞는 폭을 사용한다. 가로 공간이 부족한 탭·세그먼트는 해당 줄 안에서 스크롤하며 페이지 폭을 늘리지 않는다. 가이드의 하위 항목은 실제 콘텐츠 전환이 아니므로 32px 필터형 본문 링크로 구분하고 `aria-current="location"`을 사용한다. 상위 탭 선택을 바꾸면 본문 링크도 해당 서비스의 앵커로 연결된다.

밑줄은 공통 4px이다. 연결형은 선택 탭과 패널이 흰색으로 이어지며, 비선택 탭 아래의 경계가 이어진다. 탭 상단 양 모서리는 12px이고 패널은 0/12/12/12px이다. 링크 이동은 링크를 유지하고, 상태 전환은 Radix Tabs의 선택/패널 연결·방향키·Home/End·비활성 건너뛰기를 사용한다. 모바일 탐색은 선택한 링크를 가로로만 드러내며 문서 세로 위치를 바꾸지 않는다.

스위치·체크박스·날짜/차트 선택·페이지 번호·캐러셀 재생/인디케이터·드래그 핸들·아코디언·이미지 썸네일은 각자의 정보와 조작 구조를 유지한다. 일반 실행 버튼으로 바꾸지 않는다. 페이지 번호의 기존 투명 비활성과 36px 규격도 유지한다.

## 셀렉트

기본 HTML select와 Radix SelectTrigger는 동일한 chevron 경로, 20px 크기, 2.25 선 굵기와 16px 우측 여백을 사용한다. 문구 끝에 48px 공간을 예약한다. 커스텀 셀렉트는 열리면 화살표를 회전하고 긴 문구를 잘라 표시한다. native select의 폼·선택·키보드 동작을 보존하며 multiple/size>1 목록에는 화살표를 추가하지 않는다. 강제 색상 모드는 native 화살표를 복원한다. hover·포커스·비활성은 공통 필드 규칙을 상속하고, 비활성에서도 화살표를 유지한다. 고객 메뉴판 렌더러에는 적용하지 않는다.

## 적용 범위와 검증

- 사이트 UI 296개 TSX 파일, 77개 page 소스를 대조했다. 공통 버튼의 개별 크기·패딩·비활성 색상 덮어쓰기 202곳을 제거하고, 별도 탭·선택·도구 구현을 공통 역할에 연결했다.
- 홈·서비스·상품·요금·신청·디자인 템플릿·상세·가이드·고객센터·인증·초대·오류 화면, 마이페이지·구독·결제·계정·문의·직원·운영·메뉴 편집·미리보기·관리자 화면이 같은 스타일 진입점을 사용한다.
- 고객이 제작하는 메뉴판의 `.menu-typography`, `.aube-table-root`, `[data-template-artwork]`와 `components/menu-templates`, `components/public-menu`는 별도 디자인 경계다. 메뉴판의 폰트·배치·모바일 읽기 규칙은 변경하지 않는다.
- `lib/site-control-states.test.ts`는 공통 규격, disabled 상태 우선순위, 동일 상태표 사용, 페이지별 오버라이드 재발과 탭 역할을 검사한다. 기존 헤더 순서·아이콘 크기·접근성 대비 계약도 유지한다.
- 브라우저 검증은 실제 DOM 뷰포트를 기록하고 native 키보드/포인터 입력으로 수행한다. 저장·결제·환불·초대·주문·호출·권한 등 실제 데이터를 바꾸는 동작은 실행하지 않는다. 접근 권한이나 데이터 조건으로 열리지 않는 상태는 소스·공통 컴포넌트 검증 범위를 구분한다.

- `/apply`의 중 연결형 선택 탭과 패널은 흰색·1px 경계·0/12/12/12px 모서리를 유지한다. 가이드 하위 링크는 현재 서비스의 본문 앵커를 보존한다.
- 전체 단위/계약 테스트 838개, TypeScript, Production 빌드 통과. 변경 TS/TSX lint 오류 0개이며 기존 HomeProductStory img 경고 8개는 유지한다. 실제 저장·결제·주문·권한 작업은 실행하지 않았다.


## 고객지원 홈과 AI 진입 (2026-10-26)

사이트 퀵 메뉴에는 56×56px/20px 모서리/30px 채팅 말풍선 아이콘의 고객지원 버튼 하나를 둔다. 기존 사용가이드 퀵 링크는 홈 안의 서비스 가이드로 옮긴다. 런처와 고객센터 AI 상담 버튼은 `site-button-ai`의 공통 그라데이션 토큰과 hover/active/포커스를 사용한다. 맨 위로 버튼은 런처보다 16px 위에 놓고 safe-area를 반영한다.

런처의 첫 화면은 ‘도움이 필요하신가요?’이며 AI 실시간 문의/1:1 문의/FAQ 세 채널, 실제 가이드 링크 두 개, 기존 고객센터 데이터에서 가져온 FAQ 세 개를 제공한다. 새 소식/업데이트 피드는 추가하지 않는다. 명시적인 고객센터 AI 상담 버튼은 기존처럼 AI 화면으로 바로 들어간다. AI runtime gate·국외 이전 동의·API 요청 규칙은 그대로다. 홈에서 AI가 준비 중이면 상태를 표시하고 1:1 문의를 안내한다. 실제 AI 질의나 동의는 검수에서 실행하지 않는다.

공통 Radix Dialog를 사용해 포커스를 가두고 Escape/바깥 클릭/닫기로 종료하며, 열었던 버튼으로 포커스를 돌린다. AI 화면에서 홈으로 돌아가도 현재 열린 창의 대화는 유지하며, 다시 런처를 열면 홈부터 시작한다. 링크 이동 시 창을 닫고 본문 스크롤 잠금을 복원한다. 라이브러리도 같은 SupportHome을 렌더링한다.

지원 홈 검수: 실제 320×568, 390×844, 820×1180, 844×390, 1440×1000에서 가로 넘침 0px와 창 경계·고정 닫기·내부 스크롤을 확인했다. QR FAQ 펼침, AI 준비 중 화면과 홈 이동, 닫기/Escape·양방향 Tab 순환, 런처 및 고객센터 AI 버튼으로의 포커스 복귀, 본문 잠금 복원, 디스플레이 가이드의 plan·hash 연결을 확인했다. 기존 사용가이드 퀵 링크는 0개이며 두 AI 진입점의 computed gradient는 동일하다. 단위/계약 테스트 841개, TypeScript, 변경 파일 lint, Production 빌드를 통과했다.
