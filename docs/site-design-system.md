> 버튼·필드 라벨·드롭다운 옵션 내부의 글자·높이·간격은 [컴포넌트 크기·간격 기준](site-component-density.md)을 우선한다. 기본 조작14px, 필드32/40/44/48px, 옵션32px·gap0·안쪽8px이며 터치 기준은 별도로 유지한다. GNB·계정/사이드바 탐색·페이지/섹션/콘텐츠 제목·설명·본문은 컴포넌트 밀도 조정에서 제외하며 기존 크기와 와이드 보정을 유지한다.

- `components/menu-templates`·`components/public-menu`의 고객 메뉴판 디자인·언어·페이지 이동·주문/호출은 별도 경계다. 툴팁 꼬리와 기기 회전 안내는 별도 도형을 유지한다. 재생/일시정지는 일반 UI 아이콘 정책을 따른다.

작업 영역의 박스·안쪽 여백·제목과 설명·필드·버튼·정렬은 [본문 구성 계약](site-content-layout-contract.md)을 따른다. `site-section`/`site-card`의 표면 클래스만 붙이고 padding과 간격을 각 화면에서 선택하는 방식은 신규 작업 박스에 사용하지 않는다. `ContentPanel`은 작업 박스20/24px 안쪽 여백,12px 모서리와24px 콘텐츠 묶음을 소유한다. 조밀한 안내는16px 안쪽·6px 모서리를 쓴다. 제목-설명12px, 필드 간16px, 라벨-입력·버튼 간8px를 의미 클래스로 적용한다. `/design-system#content-composition`에서 실제 예시를 확인한다. 기존 히어로·이미지·고객 메뉴판의 별도 geometry는 유지한다.

## 관리 표 (2026-11-05)

기본 `Table` 부품과 구분해, 사이트 관리 목록은 `Table variant="management"`를 사용한다. 정식 공통 예시와 치수는 `/design-system#management-tables`에 있으며 기준값은 `lib/site-table.ts`·`styles/site-spacing.css`에서 관리한다. 회색 헤더·흰 본문·가로 구분선을 사용하고 외곽 카드·세로선·그림자를 중첩하지 않는다. 실제 긴 이름, 읽기 전용, 저장 중, 도움말과 숫자 끝 정렬을 같은 컴포넌트로 확인한다.

| 관계 | 공통 규칙 |
| --- | --- |
| 헤더 셀 | 위아래12px·좌우16px, 최소56px. 큰 조작이 있으면 자연스럽게 확장 |
| 본문 셀 | 상하좌우16px, 행 최소64px.44px Switch가 있으면76px 이상 |
| 탭 → 추가 버튼 → 목록 묶음 | 각각 `site-stack-group`의24px |
| 목록 제목 → 표 | `site-stack-block`의16px |
| 행 안 조작 | `site-action-row`의8px, compact 버튼32px·도움말40px·Switch44px 유지 |
| 글자·정렬 | 본문14px·주요 이름16px, 기존 의미 역할과 관리 화면의500 굵기. 글자는 시작·수치는 끝 정렬 |

고정 행 높이로 긴 이름이나 조작을 자르지 않는다. 이름은 여러 줄로 표시하며 실제 행동만 버튼으로 만든다. 각 버튼·스위치에 행 이름을 포함한 접근성 이름을 제공한다. 기본 표는 내용에 맞춰 너비를 정한다. 조작 표는 `columns`로 compact/text/detail/control/actions 역할을 선택하며 각 열의 공통 최소 너비 합계가 표의 최소 너비가 된다. 업무 이름별 퍼센트를 공통 CSS나 페이지에 추가하지 않는다. 좁은 화면에서 표 영역만 가로 스크롤하고 영역 이름·키보드 포커스·열 제목을 유지한다. `TableCell primary/nowrap/align`으로 정보 역할과 흐름을 지정하며 숫자는 `align="end"`로 정렬한다. management 표는 className/style로 외형·간격을 덮어쓰지 않는다.

이 기준은 새 관리 표의 공통 표현이다. 기존 모든 문서·정책·게시글 표를 한 번에 이전했다는 뜻은 아니다. 고객 메뉴판 렌더러는 독립된 경계를 유지한다.

## 운영 상태 카드

운영 대시보드의 공개·테이블·키오스크·주문·호출 상태와 매출 요약은 `OverviewCard`/`OverviewCardGroup`의 흰 표면을 사용한다. 라벨 옆에는 선택적인 의미 아이콘을 두고 상태값·설명을 패널의 왼쪽 시작선에 정렬한다. 아이콘 타일이나 아이콘이 없을 때의 빈 칸은 두지 않는다. 메뉴판 공개는 편집 페이지의 공개 설정 링크만 제공하며 대시보드 토글을 두지 않는다. 주문·호출 Switch는 오른쪽 위, 이동 버튼은 하단 구분선 아래에 둔다. 1440px 미만은 모바일·태블릿 모두2열,1440px 이상4열이며 공통40px 버튼과44px Switch 조작 높이·접근성 안내를 유지한다. 상세 구성은 아래 운영 대시보드 요약 카드 항목을 따른다.

주문·호출의 ‘미사용’은 메뉴판 공개·사용 중 테이블·기능 연결을 갖춘 상태에서 스위치를OFF로 둔 경우에만 사용한다. 메뉴판 비공개·테이블 미등록/전체 비활성·기능 제한은 ‘주문 사용 불가 / 호출 사용 불가’로 구분하고, 원인은 상태 제목 옆 `InfoTooltip`으로 제공한다. ‘메뉴판 비공개’ 같은 보조 상태 칩은 사용하지 않는다. 조회 실패/권한 부족은 실제 사용 상태를 단정하지 않고 기존 ‘상태 확인 불가 / 확인 불가’를 유지한다. 비공개가 확실하면 다른 조회가 실패했더라도 ‘사용 불가’로 표현할 수 있다.

운영 토글의 저장 결과는 `OperationActionFeedback`을 사용한다. 성공은 기존 공통 토스트로 알리고, 실패는 공통 Dialog에 원인과 확인 버튼을 표시한다. 결과를 카드 아래에 문단으로 누적하거나 카드 높이를 늘리지 않는다. 처리 완료 뒤 결과를 표시하고, 닫기/Escape/바깥 클릭은 원래 토글로 포커스를 복귀시킨다. 새 상태에서 토글이 비활성화됐다면 같은 카드의 가능한 이동 행동으로 복귀한다. 서버가 확인한ON/OFF와 기존 공개 전 필수 검사는 그대로 유지한다.

오류 레이어창의 제목 묶음은 `DialogHeader reserveCloseButton`으로 공통 닫기 버튼 폭을 확보한다. 제목/설명을 페이지의 임의 padding으로 보정하지 않으며, 긴 내용은 공통 Dialog의 제한된 화면 높이 안에서 스크롤한다. 기존 DialogHeader의 기본 동작은 바꾸지 않는다.

## 테이블의 기기 연결 표시

운영 테이블 상단의 현재 접속 기기는 `ContentPanel surface="muted"`로 한 번 표시한다. 테이블별 연결 기기는 흰 작업 `ContentPanel` 안의 일반 목록이며 개별 기기마다 카드를 중첩하지 않는다. OS·모델·브라우저는 `type-body`, 연결일은 `type-caption`, 안내는 `type-body-sm`을 사용한다. 상태 ‘기기 연결됨’은 `Badge tone="active"`, 현재/다른 기기 구분은 중립 Badge이며 상태를 녹색 버튼으로 만들지 않는다. 실제 해제는 공통 outline 버튼과 대상 확인으로 제공한다.

‘태블릿 사용 / 손님 휴대폰·QR’은 공통 `Tabs purpose="state"`로 안내와 관리 내용만 전환한다. 주문 채널의 단일 선택 스위치가 아니며 두 방식을 함께 사용할 수 있다는 안내를 유지한다. 탭을 바꿔도 테이블 이름/상태의 작성 중 입력은 보존한다. 목록 조회 실패는 미연결과 구분해 ‘연결 상태를 불러오지 못했습니다’와 ‘다시 확인’으로 표현한다. 여백·폼 정렬·필드·버튼은 기존 본문 구성 계약을 사용하며 로컬 CSS 예외는 추가하지 않는다.

## 표시 아이콘의 바탕과 실제 주변 표면 (2026-11-03)

버튼이 아닌 설명·빈 상태·현황·알림의 표시 아이콘은 **아이콘 바로 뒤 영역의 배경색**을 기준으로 한다. 모든 아이콘의 바탕을 일괄 제거하는 규칙이 아니다. 컴포넌트 라이브러리 `/design-system#indicator-surface-title`에서 흰색·회색·유색과 회색 영역 안의 흰 카드 예시를 비교한다.

| 실제 인접 표면 | 아이콘 바탕 |
| --- | --- |
| 흰색 | 알림 목록처럼 구분이 필요한 경우 옅은 회색·역할색 바탕을 유지한다. 흰 바탕에 밝은 경계도 필요한 구분에만 허용한다. 불필요한 바탕을 자동 추가하지 않는다. |
| 회색 또는 다른 유색 | 아이콘 뒤에 흰색·유색 사각형/원을 겹치지 않는다. 추가 바탕·경계·그림자 없이 기존 아이콘 선과 의미색만 표시한다. |
| 회색 페이지 안의 흰 카드 | 아이콘이 놓인 흰 카드 기준을 적용하므로 옅은 바탕을 유지할 수 있다. 페이지 전체 배경으로 결정하지 않는다. |

- 공통 표시 아이콘에 `site-indicator-icon`과 `data-icon-surface="white" | "colored"`를 사용한다. colored는 회색을 포함한 모든 비흰색 표면이다. `styles/site-design.css`가 colored의 background/border/box-shadow를 제거하며 호출부 CSS로 다시 덮어쓰지 않는다. 상태별 글자·아이콘 잉크와 기존 SVG 크기·선 굵기는 보존한다. 어두운 표면에서는 아이콘 선의 색으로 대비를 확보한다.
- `EmptyState`는 자체 회색 표면이므로 colored다. `MetricCard`는 default(흰색)일 때 white, muted(회색)일 때 colored다. 알림 패널의 흰 목록은 white이며 읽지 않은 점·노랑 바탕을 유지한다. 목록 hover로 실제 배경이 회색으로 바뀌면 아이콘 바탕만 투명하게 전환하고 알림 점은 유지한다.
- 2026-11-03 추가 수정: 회색·유색 표면에서는 배경색뿐 아니라 **장식 타일의 고정 너비·높이·최소 크기·padding·margin도 제거**한다. 아이콘 래퍼는 실제 SVG 크기만 차지한다. 빈 상태는28px, 현황은20px인 기존 SVG 크기·잉크·선 굵기는 유지하며, 공통 아이콘→문구 gap만 적용한다. 흰 표면의 유용한 타일과 흰 알림 목록의 슬롯은 유지한다. 흰 알림 행의 일시적 hover에서는 색만 전환해 행이 움직이지 않게 한다. 버튼 클릭 영역·포커스·hover, 로고·프로필·스와치는 별도 역할이다.
- `check:site-ui`는 공통 표면 규칙·컴포넌트별 표면 선택과 흰색 알림/읽지 않은 점 보존을 검사한다. `check:site-system`은 페이지 CSS에서 공통 표시 아이콘의 외형을 덮어쓰는 것을 차단한다. 실제 브라우저에서도 흰색/비흰색/중첩 표면을 확인한다.

## ON/OFF 스위치 (2026-11-03)

운영 대시보드·편집기 `SwitchField`·계정 수신 설정은 `app/components/ui/switch.tsx`의 같은 `Switch`를 사용한다. 색상·치수·상태는 `styles/ui-system.css`의 `--ui-switch-*` 토큰이 소유한다. 미정의 Tailwind 색상 이름이나 호출부의 배경·투명도로 상태를 구현하지 않는다. 실제 공통 컴포넌트의 배경별 ON/OFF·비활성 예시는 `/design-system#switch-contract-title`에 둔다.

| 배경 | 공통 API | OFF / ON | 비활성 |
| --- | --- | --- | --- |
| 흰색·밝은 회색 (`--ui-surface`, muted, soft) | 기본 또는 `surface="light"` | 중간 회색 / 차콜 경로 + 흰 손잡이 | 불투명한 옅은 회색 경로 + 회색 윤곽·손잡이 |
| 어두운 배경 (`--ui-text` 등) | `surface="dark"` 또는 `.dark` 문맥 상속 | 중간 밝기 회색 / 흰 경로 + 차콜 손잡이 | 불투명한 어두운 회색 경로 + 밝은 윤곽·손잡이 |

- 밝은 배경 세 종류는 검증된 한 팔레트를 공유한다. 어두운 배경은 명시적으로 반전 팔레트를 고른다. 배경색 자동 추정이나 화면 크기로 모드를 고르지 않는다. 중첩된 흰 영역에서는 `surface="light"`로 재설정할 수 있다. 임의의 유색 표면은 실제 인접 색과 대비를 다시 확인한다.
- 경로44×24px, 손잡이18px, 실제 조작 영역44×44px. 카드 안 위치·진입점은 유지한다. 상태는 손잡이 위치와 색상, 접근성 상태로 구분한다. ON/OFF 문구를 반복하지 않는다. 색에만 의존하지 않는다.

- 매장 운영 진입은 PC 헤더와 태블릿·모바일 전체 메뉴 모두 별도 탭/창으로 연다. 기존 위치, 표시 조건과 경로는 유지한다.
- `Link`/`a`에 `target="_blank"`와 `rel="noopener noreferrer"`를 함께 지정한다. 실제 탭/창 형태는 브라우저 설정을 따른다.
- 문구 뒤에 공통 `NewWindowIndicator`를 붙인다. 기존 Lucide 계열의 16px `ArrowUpRight`가 링크의 글자색을 상속하고, 스크린리더에는 ‘새 창으로 열기’를 추가로 전달한다. 일반 링크의 기존 글자 크기·두께·표면·포커스와 버튼 간격을 따른다.
- 이 표시는 실제 새 창 링크에만 사용하며 일반 이동·다음 단계 화살표와 구분한다. 컴포넌트 라이브러리의 ‘새 창 링크’ 예시는 같은 컴포넌트와 동작을 사용한다.

## 용도별 크기와 형태 확장 (2026-10-25)

사용자 제공 참고 이미지의 선택 카드·밑줄 탐색·큰 세그먼트·사각 이동 버튼·이미지 카드·빈 목록 구성을 기존 토큰과 컴포넌트에 확장했다. 아래 명시적 변형은 과거의 “모든 CTA/탭은 pill·40px” 제한을 대체한다. 기본값을 사용하는 기존 폼·운영 액션은 유지한다. 검수용 `/design-system`은 검색 노출을 막고 실제 공통 컴포넌트를 렌더링한다.

- 서체는 기존 Pretendard를 유지한다. 현재 공통 역할 수치는 `docs/site-typography-final.md`와 `lib/site-typography.ts`를 단일 기준으로 사용한다. 페이지 제목은28/32/36px, 제목 설명과 일반 본문은16px이며, 내부 섹션·콘텐츠·보조 문구는 각 의미 역할을 따른다. 사이트 헤더 탐색과 주요 탭은 별도 컨트롤 역할을 유지한다.
- 2026-10-25 공개 화면 참고: [크몽](https://kmong.com/)은 PC 홍보 제목 40px/주요 섹션 28–36px/일반 섹션 24px, [잡코리아](https://www.jobkorea.co.kr/)는 주 탐색 18px/정보 섹션 18px/설명 모달 제목 24px, [사람인](https://www.saramin.co.kr/)은 주 탐색 16px/추천 보조 14px를 사용했다. 관찰한 역할별 대비를 아티메뉴 토큰에 맞췄으며, 각 사이트의 CSS/이미지/문구를 복사하지 않는다. 페이지/계정/마케팅의 정보 밀도가 다르므로 모든 제목을 같은 크기로 강제하지 않는다.
- `Button`: 색상 역할(primary/outline/secondary/danger)은 유지하며 높이는 compact32/default40/header44/large48px 네 단계만 쓴다. 글자는 전 구간 15px·600, 일반 모서리는 8px다. pill은 헤더·떠 있는 짧은 CTA처럼 명시된 역할에만 쓰고, 아이콘 단독은 기본 무배경·무테이고 식별 경계가 필요하면 framed를 명시하며, 클릭 영역·정렬은 독립적으로 유지한다. 긴 문구가 줄바꿈되면 높이는 늘어날 수 있다. `sm`·`xl`·`rounded`·`square` 별칭은 폐기해 같은 의미가 여러 이름으로 생성되지 않게 한다.
- `ChoiceTile`: 기존 `site-choice` 경계 안의 아이콘+이름 선택 버튼. `inline`은 업종/짧은 필터, `feature`는 충분한 설명이 필요한 폼 선택이다. 선택한 흰 카드에 진한 경계와 노란 아이콘 바탕을 사용하며 내용 카드에 테두리를 확산하지 않는다. feature 설명은 좁은 모바일에서 시각적으로 접고 접근 가능한 설명 연결은 유지한다. 일반 선택은 aria-pressed, 탭 호출자는 기존 aria-selected/방향키 계약을 보유한다.
- `TabsList`: `segmented` 기본값과 `outline` 밝은 선택+진한 경계, `underline` 열린 밑줄 변형. `size=lg`는 큰 탐색용으로 쓰며 모든 변형은 Radix 키보드 동작을 공유한다. `TabsTrigger count`는 별도 칩 없이 건수를 표시한다. 선택/hover/active/disabled와 포커스를 구분하고 모션 감소를 존중한다.
- `EmptyState`: 넓은 옅은 바탕에 아이콘·제목·설명·명시적인 다음 행동을 배치한다. 회색 표면 위 아이콘에는 별도 바탕을 겹치지 않는다. 템플릿 필터의 빈 결과에는 실제 필터를 초기화하는 액션을 연결한다. 장식 테두리·그림자나 허위 상태 수치를 추가하지 않는다.
- 실제 적용: `/apply`의 업종은 공통 compact 아이콘 선택, 템플릿 종류는 흰 콘텐츠 면에 연결되는 section 영역형이다. 썸네일이 선택 UI보다 우선하며 카드 미리보기는 40px 실행이다. 홈·서비스·인증의 큰 CTA도 최대 48px를 사용한다. 문구 기반 폭을 기본으로 하며 과거의 52–64px hero와 448px 강제 너비는 제거했다.
- 고객 메뉴판의 서체·색상·fit·간격·장식에는 새 변형을 전파하지 않는다. 새 값은 `--ui-*`와 명시적 `site-*` 클래스에만 둔다.

## 공식 사이트 글자 리듬 (2026-11-03)

글자 크기·컨트롤 높이·색·기능 위치는 유지하며 공식 사이트의 굵기·행간·자간만 공통 기준으로 조정한다. 본문400, 항목·탐색·라벨500, 버튼·작업 제목600, 주요 제목·가격700을 사용한다. 본문은1.5배/−0.025em, 작은 설명은1.45배/−0.025em, 큰 제목은1.2–1.25배/−0.04em으로 구분한다. 작은 메타는−0.015em으로 덜 조인다. 값과 적용 범위는 `docs/site-typography-final.md`, CSS는 `styles/typography.css`, 라이브러리 표는 `SITE_TYPE_ROLES`가 소유하며 검사에서 일치를 확인한다. 고객 메뉴판·스타터·저장 디자인·렌더러 전용 CSS와 기초 글자 토큰은 이번 변경 범위 밖이다.

## 컴포넌트 표현 기준 (2026-10-18)

- 크기·타이포·콘텐츠 폭·카드 비율은 아티메뉴 기준을 유지한다. compact32px, 일반 텍스트 CTA40px, 헤더 CTA44px, floating/큰 CTA48px 네 단계이며 중복 이름을 만들지 않는다. 텍스트 버튼은 모두 15px·600이다. 기능 없는 장식 애니메이션이나 새 컴포넌트 라이브러리는 추가하지 않는다.
- `site-button-secondary`는 공통1px 경계를 가진 옅은 회색 8px 버튼, `site-button-outline`는 경계가 필요한 별도 액션이다. 흰 배경/외곽선으로 선언된 기존 액션은 outline 표현을 유지한다. 헤더 텍스트 링크는 배경 없이 색상만 바뀐다.
- 일반 입력과 검색은 흰 배경/회색 경계/기본 최소40px 높이를 공유하되 일반 입력은12px 모서리, 검색은 기존 캡슐형으로 구분한다. 오류·읽기 전용·비활성 의미를 유지한다. 네이티브 checkbox/radio는 18px와 공통 검정 선택색을 쓰며 숨겨진 필드·switch는 크기 변경에서 제외한다.
- 주요 화면은 분리된 둥근 page, 독립 콘텐츠는 section 영역형, FAQ 주제는 category 밑줄, 상태·보기는 회색 레일 state, 업종·문서 위치는 작은 필터를 사용한다. 크기는 대/중/소로 구분하며 수치는 `docs/site-control-contract.md`를 따른다. 링크 이동·본문 앵커와 Radix 탭의 키보드 동작을 구분해 보존한다.
- `site-tabs`/`site-tab`의 기본 중 규격은 48px rail과 40px 내부 버튼이다. 일반 보기 방식에는 밝은 outline 선택 경계를 사용하며, 이전 검정 선택 표면은 segmented 호환 변형으로 보존한다. Radix 탭과 공개 갤러리는 같은 클래스로 연결하며 기존 ARIA/키보드 동작을 보존한다.
- 설명 중심의 일반 본문은 열린 구성을 유지한다. 신청 정보·결제 요약·약관·편집 설정처럼 사용자가 하나의 단위로 판단하거나 입력하는 기능 영역은 옅은 회색 작업 바탕 위의 흰 패널 또는 하나의 묶인 보조 표면으로 구분한다. 패널 안의 모든 입력이나 문단을 다시 카드화하지 않으며, 제목·내부 여백·행 구분선으로 계층을 만든다. 기능 카드는 `site-card-surface`, 선택 가능한 카드는 `site-card-interactive`를 사용한다. 기능 카드/레이어는 12–16px, 판매 목록 미리보기는 16px, 큰 히어로는 기존 독립 32–48px이다. 고객 메뉴판/미리보기 내부에는 카드 규칙을 전파하지 않는다.
- 마이 메뉴와 매장 운영은 흰 페이지 바탕, `site-account-layout`의 열 폭·간격과 `site-account-summary`의 무테 회색 보조 면을 공유한다. 운영의 메뉴 선택 → 계정 → 내비게이션 순서와 모바일 세로 메뉴를 유지하고, 메뉴 패널은 `site-account-nav`와 세로형 `site-nav-stack`을 조합한다. 운영 첫 화면은 별도의 회색 작업 바탕/안쪽 패딩을 중첩하지 않고, 공통 `type-section-title`·본문 역할과 의미 기반 stack을 사용한다. 요약 카드·안내만 `surface="muted"`로 구분하며, 지표별 의미색은 유지한다. 흰 목록 패널의 경계는 `site-card`를 따른다.
- 칩은 `Badge`와 `lib/site-chip.ts`를 사용한다. 기본 높이24px/글자12px/라운드6px/무테다. 역할·서비스·추천 등 비상태 칩은 진한 중립 배경·흰 글자, 상태 칩만 성공·주의·오류·정보의 의미색을 사용한다. 결제 완료는 밝은 회색 배경/진한 회색 문구의 정산 상태 예외이며, 복구불가·처리확인 필요는 같은 붉은색이다. 이용 중·공개 중은 같은 초록이며 작성 중·비공개는 서로 구분한다. dropdown/select 항목은 최소36px/8px 라운드/옅은 hover다.
- 기본 포커스는 파란색 외곽선, 어두운 표면은 흰색 외곽선이다. hover/active는 150ms 색상 전환이며 공통 버튼/탭은 모션 감소 설정에서 전환을 끈다. 오류는 붉은 경계·포커스로 전달한다.
- 위 기준이 과거 컴포넌트 수치와 충돌할 때 현재 기준을 따른다. 기능/인증/결제/API와 메뉴판의 간격·fit·팔레트는 이 시각 변경의 대상이 아니다.

## 템플릿 선택 화면과 정렬 (2026-10-18 사용자 보정)

- 베이직·다이닝·디스플레이 서비스 전환은 페이지 전체 목록을 바꾸는 page 분리형 둥근 버튼이다. 아래 ‘디자인 템플릿 / 기본 템플릿’은 흰 목록 콘텐츠 면의 상단 경계에 붙는 section 영역형을 사용하며 기본 진입은 디자인 템플릿이다. 명시된 기존 category=standard 링크는 기본 템플릿으로 열린다. 요금과 교체 범위는 현재 서비스·종류에 연결해 표시한다.
- 필터는 기본 템플릿의 화면 구성과 디자인 템플릿의 업종을 구분한다. 모든 기기에서 공통 ChoiceGroup과 compact 아이콘 선택을 사용하며 자연스럽게 줄바꿈한다. 종류·서비스 변경 시 필터는 전체로, 종류·필터·서비스 변경 시 페이지는 1로 돌아간다. 디스플레이는 미리보기와 신청 준비 중 안내를 제공하며 종류 탭/필터는 숨긴다.
- 디자인 템플릿 목록 오른쪽 위의 공통 Select는 전체 구성/리스트형/앨범형 아이콘과 문구를 함께 표시한다. 업종과 화면 구성은 교집합으로 적용하고 화면 구성 변경 시 페이지만 1로 초기화한다. `layout=list|album`은 URL/새로고침에 보존하며 종류·서비스 전환 시 제거한다. 실제 카탈로그의 itemLayout만 사용하고 미등록 앨범형 디자인은 준비 중으로 안내한다. 카드 배열·메뉴판 렌더러를 화면 구성 필터로 바꾸지 않는다.
- 카드는 4:3 실제 메뉴판 이미지·16px 라운드, 16px/600 상품명, 12px 메타데이터, 13px 설명과 텍스트 액션으로 구성한다. 이미지와 상품명은 같은 창의 디자인 상세페이지로 이동한다. 좋아요는 이미지 바깥 제목 행 오른쪽에 놓는다. 별도 `미리보기` 액션은 기존 실제 메뉴판 새 창을 유지한다. 본문은 읽기 편하게 왼쪽 정렬한다. 밝은 이미지 경계가 필요한 경우만 옅은 안쪽 경계를 사용하며 그림자는 없다.

## 툴팁 공통 말풍선 (2026-11-01)

- hover/focus `TooltipContent`와 클릭·터치 `HelpTooltip`은 `site-tooltip-surface`, `TooltipBubbleBody`, `TooltipBubbleArrow`를 공유한다. 일반 Popover·드롭다운·고객 메뉴판에는 이 형태를 일괄 적용하지 않는다.
- 밝은형은 흰 표면·진한 제목·회색 본문, 어두운형은 차콜 표면·흰 제목·밝은 회색 본문이다. 어두운형의 핵심 문구도 흰색으로 강조한다. `tone="brand"` API는 강조 안내용 노란색으로 유지하되 동일한 형태를 쓴다.
- `--ui-radius-tooltip` 28px, 상하·좌우 여백은 `--ui-tooltip-padding-block` 20px / `--ui-tooltip-padding-inline` 24px, 최대 너비20rem와 화면 가장자리16px를 사용한다. 외곽 테두리 없이 `--site-shadow-tooltip` 그림자와 24×14px의 둥근 꼬리를 사용한다.
- 선택적 `heading`은 `--site-type-16` 16px·700, 본문은 `--type-body-sm-size` 14px·400, 제목과 본문 간격8px다. 제목이 없는 기존 필드 도움말도 동일한 표면과 꼬리를 사용한다.
- `TooltipContent` 기본 톤은 dark, `HelpTooltip` 기본 톤은 light다. Radix의 방향·충돌 처리와 포커스 동작을 보존한다. 클릭형 dark/brand의 닫기 버튼과 Escape·바깥 클릭·재진입도 유지한다. `/design-system`의 기준·토큰과 컴포넌트 라이브러리에 함께 문서화한다.
- 꼬리는 가운데 고정이 아니다. 기본 `side="top"`, `align="start"`로 왼쪽 아래에 배치하며, 둥근 모서리 안쪽28px는 꼬리를 놓지 않는다. `side`, `align="start|center|end"`, `alignOffset`으로 문맥에 맞게 조정한다. 화면 가장자리에서는 Radix가 말풍선과 꼬리를 함께 이동·반전하여 실제 안내 대상을 계속 가리킨다.
- 항상 보이는 `HintBubble`도 동일한 `site-tooltip-surface`와 `TooltipBubbleArrow`를 사용한다. 툴팁/클릭형과 구분하는 것은 노출 방식이며 별도 사각형·삼각형 스타일을 만들지 않는다. 한 줄 안내에는 compact 여백(상하10px/좌우14px)과13px 안내 글자를 사용하고 기본 톤은 dark다. `tone`과 `tailAlign="start|center|end"`으로 색과 꼬리 위치를 고른다. 템플릿 종류 탭의 안내는 첫 번째 탭 위에서 계속 보이고 `aria-describedby` 연결을 유지한다.


## 탭 경계·밑줄 검수 보정 (2026-10-26)

- 현재 section 영역형은 연결된 사각 버튼으로 독립 콘텐츠를 전환한다. 검정 선택 면·흰 글자와 흰 비선택 면·보조 글자색을 사용하며 바깥 모서리만8px다. 콘텐츠는 둘레 테두리 없이 구분하고, 템플릿 결과는 밝은 회색 공통 표면으로 묶는다. 긴 기준선·사선·mask는 사용하지 않는다.
- 선택 밑줄 두께는 공통 `--site-tab-indicator-width: 3px`을 사용한다(2026-11-11 사용자 피드백). 주요 화면의 page Tabs, 분류 underline Tabs, NavigationTabs와 CategoryFilter가 같은 토큰을 상속한다. 비선택 밑줄도 같은 두께의 투명 경계를 확보해 선택 때 글자가 이동하지 않는다. 글자 크기·컨트롤 높이·가로 간격은 공통 대/중/소 계약을 따른다.
- underline rail은 목록 바깥 좌우 여백을 만들지 않는다. 첫 탭의 시작과 rail의 시작을 맞추고, 문구 여백은 각 탭 내부에서만 확보한다. 가운데 모아 쓰는 서비스·가이드 탭은 탭 묶음 너비까지만 rail을 표시하며, 마이페이지 탐색과 알림·요금처럼 행 전체가 탐색 영역인 경우에만 전체 너비를 유지한다.
- `/design-system`의 영역형·서비스·이미지 카드·상태 탭과 `/apply`를 실제 PC·태블릿·모바일에서 확인한다. 고객 메뉴판의 서체·간격·렌더러는 변경하지 않는다.


## 마이페이지 탭과 연결 모서리 (2026-10-26)

- 호출 내역/설정 같은 주요 화면 이동은 분리된 둥근 page/md, 다국어 언어 값은 둥근 state/md, 그 안의 번역 대상은 section 영역형/sm이다. 페이지별 색·크기·밑줄 덮어쓰기 대신 Radix Tabs를 사용한다. URL 이동은 NavigationTabs를 사용하며 purpose="page"는 분리된 둥근 버튼, purpose="state"는 둥근 상태 세그먼트를 사용한다.
- NavigationTabs는 모바일에서 현재 링크가 rail 밖으로 가려지지 않도록 그 영역만 가로로 이동한다. 본문을 세로로 강제 이동하지 않는다.
- 폐기된 파일형의 비대칭·사선 윤곽은 사용하지 않는다. 영역형은 위쪽만 공통 control radius를 사용하고 콘텐츠 면과 만나는 아래쪽은 직선으로 연결한다.

## 선택 요소 위계와 셀렉트 (2026-10-26)

현재 기준은 [사이트 컨트롤 계약](site-control-contract.md)의 역할·대중소 표다. `TabsList`/`NavigationTabs`의 size API, 실제 공통 CSS와 라이브러리의 세 크기 비교를 함께 유지한다. 가이드는 상위 lg 주요 화면 버튼과 하위 32px 본문 링크로 분리한다. 모든 사이트의 native select와 Radix SelectTrigger는 20px/2.25 chevron, 우측 16px, 문구 예약 공간 48px를 공유한다. 렌더러·다중 선택·목록형 select는 제외한다.

- `모두 읽기`는 화면에 보이는10/50개만이 아니라 현재 계정의 최근90일 표시 대상 전체 미확인 알림을 처리한다. 처리 중과 미확인0건은 공통 비활성 상태, 실패는 상태를 유지하고 오류 안내/재시도를 제공한다. 성공 후 목록·읽지 않음 탭·헤더 배지를 동기화한다. 이미 읽은 시각과 처리 시점 이후 도착한 알림은 유지한다. 현재 인증 사용자·동일 출처·기존 RLS로 범위를 제한하고 스키마/권한은 변경하지 않는다. 다른 사용자나 제외된 채널/상태는 처리하지 않는다.
- 헤더·전용 알림·마이페이지 알림은 `lib/notification-display-policy.ts`의 최근90일 표시 범위를 공유한다. 생성 시각이 조회 시점에서90×24시간 전 이상인 알림을 포함하며 읽음 여부와 무관하다. 같은 조회에서 목록과 미확인 건수는 동일한 기준 시각을 사용한다. 헤더는 최대10개, 전체 알림/마이페이지는 기존 최신50개 조회 상한을 유지한다. 모두 읽기도 최근90일만 처리한다. 90일은 표시 범위다. 저장 원본은 별도1년 보관 정책을 따르고 중복 발송 방지 최소 기록은 본문과 분리한다. 고객 안내와 보관 정책 제안은 `docs/notification-retention-policy.md`를 따른다. 읽음 API·내부 경로 제한을 유지한다. 768px 이상은 Radix Popover의 Escape·바깥 클릭·포커스 복귀를 사용한다. 모바일 벨은 /notifications 전용 화면으로 이동하며 계정 카드·마이페이지 메뉴 없이 같은 알림 패널을 표시한다. 마이페이지의 알림 내역은 기존 관리 메뉴로 유지한다.
- 공유는 실제 지원되는 링크 복사와 기기 공유만 제공한다. 기기 공유는 브라우저 지원 시 표시하며 사용자가 공유 대상을 결정한다. 외부 소셜 서비스의 로고만 있는 가짜 버튼은 만들지 않는다.
- 요금 카드의 가격·상품·사업자 조건·무료체험·결제/해지 조건은 기존 상품 데이터를 사용한다. 선택은 디자인 목록으로 이동하며 이 카드에서 결제를 실행하지 않는다.
- 운영·매출의 권한 게이트, 조회 범위, 주문/결제/호출 변경, 고객 메뉴판의 렌더링과 모바일 읽기 규칙은 변경하지 않는다.


## 2026-10-26 읽기 크기·폼·카드 공통 기준

사용자 요청에 따라 티오더와 카카오비즈니스 세미나의 제목/본문/콘텐츠 구분을 참고했다. 아래 기준이 과거의 12–14px 본문, 14px 헤더 및 모든 입력 40px 규칙을 대체한다. 메뉴판과 상품 화면 축소 시안은 제외한다.

- `styles/typography.css`가 단일 폰트 기준이다. 한글 Pretendard·영문/숫자 Tenor Sans의 공통 `--font-family-site`를 사용하며 메뉴판 디자인에는 적용하지 않는다. 400 본문 / 500 보조 강조 / 600 항목·탐색 / 700 주요 제목을 구분한다. 일반 페이지 제목은 모바일28px·태블릿32px·PC36px이다.
- 일반 본문은 모든 기기에서16px, 강조 본문은18/20px, 보조 설명은14px, 날짜·메타는13px이다. `text-copy`/`text-support`/`text-meta`는 크기·줄높이만 정하므로 필요한 굵기·색상을 합성할 수 있다. `cn`의 Tailwind 병합도 이 역할을 인식한다.
- PC 글자를 키우기 위해 html/rem 또는 기초 `--font-size-*`, 기존 `text-xs`/`text-sm` 값을 바꾸지 않는다. 실제 메뉴판의 독립 폰트·핏·축소 미리보기에는 영향을 주지 않는다.
- 폼 컨트롤은 필터 `sm` 40px, 계정 `md` 44px, 신청 `lg` 48px, 큰 질문 검색 56px이다. Input/Textarea는 `fieldSize`, SelectTrigger는 `size`를 사용하며 네이티브 입력은 `data-field-size` 또는 `site-field-*`로 동일 규격을 사용한다. 네이티브 input의 `size`는 문자 수 속성으로 보존한다.
- 값 입력은16px 이상/400 굵기, 필드명15–16px/600, 안내14px/400–500이다. 입력 모서리는12px, 동일 행의 input/select는 같은 높이를 사용한다. 검색용 큰 입력을 일반 로그인/신청 화면에 적용하지 않는다.
- 입력은 기본/hover/포커스/오류/읽기 전용/비활성을 구분한다. 포커스는 기존 2px 파란 경계를 유지하고, 오류는 `aria-invalid`와 설명 연결을 함께 사용한다. checkbox/radio/color/range/file/hidden은 텍스트 입력 높이에서 제외한다.
- 정보 카드는 흰 표면·옅은 회색 경계·12px 모서리, 하위 묶음만 옅은 회색 바탕을 쓴다. 선택/요금 카드는 `site-plan-card`로 재사용한다. 선택 시 흰 바탕·진한 경계와 명시적 선택 표시, 제목18–20px·요금32px·설명14px로 구분한다. 본문 전체를 굵게 만들지 않는다.
- 라이브러리 `/design-system`의 폼·카드 예시는 실제 사이트와 같은 입력·셀렉트·CSS를 렌더링한다. 신청 약관은 중복 링크 없이 하나의 상세 보기로 연결하고, 여백과 글자 무게를 줄여 하나의 결정 묶음으로 표시한다.

## 실제 적용 역할 (2026-10-29)

- 주요 화면 전환은 purpose="page"의 텍스트와 문구 너비 선택 밑줄이다. 독립 콘텐츠는 section, 목록 주제는 category 밑줄, 상태·보기 값은 회색 레일 state를 사용한다. URL 이동도 NavigationTabs에 역할을 명시한다.
- contained 파일형·산 모양은 폐기했다. 디자인/기본 템플릿은 section 영역형, FAQ 주제는 category 밑줄이며 공지와 이용가이드는 헤더 하위 메뉴로 연결하는 독립 페이지다.
- 영역형은 탭과 아래 콘텐츠 묶음을 하나의 영역으로 전환할 때 사용한다. 콘텐츠에는 둘레 테두리를 두지 않는다. 템플릿은 카테고리 필터부터 페이지네이션까지 --ui-surface-muted의 밝은 회색 결과 표면으로 묶는다. 고객센터에는 필요 없는 하위 필터·영역을 만들지 않는다.
- 중립 배경·구분 면·푸터는 `--ui-surface`/`--ui-surface-muted`/`--ui-surface-soft`를 공유한다. 기본·보조·메타 글자색과 상태색은 같은 의미 토큰을 사용한다. 회색·유색 면에는 외곽 테두리를 추가하지 않는다.
- 페이지 h1은 `type-page-title`(28/32/36px)이다. 로그인·베이직·다이닝·디스플레이·고객센터·신청·템플릿 목록과 상세를 포함해 H1 바로 아래 문구는 모두 `type-page-description`(16px)을 사용한다.
- `type-body-lg`(18/18/20px)는 페이지별 도입 설명을 다르게 만드는 역할이 아니다. 섹션 안에서 기본 본문보다 강조할 짧은 문장에만 사용한다. 관리 화면의 조밀한 단계는 내부 섹션·카드·폼·메타에만 적용한다.
- 베이직·다이닝·디스플레이 같은 탭 문구는 본문이 아니라 컨트롤 라벨이다. `TabsList`의 공통 크기는 lg/md/sm 16/15/14px이며 주요 화면(page)은 lg18px·md16px, 독립 영역(section)은 md16px을 사용한다. 같은 역할과 크기는 페이지와 무관하게 동일하다. 주요 화면의 선택600·비선택500과 회색 토큰은 공통 스타일이 관리한다.
- 인증 화면에서 비밀번호 찾기·회원가입·로그인 복귀 같은 계정 보조 이동은 `type-body-sm`(14px)을 사용한다. 보조 이동이 기능 설명보다 크게 보이지 않게 한다.
- 작은 카드의 이름·설명·메타는 `type-card-title` 18px / `type-card-body` 14px / `type-card-detail` 13px이다. 템플릿·신청 카드와 현황·내역·요금 카드에 사용하며, 가격·통계 수치의 강조는 독립적이다.
- 팝업 제목·본문·작은 안내는 18/14/13px이다. 작은 하단 안내·폼 도움말은 PC·모바일 모두 `type-footnote` 13px·400·줄높이1.6이다. 입력값은 기존 16px을 유지한다.
- 알림창은 category 밑줄 분류와 기존 목록 구조를 사용하고 제목/본문14px·메타13px만 적용한다. AI 상담의 대화·동의·보안 안내, 계정·신청·편집의 도움말 및 결제/문의 하단 안내도 같은 문맥별 기준이다.
- 고객이 편집하는 메뉴판의 글자·색·레이아웃은 이 변경 대상에서 제외한다. 자세한 현재 기준은 [사이트 컨트롤 계약](site-control-contract.md)을 따른다.

## 2026-10-29 와이드 대응

폰트의 기본 역할과 최대 12.5% 와이드 보정, 인증 폼 폭·높이와 간격은 [폰트 계약](site-typography-final.md)의 최신 절을 따른다. 고객 메뉴판 렌더러와 root rem은 이 보정의 대상이 아니다.

와이드 기준은 기준·토큰과 컴포넌트 라이브러리의 공통 `WideScreenRules` 표에서 확인한다. 새 페이지는 의미 기반 글자 역할과 공통 레이아웃 클래스를 사용해 자동 상속하며, 지역별 글자 배율·공통 기초 토큰 재정의는 계약 검사에서 차단한다. 미리보기는 PC·태블릿별 목업 상한과 작은 보조 도구를 적용한다. 주문·호출·묶음형·채움형은 상단에 유지하며 보기 옵션 패널은 표시·디자인만 다룬다. 상세 수치는 `docs/site-typography-final.md`의 최신 절과 `lib/menu-preview-fit.ts`를 따른다.

일반 페이지 제목과 영역 탭 여백, 고객지원 경로의 현재 기준은 [페이지 간격 계약](site-page-layout-contract.md)을 따른다.

### 목업 표시 크기와 변경 범위

두 라이브러리의 `미리보기 목업 크기 기준`은 공통 fit 정책을 그대로 표시한다. 태블릿·모바일 목업은 옵션 레이어와 무관하게 페이지 전체 중앙에 배치하고, 대칭 바깥 여백 안을 최대한 채우며1.25배에서 멈춘다. PC는 테두리·라운드·그림자 없이 화면 전체를 채운다. PC·태블릿 브라우저에서는 현재 실제 뷰포트를 사용하며, 모바일에서 PC를 고르면1440×900 PC 구성을 비율대로 축소해 보여준다. 모바일 확대·축소 제한은 추가하지 않는다.

사이트 전체에서 크기·여백·폰트·반응형 배율만 조정하는 요청은 기존 기능이나 버튼의 이동·숨김·삭제·재분류를 허용하지 않는다. 현재 위치와 진입 경로를 유지하고 사용자에게 위치 변경 요청이 있을 때만 재배치한다. 이 원칙은 AGENTS와 디자인 시스템의 같은 기준 절에도 기록한다.


새 페이지 기본 틀·자동 검사·레거시 이전 원칙은 [자동 적용과 회귀 방지](site-system-enforcement.md)를 따른다. 공지사항은 큰 FAQ 검색 영역 대신 공통 BoardList와 목록 상단의 작은 검색 도구를 사용한다.

### 실제 화면 보기와 회전

태블릿 미리보기는 베이직·다이닝 모두 기존 회전 아이콘 버튼으로 가로/세로를 전환한다. 리스트·앨범, 기본·디자이너, 카탈로그·저장 메뉴판에 같은 공통 프레임을 적용한다. 가로1180×820·세로820×1180 내부 뷰포트와 기존 fit/옵션 유지 규칙을 사용하고, PC·모바일에는 회전 버튼을 표시하지 않는다.

카탈로그와 저장 메뉴판은 PC 모드를 선택했을 때만 `PreviewActualView` 링크를 표시해 일반 브라우저 새 탭을 연다. 실제 화면 안내는 브라우저 확대·축소와 전체화면을 제목이 있는 별도 영역으로 구분한다. 넓은 화면에서는 나란히, 좁은 화면에서는 위아래로 배치하며 전체화면 버튼·ESC 설명·이용 가이드는 전체화면 영역에 둔다. 미리보기 첫 진입 안내는 제거하고 실제 화면 페이지의 중앙 대화상자로 옮긴다. 기존 브라우저 그림과 오른쪽 위 더보기(⋮) → 확대·축소 안내, 전체화면·이용 가이드·닫기 버튼을 제공한다. 닫으면 아래 중앙의 작은 전체화면/안내 다시 열기 도구만 남는다. 전체화면에 들어가면 안내와 도구 모두 숨기고 ESC 종료 뒤에도 안내를 자동으로 다시 띄우지 않는다. 요청이 실패하면 정상 화면에서 오류와 가이드를 표시한다. 저장 내용·주문/호출·배치 도구 위치는 유지한다.

최상위 page 탭의3px 선택선은 클릭 영역 하단에서4px 위에 놓는다. 기존 클릭 높이·글자색·크기·굵기·키보드 동작은 유지하며 페이지별 간격 보정은 추가하지 않는다.


### 미리보기 색상 설정

보기옵션의 배경색, 글자색, 텍스트칩 색상은 좁은 PC 사이드바와 모바일 패널에서도 2열로 표시한다. 글자색은 하나의 분류 아래 ‘가게명’, ‘가게 설명·안내’, ‘카테고리명’, ‘메뉴 기본정보’, ‘메뉴 설명’, ‘하단 안내·위젯’ 순서로 배치하고, 반복 라벨과 항목별 설명·외곽 박스는 제거한다. 텍스트칩은 종류별 배경색과 글자색을 나란히 둔다. 항목명 아래에 색상 선택과 기본색 복원 도구를 배치하며 공통 서체, 색상 적용 범위, 미리보기 임시값과 저장 동작은 유지한다.

글자색 선택기는 공통 검정색 대체값보다 실제 미리보기의 네이티브 글자색을 우선 표시한다. 로딩 중에는 임의의 검정색을 보여주지 않으며 기기·레이아웃 변경 후 다시 읽는다. 기본색 복원은 해당 그룹의 임시 색상만 제외한 원래 색을 사용하고 기존 적용 버튼으로 확정한다. 값을 읽는 것만으로 스타터·고객 데이터나 임시 디자인 설정을 변경하지 않는다.

미리보기의 정렬·라운드는 `템플릿 기본값` 대신 실제 적용값을 표시한다. 상단행의 고정 정렬은 유지한다. 기본 모양은 `lib/menu-appearance.ts`의 공통 등록표를 사용한다. 각진 모양은 이미지0px·칩0px, 살짝 둥글게는8px·2px, 둥글게는16px·4px, 많이 둥글게는24px·알약형이다. 모카 포레스트와 다이닝2종은8px·2px, 루프베이글은16px·4px, 나머지 디자인과 기본 디자인10종은0px·0px이다. 반고흐 칩의 낙서 윤곽·빗금 질감은 제거하며 다른 장식은 유지한다. 고객이 저장한 개별 값이 다를 때만 혼합 값을 표시하고, 초기화하면 등록된 기본 모양으로 돌아간다. 편집기에서 사용하는 기존 상속·저장값 선택 동작은 유지한다. 세부 계약은 [텍스트 색상 소유권](template-spacing-contract.md#text-color-ownership--2026-10-24)을 따른다.

## 보조 안내·비동기 피드백·모바일 메뉴 (2026-11-02)

- 테이블·키오스크는 같은 등록 목록에서 관리하며 공통 `Tabs purpose="state"`로 리스트형/배치도형만 전환한다. 태블릿/QR은 같은 테이블 정보를 공유하므로 배타적 사용 모드 탭으로 표현하지 않는다.

### 운영 설정 후속 정리 (2026-11-03)

- 주문 설정은 전체 주문·결제 방식·알림/소리를 소유하고, 개별 허용과 기기 연결은 테이블·키오스크 관리에서 제공한다. 주문관리의 중복 ‘기기별 설정’ 탭은 제거한다. QR 관리 등의 기기 진입과 기존 `orders/settings?tab=devices` 주소는 테이블·키오스크 관리로 연결한다. 일반 주문 설정에서는 기기 목록을 읽지 않으며 기존 사장/직원 권한과 데이터는 유지한다.
- 등록 관리 표의 연결 열에는 요약과 설정 진입을 제공한다. 기기 연결됨·대수, 미연결 테이블의 미사용, 키오스크의 연결 필요, 조회 실패의 확인 불가를 구분한다. 실제 모델·OS·브라우저와 연결 조건은 InfoTooltip에서 제공한다. 휴대폰·QR은 기기 연결이 불필요하며 키오스크는 자기 번호에 매장 기기를 연결해야 한다고 안내한다. QR 주소는 별도 QR 관리에 둔다. 개별 주문·호출 허용은 아래 2026-11-06 최신 기준에 따라 등록 관리 표에서도 직접 변경한다.
- 새 접수의 브라우저 알림·소리 받기와 음색/음량/반복/음소거는 해당 주문·호출 설정의 한 카드로 통합한다. 변경은 ‘알림 설정 저장’으로 함께 적용한다. 이전 내역 화면의 활성화 선택은 읽기 호환하며 새 명시 저장값이 우선한다. 수신 OFF/시스템 알림 차단/미지원이어도 내역 화면의 새 접수 안내는 유지한다. 권한 요청은 설정 저장의 사용자 조작에서만 수행하고, 내역 화면에 활성화 박스를 반복하지 않는다.
- 삭제는 사장에게만 제공한다. 운영 카드의 일반 삭제와 보관 항목의 ‘관련 데이터까지 영구 삭제’를 분리한다. 공통 Dialog/ContentPanel/Checkbox/필드/위험 버튼을 재사용하고 삭제 대상 건수·결제 완료액 영향을 읽은 뒤 이름 입력·복원 불가 확인을 요구한다. 조회 실패/변경된 미리보기/서버 차단은 삭제 성공으로 표시하지 않으며 재확인한다. 진행 중에는 중복 실행·창 닫기를 막는다. 기능용 운영 SQL은 사용자 별도 승인 후 적용했으며 실제 삭제는 사용자의 최종 확인으로 실행한다.

`OverviewCard`/`OverviewCardGroup`는 공개 상태·테이블·키오스크·주문·호출과 대시보드 매출 요약에 사용하는 공통 표현이다. 기존 `MetricCard`의 다른 사용처는 변경하지 않는다. 흰 `ContentPanel`의 공통 경계·모서리·20/24px 안쪽 여백을 사용한다. 선택적 `icon` API로 소제목 옆에 공통 `site-label-icon`(18px, 현재 글자색)의 Lucide 아이콘을 둔다. 공개는 Globe, 테이블·키오스크는 LayoutGrid, 주문은 ShoppingBag, 호출은 Bell이다. 아이콘은 장식용 aria-hidden이며 타일·그림자·빈 슬롯은 두지 않는다. 보조 상태 칩·그룹 바깥 장식 경계와 그림자는 두지 않는다.

이번 변경은 사용자가 명시한 대시보드 정리 범위다. 다른 페이지에서 크기·간격을 조정할 때 기능을 옮겨도 된다는 일반 허용이 아니다. 기존 상태 판정·권한·주문/호출 저장·매출 계산·자동 갱신 로직은 유지한다.

이번 간소화 검수: PC와320/390px 모바일·820px 태블릿에서 카드 정렬과 느낌표 안내의 열기·Escape 닫기를 확인했다. 실제 매장 설정은 변경하지 않았다. 공통 UI 계약110건·운영/권한/매출 관련41건, TypeScript·변경 파일 ESLint·프로덕션 빌드를 통과했다.

## 문서형 탭과 짧은 이름 수정 (2026-11-05 추가 승인)

- 기존 section 영역형을 유지하며 `Tabs purpose="section" appearance="document"`를 추가한다. 흰 선택 면·검정 위/옆 경계·아래 기준선 연결과 공통8px 위쪽 모서리로 문서/룸 작업 영역을 표시한다. 과거 사선·산 모양 파일형은 재도입하지 않는다.

운영 내역 리스트와 QR 표는 management 표 자체를 사용하며 바깥 패널을 겹치지 않는다. 운영 리스트는 룸·테이블을 표시하고 내역이 없어도 헤더/등록 행을 유지한다. /design-system의 운영 내역 예시는 ‘주문 있음/없음’을 같은 실제 표로 확인한다. 의미 기반 간격은 보기→콘텐츠24px·룸→내용24px·제목→설명12px·라벨→컨트롤8px다. 이름 편집의 protectNavigation은 미저장/저장 중 입력을 공통 이동 보호에 등록하며, Enter/blur 자동 저장 성공 후에는 다시 확인하지 않는다.

## 버튼 모양별 묶음

## 등록 이미지 캐러셀 (2026-11-11)

목록과 상세는 `CatalogDesign.images`의 실제 등록 이미지 순서를 공유하고 첫 이미지를 대표 이미지(`image`)로 사용한다. 한 원본의 확대·좌우 크롭을 서로 다른 등록 이미지처럼 세지 않는다. MELLOW는 외관·내부 두 장을 사용한다.

`/design-system` 컴포넌트 라이브러리의 “이미지 캐러셀”은 같은 컴포넌트로 두 장/한 장 상태를 비교한다.

## 아이콘 버튼 공통 원칙 (2026-11-11)

**불필요한 장식은 생략하고, 테두리는 흰색 fill의 경계가 불분명할 때만 사용하며, 표현과 조작 영역은 분리한다.** 무배경으로 바꿔도 클릭 영역·중앙 정렬·포커스·상태 피드백은 제거하지 않는다. 실제 인접 표면에서 버튼이 구분되는지를 판단한다.

표현은 기본 `bare`와 명시적 `framed`만 사용한다. `Button size="icon"`의 일반40px·밀집32px 영역과 SVG 크기는 독립적이다. `iconAppearance="framed"`와 공통 variant로 면을 선택하고, `iconSize="compact"`로 밀집 크기를 선택한다. native는 같은 의미의 `data-icon-appearance`/`data-icon-size`를 사용한다. 전용 컨트롤은 등록된 크기를 유지한다.

좋아요·공유는 bare, 페이지네이션은 기본 무테·투명 및 검정 현재 페이지를 포함한 기존 전용 디자인을 유지하고, 떠 있는 맨 위로는 원형, 미리보기 접기/펼치기는 펼침·접힘 및 hover/pressed 모두 무배경·무테·그림자 없이 표시하며 클릭 영역과 중앙 정렬은 유지한다. 이는 세부 유형 목록이 아닌 공통 원칙의 예시다. [구현·상태·규격 계약](site-control-contract.md#아이콘-버튼-공통-원칙-2026-11-11)과 컴포넌트 라이브러리가 같은 기준을 사용한다. 표시 아이콘·고객지원 런처·썸네일·스위치의 기존 역할은 유지한다.


## 복합 입력·선택·달력 공통 구성 (2026-11-11)

- `InputGroup`은 입력·앞뒤 아이콘/단위·보조 행동을 한 경계 안에서 중앙 정렬한다. `InputGroupInput`은 native name·required·min/max·autocomplete·aria-describedby를 그대로 전달한다. 보조 버튼은 입력과 형제인 `InputGroupAction` 안에 둔다.
- `SearchField`는 접근 가능한 label, 선택적 검색 아이콘, 값이 있을 때의 지우기와 입력으로의 포커스 복귀를 공유한다. 기존 실시간 필터/제출 검색과 IME 보호를 바꾸지 않는다. 결과가 없다는 이유로 입력 오류를 만들거나 특수문자를 임의 차단하지 않는다.
- `PasswordField`는 초기 마스킹과 별도 표시/숨기기 버튼을 제공한다. 이 버튼은 type=button이며 검증·자동완성·폼 이름/값을 유지한다.
- 필드 크기32/40/44/48px와 기본14px·터치16px 글자,12px 안쪽 여백, 기존 아티메뉴 색상만 사용한다. 비활성은 투명도를 겹치지 않으며 읽기 전용은 선택·복사와 키보드 포커스를 유지한다.
- Radix 체크박스/라디오는 native와 같은16px 표시를 사용하며 전체/부분/비활성·오류·포커스를 구분한다. 부분 선택의 가로 표시는 Radix의 실제 data-state를 따른다.
- 달력은 일반 실행 버튼과 분리한32px 날짜·내비게이션을 사용한다. 선택 날짜는 기존 검정/흰색, 기간 중간은 기존 회색이다. 기본 키보드/월 이동/비활성 날짜는 react-day-picker에 맡긴다. 날짜 폼의 native date 입력도 유지한다.
- 라이브러리 `#composed-fields`에서 동일 컴포넌트로 확인한다. 새 입력 컴포넌트의 private 외형 재정의는 check:site-system에서 차단한다.

점검 범위·벤치마크·보존 기준은 [컴포넌트 시스템 점검](component-system-audit-2026-11-11.md)을 따른다.


2026-11-11 필드 형태·계층 후속: 라운드는 사용자 후속 지시로 이전 승인 상태(일반 입력·선택12px, 검색 캡슐형)로 복구한다. PC·태블릿의 선택 라벨/개수 간격과 화살표 최소 여유는 각각8px, 모바일 간격은 유지한다. FAQ 대표 검색은 모바일16px·PC/태블릿18px, 주제 카테고리와 행 분류명은16px이다. 최신 수치와 공통 구현은 `site-component-density.md`의 필드 모서리·선택 내부 간격·대표 검색 기준을 따른다.

## 공식 사이트 아이콘 통일 (2026-11-11)

- 일반 UI 아이콘은 `app/components/ui/site-icon.tsx`의 Remix Line을 사용한다. 24px 그리드의 로컬 SVG이며16/20/24/32px에서도 같은 윤곽 비율을 유지한다. 외부 CDN/아이콘 API 요청은 없다. 색은 `currentColor`, 굵기는 원본 윤곽을 따른다. 기존 `strokeWidth`로 윤곽을 덧그리지 않는다.
- 알림·닫기·말풍선·하트·공유·저장·검색·추가·업종/색상/분위기/레이아웃 필터·마이페이지·미리보기 도구·사이트 마케팅 UI 모두 같은 출처를 사용한다. 업종은 커피잔/식기/그릇/고블릿/빵으로 구분한다. 매장 룸에 저장된 이모지는 사용자 데이터이므로 유지한다.
- `lib/site-icon-map.ts`는 기존 이름과 원본 glyph의 매핑, `/design-system#site-icons`는 전체 glyph 예시를 제공한다. 좋아요는 `Heart`의 `filled` 또는 기존 `fill` 선택값으로 실제 채움형을 표시한다. 라디오와 메뉴의 선택점은 채움형 원이다. 의미/접근성/선택 상태를 보존한다.
- 화살표는 기존 `site-arrow.tsx`를 유지한다. 새 창/외부 링크도 기존 ↗를 유지한다. 새로고침/회전만 작은 원호 바깥으로 한쪽 곡선 날개를 둔다. 안쪽 날개와 뾰족한 stroke join을 제거해 작은 크기에서 빈 공간이 열린다.
- 툴팁 말풍선의 모양·꼬리·동작, 데이터 스와치/차트/QR/제스처 그림, 고객 메뉴판 렌더러는 변경 대상이 아니다. 메뉴판 영역에 새 사이트 아이콘을 가져오지 않는다.
- 출처는 Iconify의 Remix Icon4.8.0 Apache-2.0 스냅샷으로 고정한다. 정확한 커밋과 라이선스는 `public/licenses/remix-icon-NOTICE.txt`, `remix-icon-LICENSE.txt`에 포함한다.

공통 Switch는 기존 흑백 대비·상태·RTL·로딩·비활성·키보드/폼 동작을 유지하며 기본 트랙44×24px/손잡이18px, 소형36×20px/손잡이14px, 경계1px/안쪽2px를 사용한다. 두 크기 모두44×44px 조작 영역을 유지한다. 별도 ON/OFF 상태 문구는 추가하지 않는다.

### 서체 선택 견본 (2026-11-11)

보기 옵션·메뉴판 디자인 설정의 서체 선택은 공통 `FontSelect`다. 열린 목록은 이름을 해당 등록 서체로, 한글은 ‘가나다’와 함께 보여 준다. 견본16px·행40px/터치44px·기존 기본값/선택 체크/초점과 팝업 스크롤을 사용한다. 보이는 서체부터 기존 자산을 로드하며 선택 전후 값과 명시적 저장 동작은 유지한다. 선택 버튼과 주변 UI의 사이트 폰트는 그대로다. 상세 경계는 `site-control-contract.md`의 ‘서체 선택 목록의 견본’을 따른다.

## 모바일 알림 레이어 (2026-11-11)

종 아이콘은 기기와 관계없이 현재 화면 위에서 최근 알림을 연다.768px 이상은 기존 팝오버,768px 미만은 공통 `NotificationSheet`의 전체 너비 바텀시트(최대48rem/92dvh)를 사용한다. 헤더와 전체 메뉴의 종 버튼은 같은 알림 상태·`NotificationPanel`·전체/읽지 않음·모두 읽기·전체 알림 보기를 공유한다. 전체 메뉴에서 열 때 메뉴를 닫고 알림에 포커스를 넘기며, 닫으면 보이는 헤더 종으로 복귀한다. 인증 확인 전/비로그인 상태에서는 종을 표시하지 않는다.

알림을 열거나 닫는 동작으로 URL·브라우저 이력·아래 화면의 입력값과 스크롤을 변경하지 않는다. 시트는 배경 스크롤을 잠그고 목록 안에서만 스크롤하며 제목·닫기·분류·하단 전체보기를 유지한다. 작은 가로 화면과 safe area에서도 닫기/전체보기에 접근할 수 있어야 한다. Tab 포커스 제한, Escape·닫기·바깥 영역 닫기, 원래 버튼 포커스 복귀와 모션 감소를 지원한다. 알림 항목 또는 전체보기를 선택할 때만 해당 페이지로 이동한다.

최근90일/최근10개 조회·읽지 않은 개수·읽음 API·실패 복구는 기존대로 유지한다. 알림을 열기만 해서는 읽음 처리하지 않는다. 기존 `/notifications`와 마이페이지 알림 내역 화면은 유지한다. 고객 메뉴판 렌더러는 변경하지 않는다.

## 알림 벨 배지 위치 (2026-11-11)

헤더 PC·모바일·전체 메뉴는 공통 `NotificationBellIcon`을 사용한다. 배지는44px 클릭 영역의 모서리가 아니라23px SVG 래퍼의 오른쪽 위를 기준으로 배치한다. PC20px·모바일16px 숫자 배지와 전체 메뉴6px 점을 유지하며0건은 숨기고 기존9+ 상한을 따른다. 배지는 장식이며 버튼 접근성 이름으로 읽지 않은 건수를 제공한다. 클릭 영역·포커스·알림 열기·읽음 동작은 유지한다.
