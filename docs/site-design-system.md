# ArtiMenu 공식 사이트 디자인 시스템

탭과 선택은 [최종 역할 계약](tab-hierarchy-contract.md)을 따른다. 주요 화면(page), 독립 콘텐츠(section), 목록 주제(category), 작은 필터, 상태·보기 값(state)을 구분한다. 고정 단계와 URL 유무로 모양을 정하지 않는다. 전체 사용처는 [점검표](tab-role-audit.md)를 따른다.

2026-10-18 사용자 제공 컴포넌트 참고 문서를 기존 사이트 시스템에 재매핑했다. 원문/CSS 복사나 별도 Mobbin 스타일시트 없이 `--ui-*`와 기존 의미 클래스를 수정한다.
기존 서비스·계정·신청·운영 흐름은 유지하고, 사이트 UI의 시각 규칙을 통일한다.

- 흰 캔버스, 본문 `#15181e`, 보조 `#4b515b`, muted `#717680`, subtle `#f8f9fb`, border `#dbdee3`.
- ArtiMenu 대표 노랑은 `#f8e731`이다. 일반 안내에는 밝은 노랑을 사용하며 노란 점이 붙은 장식 소제목은 문구·여백까지 제거한다. 실제 제목과 알림 본문의 목록 기호·읽지 않은 알림 점은 유지한다.
- 주요 생성·저장·결제·로그인 완료와 주요 화면 선택은 검정/흰색이다. 영역·주제·상태 선택은 최종 탭 역할 계약의 표현을 따른다. 편집·미리보기·다운로드의 일반 보조 실행은 흰 배경/회색 경계의 `outline`, 초기화·복사 등 도구는 중간 회색 무테 `secondary`, 취소·닫기·로그아웃을 포함한 일반 흰색 버튼은 회색 1px 경계의 outline을 사용한다. 비활성은 더 옅은 회색 무테 표면과 낮은 문구 대비로 secondary와 구분한다. ghost는 좋아요·공유·아이콘 도구처럼 모양 자체로 식별되는 제어에만 사용한다. 문맥에서 가장 중요한 행동은 primary로 승격할 수 있다. 새 창은 아이콘과 접근성 이름으로 구분한다. 최종 위험 실행은 danger, 삭제 등 위험 진입은 흰 배경과 붉은 경계의 outline danger다.
- Pretendard, 히어로는 이미지·프레임 비율·라운드·배치·크롭을 유지하고, 타이포·색상만 공통 토큰을 적용한다. 현재 페이지 제목은 모바일28px·태블릿32px·PC36px, 제목 바로 아래 설명은 모든 기기16px이다. 내부 섹션·하위 제목·본문·보조 문구는 의미 기반 `.type-*` 역할을 사용한다.
- **브랜드 인상: 밝고 단정하며 정보 구분이 명확한 UI.** 외곽 카드를 제거한 자리는 제목·구분선·옅은 배경으로 다시 구성한다. 필터는 옅은 회색 배경, 반복 내역은 상하 구분선과 정렬된 정보 열, 부가 안내는 옅은 배경과 왼쪽 선을 사용한다. 입력·선택·outline 컨트롤의 회색 1px 경계는 유지하며 보조 CTA의 중간 회색 무테 표면과 구분한다. 로그인·가입·복구는 가운데 정렬된 좁은 폼이다. 입력창은 공통 16px, 선택 컨트롤은 12px 라운드다. 소개 이미지 20–32px, 기존 히어로의 독립 32–48px/배치, 판매 목록 미리보기 16px·레이어 16px, 안내 6px, 토스트 8px는 유지한다. 기본 버튼은 40px·8px 모서리·15px/600 글자다. 탭은 용도와 단계에 따라 outline·밑줄·영역형을 구분한다. 기능 카드와 이미지를 가진 카드는 무테/16px/무그림자 표면을 명시적으로 사용한다. 그림자는 떠 있는 레이어와 글래스 헤더에만 사용한다.
- FAQ 상담 진입은 아이콘·제목/설명·이동 화살표가 있는 16px 라운드의 짧은 외곽선 버튼이다. 질문 목록은 외곽 카드 없이 상하/행 구분선으로 읽는다. 마이페이지는 PC에서 사이드 구분선과 세로 메뉴, 모바일·태블릿에서는 작은 계정 요약과 줄바꿈 가능한 가로 메뉴를 사용한다. 결제 내역의 정보 열은 모바일 2열/넓은 PC 4열이며, 375px 미만 필터는 날짜/선택 값이 잘리지 않도록 1열이다.
- 사용자 요청에 따라 문서의 1160px 컨테이너 대신 기존 히어로 **안쪽 최대 1520px** 기준을 공유한다. 바깥 컨테이너 1600px, 좌우 `clamp(20px, 3vw, 40px)`. `.site-container`와 `.site-gutter`는 동일한 좌우 경계를 만든다. 폼·법률 본문 같은 읽기 영역은 이 안에서 좁은 폭을 유지할 수 있다.
- 판매 갤러리: 1280px 이상 3열, 640–1279px 2열, 639px 이하 1열. 열 간격 24px, 행 간격 40px. 서비스 탭은 검정/흰색이고 키보드 좌우/Home/End 탐색을 지원한다. 홈의 기존 공유 그리드 기준은 유지한다.
- Home·베이직·다이닝·디스플레이의 디자인 쇼케이스는 공통 태블릿 가로 미리보기인 1180×820 비율을 사용한다. 베젤·검정 테두리·카메라 장식은 없으며, 이 쇼케이스만 사용자 지정 `clamp(12px, 1.5vw, 20px)` 라운드를 사용한다. 중앙은 가장 크고 선명하다. 인접 화면은 약 68% 크기·3px 블러·62% 불투명도, 더 먼 화면은 최소 48% 크기·약 6px 블러·24% 불투명도이며 거리별로 연속 변한다. 인접 화면의 중심은 중앙보다 6–12px 위, 더 먼 화면은 최대 24px 위에 놓는다. 자동 움직임은 멈췄다가 넘기는 방식 대신 일정 속도(프레임당 0.6px)로 계속 흐르는 무한 순환이며 hover로 멈추지 않는다. 수동 화살표/숫자는 표시하지 않고 재생/일시 정지 버튼과 드래그·방향키 탐색을 제공한다. 키보드 포커스/드래그/화면 밖/비활성 탭 및 명시 일시 정지는 재생을 멈춘다. 모션 감소 설정은 기본 정지하며 사용자가 재생 버튼을 누른 경우에만 흐름을 시작한다. 모션 감소 상태의 수동 방향키 이동은 즉시 전환한다. 화면 안은 추후 사용자 이미지로 교체할 임시 메뉴 시안이며 실제 메뉴판 디자인과 독립적이다. 각 서비스의 주요 기능 제목/설명은 해당 히어로와 같은 `type-page-title`/`site-body` 크기를 사용한다. CTA는 공통 40px `site-button`의 검정 primary 또는 어두운 배경용 회색 secondary를 사용한다.
- 기본 헤더: 중앙 메뉴는 다이닝 → 디스플레이 → 템플릿 → 고객센터 순서다. 로그인 전 오른쪽은 테두리 없는 ‘로그인·회원가입’ → 검정 pill ‘만들기’, 로그인 후에는 테두리 없는 알림 벨 → 세로 구분선 → ‘마이 메뉴’ → ‘만들기’다. 모바일·태블릿의 기본 헤더는 기존 햄버거 메뉴와 로그인 후 알림 진입을 유지한다. 알림은 모든 기기에서 같은 기존 Bell(23px, 선 두께 2.1)을 공유하며 데스크톱의 벨 영역과 세로 구분선 간격은 8px다.
- PC·태블릿(768px 이상): **홈/다이닝·디스플레이 서비스 소개와 그 호환 별칭만** 스크롤 후 메뉴만 남는 글래스 헤더. 로고·만들기·알림·계정·햄버거는 숨긴다.
- 모바일 및 고객센터·템플릿 목록·계정·신청·운영·채팅·법률 등 나머지 경로: 기본 상단 부착 헤더. 모바일 전체 메뉴는 포커스 제한/Escape/포커스 복원을 지원하는 Dialog다.
- 스크롤 200px 이후에는 방향과 무관하게 ‘맨 위로’만 표시한다. 모션 감소 환경은 즉시 이동한다. PC·태블릿(768px 이상)의 고객지원·맨 위로 퀵메뉴는 본문 컨테이너나 페이지 좌우 여백에 맞추지 않고 브라우저 뷰포트 오른쪽·아래 2rem 기준으로 배치한다. 안전 영역을 보장하고 기존 세로 버튼 간격을 유지한다. 모바일 위치 규칙은 유지한다.
- 고객지원 퀵메뉴는 공통 AI 보라·파랑 그라데이션, 흰 채팅 말풍선과 56px/20px 모서리의 둥근 정사각형이다. 별도 사용가이드 퀵 링크는 지원 홈 안으로 옮긴다. 열면 세 가지 문의 채널·서비스 가이드·짧은 FAQ를 표시하고, AI 선택 후 흰 배경의 웰컴형 상담 화면으로 이동한다. 캐릭터는 사용하지 않으며 단일 반짝임 아이콘을 쓴다. 추천 질문·전송·입력은 라이브러리와 같은 실제 Button/Input 및 의미 타이포 역할을 사용한다. 고객센터 AI 상담·전송 버튼도 같은 색 토큰을 사용한다. 공통 Radix Dialog의 닫기·Escape·포커스·스크롤 복원을 따른다. 상세 기준은 `docs/site-control-contract.md`를 따른다.
- 디자인 템플릿 상세페이지는 정보·신청 버튼과의 겹침을 막기 위해 AI 상담·맨 위로 퀵 메뉴를 모든 기기에서 숨긴다. PC·태블릿은 처음에 오른쪽 내용을 자연 높이로 펼친다. 스크롤해서 미리보기/시작 버튼이 화면 하단에 도달한 뒤 갤러리를 숨기고, 헤더 아래 정보와 하단 버튼을 고정한다. 고정 상태의 정보가 넘칠 때만 내부 스크롤과 흰색 페이드를 사용하며, 위로 돌아가면 갤러리와 자연 배치를 복원한다. 모바일은 기존 자연 스크롤 순서를 유지한다.

## 용도별 크기와 형태 확장 (2026-10-25)

사용자 제공 참고 이미지의 선택 카드·밑줄 탐색·큰 세그먼트·사각 이동 버튼·이미지 카드·빈 목록 구성을 기존 토큰과 컴포넌트에 확장했다. 아래 명시적 변형은 과거의 “모든 CTA/탭은 pill·40px” 제한을 대체한다. 기본값을 사용하는 기존 폼·운영 액션은 유지한다. 검수용 `/design-system`은 검색 노출을 막고 실제 공통 컴포넌트를 렌더링한다.

- 서체는 기존 Pretendard를 유지한다. 현재 공통 역할 수치는 `docs/site-typography-final.md`와 `lib/site-typography.ts`를 단일 기준으로 사용한다. 페이지 제목은28/32/36px, 제목 설명과 일반 본문은16px이며, 내부 섹션·콘텐츠·보조 문구는 각 의미 역할을 따른다. 사이트 헤더 탐색과 주요 탭은 별도 컨트롤 역할을 유지한다.
- 2026-10-25 공개 화면 참고: [크몽](https://kmong.com/)은 PC 홍보 제목 40px/주요 섹션 28–36px/일반 섹션 24px, [잡코리아](https://www.jobkorea.co.kr/)는 주 탐색 18px/정보 섹션 18px/설명 모달 제목 24px, [사람인](https://www.saramin.co.kr/)은 주 탐색 16px/추천 보조 14px를 사용했다. 관찰한 역할별 대비를 아티메뉴 토큰에 맞췄으며, 각 사이트의 CSS/이미지/문구를 복사하지 않는다. 페이지/계정/마케팅의 정보 밀도가 다르므로 모든 제목을 같은 크기로 강제하지 않는다.
- `Button`: 색상 역할(primary/outline/secondary/danger)은 유지하며 높이는 compact32/default40/header44/large48px 네 단계만 쓴다. 글자는 전 구간 15px·600, 일반 모서리는 8px다. pill은 헤더·떠 있는 짧은 CTA처럼 명시된 역할에만 쓰고, 아이콘 단독은 원형이다. 긴 문구가 줄바꿈되면 높이는 늘어날 수 있다. `sm`·`xl`·`rounded`·`square` 별칭은 폐기해 같은 의미가 여러 이름으로 생성되지 않게 한다.
- `ChoiceTile`: 기존 `site-choice` 경계 안의 아이콘+이름 선택 버튼. `inline`은 업종/짧은 필터, `feature`는 충분한 설명이 필요한 폼 선택이다. 선택한 흰 카드에 진한 경계와 노란 아이콘 바탕을 사용하며 내용 카드에 테두리를 확산하지 않는다. feature 설명은 좁은 모바일에서 시각적으로 접고 접근 가능한 설명 연결은 유지한다. 일반 선택은 aria-pressed, 탭 호출자는 기존 aria-selected/방향키 계약을 보유한다.
- `TabsList`: `segmented` 기본값과 `outline` 밝은 선택+진한 경계, `underline` 열린 밑줄 변형. `size=lg`는 큰 탐색용으로 쓰며 모든 변형은 Radix 키보드 동작을 공유한다. `TabsTrigger count`는 별도 칩 없이 건수를 표시한다. 선택/hover/active/disabled와 포커스를 구분하고 모션 감소를 존중한다.
- `EmptyState`: 넓은 옅은 바탕에 아이콘·제목·설명·명시적인 다음 행동을 배치한다. 템플릿 필터의 빈 결과에는 실제 필터를 초기화하는 액션을 연결한다. 장식 테두리·그림자나 허위 상태 수치를 추가하지 않는다.
- 실제 적용: `/apply`의 업종은 공통 compact 아이콘 선택, 템플릿 종류는 흰 콘텐츠 면에 연결되는 section 영역형이다. 썸네일이 선택 UI보다 우선하며 카드 미리보기는 40px 실행이다. 홈·서비스·인증의 큰 CTA도 최대 48px를 사용한다. 문구 기반 폭을 기본으로 하며 과거의 52–64px hero와 448px 강제 너비는 제거했다.
- 고객 메뉴판의 서체·색상·fit·간격·장식에는 새 변형을 전파하지 않는다. 새 값은 `--ui-*`와 명시적 `site-*` 클래스에만 둔다.

## 컴포넌트 표현 기준 (2026-10-18)

- 주요 화면은 분리된 둥근 page, 독립 콘텐츠는 section 영역형, FAQ 주제는 category 밑줄, 상태·보기는 회색 레일 state, 업종·문서 위치는 작은 필터를 사용한다. 크기는 대/중/소로 구분하며 수치는 `docs/site-control-contract.md`를 따른다. 링크 이동·본문 앵커와 Radix 탭의 키보드 동작을 구분해 보존한다.

## 폐기된 연결형 탭 기록·말풍선·업종 아이콘 (2026-10-25)

이 절은 위 표의 디자인/기본 선택 방식을 대체한다. 공통 컴포넌트의 기존 변형은 유지한다.

- 역사 기록: 이 절에서 정의했던 `Tabs variant="contained"`와 파일형·산 모양 윤곽은 2026-10-28 폐기했다. 관련 목록도 현재는 section 영역형로 묶으며 상위 서비스 전환, 업종 필터, 가격·목록·URL·페이지 처리의 의미는 유지한다.
- `HelpTooltip tone="brand"`는 아티메뉴 노란색·검정 글자·작은 꼬리·닫기 버튼의 안내 말풍선이다. `trigger`, `side`, `align`으로 기준 요소와 방향을 지정한다. 기존 Radix Popover의 Escape·바깥 클릭·포커스 복귀·화면 충돌 처리를 유지한다. 다시 누르면 재진입한다. 짧은 hover/focus 힌트는 `TooltipContent tone="brand"`를 쓰고, 중요한 정보나 조작 버튼을 안에 숨기지 않는다. 기본 light/dark 도움말은 보존한다.
- 업종 `ChoiceTile`은 Lucide의 단색 선 아이콘을 사용한다. 전체/카페·베이커리/레스토랑·다이닝/일식/바·주점/패스트푸드·분식은 각각 그리드/커피/커틀러리/생선/와인/샌드위치로 구분한다. 아이콘은 장식 요소로 숨기고 버튼의 보이는 이름을 접근성 이름으로 사용한다. OS별 모양이 달라지는 컬러 이모지는 사용하지 않는다.
- 위 세 요소는 `/design-system`에서 실제 선택·도움말 열기/닫기 예시로 확인한다.


## 탭 경계·밑줄 검수 보정 (2026-10-26)

- 현재 section 영역형은 연결된 사각 버튼으로 독립 콘텐츠를 전환한다. 검정 선택 면·흰 글자와 흰 비선택 면·보조 글자색을 사용하며 바깥 모서리만8px다. 콘텐츠는 둘레 테두리 없이 구분하고, 템플릿 결과는 밝은 회색 공통 표면으로 묶는다. 긴 기준선·사선·mask는 사용하지 않는다.
- 선택 밑줄 두께는 공통 `--site-tab-indicator-width: .25rem`(기본4px)을 사용한다. 기본/큰 underline Tabs, NavigationTabs, 이미지 카드 위의 탐색 탭이 같은 토큰을 상속한다. 비선택 밑줄도 같은 두께의 투명 경계를 확보해 선택 때 글자가 이동하지 않는다. 글자 크기·컨트롤 높이·가로 간격은 공통 대/중/소 계약을 따른다.
- underline rail은 목록 바깥 좌우 여백을 만들지 않는다. 첫 탭의 시작과 rail의 시작을 맞추고, 문구 여백은 각 탭 내부에서만 확보한다. 가운데 모아 쓰는 서비스·가이드 탭은 탭 묶음 너비까지만 rail을 표시하며, 마이페이지 탐색과 알림·요금처럼 행 전체가 탐색 영역인 경우에만 전체 너비를 유지한다.
- `/design-system`의 영역형·서비스·이미지 카드·상태 탭과 `/apply`를 실제 PC·태블릿·모바일에서 확인한다. 고객 메뉴판의 서체·간격·렌더러는 변경하지 않는다.


## 마이페이지 탭과 연결 모서리 (2026-10-26)

- 호출 내역/설정 같은 주요 화면 이동은 분리된 둥근 page/md, 다국어 언어 값은 둥근 state/md, 그 안의 번역 대상은 section 영역형/sm이다. 페이지별 색·크기·밑줄 덮어쓰기 대신 Radix Tabs를 사용한다. URL 이동은 NavigationTabs를 사용하며 purpose="page"는 분리된 둥근 버튼, purpose="state"는 둥근 상태 세그먼트를 사용한다.

- 폐기된 파일형의 비대칭·사선 윤곽은 사용하지 않는다. 영역형은 위쪽만 공통 control radius를 사용하고 콘텐츠 면과 만나는 아래쪽은 직선으로 연결한다.

## 선택 요소 위계와 셀렉트 (2026-10-26)

현재 기준은 [사이트 컨트롤 계약](site-control-contract.md)의 역할·대중소 표다. `TabsList`/`NavigationTabs`의 size API, 실제 공통 CSS와 라이브러리의 세 크기 비교를 함께 유지한다. 가이드는 상위 lg 주요 화면 버튼과 하위 32px 본문 링크로 분리한다. 모든 사이트의 native select와 Radix SelectTrigger는 20px/2.25 chevron, 우측 16px, 문구 예약 공간 48px를 공유한다. 렌더러·다중 선택·목록형 select는 제외한다.

## 2026-10-26 읽기 크기·폼·카드 공통 기준

사용자 요청에 따라 티오더와 카카오비즈니스 세미나의 제목/본문/콘텐츠 구분을 참고했다. 아래 기준이 과거의 12–14px 본문, 14px 헤더 및 모든 입력 40px 규칙을 대체한다. 메뉴판과 상품 화면 축소 시안은 제외한다.

- `styles/typography.css`가 단일 폰트 기준이다. Pretendard 400 본문 / 500 보조 강조 / 600 항목·탐색 / 700 주요 제목을 구분한다. 일반 페이지 제목은 모바일28px·태블릿32px·PC36px이다.
- 일반 본문은 모든 기기에서16px, 강조 본문은18/20px, 보조 설명은14px, 날짜·메타는13px이다. `text-copy`/`text-support`/`text-meta`는 크기·줄높이만 정하므로 필요한 굵기·색상을 합성할 수 있다. `cn`의 Tailwind 병합도 이 역할을 인식한다.
- PC 글자를 키우기 위해 html/rem 또는 기초 `--font-size-*`, 기존 `text-xs`/`text-sm` 값을 바꾸지 않는다. 실제 메뉴판의 독립 폰트·핏·축소 미리보기에는 영향을 주지 않는다.
- 폼 컨트롤은 필터 `sm` 40px, 계정 `md` 44px, 신청 `lg` 48px, 큰 질문 검색 56px이다. Input/Textarea는 `fieldSize`, SelectTrigger는 `size`를 사용하며 네이티브 입력은 `data-field-size` 또는 `site-field-*`로 동일 규격을 사용한다. 네이티브 input의 `size`는 문자 수 속성으로 보존한다.
- 값 입력은16px 이상/400 굵기, 필드명15–16px/600, 안내14px/400–500이다. 입력 모서리는12px, 동일 행의 input/select는 같은 높이를 사용한다. 검색용 큰 입력을 일반 로그인/신청 화면에 적용하지 않는다.
- 입력은 기본/hover/포커스/오류/읽기 전용/비활성을 구분한다. 포커스는 기존 2px 파란 경계를 유지하고, 오류는 `aria-invalid`와 설명 연결을 함께 사용한다. checkbox/radio/color/range/file/hidden은 텍스트 입력 높이에서 제외한다.
- 정보 카드는 흰 표면·옅은 회색 경계·12px 모서리, 하위 묶음만 옅은 회색 바탕을 쓴다. 선택/요금 카드는 `site-plan-card`로 재사용한다. 선택 시 흰 바탕·진한 경계와 명시적 선택 표시, 제목18–20px·요금32px·설명14px로 구분한다. 본문 전체를 굵게 만들지 않는다.
- 라이브러리 `/design-system`의 폼·카드 예시는 실제 사이트와 같은 입력·셀렉트·CSS를 렌더링한다. 신청 약관은 중복 링크 없이 하나의 상세 보기로 연결하고, 여백과 글자 무게를 줄여 하나의 결정 묶음으로 표시한다.


## 2026-10-26 버튼 모서리와 게시글 목록

- `site-button-header`: 공통 44px·pill 모서리의 헤더 진입 버튼. 일반 본문/폼은 기본 `site-button`의 8px 사각형이다. 페이지 번호의 8px 사각형·작은 아이콘의 원형과 고객지원 56px/20px 모서리는 별도 역할이다.
- `ContentList`/`ContentListItem`: 공지·게시글용 구분선 목록. 유형/제목/날짜의 3열이며 모바일은 유형·날짜 다음에 제목이 이어진다. 카드·박스를 각 행에 중복하지 않는다.
- `ArticleNavigation`: 이전글/다음글의 제목·날짜, 글이 없을 때의 비활성 안내. 공지 상세에서는 공개된 현재 시점 이전 글만 시간+UUID 순으로 조회한다. 상단 고정은 상세 이동 순서를 바꾸지 않는다.
- `SitePagination`: 고객센터와 템플릿 목록이 함께 사용하는 페이지 번호. 모바일은 번호 최대 3개와 네 이동 화살표(32px), 640px 이상은 번호 최대 7개와 네 이동 화살표(40px)다. 현재 페이지는 8px 라운드의 검정 사각형·흰 숫자다. 처음/이전/다음/마지막 이동과 포커스/비활성 상태를 구분한다. ellipsis는 사용하지 않는다. 라이브러리에서도 같은 구현을 사용한다.


## 영역형 탭과 공통 푸터 (2026-10-27)

- `Tabs purpose="section"` (2026-10-31 최종): 연결형 사각 버튼을 사용한다. 선택은 검정 바탕·흰 글자, 비선택은 흰 바탕·보조 글자색이다. 인접1px 경계는 한 줄로 보이며 바깥 네 모서리만8px다. 긴 기준선·사선·산 모양 mask·그림자는 사용하지 않는다. 템플릿의 두 종류는 equal 분배로 중앙에 배치한다.
- 영역형은 하나의 기능·작업·목록 영역 안에서 내용만 바꿀 때 사용한다. 주요 화면에는 분리된 둥근 page, 목록 주제에는 밑줄 category, 상태·보기 값에는 회색 레일의 state를 사용한다.
- Root에 지정한 변형을 List/Trigger/Content가 상속한다. `size="sm|md|lg"`의 영역형44/52/56px 및 14/16/16px, `distribution="content|equal"`, disabled, 방향키/Home/End 계약을 재사용한다. 좁은 화면의 긴 탭 목록은 영역 안에서만 가로 스크롤한다.
- 라이브러리의 `#shaped-tabs`에서 영역형과 대·중·소를 실제로 전환하고 상태 표에서 기본/hover/pressed/focus/disabled를 비교한다. 폐기한 파일형·라운드 연결형을 새 화면에 사용하지 않는다.
- 공통 Footer는 옅은 라운드 표면에 브랜드/서비스/이용 안내/고객지원, 사업자 정보, 약관을 묶고 같은 회색 표면의 맨 아래에 배경보다 조금 진한 연회색 장식 워드마크를 배치한다. 워드마크의 하단은 표면의 둥근 경계 안에서 잘리며, 박스 바깥에는 표시하지 않는다. 실제 정보는 보통 본문·보조 크기를 유지하며 장식 글자만 의도적으로 일부 잘라 표시하고 `aria-hidden` 처리한다. 외부 사업자 확인 링크와 기존 사업자·연락 정보는 유지한다.
- 스타일은 `app/components/layout/Footer.module.css` 한 곳에서 관리한다. 구 landing Footer도 동일 컴포넌트를 다시 내보내며 페이지별 푸터 디자인을 복제하지 않는다. `#site-footer`는 라이브러리 바로가기에서도 실제 푸터를 보여준다.


## 표면과 테두리 선호 (2026-10-26 사용자 재확인)

- 테두리는 흰 배경의 표면에서만 필요한 경우 사용한다. 회색·유색 배경 박스에는 외곽 테두리를 넣지 않고 면색과 여백으로 구분한다.
- 회색 푸터는 테두리와 내부 구분선을 사용하지 않는다. 큰 연회색 워드마크는 회색 박스 안 하단에서 잘린 장식으로만 사용한다.


## 실제 적용 역할 (2026-10-29)

- 주요 화면 전환은 purpose="page"의 텍스트와 문구 너비 선택 밑줄이다. 독립 콘텐츠는 section, 목록 주제는 category 밑줄, 상태·보기 값은 회색 레일 state를 사용한다. URL 이동도 NavigationTabs에 역할을 명시한다.
- contained 파일형·산 모양은 폐기했다. 디자인/기본 템플릿은 section 영역형, FAQ 주제는 category 밑줄이며 공지와 이용가이드는 헤더 하위 메뉴로 연결하는 독립 페이지다.
- 영역형은 탭과 아래 콘텐츠 묶음을 하나의 영역으로 전환할 때 사용한다. 콘텐츠에는 둘레 테두리를 두지 않는다. 템플릿은 카테고리 필터부터 페이지네이션까지 --ui-surface-muted의 밝은 회색 결과 표면으로 묶는다. 고객센터에는 필요 없는 하위 필터·영역을 만들지 않는다.
- 중립 배경·구분 면·푸터는 `--ui-surface`/`--ui-surface-muted`/`--ui-surface-soft`를 공유한다. 기본·보조·메타 글자색과 상태색은 같은 의미 토큰을 사용한다. 회색·유색 면에는 외곽 테두리를 추가하지 않는다.
- 페이지 h1은 `type-page-title`(28/32/36px)이다. 로그인·베이직·다이닝·디스플레이·고객센터·신청·템플릿 목록과 상세를 포함해 H1 바로 아래 문구는 모두 `type-page-description`(16px)을 사용한다.
- `type-body-lg`(18/18/20px)는 페이지별 도입 설명을 다르게 만드는 역할이 아니다. 섹션 안에서 기본 본문보다 강조할 짧은 문장에만 사용한다. 관리 화면의 조밀한 단계는 내부 섹션·카드·폼·메타에만 적용한다.
- 베이직·다이닝·디스플레이 같은 탭 문구는 본문이 아니라 컨트롤 라벨이다. `TabsList`의 공통 크기는 lg/md/sm 16/15/14px이며 주요 화면(page)은 lg18px·md16px, 독립 영역(section)은 md16px을 사용한다. 같은 역할과 크기는 페이지와 무관하게 동일하다. 주요 화면의 선택600·비선택500과 회색 토큰은 공통 스타일이 관리한다.
- 인증 화면에서 비밀번호 찾기·회원가입·로그인 복귀 같은 계정 보조 이동은 `type-body-sm`(14px)을 사용한다. 보조 이동이 기능 설명보다 크게 보이지 않게 한다.
- 작은 카드의 이름·설명·메타는 `type-card-title` 18px / `type-card-body` 14px / `type-card-detail` 13px이다. 템플릿·신청 카드와 현황·내역·요금 카드에 사용하며, 가격·통계 수치의 강조는 독립적이다.
- 팝업 제목·본문·작은 안내는 18/14/13px이다. 작은 하단 안내·폼 도움말은 PC·모바일 모두 `type-footnote` 13px·400·줄높이1.6이다. 입력값은 기존 16px을 유지한다.
- 알림창은 category 밑줄 분류와 기존 목록 구조를 사용하고 제목/본문14px·메타13px만 적용한다. AI 상담의 대화·동의·보안 안내, 계정·신청·편집의 도움말 및 결제/문의 하단 안내도 같은 문맥별 기준이다.
- 고객이 편집하는 메뉴판의 글자·색·레이아웃은 이 변경 대상에서 제외한다. 자세한 현재 기준은 [사이트 컨트롤 계약](site-control-contract.md)을 따른다.

## 2026-10-29 와이드 대응

폰트의 기본 역할과 최대 12.5% 와이드 보정, 인증 폼 폭·높이와 간격은 [폰트 계약](site-typography-final.md)의 최신 절을 따른다. 고객 메뉴판 렌더러와 root rem은 이 보정의 대상이 아니다.

와이드 기준은 기준·토큰과 컴포넌트 라이브러리의 공통 `WideScreenRules` 표에서 확인한다. 새 페이지는 의미 기반 글자 역할과 공통 레이아웃 클래스를 사용해 자동 상속하며, 지역별 글자 배율·공통 기초 토큰 재정의는 계약 검사에서 차단한다. 미리보기는 PC·태블릿별 목업 상한과 작은 보조 도구를 적용한다. 주문·호출·묶음형·채움형은 상단에 유지하며 보기 옵션 패널은 표시·디자인만 다룬다. 상세 수치는 `docs/site-typography-final.md`의 최신 절과 `lib/menu-preview-fit.ts`를 따른다.

일반 페이지 제목과 영역 탭 여백, 고객지원 경로의 현재 기준은 [페이지 간격 계약](site-page-layout-contract.md)을 따른다.

### 목업 표시 크기와 변경 범위

두 라이브러리의 `미리보기 목업 크기 기준`은 공통 fit 정책을 그대로 표시한다. 태블릿·모바일 목업은 옵션 레이어와 무관하게 페이지 전체 중앙에 배치하고, 대칭 바깥 여백 안을 최대한 채우며1.25배에서 멈춘다. PC는 테두리·라운드·그림자 없이 화면 전체를 채운다. PC·태블릿 브라우저에서는 현재 실제 뷰포트를 사용하며, 모바일에서 PC를 고르면1440×900 PC 구성을 비율대로 축소해 보여준다. 모바일 확대·축소 제한은 추가하지 않는다.

사이트 전체에서 크기·여백·폰트·반응형 배율만 조정하는 요청은 기존 기능이나 버튼의 이동·숨김·삭제·재분류를 허용하지 않는다. 현재 위치와 진입 경로를 유지하고 사용자에게 위치 변경 요청이 있을 때만 재배치한다. 이 원칙은 AGENTS와 디자인 시스템의 같은 기준 절에도 기록한다.


새 페이지 기본 틀·자동 검사·레거시 이전 원칙은 [자동 적용과 회귀 방지](site-system-enforcement.md)를 따른다. 공지사항은 큰 FAQ 검색 영역 대신 공통 BoardList와 목록 상단의 작은 검색 도구를 사용한다.

### 실제 화면 보기와 회전

카탈로그와 저장 메뉴판은 PC 모드를 선택했을 때만 `PreviewActualView` 링크를 표시해 일반 브라우저 새 탭을 연다. 실제 화면 안내는 브라우저 확대·축소와 전체화면을 제목이 있는 별도 영역으로 구분한다. 넓은 화면에서는 나란히, 좁은 화면에서는 위아래로 배치하며 전체화면 버튼·ESC 설명·이용 가이드는 전체화면 영역에 둔다. 미리보기 첫 진입 안내는 제거하고 실제 화면 페이지의 중앙 대화상자로 옮긴다. 기존 브라우저 그림과 오른쪽 위 더보기(⋮) → 확대·축소 안내, 전체화면·이용 가이드·닫기 버튼을 제공한다. 닫으면 아래 중앙의 작은 전체화면/안내 다시 열기 도구만 남는다. 전체화면에 들어가면 안내와 도구 모두 숨기고 ESC 종료 뒤에도 안내를 자동으로 다시 띄우지 않는다. 요청이 실패하면 정상 화면에서 오류와 가이드를 표시한다. 저장 내용·주문/호출·배치 도구 위치는 유지한다.

최상위 page 탭의3px 선택선은 클릭 영역 하단에서4px 위에 놓는다. 기존 클릭 높이·글자색·크기·굵기·키보드 동작은 유지하며 페이지별 간격 보정은 추가하지 않는다.


### 미리보기 색상 설정

보기옵션의 배경색, 글자색, 텍스트칩 색상은 좁은 PC 사이드바와 모바일 패널에서도 2열로 표시한다. 글자색은 하나의 분류 아래 가게명·카테고리명·상품 기본정보·대표영역 설명·메뉴영역 설명·안내사항 및 위젯 텍스트를 모으고, 반복 라벨과 항목별 설명·외곽 박스는 제거한다. 텍스트칩은 종류별 배경색과 글자색을 나란히 둔다. 항목명 아래에 색상 선택과 기본색 복원 도구를 배치하며 공통 서체, 색상 적용 범위, 미리보기 임시값과 저장 동작은 유지한다.
