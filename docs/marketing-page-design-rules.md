# 아티메뉴 마케팅 페이지 디자인 규칙

이 규칙은 홈페이지, 서비스 소개, 인증, 고객센터, 신청·결제, MY/메뉴판과 운영 화면을 포함한 사이트 UI 전체에 적용한다. 실제 메뉴판 템플릿과 공개 메뉴·대기번호판은 고객이 편집하는 별도 타이포그래피 시스템을 사용하므로 적용 대상에서 제외한다.

## 메인 콘텐츠 최대 너비 (2026-11-19, 현행)

메인의 제목·본문·버튼·콘텐츠 그리드는 헤더·푸터와 같은 최대1600px 중앙 컨테이너를 사용한다. 공통 `--site-content-max`와 기존 `--site-gutter`를 재사용하며, `[data-marketing-page="home"] .site-marketing-container`에만 적용한다. 현재 메인 안으로 통합된 베이직·다이닝·디스플레이 프레임도 같은 기준이다. 좁은 화면의 기존 gutter·글자 크기·간격은 유지한다.

배경 이미지와 배경색은 화면 전체를 채우고, 사진/시연 카메라·기기 배율·스크롤 길이·외곽 블러/페이드는 변경하지 않는다. 배경을 담은 section/stage/page 전체를 제한하거나 중첩 콘텐츠 최대 폭을 추가하지 않는다. 헤더·푸터와 다른 경로는 그대로다. 아래2026-11-17의 최대 폭 제거 지침은 메인에서 이 규칙으로 대체한다.

## 메인 타이포그래피 시범 적용 (2026-11-19, 현행)

메인 본문만 주요 제목28/32/36px·500·1.28, 소개 문장18/18/20px·500·1.55, 자세한 본문16px·400·1.65로 구분한다. 주요 제목 자간은 모바일-.04em/태블릿·PC-.05em, 소개-.03em/본문-.02em이다. 기존 `type-section-title`·`type-body-lg`·`type-body` 역할을 사용하고, 역할 사이 크기 차이를 위해 소개 문장을 명시적으로 표시한다. 자세한 수치와 범위는 [최종 사이트 폰트 기준](site-typography-final.md#메인페이지-글자-위계-시범-적용-2026-11-19-현행-메인만)과 `SITE_HOME_TYPE_POLICY`를 따른다. 전체 사이트로의 확대는 보류하며 헤더·푸터·조작 글자·메뉴판 화면·다른 페이지는 기존 기준이다. 아래 과거 마케팅 기준보다 메인에서 우선한다.

## 메인·베이직·다이닝·디스플레이 글자·간격 기준 (2026-11-17, 본문 최대 폭은 위 후속 기준 우선)

`/`, `/services/basic`, `/services/dining`, `/services/display`의 본문에만 `.site-marketing-page`를 사용한다. 서비스 첫 H1·섹션 H2·큰 기능 스토리 제목은 같은 스타일로 통일한다. 메인의 첫 H1만 아래 전용 히어로 예외를 사용한다. 기준은 모바일24px / 태블릿32px / PC36px, 굵기700·줄높이1.2·자간-.04em이다. 1600–2600px의 기존 공통 와이드 보정을 그대로 받아 최대12.5% 커진다. 서비스 소개에는 별도 hero display 단계를 두지 않으며 카드·요금·가이드 내부의 하위 제목과 시연 화면 글자는 각 역할을 유지한다. 다른 일반 페이지의 제목·폰트 역할은 변경하지 않는다.

메인 첫 제목의 `type-display` 히어로 스타일은 유지한다(같은 날 후속 요청 우선). 메인에만 titleRole="hero"를 사용하고 모바일32px / 태블릿44px / PC56px,700·줄높이1.2로 크게 구분한다. 기존 공통 와이드 규칙과 동일하게1600–2600px에서 최대12.5% 커져 PC 최대63px이다. 서비스 첫 제목과 다른 모든 섹션·카드에 이 크기를 적용하지 않는다.

네 페이지 첫 타이틀은 공통 SitePageHeader를 사용한다. 헤더의 spacer 다음에 --site-page-heading-top(기본40–64px, 와이드 최대72px)을 한 번만 적용한다. 홈 전용48–112px 여백과 별도 hero 줄높이를 제거한다. 설명과의12px 및 도입부 아래32/40px는 기존 공통 계약을 사용한다.

당시 `.site-marketing-container`의 최대 폭을 제거한 정책은 메인에서 위2026-11-19 기준으로 대체한다. 주요 스토리·카드·요금·가이드 그리드에 별도70/72/80rem 중앙 최대 폭을 중첩하지 않고 짧은 텍스트의 읽기 폭은 유지한다. 헤더·푸터, 템플릿·FAQ·신청·관리·일반 페이지는 기존 site-container/site-gutter 최대 폭을 유지한다. 색상·버튼·이미지 비율·고객 메뉴판 렌더러는 이 정책의 대상이 아니다.

공통 구현은 styles/typography.css와 app/globals.css, 표시 기준은 lib/site-typography.ts 및 /design-system의 와이드 기준 표를 따른다. 아래 일반 사이트 표/과거 설명의 메인 hero 예외보다 이 범위의 최신 기준이 우선이다.

## 타이포그래피 위계

`페이지 제목 > 필요한 콘텐츠 제목 > 본문 > 보조문` 순서로 크기와 시각적 중요도를 유지한다. 장식용 소제목을 추가해 단계를 채우지 않는다. 사이트 UI는 영문 Tenor Sans·한글 Pretendard 공통 스택을 사용하며, 일반 페이지 제목에는 홈페이지 히어로용 디스플레이 스타일을 사용하지 않는다.

| 역할 | 공통 클래스 | 모바일 | 데스크톱 | 용도 |
| --- | --- | --- | --- |
| 디스플레이 | `type-display` | 28px | 36px (태블릿 32px) | 홈페이지·서비스 대표 문구 |
| 페이지 제목 | `type-page-title` | 28px | 36px (태블릿 32px) | 일반 페이지 H1 |
| 페이지 설명 | `type-page-description` | 16px | 16px | 모든 일반 페이지의 H1 바로 아래 설명 |
| 섹션 제목 | `type-section-title` | 24px | 28px | 큰 콘텐츠 구획 |
| 하위 섹션 | `type-subsection-title` | 20px | 24px (태블릿 20px) | 폼 단계·카드군 제목 |
| 콘텐츠 제목 | `type-content-title` | 18px | 20px | 카드·본문 제목 |
| 항목 제목 | `type-item-title` | 18px | 18px | 목록·운영 카드 제목 |
| 강조 본문 | `type-body-lg` | 18px | 20px | 섹션 안에서 기본 본문보다 강조할 짧은 문장 |
| 기본 본문 | `type-body`, `text-copy` | 16px | 16px | 일반 설명·중요 안내 |
| 보조 본문 | `type-body-sm`, `text-support` | 14px | 14px | 도움말·부가 설명 |
| 레이블·탐색 | `type-label`, `type-nav` | 15px | 16px | 필드명·헤더 |
| 캡션 | `type-caption`, `text-meta` | 13px | 13px | 날짜·짧은 메타 정보 |

- 토큰과 클래스의 단일 기준: `styles/typography.css`
- 마케팅 설명 섹션의 공통 구현: `app/components/home/MarketingSectionCopy.tsx`
- 제목은 역할에 맞는 클래스를 반드시 사용하고, 개별 페이지에서 임의의 `text-*`, `font-black` 조합으로 다시 정의하지 않는다.
- 문구는 위치가 아니라 역할로 고른다. 로그인·서비스·고객센터·신청·템플릿 목록과 상세를 포함한 모든 일반 페이지의 H1 바로 아래 설명은 `type-page-description`을 사용한다.
- 읽는 문구는 페이지 설명·강조 본문·일반 본문·보조 본문·캡션 중 하나를 선택한다. `type-body-lg`는 페이지마다 크기가 달라지는 도입문으로 사용하지 않는다.
- 베이직·다이닝·디스플레이 같은 탭 문구는 본문이 아니라 컨트롤 라벨이다. `TabsList`의 lg/md/sm 크기와 각각 16/15/14px로 연결한다.
- 메뉴판과 공유하는 `text-xs`부터 `text-7xl`까지 기초 크기는 변경하지 않는다. 사이트 본문은 `text-copy`/`text-support`/`text-meta` 의미 유틸리티를 사용한다. 기초 크기는 `styles/theme.css`에서 승인된 `--font-size-*` 기초 토큰에 연결한다.
- 일반 사이트 UI의 최상위 굵기는 700이다. `font-black`과 `font-extrabold`, 숫자를 직접 넣은 글자 크기는 사용하지 않는다.
- 라우트 파일뿐 아니라 `components`의 모달·폼·MY/메뉴판 사이드바·편집기 등 실제 화면을 구성하는 중첩 UI에도 같은 계약을 적용한다.
- 홈페이지 안의 기기·메뉴판 예시처럼 실제 제품 화면을 축소해 보여주는 시각 프리뷰는 프레임 비율 유지를 위해 별도 크기 규칙을 사용할 수 있다.
- 고객이 직접 글꼴과 크기를 설정하는 공개 메뉴판·템플릿·대기번호판은 사이트 UI 계약과 분리한다.

## 설명 섹션 레이아웃

- 위 네 마케팅 페이지의 본문은 `.site-marketing-container`를 사용한다. 다른 일반 콘텐츠 폭은 공통 `.site-container`를 따른다. 바깥 최대 1,600px·안쪽 최대 1,520px과 공통 좌우 여백을 공유하며, 가이드 같은 일반 콘텐츠에 별도 최대 폭을 중첩해 좁히지 않는다. 폼·법률 등 승인된 읽기 영역만 예외다.
- 데스크톱: 설명과 이미지가 2열을 이루고 섹션마다 좌우 순서를 번갈아 배치한다.
- 열 사이 간격: 80px
- 모바일: 설명을 먼저 읽고 이미지를 이어서 보도록 1열로 배치한다.
- 공통 이미지 프레임 높이: 모바일 380px, 데스크톱 500px
- 검정 배경 스토리 섹션의 상하 여백: 모바일 80px, 데스크톱 96px
- 검정 배경의 첫 콘텐츠와 마지막 콘텐츠는 둥근 영역 경계에서 실제로 약 104~144px 떨어져 보이도록 겹침값을 포함해 보정한다.
- 검정 배경의 마지막 섹션은 모바일 144px, 데스크톱 208px의 하단 여백을 사용한다.

## 흰 배경 섹션 간격

- 같은 흰 배경에서 연속되는 섹션은 양쪽에 큰 여백을 중복 적용하지 않는다.
- 둥근 흰 배경의 첫 콘텐츠 상단 여백은 모바일·데스크톱 64px을 기준으로 한다.
- AI 기능과 매장 활용 장면 사이의 콘텐츠 간격은 데스크톱 기준 약 160px을 목표로 한다.
- 카드 목록 앞 간격은 모바일 56px, 데스크톱 80px 안팎으로 유지한다.

## 버튼·카드 시스템

현재 컴포넌트의 단일 기준은 `docs/site-design-system.md`와 `styles/ui-system.css` / `styles/site-design.css`다. 기존 공통 Button/Input/Tabs 등을 재사용한다.

- 기본 실행은 40px pill, 헤더는 44px, floating은 48px을 유지한다. 2026-10-25 사용자 승인 변형은 역할에 따라 48/56px CTA, 8px/6px 사각 버튼, 아이콘 선택 카드, 큰 outline 세그먼트와 밑줄 탭을 사용한다. 상세 기준은 `docs/site-design-system.md`의 최신 확장을 따른다.
- 주요 액션은 검정/흰색, 보조 CTA는 옅은 회색 무테, outline 액션은 흰색/회색 경계다. 위험·성공·정보·주의 의미 색상은 유지한다.
- hover는 색상만 바꾸고, 기본 키보드 포커스는 파란색/어두운 표면에서는 흰색이다. disabled는 기능별 안내와 비활성 동작을 유지한다.
- 일반 콘텐츠는 열린 섹션, 기능 카드만 16px 무테 표면, 판매 미리보기는 20px, 기존 히어로는 독립 32–48px 라운드다. 그림자는 떠 있는 레이어에 한정한다. 헤더는 공통 스크롤 배경 규칙을 따른다.
- 실제 메뉴판, 공개 메뉴·대기번호판, 축소 제품 화면의 콘텐츠는 독립된 디자인을 유지한다.

## 유지 원칙

- 새로운 랜딩 섹션은 먼저 공통 타이포그래피 컴포넌트를 사용한다.
- 섹션 제목은 구어체 종결어미를 피하고 짧고 단정한 문구로 작성한다.
- 본문은 한두 문장 이내로 유지하고 기능 설명만 남긴다.
- 노란 점과 함께 붙는 장식 소제목은 문구·여백까지 제거하며 새 화면에도 추가하지 않는다. 실제 제목과 안내 본문의 목록 기호·읽지 않은 알림 점은 유지한다. 불필요한 칩과 장식 페이지 인디케이터도 추가하지 않는다.
- 새 화면은 `site-button`, `site-card`, `site-nav-item` 또는 공통 컴포넌트를 먼저 사용하며 임의의 그림자·모서리·확대 호버를 추가하지 않는다.
