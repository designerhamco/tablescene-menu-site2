# 사이트 읽기 크기·폼·목록 검수 (2026-10-26)

## 기준과 범위

- 참고: [티오더](https://www.torder.com/), [카카오비즈니스 세미나](https://bizseminar.kakao.com/).
- 실제 DOM에서 티오더의 PC 히어로 60px / 모바일 32px, 모바일 설명 17px, 카카오의 모바일 콘텐츠 제목 16px / 섹션 제목 21px 등을 확인했다. 절대 크기를 복제하지 않고 아티메뉴의 본문/제목/제어 계층으로 정리했다.
- 메인·공개 서비스·템플릿 탐색/상세·고객센터·인증/법률·신청·마이페이지 및 운영/편집/관리 UI가 대상이다. 메뉴 렌더러와 축소 상품 시안은 제외했다.

## 자동 검증

- 전체 테스트 850개 통과, TypeScript 및 Production 빌드 통과.
- 수정 파일 ESLint 오류 0개. 기존 이미지 태그/미사용 import 경고는 별도 작업으로 유지했다.
- 의미 유틸리티의 색상/크기 병합, 기초 메뉴 토큰 불변, 작은 본문 유틸리티 재유입, 입력 크기와 checkbox 제외, 페이지 번호 최대 너비, 공개 인접 글의 필터/동률 정렬을 검사했다.
- 기존 공개 읽기 클라이언트로 이전/다음 공지 쿼리를 실행해 두 요청 HTTP 200을 확인했다. 스키마·권한·데이터 변경은 없다.

## 실제 브라우저 검수

- 실제 viewport 320×844 / 820×1180 / 1440×1000에서 공개 16개 경로(메인, 서비스 3개, 템플릿 목록/상세, 만들기, 고객센터, 가이드, 인증 4개, 약관/개인정보, 라이브러리)를 확인했다. 320px 신청 진입의 로그인 보호도 추가 확인했다.
- 가로 넘침 및 일반 실행 버튼/셀렉트 문구 잘림 없음. 모바일 390×844 고객센터·실제 공지 상세도 확인했다.
- 입력 예시에서 실제 40/44/48px, 검색 PC 64px, 입력값 16px/400, textarea 160px를 측정했다. Tab 2px 포커스·오류 경계·readonly/disabled 표면, 셀렉트 Escape와 포커스 복귀를 확인했다.
- 선택 카드는 hover에서도 흰 표면/진한 테두리를 유지한다. 헤더 pill, 본문 버튼 8px, 카드 12px를 측정했다.
- 320px 목록 페이지 5 선택 상태에서 페이지 번호 그룹 248px/페이지 가로 넘침 0px를 확인했다.
- 실제 공지 한 건의 상세에서는 이전/다음 없음이 비활성 DIV로 표시된다. 링크가 있는 예시는 라이브러리에서 확인한다.
- 모바일 REAL MATCHA를 기존 Production과 로컬에서 같은 viewport로 비교: 가게명 56px, 카테고리 26px, 메뉴명 16px, 설명 14px 및 서체/줄높이가 모두 같았다. `app/globals.css`, 메뉴 렌더러·공개 메뉴 컴포넌트는 수정하지 않았다.
- 로그인된 마이페이지와 신청 화면의 Production smoke 결과는 해당 PR의 배포 검수 기록에 남긴다. 실제 계정/메뉴/결제/문의 쓰기는 수행하지 않는다.
