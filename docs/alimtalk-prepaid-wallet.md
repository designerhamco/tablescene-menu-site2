# 조리완료 알림톡 선충전 잔액

2026-11-25 사용자 결정: 성공한 발송 1건당 **12원, 부가세 포함**, 충전 금액 **10,000 / 30,000 / 50,000원**. 같은 사장님 계정의 매장들이 원화 잔액을 공유한다. AI 크레딧, 고객 포인트, 서비스 구독료와 별개다. 월별 초기화나 자동 만료는 구현하지 않는다.

## 자금과 발송 흐름

1. 사장님만 `주문 설정 → 조리완료 알림톡`에서 잔액과 최근 50건을 조회한다. 직원은 이 계정 전체 정보를 받지 않는다.
2. 서버가 메뉴 소유권·이용 상태·요금 활성화를 확인하고, 무작위 결제 ID와 금액·소유자·메뉴·PG 상점·채널을 저장한다. 카드 결제창은 기존 PortOne V2 SDK를 사용한다. 자동 결제나 빌링키 청구는 하지 않는다.
3. 브라우저 완료/모바일 리다이렉트/웹훅은 모두 같은 결제 대사 함수로 들어간다. 웹훅 본문의 상태·금액·소유자를 신뢰하지 않는다. 저장된 결제 ID에 한해 PortOne API로 새로 조회한다. ID, 상점, 채널 **key**, 목적, 계정, 메뉴, 통화, 총액·실제 납부액·취소액이 모두 맞아야 충전한다. 이는 [PortOne 공식 웹훅 문서](https://developers.portone.io/opi/ko/integration/webhook/readme-v2)의 서버 재조회 전략이다.
4. 결제 ID와 충전 내역의 유일 제약, 결제·잔액 행 잠금으로 완료 요청이 반복돼도 한 번만 적립한다. 결제창을 닫아도 결과 확인과 웹훅으로 복구한다. 충전 중단 후에도 이미 결제된 건의 대사는 계속 허용한다.
5. 발송 시도 INSERT와 같은 트랜잭션의 트리거가 해당 채널 소유자의 잔액 행을 잠그고 12원을 확보한다. `전체 잔액 - 확인 중인 금액`보다 비싸면 시도 자체가 롤백되어 NHN 발송을 호출하지 않는다. 여러 매장이 동시에 보내도 같은 행에서 직렬화된다.
6. 최종 성공은 확보액만 차감하고, 확정 실패는 확보액을 해제한다. 결과를 모르는 발송은 계속 확보 상태로 둔다. 과거 발송 이력은 소급 과금하지 않는다. 가격이 바뀌어도 이미 확보한 금액은 그대로 정산한다. 픽업·서빙 상태는 변경하지 않는다.
7. 취소된 충전 결제가 발견되면 재적립하지 않고 검토 대상으로 남긴다. 이미 적립했다면 지갑을 동결하여 사용을 막는다. 실제 환불을 자동 실행하지 않는다.

## 데이터 경계

`alimtalk_wallets`, `alimtalk_topups`, `alimtalk_wallet_holds`, `alimtalk_wallet_entries`는 RLS를 켜고 anon/authenticated 접근을 차단한다. 서버의 소유권 검증 후 service_role만 접근한다. 사용 내역은 서버에서 최소 DTO로 변환하고, 이전한 매장의 현재 이름·주문 정보는 반환하지 않는다. 장부는 service_role에도 UPDATE/DELETE 권한을 주지 않는다.

완료된 주문을 사용자가 이력과 함께 삭제하더라도 장부와 잔액은 보존하고 주문 링크만 해제한다. 미정산 발송이 있으면 삭제를 막는다. 금융 잔액/장부가 있는 계정의 영구 삭제는 자동 전파하지 않는다. 계정 영구 삭제·금융 기록 보존 처리에서는 이 별도 지갑도 함께 정리해야 한다.

## 이번 배포와 운영 개시 경계

마이그레이션 `20261125072555`는 단가를 12원으로 기록하되 **topup_enabled=false / metering_enabled=false**로 시작한다. 기존 채널의 `sending_enabled=false` CHECK와 전역 `ORDER_ALIMTALK_ENABLED=false`도 유지한다. 이번 변경만으로 카드 결제나 고객 발송이 열리지 않는다.

운영 개시 전에는 미사용 충전금 환불·만료 정책 및 요금 동의 화면을 정하고, 실제 PG 상점의 충전 상품 취급 가능 여부와 결제/취소 대사를 검수해야 한다. 이는 기존 AI 크레딧의 환불 제한 문구를 자동 재사용하지 않는다. NHN 공급자 과금·잔액/한도는 이 점주 장부와 독립적이며 이 기능이 NHN 계정에 자동 충전하지 않는다.

운영 개시 승인 없이 안전 CHECK를 제거하거나 요금 스위치를 켜지 않는다. DB 적용 시 기존 마이그레이션 이력 차이 때문에 과거 파일을 다시 실행하지 말고, 현재 원격 이력을 맞춘 격리 release 디렉터리에서 새 파일만 dry-run으로 확인한다. 중단 시 게이트만 OFF로 돌리고 충전·발송 장부를 삭제하지 않는다.
