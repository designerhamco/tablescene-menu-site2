# 아티메뉴 조리완료 알림톡 선충전·환불 운영 기준

2026-11-25 사용자 결정: 성공한 발송 1건당 **12원, 부가세 포함**, 충전 금액 **10,000 / 30,000 / 50,000원**. 이 로그인 계정에서 관리하는 모든 메뉴판이 원화 잔액을 공유한다. AI 크레딧, 고객 포인트, 서비스 구독료와 별개다. 미사용 충전금은 **별도 소멸 없이 유지**, **미사용 유상 잔액 전체를 수수료 없이 원래 결제수단으로 환불 신청**할 수 있다. 결과 확인 중인 발송은 먼저 정산한다. 이 만료·환불 기준에 맞는 PG 계약 범위 확인은 별도다.

제품 조건 원본은 `lib/alimtalk-billing-policy.ts`와 `/policies/alimtalk`이다. 충전 동의창은 같은 원본을 사용한다. 서버는 최신 버전·동의한 단가를 검증하고 결제 시도에 동의 시각을 저장한다. 기존 AI 크레딧의 환불 제한을 이 상품에 적용하지 않는다.

## 자금과 발송 흐름

1. 사장님만 `주문 설정 → 조리완료 알림톡`에서 잔액과 최근 50건을 조회한다. 직원은 이 계정 전체 정보를 받지 않는다.
   `마이페이지 → 구독/결제 내역 → 알림톡 충전/사용내역`은 로그인한 본인 계정의 잔액·환불만 관리한다. `/mypage/alimtalk`의 이전 주소는 이 탭으로 연결하며 별도 사이드 메뉴는 없다. 운영할 메뉴판이 전부 없어져도 원 결제 확인과 미사용금 환불 신청은 가능하다. 직원으로 접속해도 고용주 계정의 잔액을 읽는 경로가 아니다. 직원 전용 계정의 기존 구독·AI 결제 탭 제한은 유지한다.
   주문 설정의 `조리완료 알림톡` 탭에서는 채널·안내 메시지 설정 바로 아래의 기존 잔액·충전·이용 내역 영역을 유지한다. 프로필 메뉴나 운영 대시보드에 별도 잔액 요약은 추가하지 않는다. 두 화면은 같은 계정의 지갑 원본을 조회한다.
2. 서버가 메뉴 소유권·이용 상태·요금 활성화를 확인하고, 무작위 결제 ID와 금액·소유자·메뉴·PG 상점·채널을 저장한다. 카드 결제창은 기존 PortOne V2 SDK를 사용한다. 자동 결제나 빌링키 청구는 하지 않는다.
3. 브라우저 완료/모바일 리다이렉트/웹훅은 모두 같은 결제 대사 함수로 들어간다. 웹훅 본문의 상태·금액·소유자를 신뢰하지 않는다. 저장된 결제 ID에 한해 PortOne API로 새로 조회한다. ID, 상점, 채널 **key**, 목적, 계정, 메뉴, 통화, 총액·실제 납부액·취소액이 모두 맞아야 충전한다. 이는 [PortOne 공식 웹훅 문서](https://developers.portone.io/opi/ko/integration/webhook/readme-v2)의 서버 재조회 전략이다.
4. 결제 ID와 충전 내역의 유일 제약, 결제·잔액 행 잠금으로 완료 요청이 반복돼도 한 번만 적립한다. 결제창을 닫아도 결과 확인과 웹훅으로 복구한다. 충전 중단 후에도 이미 결제된 건의 대사는 계속 허용한다.
5. 발송 시도 INSERT와 같은 트랜잭션의 트리거가 해당 채널 소유자의 잔액 행을 잠그고 12원을 확보한다. `전체 잔액 - 확인 중인 금액`보다 비싸면 시도 자체가 롤백되어 NHN 발송을 호출하지 않는다. 여러 매장이 동시에 보내도 같은 행에서 직렬화된다.
6. 최종 성공은 확보액만 차감하고, 확정 실패는 확보액을 해제한다. 결과를 모르는 발송은 계속 확보 상태로 둔다. 과거 발송 이력은 소급 과금하지 않는다. 가격이 바뀌어도 이미 확보한 금액은 그대로 정산한다. 픽업·서빙 상태는 변경하지 않는다.
7. 사장님이 환불을 신청하면 미사용 잔액 전체를 보류하고 원 결제별 환불 배분을 고정한다. 사용료는 먼저 충전한 금액부터 소진하는 기준이며 남은 금액은 최근 결제부터 환불한다. 신청 ID와 계정당 한 건의 진행 중 신청 제약으로 중복 보류를 막는다. 처리 시작 전의 신청 취소만 보류를 해제한다.
8. `/admin/alimtalk-refunds`에서 관리자가 신청을 열고 ‘환불 처리 시작’으로 담당자를 기록한다. 이후 원 결제 ID와 지정 금액을 대조하여 **포트원에서 원래 결제수단을 취소**한다. 아티메뉴의 해당 버튼은 카드 취소를 실행하지 않는다. 실제 취소의 외부 검수·실행은 아직 별도 단계다.
9. 웹훅 또는 ‘이 페이지 결제 결과 확인’은 서버에서 PortOne을 새로 조회한다. 관리자가 처리 중인 배분과 맞는 누적 취소액만 잔액·보류액에서 차감하고 환불 장부를 추가한다. 부분 취소·여러 원 결제·반복 통보·늦게 도착한 통보는 누적 금액으로 정산한다. 내부 상태만으로 환불 완료를 만들지 않는다.
10. 신청과 맞지 않는 취소·상태/금액 모순은 재적립하지 않고 수동 검토 대상으로 남기며, 이미 적립된 지갑은 사용을 중지한다. 검토 중인 건은 운영자가 외부 이력과 대조하기 전 자동으로 보류를 해제하거나 재처리하지 않는다.

## 데이터 경계

`alimtalk_wallets`, `alimtalk_topups`, `alimtalk_wallet_holds`, `alimtalk_wallet_entries`는 RLS를 켜고 anon/authenticated 접근을 차단한다. 서버의 소유권 검증 후 service_role만 접근한다. 사용 내역은 서버에서 최소 DTO로 변환하고, 이전한 매장의 현재 이름·주문 정보는 반환하지 않는다. 장부는 service_role에도 UPDATE/DELETE 권한을 주지 않는다.

완료된 주문을 사용자가 이력과 함께 삭제하더라도 장부와 잔액은 보존하고 주문 링크만 해제한다. 미정산 발송이 있으면 삭제를 막는다. 금융 잔액/장부가 있는 계정의 영구 삭제는 자동 전파하지 않는다. 계정 영구 삭제·금융 기록 보존 처리에서는 이 별도 지갑도 함께 정리해야 한다.

## 이번 배포와 운영 개시 경계

마이그레이션 `20261125072555`는 단가를 12원으로 기록하되 **topup_enabled=false / metering_enabled=false**로 시작한다. `20261125080151`은 동의 기록과 환불 장부 및 PG 계약 검토 게이트를 더한다. 기존 채널의 `sending_enabled=false` CHECK와 전역 `ORDER_ALIMTALK_ENABLED=false`도 유지한다. PG 계약 확인 시각·승인된 상점/채널 없이 충전 게이트만 켜는 것은 DB 제약으로 거부한다. 설정이 승인받은 상점/채널과 다르면 새 충전을 열지 않으며, 결제사 조회의 채널 환경이 **LIVE가 아니면 운영 잔액을 적립하지 않는다**. 이 변경들만으로 카드 결제나 고객 발송이 열리지 않는다.

2026-11-25 계정 실조회: 사용자가 직접 로그인한 포트원 대표상점의 실연동 채널 0개, 테스트 채널 4개, 전자결제 신청 내역 없음. 로컬 설정은 해당 상점의 NHN KCP 일반/빌링 테스트 채널과 일치한다. 사용자 답변으로 별도 PG 계약도 없음을 확인했다. 운영 PG 계약·실연동 채널 구축이 완료됐다고 설명하지 않는다. 이 조회는 신규 가입 신청이나 업체 문의 발송이 아니다.

환불·만료 기준은 사용자 승인으로 정해졌으며 동의·환불 신청·관리자 확인 화면을 구현했다. 운영 개시 전에는 **현재 PG/MID 계약의 이 충전 상품·사용기간·부분 취소 허용 여부 확인**과 **실제 결제/취소 대사 검수**가 남아 있다. 문의 준비안은 [아티메뉴 PG 계약 확인 요청안](alimtalk-pg-review-request.md)이다. NHN 공급자 과금·잔액/한도는 이 점주 장부와 독립적이며 이 기능이 NHN 계정에 자동 충전하지 않는다.

운영 개시 승인 없이 안전 CHECK를 제거하거나 요금 스위치를 켜지 않는다. DB 적용 시 기존 마이그레이션 이력 차이 때문에 과거 파일을 다시 실행하지 말고, 현재 원격 이력을 맞춘 격리 release 디렉터리에서 새 파일만 dry-run으로 확인한다. 중단 시 게이트만 OFF로 돌리고 충전·발송 장부를 삭제하지 않는다.
