# 사이트 탭 역할과 포함 관계 — 최종 기준

2026-10-28 사용자 합의와 최상위 둥근 버튼 요청을 반영한다. 과거 primary/secondary/filter/embedded 고정 순서와 고객센터 예외를 대체한다. 역할을 먼저 고르고 실제 포함 관계로 위계를 구성한다. 영역형은 특정 단계에 고정하지 않는다.

## 역할 선택

| 역할 | 공통 API | 표현 | 사용처 |
| --- | --- | --- | --- |
| 주요 화면 전환 | Tabs/NavigationTabs purpose="page" | 서로 분리된 둥근 버튼. 검정 선택 면/흰 글자, 흰 비선택 면/얇은 회색 선 | 서비스별 목록, 기준·토큰/컴포넌트 라이브러리, 편집 설정 |
| 독립 콘텐츠 영역 전환 | Tabs/NavigationTabs purpose="section" | 화이트 콘텐츠에 연결된 상단 영역 탭 | 디자인/기본 템플릿, 결제/AI 내역, 미리보기 기능/디자인, 번역 대상, 요금 상품 유형 |
| 목록 분류 | CategoryFilter, 패널을 나누면 Tabs purpose="category" | 밑줄형. 별도 콘텐츠 박스 없음 | 고객센터 주제, 새 메뉴판 템플릿 주제, 전체/읽지 않은 알림 |
| 목록 조건·본문 이동 | ChoiceTile, site-filter, 링크 | 작은 필터·아이콘 버튼 | 영역 내부 업종·구성, 본문 바로가기, 홈의 짧은 FAQ·업종 조건 |
| 상태·보기 값 변경 | Tabs/NavigationTabs purpose="state" | 하나의 회색 레일 안에 묶인 둥근 세그먼트. 흰 선택 면/검정 선택 테두리 | 이용 중/보관 중/종료됨, 언어, 운영할 메뉴판, 이미지/목록 보기 |

최상위 버튼은 각각 떨어져 있고 검정 선택 면을 사용한다. 상태 세그먼트는 회색 레일 안에 묶이고 흰 선택 면을 사용한다. 둘 다 둥글지만 구조와 선택 색으로 구분한다.

사용자 최종 조정: 알림의 전체/읽지 않음은 알림 목록 분류로 보고 기존 밑줄형을 사용한다. 헤더 알림 레이어·알림 페이지·라이브러리 예시 모두 NotificationPanel을 공유하며 회색 세그먼트 레일을 넣지 않는다. 읽음 처리와 건수·목록 동작은 유지한다.

## 대표 포함 관계

- 디자인 템플릿: 주요 화면(베이직/다이닝/디스플레이) → 영역(디자인/기본 템플릿) → 영역 안 업종·구성 필터 → 썸네일 결과.
- 고객센터: FAQ 밑줄 주제(전체/이용 환경/메뉴판 생성·관리 등) → 질문 목록 → 최신 공지3건·전체보기. FAQ/공지사항 전환 탭은 사용하지 않는다. 전체보기는 /faq/notices의 검색·주제·전체 공지 목록으로 이동한다.
- 일반 위계 예시: 주요 화면 → 밑줄 분류 → 필요한 경우에만 작은 하위 필터. 현재 고객센터에는 추가 하위 필터를 만들지 않는다.

영역형은 탭과 그 아래 썸네일·설정 같은 콘텐츠를 하나의 영역으로 묶어 전환할 때 쓴다. 박스 안에 가두기 위한 테두리가 필수인 것은 아니다. 콘텐츠는 무테 화이트를 유지한다. 고객센터는 별도 독립 영역이 필요하지 않아 영역 탭을 추가하지 않는다.

## 판단 순서

1. 아래 주요 콘텐츠 전체를 바꾸면 page.
2. 그 안에서 독립 콘텐츠 묶음을 전환하고 영역에 연결할 필요가 있으면 section.
3. 별도 영역 없이 목록 주제를 나누면 category.
4. 현재 목록의 업종·구성 같은 보조 조건은 작은 필터, 본문 위치 이동은 링크.
5. 이용 상태·언어·보기 방식 같은 현재 작업의 값만 바꾸면 state.

URL 변경 여부는 모양의 기준이 아니다. 상태를 query string에 보존해도 state이며, URL을 유지하며 주요 화면을 바꿔도 page다. URL 이동은 NavigationTabs의 링크 동작을 유지하고 purpose를 명시한다. 사이드바·헤더·마이페이지 메뉴 레일은 기존 사이트 내비게이션이다.

CategoryFilter는 기존 결과 목록을 필터링하므로 버튼/aria-pressed를 사용한다. 가짜 탭 패널을 만들지 않고 Tab·Enter·Space 동작을 유지한다. 실제 패널 전환은 Radix의 선택·ARIA·방향키·Home/End·비활성 건너뛰기를 사용한다.

## 형태와 크기

- lg 48px/16px: 공개 페이지 주요 전환. md 44px/15px: 마이페이지·편집기 일반 전환. sm 40px/14px: 영역 내부·밀집 도구.
- 영역형 md는 독립 콘텐츠 전환이 하위 필터보다 작아 보이지 않도록 44px/16px를 사용한다. 템플릿 목록은 주요 화면48px/16px → 영역44px/16px → compact 업종·구성 필터40px/14px 순서다. 기존 영역 탭의 형태와 선택·방향키 동작은 유지한다.
- 선택 글자600, 비선택500. 공통 의미 타이포와 색상 토큰을 사용한다.
- PC·태블릿 768px 이상 주요 화면 버튼은 내용 폭+좌우 각각24px 여백이며 전체 폭으로 늘리지 않는다. 모바일은 기존 가로 폭·영역 내 스크롤을 유지한다.
- 영역 탭은 수직 옆면, 위쪽 두 모서리8px/아래0px, 일반 최소 너비144px다. 사선·산 모양·pill 토큰을 사용하지 않는다.
- 선택 영역 탭은 화이트, 비선택은 옅은 회색 무테. 콘텐츠도 화이트이며 좌우·하단 둘레 테두리가 없다. 선택 탭 윤곽선과 아래1px 기준선만 유지한다.
- 회색·유색 면에 장식용 테두리를 추가하지 않는다. 작은 필터는 문구·아이콘 기준 폭으로 상위 전환보다 강하게 만들지 않는다.

## 새 페이지 구현 규칙

- 제품 Tabs는 purpose="page|section|category|state"를 반드시 선언한다. 이전 hierarchy API와 검정 레일 호환 segmented 변형은 폐기한다.
- 저수준 variant는 라이브러리 상태 비교표에서만 사용한다. TabsList나 페이지 CSS로 역할의 모양·색·높이·굵기·라운드를 덮어쓰지 않는다.
- 공통 Tabs, NavigationTabs, CategoryFilter, ChoiceTile을 재사용한다. 필요한 단계만 사용하며 없는 분류를 새로 추가하지 않는다.
- 고객 메뉴판의 .menu-typography, .aube-table-root, [data-template-artwork], 메뉴 렌더러와 공개 주문/호출·수령 제품은 이 계약과 분리한다.
