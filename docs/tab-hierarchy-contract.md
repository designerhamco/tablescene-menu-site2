# 사이트 탭 역할과 포함 관계 — 최종 기준

2026-10-31 사용자 최종 요청에 따라 최상위 탭의 밑줄을 글자 가까이 올리고, 영역 탭을 연결형 사각 버튼으로 변경한다. 최상위 텍스트와 짧은 밑줄 정책은 유지한다. 이전 최상위 둥근 버튼 표현을 대체한다. 과거 primary/secondary/filter/embedded 고정 순서와 고객센터 예외를 대체한다. 역할을 먼저 고르고 실제 포함 관계로 위계를 구성한다. 영역형은 특정 단계에 고정하지 않는다.

## 역할 선택

| 역할 | 공통 API | 표현 | 사용처 |
| --- | --- | --- | --- |
| 주요 화면 전환 | Tabs/NavigationTabs purpose="page" | 배경·테두리 없는 텍스트. 선택은 검정 글자와 문구 너비의 3px 밑줄, 비선택은 읽기 쉬운 회색 | 서비스별 목록, 기준·토큰/컴포넌트 라이브러리, 편집 설정 |
| 독립 콘텐츠 영역 전환 | Tabs/NavigationTabs purpose="section" | 연결형 사각 버튼. 검정 선택 면·흰 글자, 흰 비선택 면·회색 글자 | 디자인/기본 템플릿, 결제/AI 내역, 미리보기 기능/디자인, 번역 대상, 요금 상품 유형 |
| 목록 분류 | CategoryFilter, 패널을 나누면 Tabs purpose="category" | 밑줄형. 별도 콘텐츠 박스 없음 | 고객센터 주제, 새 메뉴판 템플릿 주제, 전체/읽지 않은 알림 |
| 목록 조건·본문 이동 | ChoiceTile, site-filter, 링크 | 작은 필터·아이콘 버튼 | 영역 내부 업종·구성, 본문 바로가기, 홈의 짧은 FAQ·업종 조건 |
| 상태·보기 값 변경 | Tabs/NavigationTabs purpose="state" | 하나의 회색 레일 안에 묶인 둥근 세그먼트. 흰 선택 면/검정 선택 테두리 | 이용 중/보관 중/종료됨, 언어, 운영할 메뉴판, 이미지/목록 보기 |

최상위 탭은 문구 너비의 밑줄만 사용하며 전체 폭 기준선이나 버튼 면을 넣지 않는다. 상태 세그먼트는 회색 레일 안에 묶이고 흰 선택 면을 유지한다. 영역 탭은 연결된 사각 버튼을 사용하며 목록 주제·필터의 기존 형태는 유지한다.

사용자 최종 조정: 알림의 전체/읽지 않음은 알림 목록 분류로 보고 기존 밑줄형을 사용한다. 헤더 알림 레이어·알림 페이지·라이브러리 예시 모두 NotificationPanel을 공유하며 회색 세그먼트 레일을 넣지 않는다. 읽음 처리와 건수·목록 동작은 유지한다.

## 대표 포함 관계

- 디자인 템플릿: 주요 화면(베이직/다이닝/디스플레이) → 영역(디자인/기본 템플릿) → 영역 안 업종·구성 필터 → 썸네일 결과.
- 고객센터: 헤더 고객센터 하위 메뉴에서 FAQ·공지·이용가이드의 독립 페이지로 이동한다. FAQ는 주제별 질문5개, 공지는 별도 목록10개씩 제공한다.
- 일반 위계 예시: 주요 화면 → 밑줄 분류 → 필요한 경우에만 작은 하위 필터. 현재 고객센터에는 추가 하위 필터를 만들지 않는다.

영역형은 탭과 그 아래 썸네일·설정 같은 콘텐츠를 하나의 영역으로 묶어 전환할 때 쓴다. 박스 안에 가두기 위한 테두리가 필수인 것은 아니다. 콘텐츠는 무테 표면을 사용한다. 템플릿 목록은 업종·구성 필터부터 페이지네이션까지 --ui-surface-muted의 밝은 회색 면으로 묶는다. 고객센터는 별도 독립 영역이 필요하지 않아 영역 탭을 추가하지 않는다.

## 판단 순서

1. 아래 주요 콘텐츠 전체를 바꾸면 page.
2. 그 안에서 독립 콘텐츠 묶음을 전환하고 영역에 연결할 필요가 있으면 section.
3. 별도 영역 없이 목록 주제를 나누면 category.
4. 현재 목록의 업종·구성 같은 보조 조건은 작은 필터, 본문 위치 이동은 링크.
5. 이용 상태·언어·보기 방식 같은 현재 작업의 값만 바꾸면 state.

URL 변경 여부는 모양의 기준이 아니다. 상태를 query string에 보존해도 state이며, URL을 유지하며 주요 화면을 바꿔도 page다. URL 이동은 NavigationTabs의 링크 동작을 유지하고 purpose를 명시한다. 사이드바·헤더·마이페이지 메뉴 레일은 기존 사이트 내비게이션이다.

CategoryFilter는 기존 결과 목록을 필터링하므로 버튼/aria-pressed를 사용한다. 가짜 탭 패널을 만들지 않고 Tab·Enter·Space 동작을 유지한다. 실제 패널 전환은 Radix의 선택·ARIA·방향키·Home/End·비활성 건너뛰기를 사용한다.

## 형태와 크기

- 공통 크기 기준은 lg 48px/16px, md 44px/15px, sm 40px/14px다. 주요 화면(page)은 위계를 분명히 하기 위해 lg 48px/18px, md 44px/16px, sm 40px/14px를 사용한다.
- 영역형 md는 독립 콘텐츠 전환이 하위 필터보다 작아 보이지 않도록 52px/16px를 사용한다. 템플릿 목록은 주요 화면48px/18px → 영역52px/16px → compact 업종·구성 필터40px/14px 순서다. 선택·방향키 동작은 유지한다.
- 주요 화면은 선택600·비선택500이며 비선택은 중성 회색 토큰(--ui-tab-inactive-text, #969696)을 사용한다. 다른 역할의 굵기·색상은 유지한다. 공통 의미 타이포와 색상 토큰을 사용한다.
- 주요 화면 탭은 모든 기기에서 문구 너비를 사용하며 가로 패딩과 버튼 면을 넣지 않는다. lg 간격24px, md20px, sm16px이며 컨트롤 높이48/44/40px와 가로 스크롤·키보드 포커스를 유지한다. 3px 선택선은 클릭 영역 하단에서 4px 위에 놓아 글자와의 간격을 줄인다.
- 영역 탭은 연결형 사각 버튼이며 첫·마지막 버튼의 바깥 모서리만8px다. 일반 md는 높이52px·상하12px·좌우24px·최소 너비160px를 유지한다. equal 분배는 최대36rem 안에서 같은 폭을 나누며 모바일에서는 최소 너비를 해제해 두 버튼이 한 줄에 들어간다. 사선·산 모양·pill 토큰은 사용하지 않는다.
- 선택 영역 탭은 --ui-text 검정 바탕·--ui-surface 흰 글자, 비선택은 흰 바탕·보조 글자색이다. 흰 버튼 경계만 --ui-border 1px로 구분하며 인접 경계는 겹쳐 한 줄로 보인다. 콘텐츠까지 이어지는 긴 기준선과 콘텐츠 둘레 테두리는 사용하지 않는다.
- 회색·유색 면에 장식용 테두리를 추가하지 않는다. 작은 필터는 문구·아이콘 기준 폭으로 상위 전환보다 강하게 만들지 않는다.

## 새 페이지 구현 규칙

- 제품 Tabs는 purpose="page|section|category|state"를 반드시 선언한다. 이전 hierarchy API와 검정 레일 호환 segmented 변형은 폐기한다.
- 저수준 variant는 라이브러리 상태 비교표에서만 사용한다. TabsList나 페이지 CSS로 역할의 모양·색·높이·굵기·라운드를 덮어쓰지 않는다.
- 공통 Tabs, NavigationTabs, CategoryFilter, ChoiceTile을 재사용한다. 필요한 단계만 사용하며 없는 분류를 새로 추가하지 않는다.
- 고객 메뉴판의 .menu-typography, .aube-table-root, [data-template-artwork], 메뉴 렌더러와 공개 주문/호출·수령 제품은 이 계약과 분리한다.

사용처별 판단은 [역할 점검표](tab-role-audit.md), 검증은 [탭 QA](area-tabs-qa.md)를 따른다.


일반 페이지 제목과 영역 탭 여백, 고객지원 경로의 현재 기준은 [페이지 간격 계약](site-page-layout-contract.md)을 따른다.

## 2026-10-31 연결형 영역 탭 검수

- 공통 page 선택선은48px 클릭 영역을 유지하고 하단에서4px 위로 배치했다. 템플릿 section은 equal 분배와 공통 흑백 선택 색을 사용한다.
- 로컬 실제1280×720 PC, 820×1000 태블릿, 320×780 모바일에서 가로 넘침0을 확인했다. 모바일 두 영역 버튼은 각각140.5px×52px로 한 줄에 표시됐다.
- End로 기본 템플릿 전환, 베이직·다이닝의 종류 전환, 목록2페이지와1페이지 복귀, 회색 표면 내부의 페이지네이션 포함을 확인했다.
- 공통 UI 계약92건, 자동 디자인 시스템 검사, 변경 TSX ESLint, TypeScript와 diff 공백 검사를 통과했다. 고객 메뉴판 렌더러는 변경하지 않았다.
