# 사이트 탭 역할과 포함 관계 — 최종 기준

화면 전환의 기본은 밑줄이다. 선택한 대상이 아래 작업 패널과 한 영역을 이룰 때는 콘텐츠 연결형을 쓴다. 같은 목록의 조회 범위는 상태 필터로 제공한다.

## 역할 선택

| 역할 | 공통 API | 표현 | 사용처 |
| --- | --- | --- | --- |
| 주요 화면 전환 | Tabs/NavigationTabs purpose="page" | 배경·테두리 없는 텍스트. 선택은 검정 글자와 문구 너비의 3px 밑줄 | 주문 관리, 결제·AI·알림톡 내역, 편집 설정, 요금 상품 |
| 작업 영역 전환 | Tabs purpose="section" appearance="document" | 선택 탭의 흰 바탕이 아래 패널과 이어지고 그 자리의 기준선이 열린다 | 테이블·키오스크 관리의 룸 |
| 목록 분류 | CategoryFilter, 패널을 나누면 Tabs purpose="category" | 밑줄형. 별도 콘텐츠 박스 없음 | 고객센터 주제, 새 메뉴판 템플릿 주제, 전체/읽지 않은 알림 |
| 목록 조건·본문 이동 | ChoiceTile, site-filter, 링크 | 작은 필터·아이콘 버튼 | 영역 내부 업종·구성, 본문 바로가기, 홈의 짧은 FAQ·업종 조건 |
| 상태·보기 필터 | NavigationTabs / Tabs purpose="state" | 하나의 회색 레일 안에서 현재 값만 검정 면과 흰 글자로 표시 | 내 메뉴판의 이용 상태, 주문·주방의 보기 방식 |

화면 탭과 목록 주제는 3px 밑줄을 공유하며 글자 크기와 간격으로 위계를 표현한다. 상태 필터 건수는 보조 글자 크기로 표시한다. 콘텐츠 연결형의 룸 추가는 탭 목록 왼쪽에 고정된 별도 아이콘 버튼이다. 룸 이름 탭만 가로로 스크롤한다.

디자인 템플릿 목록·상세·미리보기는 기존 규격을 적용한다. 검정 선택 면의 영역형과 주문·호출의 룸 선택은 각 화면의 계약을 따른다. 고객 메뉴판의 탭·선택기는 고객 렌더러가 관리한다.

사용자 최종 조정: 알림의 전체/읽지 않음은 알림 목록 분류로 보고 기존 밑줄형을 사용한다. 헤더 알림 레이어·알림 페이지·라이브러리 예시 모두 NotificationPanel을 공유하며 회색 세그먼트 레일을 넣지 않는다. 읽음 처리와 건수·목록 동작은 유지한다.

## 대표 포함 관계

- 디자인 템플릿: 가운데 정렬한 디자인/기본 템플릿 영역 탭 → 필터 영역 → 썸네일 결과. 필터 영역 첫 줄은 메뉴판 유형 전용이다. 베이직·다이닝·디스플레이를 공통 대형 세그먼트 ToggleGroup으로 고르고, 유형 링크가 없으면 베이직에서 시작한다. 결과 개수는 필터 밖의 카드 목록 왼쪽 위에 표시한다.
- 고객센터: 헤더 고객센터 하위 메뉴에서 FAQ·공지·이용가이드의 독립 페이지로 이동한다. FAQ는 주제별 질문5개, 공지는 별도 목록10개씩 제공한다.
- 일반 위계 예시: 주요 화면 → 밑줄 분류 → 필요한 경우에만 작은 하위 필터. 현재 고객센터에는 추가 하위 필터를 만들지 않는다.

테이블·키오스크 관리의 작업 패널은 룸 탭의 기준선을 상단 경계로 공유한다. 탭의 선택 상태와 작업 패널은 흰 바탕으로 이어지며 패널 내부의 등록·편집·저장 순서는 기존 계약을 따른다.

## 판단 순서

1. 보여 주는 화면이나 독립 콘텐츠를 바꾸면 밑줄형 page.
2. 선택한 대상과 아래 작업 패널이 한 영역을 이루면 콘텐츠 연결형 document.
3. 별도 영역 없이 목록 주제를 나누면 category.
4. 현재 목록의 업종·구성 같은 보조 조건은 작은 필터, 본문 위치 이동은 링크.
5. 동일 목록의 이용 상태 범위를 바꾸면 상태 필터.

URL 변경 여부는 모양의 기준이 아니다. 상태를 query string에 보존해도 state이며, URL을 유지하며 주요 화면을 바꿔도 page다. URL 이동은 NavigationTabs의 링크 동작을 유지하고 purpose를 명시한다. 사이드바·헤더·마이페이지 메뉴 레일은 기존 사이트 내비게이션이다.

CategoryFilter는 기존 결과 목록을 필터링하므로 버튼/aria-pressed를 사용한다. 가짜 탭 패널을 만들지 않고 Tab·Enter·Space 동작을 유지한다. 실제 패널 전환은 Radix의 선택·ARIA·방향키·Home/End·비활성 건너뛰기를 사용한다.

## 형태와 크기 — 2026-11-25 PC 위계 수정

- 내 메뉴판의 총 건수는 각 상태 필터에 표시하고, 검색어가 있을 때 목록에 검색 결과 건수를 표시한다.
- 마이페이지 메뉴판 상태는 `purpose="state" size="lg"`로 표시한다. PC는 탭40px·레일48px·글자16px, 모바일·태블릿은 기존 탭36px·레일44px·글자14px이다.
- PC 1024px 이상에서 `purpose="page"`의 md/lg는 공개·관리 화면 모두18px·최소44px이다. 독립 영역·목록 분류·상태 md/lg는16px이며, 영역·분류는최소44px·상태 레일은44/48px이다. sm 보조 도구는14px, 작은 page 탐색은16px이며 룸 이름은 전용16px을 유지한다. 알림 분류는 팝업·이력에서 기존14px을 유지한다. 템플릿 목록의 종류 영역 탭은16px, 보조 업종·구성 필터는14px이다. 선택 상태와 방향키 동작은 각 역할을 따른다.
- 주요 화면은 선택600·비선택500이며 비선택은 중성 회색 토큰(--ui-tab-inactive-text, #969696)을 사용한다. 다른 역할의 굵기·색상은 유지한다. 공통 의미 타이포와 색상 토큰을 사용한다.
- 주요 화면 탭은 모든 기기에서 문구 너비를 사용하며 가로 패딩과 버튼 면을 넣지 않는다. lg 간격20px, md16px, sm12px이며 최소 컨트롤 높이40/36/32px와 가로 스크롤·키보드 포커스를 유지한다. 3px 선택선은 클릭 영역 하단에서 4px 위에 놓아 글자와의 간격을 줄인다.
- 콘텐츠 연결형은 sm/md/lg 최소 40/44/48px와 상단 8px 모서리를 사용한다. 룸 이름은 16px, 왼쪽 추가는 탭 높이와 같은 크기의 아이콘 버튼이다.
- 디자인 템플릿의 기존 영역형은 연결된 검정 선택 면, 바깥 모서리 8px, 흰 비선택 면과 1px 경계를 사용한다. 크기와 equal 분배는 기존 카탈로그·미리보기 계약을 따른다.
- 회색·유색 면에 장식용 테두리를 추가하지 않는다. 작은 필터는 문구·아이콘 기준 폭으로 상위 전환보다 강하게 만들지 않는다.

## 새 페이지 구현 규칙

- 공통 컨트롤에 purpose와 크기를 명시한다. 새 화면 탐색은 page, 연결된 작업 패널은 section + document를 사용한다. 목록 분류와 상태 필터는 의미에 맞는 링크나 버튼 동작을 사용한다.
- 저수준 variant는 라이브러리 상태 비교표에서만 사용한다. TabsList나 페이지 CSS로 역할의 모양·색·높이·굵기·라운드를 덮어쓰지 않는다.
- 공통 Tabs, NavigationTabs, CategoryFilter, ChoiceTile을 재사용한다. 필요한 단계만 사용하며 없는 분류를 새로 추가하지 않는다.
- 고객 메뉴판의 .menu-typography, .aube-table-root, [data-template-artwork], 메뉴 렌더러와 공개 주문/호출·수령 제품은 이 계약과 분리한다.

사용처별 판단은 [역할 점검표](tab-role-audit.md), 검증은 [탭 QA](area-tabs-qa.md)를 따른다.


일반 페이지 제목과 영역 탭 여백, 고객지원 경로의 현재 기준은 [페이지 간격 계약](site-page-layout-contract.md)을 따른다.

## 2026-10-31 연결형 영역 탭 검수

- 공통 page 선택선은48px 클릭 영역을 유지하고 하단에서4px 위로 배치했다. 템플릿 section은 equal 분배와 공통 흑백 선택 색을 사용한다.
- 로컬 실제1280×720 PC, 820×1000 태블릿, 320×780 모바일에서 가로 넘침0을 확인했다. 모바일 두 영역 버튼은 각각140.5px×52px로 한 줄에 표시됐다.
- End로 기본 템플릿 전환, 베이직·다이닝의 종류 전환, 목록2페이지와1페이지 복귀, 회색 표면 내부의 페이지네이션 포함을 확인했다.
- 공통 UI 계약92건, 자동 디자인 시스템 검사, 변경 TSX ESLint, TypeScript와 diff 공백 검사를 통과했다. 고객 메뉴판 렌더러는 변경하지 않았다.

## 카탈로그 안내와 카드 동작 (2026-11-01)

- 템플릿 종류의 보조 문구는 각각의 영역 탭 안에서 caption 크기로 표시하고 aria-describedby로 연결한다. 메뉴판 유형은 같은 목록의 조건으로 취급하며 검색과 다른 호환 필터와 함께 적용한다.
- 카탈로그 카드는 썸네일과 이름으로 상세에 진입한다. 별도 미리보기 링크는 새 창에서 열린다. 디자인 카드는 메뉴판 유형·업종과 이름을 표시하고, 구조와 대표 분위기 하나를 중립 칩으로 보여준다. 기본 디자인은 유형과 이름, 짧은 설명을 표시한다. 페이지가 하나 이하일 때 페이지네이션을 숨긴다.
- 좋아요 등록·취소 알림은 공통 Sonner 토스트를 사용하며 저장 응답으로 확인한 상태를 안내한다. 실패·잘못된 저장 응답은 낙관적 하트를 복원하고 기존 오류 안내를 유지하며 성공 알림을 표시하지 않는다.

## 2026-11-11 공지 분류와 가이드 바로가기

- 공지사항은 사용자 지정에 따라 디자인 템플릿의 베이직/다이닝/디스플레이와 같은 `Tabs purpose="page"`, `size="lg"`를 사용한다. 전체 공지/서비스 안내/업데이트/점검 안내가 목록 전체를 전환하며 검색 조건과 페이지 초기화는 유지한다. 카테고리 select는 제거한다.
- 이용가이드 본문 바로가기는 공통 outline Button의 기본 모서리를 사용한다. 긴 문구와 준비 중 제어를 작은 pill 필터로 표현하지 않는다. 준비 중 비활성과 기존 앵커는 유지하며, 권장 브라우저 도움말은 전체 화면 안내 제목에 둔다.
- 알림 분류의 여백은 [컴포넌트 밀도 기준](site-component-density.md)의 공통 NotificationPanel 규격을 따른다.

## 2026-11-11 선택 밑줄 두께

주요 화면·목록 분류 탭의 선택선은 `--site-tab-indicator-width: 3px`을 공유한다. 기존4px이 두껍고 이후2px은 너무 얇다는 사용자 후속 피드백에 따라 중간3px로 확정한다. 알림 팝업·모바일 시트·이력과 디자인 시스템 예시는 공통 NotificationPanel을 그대로 사용한다. 높이·상하 여백·선택선의 위치와 너비·글자·색·포커스·키보드 동작은 유지한다. 비선택 분류 탭도3px 투명 경계를 확보해 전환 시 콘텐츠가 움직이지 않도록 한다.
