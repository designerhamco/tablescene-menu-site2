# 원페이지 메뉴판의 자동 배치 규칙 — 2026-10-13

## 적용 범위

REAL MATCHA, KOHI, Mocha Forest, Sunday Roasters, Van Gogh, ROSY ORANGE, Loop Bagel의 PC·태블릿 원페이지 화면에 적용한다. 세로 태블릿(실제 폭 768–1023px)은 기존 읽기 화면으로 자연스럽게 스크롤하며 PC·태블릿의 글자 연동 규칙을 사용한다. 이 폭에서 fit 엔진이 실행되지 않는 가로 화면용 고정 보드를 노출하지 않는다. 모바일 본문은 독립적인 읽기 정책을 유지한다. Display, 멀티페이지, 판매하지 않는 엔진에는 새 자동 배치 정책을 적용하지 않는다.

이번 사용자 요청은 앞선 ‘세 가지 수정만 허용 / 여백 확대 금지’ 범위를 대체한다. 이름·보조언어명·설명이라는 세 필드의 의미는 유지하되, 숨긴 설명을 가상의 빈 줄로 예약하여 글자를 작게 만드는 방식은 PC·태블릿의 실제 fit에서 사용하지 않는다. 긴 실제 문장은 줄바꿈하여 전체를 보존한다.

## 카테고리 배치의 우선순위

1. 저장된 등록 순서대로 연속 카테고리를 묶는다. 저장된 순서와 고객 데이터는 변경하지 않는다.
2. 그 방식으로 여백 편차가 크거나 읽을 수 있는 크기로 들어가지 않을 때만, 의미상 연관된 카테고리를 같은 열에 묶는 대안을 비교한다.
3. 관련 카테고리 재묶기로 해결되지 않으면 읽을 수 있는 네 번째 메뉴 열을 구조 후보로 사용한다. 그 열의 실제 내부 폭이 최소 `12rem`이어야 한다.
4. 묶음 전체가 들어갈 수 없으면 등록 순서를 유지하는 아이템 흐름을 마지막으로 시도한다. 한 카테고리가 다음 열로 이어질 수 있다.
5. 메뉴가 지나치게 많거나 문장이 길어 어떤 후보도 가독성 하한에서 들어가지 않으면, 본문에 세로 스크롤을 허용한다. 텍스트를 자르거나 하한 아래로 축소하지 않는다. 이 경우 다단 흐름이 오른쪽으로 계속 생기지 않도록 카테고리 열을 세로로 스크롤한다.

관련성은 템플릿 이름으로 하드코딩하지 않는다. 카테고리 이름의 음식·음료 어휘를 먼저 사용한다. 이름이 ‘추천 메뉴’처럼 모호한 경우, 상품명 두 개 이상이면서 2/3 이상이 한 분류에 일치할 때만 분류한다. 베이글·빵과 크림치즈·스프레드는 같은 분류로, 샌드위치는 별도 분류로 구분한다. 커피와 티·기타 음료는 음료라는 공통 맥락으로 함께 묶을 수 있다. 디저트와 음료를 무조건 혼합하지 않는다.

예: `클래식 베이글 → 베이글 샌드위치 → 크림치즈 → 커피&드링크`가 기본이다. 공간 문제가 크고 **클래식 베이글과 크림치즈를 실제로 같은 열에 넣을 수 있을 때** `클래식 베이글 → 크림치즈 → 베이글 샌드위치 → 커피&드링크`를 비교한다. 순서만 바뀌고 새 연관 묶음이 생기지 않는 후보는 제외한다.

페이지, 위젯, 분류를 알 수 없는 카테고리를 가로질러 이동하지 않는다. 한 카테고리 안의 상품 순서와 가격 대응은 유지한다. 후보는 최대 8개의 제한된 관련 이동만 생성하며 전체 순열을 무차별로 검색하지 않는다.

정량 기준은 다음과 같다.

- 기존 후보의 가장 짧은 열이 높이 예산의 60% 미만이거나, 가장 긴 열과 짧은 열의 차이가 예산의 25%를 넘을 때 ‘편차가 큰 배치’로 판단한다.
- 관련 후보는 가장 짧은 열을 예산의 12% 이상 개선하거나, 가장 긴 열의 높이를 예산의 8% 이상 줄여야 한다. 넘치는 후보는 제외한다.
- 동일한 결과에서는 등록 순서 후보가 우선이다. 재배치 후보에는 추가 비용을 부여하여 사소한 차이로 순서를 바꾸지 않는다.
- 측정한 분할점과 전체 카테고리 순서를 함께 기록하고 그대로 렌더링한다. 측정은 재배치하고 실제 화면은 원래 순서로 나오는 불일치를 방지한다.

## PC·태블릿의 글자 크기와 여백

상품명·가격은 하나의 기본 크기에서 출발한다. 기본 크기는 템플릿의 기존 글자 기준과 고객 폰트 설정에 fit 배율을 적용한다. 가독성 하한은 `1rem`, 상한은 `2.5rem`이다. 16px 루트에서는 16px / 40px에 해당하며 모든 화면을 그 고정 크기로 만드는 뜻은 아니다.

**가게 설명 = 상품 설명 = 안내사항 1·2·3 = 대표 영역 상품명**은 하나의 지원 문구 크기를 공유한다. 이 크기는 상품명 × 템플릿의 기존 지원 문구 비율로 계산하고, 하한은 `0.75rem`이다. 기본 루트의 12px 하한은 밀집한 화면을 위한 안전 장치이며, 여유가 있으면 그 이상으로 함께 커진다. 대표 설명과 위젯 본문도 같은 크기를 사용한다. 카테고리 설명의 별도 강조 역할은 유지한다. 보조언어명은 기존 역할 비율을 사용하고 `0.75rem` 아래로 내리지 않는다. 모바일의 14px 지원 문구 규칙과는 별개다.

PC와 태블릿의 상품명·지원 문구·대표 상품명에 서로 다른 장치 배율을 중복 적용하지 않는다. 실제 사용할 수 있는 열 폭과 높이를 기준으로 다시 계산한다. 한 역할만 따로 작아지는 wrap 보정은 이 정책에서 사용하지 않는다.

메뉴가 적을 때는 최대 2.0 fit 배율까지 실제 문장·이미지·가격·칩·안내 영역이 들어가는 후보를 탐색한다. 선택한 분할을 실제 렌더링한 뒤에도 여유가 있으면, 최대 9번의 이분 탐색으로 안전한 확대를 확인한다. 텍스트와 기존 글자-간격 계산식이 같이 커지며, 간격만 늘려 화면을 채우지 않는다. 가격과 이름, 배지, 위젯, 하단 안내·언어 UI의 안전 영역을 모두 지킨다. 실제 확대가 불가능한 잔여 공간은 남을 수 있다.

기존 템플릿의 카테고리 간격, 외곽 여백, 열 간격, 구분선, 안내 위치는 유지한다. 상품 사이 간격만 기존 기본 간격에 아래 계수를 한 번 적용한다.

| 보이는 지원 정보 | 상품 사이 계수 |
| --- | --- |
| 보조언어명과 설명 모두 표시 / 추가 프로모션·원산지·특성 표시 | 1.00 |
| 둘 중 하나 표시 | 1.10 |
| 둘 다 숨김 | 1.20 |

마지막 상품, 카테고리 경계, 제목과 설명의 내부 간격에는 이 계수를 적용하지 않는다. 기존 3필드 참조 검증과 새 실제-content 검증이 동시에 배율을 되돌리는 경쟁 루프도 제외한다. 확대와 최종 잘림 안전 검증을 하나의 정책에서 수렴시킨다.

## 가게명과 상단 행

Sunday Roasters와 Van Gogh의 상단 행은 **기존 외곽 여백과 행 간격을 제외한 높이의 18%**, 본문은 82%로 유지한다. 가게명을 두 줄로 표시한다고 행이 늘어나지 않는다. 중앙 제목 셀 안의 실제 행 높이에 맞춰 두 줄의 글자를 더 작게 계산한다. 고정 px 행 높이를 사용하지 않는다. 고객이 매우 긴 가게명·가게 설명·안내 문구를 입력하여 하한 크기로도 행에 들어가지 않는 경우에는 해당 상단 셀 안에서 스크롤하여 전체 문구를 읽을 수 있게 한다. 행을 늘리거나 문구를 잘라 버리지 않는다.

상단의 설명 / 가게명 / 안내사항은 동일한 폭의 세 셀이다. 가게명과 각 줄은 가운데 셀의 중앙에 놓는다. 상단 제목은 중앙 셀 내부 폭의 60%, 세로 브랜드 열은 내부 폭의 75%를 목표로 한다. 가게명 크기는 메뉴 fit과 별도로 실제 저장된 폰트 폭·행 높이로 계산한다.

한 줄과 균형 잡힌 두 줄을 같은 정책으로 비교한다. 두 줄이 최소 15% 더 큰 글자를 허용하면 선택할 수 있다. 한 줄의 상대 하한이 목표 폭을 5% 넘게 초과하는 경우에도 균형 잡힌 두 줄을 선택한다. 짧은 줄 / 긴 줄의 폭 비율은 최소 0.5이다. 모든 줄은 같은 크기를 사용한다. 가게명 전체와 단어를 보존하며, 불가피한 긴 단어는 안전한 글자 단위로 줄바꿈한다. 로고는 텍스트 fitting을 거치지 않는다.

## 모바일에서 바뀐 부분과 유지하는 부분

가게명의 최대 크기만 줄였다. 390px 화면 / 내부 폭 342px에서 한 줄 상한은 **88 → 72px**, 여러 줄 상한은 **64 → 56px**이다. 실제 내부 폭에 비례하므로 320px·430px에서도 동일한 화면 비율을 유지한다. 최소 크기는 `max(44px, 2.75rem)`으로 유지한다.

모바일의 상품명·가격 16px, 지원 문구·안내 14px, 보조언어명 12px, 카테고리 26px, 상품 간격 20px, 제목 뒤 24px, 섹션 경계 48px는 그대로다. 내부 간격은 상품 문구 2px / 카테고리 문구 8px / 브랜드 설명 12px / 상단 블록 24px를 유지한다. 모바일은 메뉴 개수에 맞춰 본문을 축소하거나 확대하지 않고 자연스럽게 스크롤한다. 폰트·언어 변경에 따른 가게명 fitting은 독립적으로 실행한다.

## 고객 수정과 검증

메뉴 개수나 ID가 같아도 상품명·보조명·설명·가격·가격 라벨·가격 옵션·이미지·배지·품절·원산지·카테고리·위젯·지원 문구·폰트 설정 변경은 재측정한다. 가게 설명과 안내사항을 바꾸어 하단 영역의 높이가 달라지는 경우도 포함한다. 기기나 실제 viewport 크기가 달라지면 이전 구조의 최종 fallback을 해제하고 처음부터 다시 비교한다. 타이머의 매초 숫자 변화는 이 서명에 포함하지 않는다.

`npm test`, TypeScript, ESLint, production build와 함께 실제 브라우저에서 검사한다. 요청한 크기 대신 실제 `innerWidth × innerHeight`를 기록하고, 폰트·이미지 로드, 브랜드 fit, 본문 fit과 로딩 덮개의 해제가 끝난 뒤 판정한다. 상품 누락, 가격 정렬, 가로 overflow, 내용 잘림, 모바일 숫자 간격과 제외 엔진의 정책 누출을 확인한다.

검증 명령: `node scripts/qa-one-page-adaptive.mjs`. `ADAPTIVE_QA_FULL=1`은 기기·언어 전체, `ADAPTIVE_QA_FIXTURES=1`은 로컬 전용 메뉴 변경 사례, `ADAPTIVE_QA_BASE`는 검증 주소를 선택한다. `scripts/qa-one-page-mobile-common.mjs`로 기존 모바일 상세 계약도 검증한다. 최종 실행 결과는 작업 완료 기록과 함께 보관한다.

- 설명 전체·일부·숨김, 희소 메뉴와 4배 밀집 메뉴: Sunday Roasters·KOHI·Loop Bagel의 21건 통과. 밀집한 메뉴는 가독성 하한을 유지한 세로 스크롤로 전체 항목을 보존했다.

브라우저 검사는 가독성 하한, 네 역할의 크기 일치, 가격 정렬, 모바일 간격, 가로 overflow, 18% 상단 행과 렌더링 완료를 확인한다. 모든 고객 입력의 미관을 보장하는 테스트는 아니며, 확인된 공간·가독성 규칙을 지키면서 내용 수정 때마다 다시 계산한다.
