# 원페이지 메뉴판의 자동 배치 규칙 — 2026-10-13

## 적용 범위

REAL MATCHA, KOHI, Mocha Forest, Sunday Roasters, Van Gogh, ROSY ORANGE, Loop Bagel의 PC·태블릿 원페이지 화면에 적용한다. 가로·세로 태블릿 모두 원페이지 fit을 실행하며, 실제 폭 768–1023px에서도 모든 메뉴·가게명·가게 설명·안내·대표 영역을 한 화면에 배치한다. PC·태블릿의 본문과 상단 셀에 스크롤을 추가하지 않는다. 모바일 본문은 독립적인 읽기 정책과 자연스러운 스크롤을 유지한다. Display, 멀티페이지, 판매하지 않는 엔진에는 새 자동 배치 정책을 적용하지 않는다.

이름·보조언어명·설명의 세 필드 참조는 기본 측정 기준이다. 숨긴 지원 필드도 한 줄씩 있는 것으로 계산해 표시 옵션에 따른 크기의 급격한 변화를 줄이되, 실제 화면에 여백이 과도하게 남는 경우에는 아래 조건부 실제-content 측정으로 완화한다. 참조 문단은 동기 측정 중에만 사용하며, 실제 화면에는 빈 줄을 남기지 않는다. 실제 긴 문장은 줄바꿈하여 전체를 보존한다.

## 세 필드 기준의 조건부 완화

- 첫 계산과 고객 내용·폰트·기기·viewport 변경 후에는 항상 `three-field`부터 시작한다.
- 보조명 또는 설명이 숨겨져 있고, 가장 긴 열에도 높이 예산의 18% 이상 여백이 남거나, 8% 이상 여백과 평균 채움 72% 미만이 함께 나타날 때 실제 내용 확대 후보를 비교한다.
- 실제 내용으로 안전하게 계산한 글자 배율이 참조 배율보다 최소 8% 커질 수 있을 때만 `actual` 기준으로 전환한다. 짧은 열 하나만 비어 있는 경우에는 이 조건을 충족하지 않는다.
- 실제 문장의 여러 줄이 한 줄 참조보다 커서 최종 잘림 검증에 실패하는 경우에도 실제 내용으로 재측정한다. 이때는 공간 채움보다 전체 텍스트의 보존이 우선이다.
- 같은 내용·viewport에서 실제 기준으로 전환한 뒤 기본 기준으로 반복 복귀하지 않는다. 내용이나 viewport가 바뀌면 다시 기본 기준부터 비교한다. 측정 기준은 fit 캐시 키에 포함한다.
- 측정 가정만 완화한다. 상품명·보조명·설명의 역할 비율과 가게 설명 = 상품 설명 = 대표 설명 = 안내의 크기 연동은 유지한다.

## 카테고리 배치의 우선순위

1. 저장된 등록 순서대로 연속 카테고리를 묶는다. 저장된 순서와 고객 데이터는 변경하지 않는다.
2. 그 방식으로 여백 편차가 크거나 읽을 수 있는 크기로 들어가지 않을 때만, 의미상 연관된 카테고리를 같은 열에 묶는 대안을 비교한다.
3. 관련 카테고리 재묶기로 해결되지 않으면 읽을 수 있는 네 번째 메뉴 열을 구조 후보로 사용한다. 그 열의 실제 내부 폭이 최소 `12rem`이어야 한다.
4. 묶음 전체가 들어갈 수 없으면 등록 순서를 유지하는 아이템 흐름을 마지막으로 시도한다. 한 카테고리가 다음 열로 이어질 수 있다.
5. 어떤 후보도 들어가지 않으면 기존 fit 실패 처리를 유지한다. 스크롤·잘림·가로로 넘치는 추가 열을 정상 완료로 간주하지 않는다. 스크롤을 자동 배치의 해결책으로 사용하지 않는다.

관련성은 템플릿 이름으로 하드코딩하지 않는다. 카테고리 이름의 음식·음료 어휘를 먼저 사용한다. 이름이 ‘추천 메뉴’처럼 모호한 경우, 상품명 두 개 이상이면서 2/3 이상이 한 분류에 일치할 때만 분류한다. 베이글·빵과 크림치즈·스프레드는 같은 분류로, 샌드위치는 별도 분류로 구분한다. 커피와 티·기타 음료는 음료라는 공통 맥락으로 함께 묶을 수 있다. 디저트와 음료를 무조건 혼합하지 않는다.

예: `클래식 베이글 → 베이글 샌드위치 → 크림치즈 → 커피&드링크`가 기본이다. 공간 문제가 크고 **클래식 베이글과 크림치즈를 실제로 같은 열에 넣을 수 있을 때** `클래식 베이글 → 크림치즈 → 베이글 샌드위치 → 커피&드링크`를 비교한다. 순서만 바뀌고 새 연관 묶음이 생기지 않는 후보는 제외한다.

페이지, 위젯, 분류를 알 수 없는 카테고리를 가로질러 이동하지 않는다. 한 카테고리 안의 상품 순서와 가격 대응은 유지한다. 후보는 최대 8개의 제한된 관련 이동만 생성하며 전체 순열을 무차별로 검색하지 않는다.

정량 기준은 다음과 같다.

- 기존 후보의 가장 짧은 열이 높이 예산의 60% 미만이거나, 가장 긴 열과 짧은 열의 차이가 예산의 25%를 넘을 때 ‘편차가 큰 배치’로 판단한다.
- 관련 후보는 가장 짧은 열을 예산의 12% 이상 개선하거나, 가장 긴 열의 높이를 예산의 8% 이상 줄여야 한다. 넘치는 후보는 제외한다.
- 동일한 결과에서는 등록 순서 후보가 우선이다. 재배치 후보에는 추가 비용을 부여하여 사소한 차이로 순서를 바꾸지 않는다.
- 측정한 분할점과 전체 카테고리 순서를 함께 기록하고 그대로 렌더링한다. 측정은 재배치하고 실제 화면은 원래 순서로 나오는 불일치를 방지한다.

## PC·태블릿의 글자 크기와 여백

상품명·가격은 하나의 기본 크기에서 출발한다. 기본 크기는 템플릿의 기존 글자 기준과 고객 폰트 설정에 fit 배율을 적용한다. 가독성 하한은 `1rem`, 공통 상한은 PC `1.35rem`·태블릿 `1.30rem`이다. 16px 루트에서는 각각 16px / 21.6px / 20.8px에 해당하며 모든 화면을 그 고정 크기로 만드는 뜻은 아니다. 모바일은 별도의 읽기 규칙을 사용한다.

**가게 설명 = 상품 설명 = 대표 설명 = 안내사항 1·2·3**은 하나의 지원 문구 크기를 공유한다. 이 크기는 상품명 × 템플릿의 기존 지원 문구 비율로 계산하고, 하한은 `0.75rem`이다. 기본 루트의 12px 하한은 밀집한 화면을 위한 안전 장치이며, 여유가 있으면 그 이상으로 함께 커진다. 위젯 본문도 같은 크기를 사용한다. 대표 상품명·칩·가격은 각각 메뉴 상품명·칩·가격과 같은 크기를 사용한다. 카테고리 설명의 별도 강조 역할은 유지한다. 보조언어명은 기존 역할 비율을 사용하고 `0.75rem` 아래로 내리지 않는다. 모바일의 14px 지원 문구 규칙과는 별개다.

PC와 태블릿의 상품명·지원 문구·대표 상품명에 서로 다른 장치 배율을 중복 적용하지 않는다. 실제 사용할 수 있는 열 폭과 높이를 기준으로 다시 계산한다. 한 역할만 따로 작아지는 wrap 보정은 이 정책에서 사용하지 않는다.

메뉴가 적을 때는 최대 2.0 fit 배율까지 실제 문장·이미지·가격·칩·안내 영역이 들어가는 후보를 탐색한다. 선택한 분할을 실제 렌더링한 뒤에도 여유가 있으면, 최대 9번의 이분 탐색으로 안전한 확대를 확인한다. 텍스트와 기존 글자-간격 계산식이 같이 커지며, 간격만 늘려 화면을 채우지 않는다. 가격과 이름, 배지, 위젯, 하단 안내·언어 UI의 안전 영역을 모두 지킨다. 실제 확대가 불가능한 잔여 공간은 남을 수 있다.

기존 템플릿의 카테고리 간격, 외곽 여백, 열 간격, 구분선, 안내 위치는 유지한다. 상품 사이 간격만 기존 기본 간격에 아래 계수를 한 번 적용한다.

| 보이는 지원 정보 | 상품 사이 계수 |
| --- | --- |
| 보조언어명과 설명 모두 표시 / 추가 프로모션·원산지·특성 표시 | 1.00 |
| 둘 중 하나 표시 | 1.10 |
| 둘 다 숨김 | 1.20 |

마지막 상품, 카테고리 경계, 제목과 설명의 내부 간격에는 이 계수를 적용하지 않는다. 기존 3필드 참조 검증과 새 실제-content 검증이 동시에 배율을 되돌리는 경쟁 루프도 제외한다. 확대와 최종 잘림 안전 검증을 하나의 정책에서 수렴시킨다.

## 가게명과 상단 행

PC에서 실제 폰트 fitting 결과 가게명이 한 줄이면 상단→메뉴 간격을 기본값의 75%로 줄인다. 두 줄 이상, 자연 줄바꿈 여부가 불확실한 경우, 로고 및 태블릿은 기본 간격을 유지한다. 제목 후보는 축소 전 기본 간격으로 계산하여 줄 수·간격이 반복해서 바뀌는 것을 방지한다.

상단 행형 두 템플릿의 외곽 여백과 상단→메뉴 행 간격은 같은 유동 계산식을 사용한다. 반고흐의 PC 전용 작은 상하 여백·행 간격 예외는 제거했다.

Sunday Roasters와 Van Gogh의 상단 행은 **기존 외곽 여백과 행 간격을 제외한 읽기 프레임 높이의 16%**를 함께 사용한다. 한 줄과 두 줄 가게명 모두 실제 고정 행 안에서 글자 크기를 계산하며, 두 줄 때문에 행 자체를 늘리거나 셀 내부 스크롤을 사용하지 않는다.

상단 설명 / 가게명 / 안내사항은 동일한 폭의 세 셀이다. 제목은 가운데 셀 중앙에 놓이고 내부 폭의 **60%**를 목표로 한다. 상단 제목의 최소/최대 글자 크기는 중앙 셀 폭의 **10% / 22%**이며 브라우저의 기본 글자 확대를 반영한다. 16% 행 높이 한도도 함께 지킨다. 세로 브랜드 열은 PC·태블릿 모두 75% 폭 목표 / 10% 폭 하한 / 18% 높이 예산을 유지한다. 실제 저장된 폰트 폭·행 높이로 계산한다.

한 줄과 균형 잡힌 두 줄을 같은 정책으로 비교한다. 두 줄이 최소 15% 더 큰 글자를 허용하면 선택할 수 있다. 한 줄의 상대 하한이 목표 폭을 5% 넘게 초과하는 경우에도 균형 잡힌 두 줄을 선택한다. 짧은 줄 / 긴 줄의 폭 비율은 최소 0.5이다. 모든 줄은 같은 크기를 사용한다. 가게명 전체와 단어를 보존하며, 불가피한 긴 단어는 안전한 글자 단위로 줄바꿈한다. 로고는 텍스트 fitting을 거치지 않는다.

## 모바일에서 바뀐 부분과 유지하는 부분

가게명의 최대 크기를 추가로 줄였다. 390px 화면 / 내부 폭 342px에서 현재 한 줄 상한은 **56px**, 여러 줄 상한은 **44px**이다. 실제 내부 폭에 비례하되 최소 크기 `max(44px, 2.75rem)`을 우선한다. PC는 공간·줄 수로 계산한 기존 가게명 후보 상한의 **87.5%**를 사용하며 기존 최소 크기는 유지한다. 태블릿 가게명 상한은 유지한다.

언어 UI → 가게명과 가게명 → 가게 설명 간격은 같은 `--cafe-a-mobile-brand-copy-gap` 토큰(기본 12px)에 연결한다. 모든 원페이지 PC·태블릿·모바일에서 안내사항 1·2·3과 언어 UI의 버튼/선택 항목 텍스트는 상품 설명의 공통 기본 크기를 사용한다. 안내는 한글·영어 모두 저장된 한글 폰트를 사용한다. 언어 UI는 저장된 한글/영문 폰트를 각각 사용한다.

모바일의 상품명·가격 16px, 지원 문구·안내 14px, 보조언어명 12px, 카테고리 26px, 상품 간격 20px, 제목 뒤 24px, 섹션 경계 48px는 그대로다. 내부 간격은 상품 문구 2px / 카테고리 문구 8px / 브랜드 설명 12px / 상단 블록 24px를 유지한다. 모바일은 메뉴 개수에 맞춰 본문을 축소하거나 확대하지 않고 자연스럽게 스크롤한다. 폰트·언어 변경에 따른 가게명 fitting은 독립적으로 실행한다.

## 두 필드 상품의 작은 강조

상품명+보조언어명 또는 상품명+상품설명만 표시하는 상품은 남은 보조언어명/설명을 기본 크기보다 5% 키운다. 세 필드를 모두 쓰거나 상품명만 쓰는 경우는 그대로다. 텍스트칩이나 할인 정보의 유무는 이 두 필드 판단을 바꾸지 않는다.

이는 해당 상품만의 명시적인 예외다. 카테고리 설명·가게 설명·안내·언어 UI는 같은 공통 기본 크기를 유지한다. 해당 상품의 할인 설명과 연결된 대표영역 설명은 그 상품 설명과 같은 5% 확대 크기를 사용한다. 모바일 기본 루트에서는 보조언어명 12→12.6px, 설명 14→14.7px이며 기존 상품/섹션/내부 간격은 유지한다. PC·태블릿은 실제 확대된 크기를 포함해 다시 배치한다. 읽기 하한에 도달해도 실제 배치가 넘치면 그 내용·화면에서는 선택적인 5% 강조만 해제하고 기본 크기로 다시 계산한다. 내용·화면 변경 후에는 다시 확대를 시도한다.

안내사항 1·2·3은 한글·영어 모두 설정한 한글 폰트를 사용한다. 언어 UI는 한글/영문 설정 폰트를 각각 유지한다. 카테고리 설명과 할인 설명의 기본 크기는 상품 설명 기본 크기에 연결한다. 카테고리 강조 굵기·색상과 할인 가격·칩의 별도 역할은 유지한다.

기간할인 안내 문구·마감 시각·`00:00:00` 카운트다운도 모든 원페이지 PC·태블릿·모바일에서 한글·영어·숫자 모두 설정한 한글 폰트를 사용한다. 할인 가격과 언어 UI의 폰트 규칙은 유지하며, 멀티페이지·디스플레이에는 적용하지 않는다.

## 상품명과 텍스트 칩

모든 원페이지 PC·태블릿·모바일에서 메뉴·대표영역 텍스트칩은 한글에 설정한 한글 폰트, 영어에 설정한 영문 폰트를 사용한다. 할인·품절·특성 칩도 포함하고 혼합 문구는 언어별로 나눠 표시한다. 기존 고정 칩 폰트보다 이 규칙이 우선하며, 크기·색상과 배치 규칙은 유지한다. 기간할인 안내 문구·타이머는 별도의 한글 폰트 고정 규칙을 유지한다.

일곱 원페이지 PC·태블릿에서 상품명 자체는 한 줄에 들어가지만 칩을 옆에 놓으면 넘치는 경우에만 칩을 상품명 바로 아래로 옮긴다. 상품명 자체가 너무 길면 줄바꿈은 허용하되, 칩 때문에 줄 수가 더 늘어나면 칩을 아래로 옮긴다. 로지오렌지는 연결선의 최소 폭도 먼저 예약하며, 칩이 내려간 행에서도 상품명 첫 줄 옆의 선을 유지한다. 후보 계산과 최종 잘림 검증에서 동일한 실제 글자 폭을 사용하고 폰트·폭이 바뀌면 다시 판단한다. 상품명·가격의 첫 행 정렬은 유지한다. 모바일과 다중 페이지에는 적용하지 않는다.
