# 영역형 탭 기준과 검수

## 기준

- 라이브러리의 파일형(`folder`)과 라운드 연결형(`flow`) 추가 시안은 폐기한다. 두 시안은 같은 역할에 서로 다른 윤곽을 제공해 선택 기준을 흐리고, 사선·연결선·패널 외곽이 사이트의 단순한 면 구성과 맞지 않았다.
- 공식 영역형은 `Tabs hierarchy="embedded"` 하나다. 현재 공통 API가 이를 `area` 표현으로 연결한다. 선택 탭과 콘텐츠는 흰색으로 이어지고, 비선택 탭만 옅은 회색 무테 면으로 구분한다. 탭 아래의 곧은 1px 기준선은 콘텐츠 폭 안에서 끝나며 사선·산 모양 mask·그림자를 넣지 않는다.
- area는 하나의 기능·작업·목록 영역 안에서 내용만 전환하는 4단계 embedded 표현이다. 페이지 전체 보기 전환은 primary/outline, 주요 분류는 secondary/underline, 필터·본문 이동은 site-filter/링크를 사용한다. 실제 템플릿 페이지의 베이직/다이닝/디스플레이와 고객센터 공지사항/FAQ는 primary, 디자인/기본 템플릿은 embedded area다.
- sm/md/lg 40/44/48px와 14/15/16px 글자, 내용 폭, disabled, 방향키/Home/End 계약을 공통으로 사용한다. 좁은 화면의 긴 목록은 영역 안에서만 가로 스크롤한다.

## 검증

- 계약 테스트는 folder/flow/contained API와 전용 CSS·mask가 제거되고 area의 흰 선택 탭·흰 콘텐츠 면·옅은 회색 비선택 탭·곧은 기준선이 존재하는지 확인한다.
- `npm run qa:shaped-tabs`는 375/820/1440px에서 영역형의 선택·키보드 이동·비활성 건너뛰기·포커스·가로 넘침을 검사한다. 실제 `/templates`, `/faq`, `/guides`에서는 기존 탭 역할과 페이지 가로 넘침을 회귀 확인한다.
- 변경 TSX lint, TypeScript, 단위·계약 테스트, 최적화 빌드와 `git diff --check`를 통과한 뒤 실제 브라우저로 PC·태블릿·모바일 화면을 비교한다.

## 결과

- 단위·계약 테스트 877건, TypeScript, 변경 파일 lint, 최적화 빌드와 공백 검사를 통과했다.
- 실제 Chromium 375/820/1440px에서 영역형의 선택 전환·방향키·비활성 건너뛰기·포커스, 흰 콘텐츠 연결, 기준선의 영역 내 종료와 페이지 가로 넘침 0을 확인했다.
- 같은 세 화면에서 `/templates`, 템플릿 미리보기 옵션, `/faq`, `/guides`를 재검수했다. 템플릿 종류와 미리보기 옵션은 embedded area, 고객센터는 primary 위계로 분리되며 브라우저 오류와 가로 넘침이 없다.
