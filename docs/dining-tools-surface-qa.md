# 다이닝 커버 운영 UI 표면·색상 검수

## 원인과 수정 범위

사진 커버에만 도구 투명 처리가 걸려 있어 커버 이미지를 끄면 PC·태블릿 도구에 흰 박스, 모바일 상·하단에 흰 바가 생겼다. 모바일 헤더는 고정 짙은 글자색도 사용했다. 밝은 언어 목록의 링크는 전역 a 색상 상속 때문에 커버의 흰 글자색을 물려받았다.

커버 활성 여부와 사진 활성 여부를 구분한다. 모든 커버에서 상단 도구와 모바일 상·하단 바의 바탕은 투명하고 커버가 그 뒤까지 이어진다. 본문에서는 실제 메뉴 지면색을 사용한다. 사진 커버 도구는 기존 흰색을 유지하며 단색 커버/본문에서는 카테고리색을 우선하되 표면 대비 4.5 미만이면 읽기 좋은 흰색 또는 짙은색으로 보정한다. 언어 트리거·주문내역 아이콘·테이블 번호는 같은 도구 잉크를 쓴다. 언어 목록은 별도의 흰 표면 잉크를 사용하여 바깥 도구의 흰색을 상속하지 않는다.

## 보존하는 액션 규칙

- PC·태블릿: 다이닝 우하단 원형 호출 버튼, 상단 언어·주문내역 도구.
- 모바일: 하단 사각형 주문·호출 버튼 가로 배치. 기능 하나만 켜면 해당 버튼만 표시.
- 주문 버튼과 원형 호출 버튼의 채움은 카테고리명 색상. 주문 글자·아이콘은 밝은 메뉴색이 읽히면 우선하고, 부족하면 설정된 메뉴색 중 가장 짙은 읽기 가능한 색을 선택한 뒤 중립색으로 보정한다. 원형 호출은 기존 밝은 메뉴색 및 가독성 fallback을 유지.
- 사각형 호출 버튼은 가장 밝은 메뉴 색으로 채우고 카테고리색 글자·테두리를 사용.
- 커버/본문/로고 전환으로 액션 팔레트를 바꾸지 않는다. Basic의 기존 모양·색상·읽기 규칙은 변경하지 않는다.
- 안내사항은 PC·태블릿 가로 배치, 모바일 가운데 정렬 세로 1열. dot은 안내 아래 기존 하단 고정 위치를 유지하고 호출 도크를 피한다.

## 검증

`scripts/qa-dining-tools-surface.mjs`가 기본/중립 전면·사이드바 리스트·앨범에서 사진/짙은 단색/밝은 단색, 호출만/주문만/둘 다, PC·태블릿·모바일 및 320/430px를 검사한다. 도구 표면·잉크 대비, 테이블 번호 연결, 펼친 언어 목록, 안내·dot·도크 경계, 원형/사각형 모양과 커버→본문 액션 색상 유지를 실제 DOM으로 비교한다. 고객 데이터 쓰기 요청은 차단한다.

최종 로컬 검수: 운영 기능 ON 조합 38개와 모두 OFF 조합 12개, 총 50개 고유 다이닝 조건 통과. OFF 검사는 실제 styled CSS가 적용된 뒤 측정하도록 로딩 대기를 보완했다. 별도 긴 안내/좁은 모바일 18조건과 기존 9종 호출 정책 검사도 통과했고, 원래 스타터 팔레트 6조건에서도 재확인했다. 브라우저 예외·고객 데이터 쓰기 0. 전체 단위 1,189개, 사이트 UI 134개 및 후속 관련 50개 검사 통과. 타입·변경 파일 린트·diff 검사 완료 후 공급자 빌드로 배포한다.

동시에 반영된 최신 공통 코드(#530–#532)를 보존하여 합친 뒤 전체 단위 1,193개, 사이트 UI 134개와 원래 스타터 팔레트 6조건을 다시 통과했다. 주문의 밝은 글자 대비가 부족할 때 설정된 짙은 메뉴색을 먼저 고르는 최신 규칙과 한 언어 표시·패널 측정 변경을 유지했다.
