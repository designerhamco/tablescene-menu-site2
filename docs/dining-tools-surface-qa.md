# 다이닝 제목·설명 색상과 운영 UI 검수

## 현재 보완 규칙 — 2026-11-11

- PC/태블릿의 언어 UI는 보드 안쪽 왼쪽, 테이블번호는 가로 정중앙, 주문내역은 오른쪽에 배치한다. 전면/사이드바·리스트/앨범·디자이너/기본 디자인에 동일하다.
- 모든 기기의 커버는 주문/호출 ON/OFF와 관계없이 언어 UI만 표시한다. 테이블·주문내역·호출·모바일 하단 액션은 숨기고 하단 예약 공간도 해제한다. 본문은 기존 조건에 따라 복원한다.
- 원형 호출과 주문 버튼의 아이콘/글자는 페이지 팔레트에서 가장 밝은 색을 공유한다. 기존 대비 임계값으로 어두운 색으로 바꾸지 않는다. 배경색과 완전히 같은 경우에만 기존 팔레트의 읽을 수 있는 색으로 대체한다. 베이직은 변경하지 않는다.
- 색상 설정의 상품명(`product`)과 가격(`price`)는 독립적이다. 가격 그룹은 코스/메뉴/옵션 가격을 포함한다. 코스 가격 안내(예: 1인 기준 · 와인 페어링)는 상품설명·코스 설명과 같은 메뉴 설명 색이다. 코스/아이템 옆 담기 아이콘은 상품명 색을 따른다. 상단 주문내역은 언어·번호와 같은 도구 색 규칙을 유지한다.
- 가격이 설정된 코스의 설명은 상품설명 색과 같다. 일반 카테고리 설명은 페이지 설명과 같은 색이다. 첨부 예시의 첫 줄은 코스 설명, 두 번째 줄은 코스 가격 안내다.



## 색상 그룹과 호환성 — 2026-11-10

- 다이닝 보기옵션과 메뉴 편집의 디자인은 같은 9개 글자색 그룹을 사용한다. 페이지 제목(`pageTitle`)과 카테고리명(`category`)은 독립적이며, 페이지 제목 아래 설명과 일반 카테고리 설명은 `sectionDescription` 하나를 공유한다. 코스 설명은 상품설명 색이다. 가게명/커버 제목, 가게 설명·안내, 메뉴 설명, 위젯은 기존 역할을 유지한다. 상품명과 가격는 분리한다. Basic은 기존 6개 그룹을 유지한다.
- 미리보기 기능 옵션에 페이지 설명 표시를 추가한다. 카테고리 설명 표시와 독립적이다. 실제 메뉴 편집의 기존 페이지/카테고리 설명 입력·표시 기능은 유지한다.
- 주문과 PC·태블릿 원형 호출의 배경은 페이지 제목 색이다. 모바일 사각형 호출은 가장 밝은 메뉴색 배경에 페이지 제목색 글자·테두리를 사용한다. 주문과 원형 호출 글자는 가장 밝은 페이지색을 공유하며, 배경과 같은 색일 때만 읽을 수 있는 색으로 대체한다. 페이지 전환으로 액션 팔레트를 바꾸지 않는다.
- 모든 다이닝 PC·태블릿 본문은 상단 언어·장바구니 도구를 표시한다. 커버는 언어만 표시한다. 주문 또는 호출이 ON이면 테이블 번호를 표시하고, 둘 다 OFF이면 번호를 숨긴다. 미리보기 번호는 Table 1이다. 주문할 수 없는 상태의 장바구니는 비활성화하며 서버/세션 권한은 확장하지 않는다.
- 언어·주문 아이콘·테이블 번호의 글자색은 가게/커버 설명 색이 1순위다. 배경과 4.5:1 대비가 부족하면 어두운 배경에서는 현재 페이지 팔레트의 가장 밝은 읽기 가능한 색, 밝은 배경에서는 가장 짙은 읽기 가능한 색을 고른다. 메뉴 팔레트로도 부족할 때만 중립색으로 보정한다.
- 사진 유무만으로 흰색을 강제하지 않는다. 가능하면 도구 뒤 사진의 실제 영역과 오버레이 합성색을 읽는다. 원격 이미지가 픽셀 읽기를 허용하지 않으면 기존 이미지를 교체하지 않고 설정된 커버 표면을 사용한다. 언어 목록은 팝업 표면에 맞는 별도 카테고리색을 유지한다.
- 커버 도구·모바일 상하단 컨테이너는 투명하다. 본문의 기존 PC 원형/모바일 사각형 구성, 이미지 비율, 안내사항/페이지 점 위치와 모바일 읽기 간격은 유지한다. 사용자 정의 dot은 `appearance: none`으로 기본 버튼 외형을 해제한다.

## 호환성

기존 합쳐진 카테고리/페이지 제목 색은 읽을 때 새 제목 그룹에 승계하고, 새 편집·미리보기에서 처음 적용한 뒤 `diningTextColorGroupsVersion: 2`로 독립시킨다. 버전 1 이하의 상품명/가격 공통 색은 읽을 때 가격으로 승계하고, 새 독립 편집 후에는 한쪽 초기화가 다른 쪽에 영향을 주지 않는다. 이후 한쪽 수정/초기화가 다른 쪽을 바꾸지 않는다. 저장 검증은 등록된 색상 키만 허용하고 관련 없는 JSON과 구형 폼의 미제출 필드를 유지한다. 고객 데이터의 일괄 변경이나 DB 스키마 변경은 없다.

## 검수 도구

- `scripts/qa-dining-semantic-colors.mjs`: 기본 A/B·중립 전면/사이드바·리스트/앨범의 PC/태블릿/모바일, 밝고 어두운 단색/사진, 기능 OFF, 독립 색상 및 실제 편집 폼, 페이지 설명 표시를 검사한다.
- `scripts/qa-dining-tools-surface.mjs`: 기존 50개 표면/기기/운영 조합과 팝업, 페이지 점, 안내/도크 경계, 커버→본문 팔레트 보존을 검사한다.
- `scripts/qa-call-button-policy.mjs`: Basic 7종과 Dining 2종의 모양·동작·페이지 전환 일관성을 검사한다.
- 모든 브라우저 검사는 고객 데이터 쓰기 요청을 차단한다. 실제 인앱 브라우저에서도 디자인 색상 적용, 세 도구의 ON/OFF, 제목과 버튼 색상 연결을 확인한다.

이전 흰 박스/바 원인은 사진 커버에만 걸렸던 투명 처리였다. 이전의 사진 흰색 고정 및 카테고리 강조색 규칙은 위 현재 규칙으로 대체했다.

사이드바와 본문 배경이 다르면 왼쪽 언어 UI는 사이드바의 실제 배경으로 대비를 계산한다. 동일한 공통 색상 선택 규칙을 사용하되, 다른 배경 위의 도구에 같은 최종 색을 강제하지 않는다. 배치와 사이드바 구조는 유지한다.
