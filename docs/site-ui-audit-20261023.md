# 공식 사이트 UI 정리 — 2026-10-23

## 승인 범위와 순서

1. 기존 `--ui-*`, `site-button`, `site-field`, `Badge`, `site-notice`를 공통 기준으로 정리한다.
2. 사업자 플랜 칩과 이전 가입 구조를 전제로 한 표현을 제거한다. 첫 구독의 무료체험 상태·첫 결제 예정일과 과거 체험 메뉴판의 구독 전환·복구는 보존한다.
3. 주요 실행 / 보조 실행 / 도구 / 취소 / 위험 행동 / 선택 컨트롤에 따라 버튼을 적용하고 입력·안내를 통일한다.
4. 노란 점 장식 소제목은 문구와 여백까지 제거한다. 알림 본문의 목록 기호와 읽지 않은 알림 점은 보존한다.
5. 좋아요를 썸네일 바깥 제목 행으로 옮기고 상세페이지 공유 옆에 연결한다. 접힌 보기 옵션은 44px 팔레트 아이콘이다.
6. 정적 검사, 실제 브라우저의 공개 화면·샘플 계정 UI, 최적화 빌드와 배포 결과를 확인한다.

## 적용 기준

- 사장·직원 역할 칩: 흰 배경·회색 경계·회색 글자. 이용 중·공개 중: 같은 초록. 작성 중·비공개·결제 완료는 서로 다른 색이다.
- 나머지 칩: 채도가 있는 진한 배경·흰 글자·무테. 24px 높이/12px 글자/6px 라운드다. `Badge`가 의미를 `lib/site-chip.ts`에 연결한다.
- 검색을 포함한 일반 필드: 흰 배경/회색 경계/16px 라운드/16px 글자/최소 40px 높이/공통 안쪽 여백. 선행 아이콘은 별도 inset을 확보한다. 체크·라디오·색상·범위·파일·숨김 필드는 각 역할을 유지한다.
- 안내: 밝은 노랑 `#fff8d6`와 진한 본문. 중요 문구에만 붉은 강조를 사용한다.
- 기존 고객 메뉴판의 글꼴·칩 팔레트·fit·간격·그림과 콘텐츠는 제외한다. 사이트 편집 도구와 실제 고객 디자인 미리보기를 구분한다.
- 계약·상품 키, 권한·결제·보관 정책 및 실제 데이터는 변경하지 않는다. 이메일은 기존 템플릿 문구만 정리하며 발송하지 않는다.

## 검수 기록

- 구현·로컬 검수 완료. 로그인 검수용 계정이 없어 계정 화면은 실제 공통 컴포넌트에 샘플 데이터를 넣어 확인했다. 실제 계정의 쓰기 동작과 결제·메일 발송은 실행하지 않았다.
- 브라우저 좋아요 쓰기는 Playwright의 샘플 응답으로 대체한다. 등록·취소 및 목록→상세 동기화를 확인한다.
- 임시 검수 경로 `/qa/site-ui-audit`는 브라우저 확인 후 제거했다. 최적화 빌드에는 포함하지 않는다.
- 단위 테스트 811/811, TypeScript, 최적화 빌드 통과. ESLint 오류 0이며 작업 밖의 기존 미사용 변수 경고 2건은 유지했다.
- 실제 DOM 320/390/820/1440px의 샘플 계정·칩·문의 검색/포커스, 390/820/1440px의 목록/상세 좋아요 동기화·팔레트 열기/닫기/Escape 등 10건 통과. 역할 칩의 흰 배경/회색 경계, 공개·이용의 같은 초록, 작성·비공개·결제 완료의 구분과 24px 칩 높이, 흰 검색창/16px 라운드, 노랑 안내, 가로 넘침 0을 확인했다.
- 최적화 빌드에서 카탈로그 20종 상세를 390/1440px로 확인한 40건과 공개 화면·기존 메뉴판 미리보기 49건 통과. 페이지 오류·깨진 이미지·가로 넘침·WCAG critical/serious 오류 0이다.
- 기존 공개 QA의 구형 fit 전용 가정을 현재 contained reading과 분기했다. 세로 내부 스크롤을 오류로 처리하지 않고 준비 상태·메뉴 영역·열 수·실제 가로 경계를 확인한다. REAL MATCHA의 이전 주소는 현재 다이닝 엔진 경로이므로 단일 페이지 fit 대상에서 제외했다.
- PR #320의 연속 캐러셀·베이직 상단 CTA 보정·서비스 제목 크기 변경을 보존한 최신 운영 기준 위에서 검증했다. 릴리스 결과는 PR의 Vercel 체크와 최종 보고를 기준으로 한다.
