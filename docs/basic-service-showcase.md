# 메인 서비스 기능 시연

베이직·다이닝·디스플레이는 메인 페이지에서 같은 `ServiceFeatureStory`를 사용한다. PC는 왼쪽 ⅓에 제목·설명과 관리 화면, 진행 막대와 Skip을 놓고, 오른쪽 ⅔를 목업 크기와 위치를 정하는 가이드로 쓴다. 손과 페이드는 가이드와 자연스럽게 이어진다. 관리 화면과 진행 막대는 스테이지 하단을 기준으로 정렬한다. 좁은 태블릿은 읽기 영역에 40%를 배정한다. 목업의 크기는 기기 베젤을 기준으로 잡는다. 모바일에서는 태블릿 베젤을 화면 가로 중앙에 정렬하고, 화면 가장자리에 닿는 손목은 배경으로 부드럽게 페이드한다. 설명과 목업 사이에 공통 간격을 두고, 목업 하단이 이어지는 곳에는 어두운 페이드 위로 진행 막대와 Skip을 배치한다. 첫 장면은 서비스 소개다. 공통 중앙 콘텐츠 컨테이너, 의미 기반 타이포그래피와 간격 토큰을 사용한다.

스크롤 위치가 베이직 6개, 다이닝 8개, 디스플레이 4개 기능을 고른다. 소개에서는 모든 진행 막대가 비어 있다. 기능에 진입하면 진행 막대가 스크롤을 따라 채워지고 되감긴다. 클릭과 화살표 키로 기능을 선택하고 Home 키로 소개에 돌아갈 수 있다. Skip은 다음 프레임으로 이동하고, 디스플레이에서는 매장 운영으로 이동한다. 전환 후 도착한 제목으로 포커스를 옮긴다.

## 목업과 화면

- 베이직은 실버 모니터 앞에 손에 든 휴대폰을 놓는다. 모니터와 휴대폰은 같은 기능의 REAL MATCHA PC·모바일 캡처를 사용한다. 두 파일을 디코딩한 뒤 함께 교체하며, 확대나 원근 변환에도 사진과 합성 화면이 같은 모서리를 공유한다.
- 다이닝과 디스플레이는 승인된 `public/assets/basic-showcase-v1/tablet-hands-cutout.png`와 기존 화면 좌표를 재사용한다. 메뉴 미리보기 캡처는 `lib/service-story-screens.ts`에 등록한다. 디스플레이 목업만 교체할 때는 `ServiceFeatureStory`의 디스플레이 시각화 분기에서 별도 사진과 화면 좌표를 연결할 수 있다.
- 실제 고객 메뉴는 그대로 렌더링한다. 홈의 캡처는 정지 이미지이며 주문이나 호출을 전송하지 않는다. 관리 화면 영상이 등록되면 데스크톱에서 공통 `MediaPlayback`으로 재생하며 장면 전환이나 이탈 시 정지한다. 현재는 비활성 재생 자리로 표시한다.

### 이미지 생성

두 하드웨어 원본은 내장 ImageGen의 투명 배경 모드로 생성했다. 사이트는 알파를 보존한 WebP를 사용한다.

- `public/assets/service-mockups-v2/silver-monitor.webp` — 실제 제품 사진처럼 보이는 무브랜드 27인치 16:9 모니터. 오른쪽이 약 5–6° 높게 보이는 얕은 원근, 가는 검은 베젤, 밝은 무광 실버 옆면과 받침대, 비어 있는 화면. 바닥, 로고, 배경 없이 투명하게 촬영한 구도.
- `public/assets/service-mockups-v2/handheld-phone.webp` — 성인의 손에 자연스럽게 잡힌 무브랜드 세로 스마트폰. 흑연빛 실버 옆면, 따뜻하고 얇은 윤곽광, 손가락이 가리지 않는 빈 화면, 투명 배경.

## 검수

`BASIC_STORY_QA_BASE=<server> node scripts/qa-basic-feature-story.mjs`는 여러 화면 폭에서 고정 레이아웃, 앞뒤 스크롤, PC·모바일 캡처의 동시 전환, 진행 막대와 키보드 이동, Skip의 목적지 포커스와 가로 넘침을 검사한다.
