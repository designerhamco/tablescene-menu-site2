# 고객센터 검색 실행·결과 배치

## 동작

- 입력 중인 검색어와 실행한 검색어를 분리한다. 오른쪽의 배경 없는 진한 돋보기 또는 Enter로 실행하며, 한글 IME 조합 중 Enter는 제출하지 않는다.
- 실행 전에는 기존 공지사항·FAQ 탐색 목록을 유지한다. 검색하면 같은 공통 탭/주제 필터/목록/페이지 이동을 상단 회색 hero 안에 표시하며 하단에 중복 목록을 만들지 않는다.
- 제출 시 주제·페이지·열린 답변을 초기화한다. 실행 후 입력만 수정하면 기존 결과와 답변은 유지한다. 검색 해제 또는 빈 검색어 제출 시 기본 목록으로 돌아가며, 검색 해제는 입력창으로 포커스를 돌린다.
- 공지사항 API는 실행한 검색어만 받는다. 원래 조회/오류/재시도·상세 링크와 FAQ 아코디언을 유지한다. 검색 입력은 공통 큰 검색 필드, 돋보기는 공통 `Button variant="link" size="icon"`의 투명 표면·진한 글자색과 2.5px 선을 사용한다. 40px 클릭 영역과 포커스를 유지하며 hover/pressed에도 채워진 배경을 만들지 않는다.

## 검증

변경 TSX lint, TypeScript, 기존 테스트와 최적화 빌드를 실행한다. 브라우저에서는 실제 viewport, 입력 중 결과/답변 유지, 클릭·Enter·IME, 회색 영역 내부 배치, 빈 결과, 해제/빈 검색, 페이지·주제 초기화와 공지 조회/실패/재시도를 확인한다. 공지 데이터는 로컬 검수 응답을 사용하며 운영 데이터는 변경하지 않는다.

## 로컬 결과

아래는 최초 검색 기능 반영 당시 결과다. 이후 사용자 정정에 따라 검정 원형 배경을 제거하고 배경 없는 아이콘으로 변경했다.

- 기존 테스트 851건, TypeScript, 변경 TSX lint, 최적화 빌드와 diff 공백 검사를 통과했다. 최신 운영 브랜치의 공통 flow 탭 변경을 유지해 통합한 뒤 빌드·테스트·브라우저 검수를 다시 통과했다.
- 실제 320×568, 390×844, 820×1180, 1440×1000, 1920×1080에서 페이지/결과 영역 가로 넘침 0, 실행 오류 0건이다. 결과가 hero 내부에 한 번만 표시되고 돋보기는 입력 오른쪽의 공통 40px primary 버튼임을 확인했다.
- 입력 중 목록 개수·열린 답변 유지, 클릭/Enter 실행, 한글 조합 Enter 취소, 새 검색의 페이지/주제/답변 초기화, 빈 결과, 검색 해제의 포커스 복귀와 빈 검색 복원을 확인했다.
- 공지사항은 모의 23개 데이터로 검색·페이지 이동·오류/재시도·해제를 확인했다. 입력만 수정할 때 추가 API 요청이 없었으며 실행된 검색어만 요청에 포함됐다.
- 운영 완료는 병합 커밋 Vercel 성공과 실제 공개 `/faq`에서 390/1440px 검색 흐름을 별도로 확인한다.

## 돋보기 배경 제거 정정

- 공통 link 아이콘 버튼으로 교체해 기본/hover/pressed/focus의 배경과 테두리가 모두 투명함을 확인했다. 기본 돋보기 색은 `#15181e`, 선은 2.5px이며 오른쪽 40px 클릭 영역을 유지한다.
- 변경 TSX lint와 최적화 빌드를 통과했다. 실제 390×844, 1440×1000에서 입력 중 결과 유지, 클릭/Enter 검색과 회색 hero 내부 결과를 확인했다. 가로 넘침·브라우저 실행 오류 0건이다.
