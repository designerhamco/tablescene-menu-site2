# 스타터 번역·텍스트칩 공통 검수

## 확인된 원인

- Basic의 단일 페이지 번역은 상품명/설명만 적용하고 일반 칩과 추천 기본값은 한국어로 남겼다. 고정 UI 사전도 추천/베스트 외 기본 칩을 충분히 포함하지 않았다.
- MELLOW는 en/zh/ja 할인칩 번역본 안에 `모닝딜`, `재고 마감`을 그대로 넣고, 기존 테스트도 이 오기를 고정했다.
- 구매용 번역 생성은 단일 페이지에 한정됐고, 다이닝/디스플레이 미리보기 사전·가격 안내·옵션·위젯 번역과 분리돼 있었다. 단일 페이지 일반 칩도 한국어 원본을 외국어 행에 복사했다.

## 수정 계약

- 미리보기의 en/zh/ja 문구를 실제 구매 생성 ID에 연결해 기존 번역 테이블에 `completed`로 저장한다. 페이지/카테고리/전체 메뉴(직접 추가 메뉴 포함), 가격 옵션, 할인칩/문구, 텍스트 위젯을 포함한다. 기본·디자이너 디자인, 리스트·앨범, Basic·Dining·Display가 같은 경로를 사용한다.
- 기본 칩과 추천/타입 기본값은 현재 언어로 표시한다. 일반·대표상품·할인칩에 모두 적용한다. 사용자 직접 입력 문구/저장 번역은 보존하고, 기존 칩의 원래 색상 역할은 유지한다.
- 고객이 입력한 가게명은 번역본의 데모 이름으로 바꾸지 않는다. 숫자 가격·이미지·글꼴·간격은 유지한다. 공통 HOT/ICE/사이즈 역할 문구는 미리보기/저장 조회에서 같은 사전을 사용한다.
- 번역 저장 오류는 생성 실패다. 결제 재시도도 번역 누락을 검사하며, 기본 메뉴 행이 있다는 이유로 완료 처리하지 않는다. 완성된 스타터는 다시 생성하거나 고객 콘텐츠를 덮어쓰지 않는다.
- 기존 고객 메뉴의 일괄 수정/백필, 실제 결제, Production SQL/Storage 변경은 수행하지 않는다.

## 검증

- `lib/starter-translation-parity.test.ts`: 카탈로그 21개 디자인 × 3개 번역. 실제 생성 함수와 미리보기 원본을 비교하고, 삽입 결과 역순·직접 메뉴·옵션·위젯·할인 문구·칩 스타일·다이닝 언어 활성화·실패/재시도를 검증한다.
- `scripts/qa-catalog-starter-parity.mjs`: 실제 카탈로그 서버 라우트와 실제 생성 함수, 112개 확인 통과, 실제 결제/Production 쓰기 0건.
- `scripts/qa-starter-chip-locales.mjs`: 영어/중국어/일본어 × PC 1440×900 / 태블릿 1180×820 / 모바일 390×844. 일반칩·할인칩을 모두 검사한다. 브라우저 POST/쓰기 요청은 차단한다.
- 실제 언어 선택 버튼으로 MELLOW의 한국어 → 영어 → 중국어 전환과 일반/할인 칩 변경을 확인한다.

최종 로컬 결과(2026-11-11): 21개 디자인 × 3언어 × 3기기 = 189개 화면 조합 통과, 런타임 오류/쓰기 0건. 실제 생성/미리보기 비교 112건, 단위 1,229건, 공통 UI 137건, TypeScript·변경 파일 ESLint 통과. MELLOW의 실제 언어 선택 UI로 영어·중국어·일본어를 모두 확인했다. 구매 검증은 메모리 클라이언트로 실행했으며 실제 결제와 고객 데이터 쓰기는 0건이다.

디스플레이는 첫 홍보 화면 대신 실제 전체 메뉴 페이지(`page=3`)를 검수한다. 칩이 있는 Basic/Display 데이터는 최소 한 개의 실제 칩이 렌더링될 때까지 기다려, 초기 로딩/홍보 화면의 빈 목록으로 검수가 통과하지 않도록 한다.

온유의 TABLE SPECIAL/SEASONAL도 중국어·일본어 번역본을 분리한다. 모든 스타터의 zh/ja 할인칩이 원본 문구를 그대로 재사용하지 않는지 검증해, 한국어 누락뿐 아니라 영어 고정 문구도 재발을 막는다.

세 언어는 번역 테이블별로 묶어 한 번씩 저장한다. 초기 생성에서 언어 수만큼 네트워크 요청이 늘지 않도록 삽입 호출 수도 검증한다.
