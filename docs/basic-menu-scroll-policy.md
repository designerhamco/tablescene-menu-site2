# REAL MATCHA 원페이지 스크롤 배치 규칙

적용: `cafe_design_a`의 단일 페이지 PC·태블릿과 호환 테스트 `cafe_real_matcha_paged_test`. 모바일, 다른 여섯 Basic 템플릿, 다이닝 멀티페이지와 Display는 각자의 기존 엔진을 유지한다.

## 읽기 크기를 유지하고 넘침 허용

원페이지는 여러 페이지로 분할하지 않는다는 뜻이다. 대표열과 하단 액션은 고정하고, 메뉴만 하나의 공통 세로 스크롤 영역을 사용한다. 묶음형과 채움형은 동일한 기기별 읽기 상한 크기와 기본 간격을 사용한다. 내용이 넘치면 두 방식 모두 메뉴 안에서 스크롤한다. 배치 전환을 이유로 글자를 축소하거나 확대하지 않는다.

- 기존 공통 상품명/가격 하한 `1rem`, PC 상한 `1.35rem`, 태블릿 상한 `1.30rem`을 재사용한다. 각 실제 열 폭에서 같은 기기별 읽기 크기를 측정한다. 큰 화면에서도 상한을 넘지 않는다.
- 기존 세 의미 필드 참조와 실제 전체 문장을 모두 검사한다. 참조는 측정 중에만 켜고 실제 화면에 빈 줄을 만들지 않는다. 실제 긴 문장·가격·이미지·칩이 참조보다 크면 그 높이도 우선한다.
- 카테고리 = 상품명 × 1.6 × 저장 역할 배율, 설명/대표 설명/가게 설명/안내는 기존 지원 문구 토큰, 보조명은 기존 역할 비율을 공유한다. 저장된 서체·색상·굵기·두 필드 5% 예외는 공유 컴포넌트에서 유지한다. 안내의 모든 문자는 저장한 한글 서체를 사용한다.
- 기존 공통 ordered gap mapper와 0.74 계수, 상품의 1/1.10/1.20 리듬, REAL MATCHA 카테고리 경계 2.9를 사용한다. 카테고리 경계가 상품 간격에 중복 가산되지 않는다. 가격옵션명 간격과 상품 내부 문구 간격은 기존 컴포넌트가 관리한다.

## 열 수와 두 가지 배치

카테고리 제목(설명이 있으면 설명 포함)부터 첫 상품까지는 기존 제목 비율과 상품 기본 간격 × 1.25 중 큰 값을 사용한다. 상품 간 최대 리듬 1.20보다 아주 조금 넓게 두되, 카테고리·위젯·안내 경계 2.9와 상품 내부 간격은 유지한다. 모바일 위임 경로는 사용자 요청으로 제목 아래만 24→26px로 바꾸며 상품 20px/섹션 48px는 유지한다.

대표열을 제외한 메뉴 영역에서 **상품명 가독성을 기준으로 2·3열을 비교**한다. 자동 4열은 사용하지 않는다. 내용이 매우 적거나 실제 메뉴 열의 안쪽 폭 12rem를 두 열 모두 확보할 수 없으면 기존 1열 예외를 유지한다. 한 열은 최대 40rem로 제한해 지나치게 긴 행을 방지한다. CSS grid의 소수점 내부 폭과 안정된 스크롤바 공간을 사용한다.

- 각 후보를 **동일한 기기별 읽기 상한 크기**에서 먼저 렌더링하고 썸네일·가격 열·간격·칩 배치 후 남은 상품명 폭과 실제 텍스트 줄 수를 측정한다. 3열 글자를 먼저 줄여 좁은 이름 공간을 감추지 않는다. 한국어/영어 등 실제 서체·단어 줄바꿈을 사용하며 글자 수나 가격 옵션 개수만으로 열을 강제하지 않는다.
- 2열에서 이름 폭이 15% 이상 늘고 실제 줄바꿈/가로 잘림이 개선되는지 확인한다. 3줄 이상 이름 또는 가로 잘림 하나가 개선되면 2열을 우선한다. 2줄 이름은 자연 너비와 8em 중 작은 폭을 기준으로 여러 상품(최소 2개)이 좁아진 경우에만 2열을 우선한다. 정상적인 한 상품의 2줄 제목이나 열을 넓혀도 개선되지 않는 긴 이름은 단독 전환 사유가 아니다.
- 이 가독성 판단은 한 화면 맞춤·점유율보다 우선한다. 3열이 한 화면에 들어가더라도 2열에서 상품명을 훨씬 잘 읽을 수 있으면 2열을 선택하고 넘치는 내용은 스크롤한다. 양쪽 모두 읽기 좋은 경우 아래의 기존 내용량/높이 기준을 사용한다.

1. 채움형은 각 열 수를 같은 기기별 읽기 크기로 실측한다. 가독성 기준을 충족하는 후보 중 한 화면에 들어가는 배치를 우선하고, 모두 넘치면 실제 스크롤 길이가 가장 짧은 배치를 고른다. 묶음형도 같은 기기별 읽기 크기를 사용하고 카테고리를 통째로 배치한다. 한 화면에 맞추기 위한 별도 이진 탐색/축소는 사용하지 않는다.
2. **채움형**은 카테고리 제목+첫 상품을 한 단위로 두고, 이후 상품은 다음 열로 이어질 수 있다. 카테고리 제목은 한 번만 표시한다. 연속 단위의 최대 열 높이를 최소화하여 균형을 잡는다. 등록된 카테고리·상품·위젯 순서를 바꾸지 않는다.
3. **묶음형**은 카테고리 전체를 한 단위로 두어 분리하지 않는다. 긴 카테고리는 그대로 스크롤로 이어진다. 채움형의 간격 확장은 하지 않는다.
4. 빈 열을 배제한다. 채움형은 한 화면에 들어가는 후보 중 평균 자연 높이 점유율 80% 이상을 우선하고, 같은 조건에서는 더 많은 읽기 열을 쓴다. 희박하면 더 적은 열을 사용한다. 묶음형은 다른 안전 후보보다 글자를 8% 넘게 줄여야 하는 열 수를 여백 개선만을 위해 선택하지 않는다. 한 화면에 들어가는 후보가 있으면 점유율만을 이유로 넘치는 후보를 선택하지 않는다. 상품명 가독성을 위한 2열 선택은 이 여백 순위와 별개의 상위 기준이다.

## 상하 균형과 하단 영역

- 페이지 네 면의 여백은 원본 적응형 보드와 같은 PC `clamp(2rem, 4.2vmin, 4.25rem)`, 세로 태블릿(768–1023px 폭) `clamp(1.25rem, 3vmin, 2rem)`이다. 가로 태블릿은 원본처럼 PC 폭 구간을 따른다. 대표열→메뉴, 메뉴 열→메뉴 열, 숨김 측정 폭의 gutter는 모두 이 페이지 여백과 같다. 실제 DOM 소수점 폭과 이 gutter로 후보를 다시 계산한다.
- 버튼 위의 실제 빈 안전여백은 페이지 여백의 75%를 사용하되 `clamp(.875rem, 페이지 여백 × .75, 1.25rem)`으로 14–20px에 묶는다(기본 16px 루트). 큰 바깥 여백이 버튼 위에 그대로 추가되지 않도록 한 작은 예외다. 내용이 페이드에 가려지는 영역과 별도로 확보하며 버튼이 없을 때는 공간을 만들지 않는다.

- 호출·주문 버튼의 실제 높이와 버튼 위 간격을 제외한 **메뉴 viewport 전체 높이**를 사용한다. 안내 높이를 모든 열에서 일괄 차감하지 않는다.
- 안내 1/2/3은 마지막 실제 메뉴 열에서만 높이를 사용한다. 안내만 남은 빈 열을 만들지 않으며 마지막 카테고리 또는 위젯 다음에 표시한다. 그 앞 간격은 카테고리↔카테고리, 카테고리↔위젯, 위젯↔위젯과 동일한 REAL MATCHA 2.9 경계 토큰이다. 남은 화면 높이로 이 간격을 늘리지 않는다.
- 채움형은 기존 상품·카테고리·위젯·안내 간격의 의미 비율을 그대로 유지한다. 남은 높이를 메우려고 간격을 늘리거나 메뉴 열 전체를 아래로 내리지 않는다. 열 마지막의 불필요한 간격은 제거하되 실제 안내가 있는 마지막 열은 그 경계를 유지한다.
- 채움형의 마지막 실제 메뉴/안내 뒤에는 페이지 바깥 여백과 동일한 하단 안전여백을 **스크롤 영역 안에만** 둔다. 스크롤을 허용하되 이 빈 여백만 남았을 때는 페이드로 추가 메뉴를 암시하지 않는다. 묶음형에는 이 여백을 추가하지 않는다.
- 위젯은 저장된 순서대로 카테고리와 같은 수준의 블록으로 흐른다. 맨 마지막 위젯과 안내 사이도 동일한 카테고리 경계 간격을 쓴다. 별도의 위젯 상단 고정 여백이나 하단 자동 밀기는 두지 않는다.
- 실제 메뉴/안내 내용이 viewport 아래에 2px 넘게 남을 때만 배경색 페이드를 표시한다. 마지막에 도달하거나 내용이 적으면 숨긴다. 페이드는 터치를 가로채지 않는다. 하단 안전여백만으로 페이드를 켜지 않는다.

## 재측정과 회귀

내용/가격/옵션/이미지/위젯/안내/서체/기기/화면 폭·높이/기능 변화마다 새 후보를 측정한다. ID나 개수가 같아도 문구 변경을 반영한다. 할인 카운트다운 초 단위 갱신은 측정 원인이 아니다. 폰트 로딩과 방향 전환 후에도 측정 폭·칩 위치·최종 렌더링이 같아야 한다.

`lib/basic-menu-scroll.test.ts`, `scripts/qa-real-matcha-fill.mjs`는 순서·제목 중복·열 수·간격 상한·실제 viewport·읽기 크기·고정영역·페이드·희박/빈/밀집/긴 문구·안내·위젯·텍스트 확대·상태 안정성을 검사한다. `scripts/qa-basic-readable-columns.mjs`는 태블릿 2열/큰 PC 3열, 같은 문서의 폭 변경, 이미지/가격 옵션 전환에 따른 재선택과 이름/가격/썸네일 경계를 검사한다. 기존 주문/모바일/다이닝 회귀도 통과해야 한다.

## 기본 좌상단 배치형 예외 (2026-10-20)

기본 좌상단형은 사용자 변경 요청에 따라 대표영역을 고정하지 않는다. 첫 번째 메뉴 열의 선행 블록으로 렌더링하고 실제 높이+공통 간격을 분배 계산에 한 번만 포함한다. 메뉴와 함께 스크롤하며 하단 호출/주문 액션은 고정한다. 대표 이미지 부분은 PC·태블릿·모바일 모두 4:3이며, 대표영역 전체는 언어/가게명/설명과 이미지의 자연 높이를 사용한다. 다른 대표열/상단행 고정·기존 디자이너 좌상단 엔진·모바일에는 적용하지 않는다.

## 기본 디자인 시안 상품 크기 보정 (2026-10-20)

기본 베이직 4종만 상품 블록과 대표상품의 이름·가격·보조명·설명을 공통 기기별 크기의 94%로 표시한다(기존 읽기 하한 유지). 측정 행과 실제 행에 같은 토큰을 적용하므로 남은 이름 폭/줄바꿈 기준 2·3열 선택은 실제 보이는 크기를 사용한다. 카테고리/가게명/안내 크기와 공통 간격은 이전 참조 크기를 유지한다. 묶음형/채움형은 이 보정도 동일하게 공유한다. 원본 REAL MATCHA 및 다른 디자이너 템플릿과 모바일에는 적용하지 않는다.

기본 1열/중앙열의 4:5 대표 이미지는 가용 대표열 맨 아래에 맞춘다. 중앙형은 이미지 아래 24px 경계와 고정 호출/주문 버튼을 유지한다. 좌상단형은 앞 절의 자연 높이/스크롤 예외를 계속 따른다.
