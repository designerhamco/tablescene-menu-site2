# REAL MATCHA 원페이지 스크롤 배치 규칙

적용: `cafe_design_a`의 단일 페이지 PC·태블릿과 호환 테스트 `cafe_real_matcha_paged_test`. 모바일, 다른 여섯 Basic 템플릿, 다이닝 멀티페이지와 Display는 각자의 기존 엔진을 유지한다.

## 한 화면을 우선하고 읽기 하한부터 넘침 허용

원페이지는 여러 페이지로 분할하지 않는다는 뜻이다. 대표열과 하단 액션은 고정하고, 메뉴만 하나의 공통 세로 스크롤 영역을 사용한다. 묶음형·채움형 모두 읽을 수 있는 후보가 한 화면에 들어가는지 먼저 검사한다. 읽기 하한에서도 넘치는 내용은 잘라내거나 글자를 계속 줄이지 않고 스크롤로 이어진다.

- 기존 공통 상품명/가격 하한 `1rem`, PC 상한 `1.35rem`, 태블릿 상한 `1.30rem`을 재사용한다. 각 실제 열 폭·높이에서 가장 큰 안전 후보를 측정한다. 큰 화면에서도 상한을 넘지 않는다.
- 기존 세 의미 필드 참조와 실제 전체 문장을 모두 검사한다. 참조는 측정 중에만 켜고 실제 화면에 빈 줄을 만들지 않는다. 실제 긴 문장·가격·이미지·칩이 참조보다 크면 그 높이도 우선한다.
- 카테고리 = 상품명 × 1.6 × 저장 역할 배율, 설명/대표 설명/가게 설명/안내는 기존 지원 문구 토큰, 보조명은 기존 역할 비율을 공유한다. 저장된 서체·색상·굵기·두 필드 5% 예외는 공유 컴포넌트에서 유지한다. 안내의 모든 문자는 저장한 한글 서체를 사용한다.
- 기존 공통 ordered gap mapper와 0.74 계수, 상품의 1/1.10/1.20 리듬, REAL MATCHA 카테고리 경계 2.9를 사용한다. 카테고리 경계가 상품 간격에 중복 가산되지 않는다. 가격옵션명 간격과 상품 내부 문구 간격은 기존 컴포넌트가 관리한다.

## 열 수와 두 가지 배치

폭 12rem 이상인 메뉴 열을 최대 세 개까지 실제 폭으로 각각 측정한다. 한 열은 최대 40rem로 제한해 지나치게 긴 행을 방지한다. CSS grid의 소수점 내부 폭과 안정된 스크롤바 공간을 사용한다.

1. 각 열 수에서 공통 글자 상·하한 사이의 최대 한 화면 후보를 찾는다. 어떤 후보도 한 화면에 들어가지 않으면 읽기 하한에서 최대 세 열의 내부 스크롤을 사용한다.
2. **채움형**은 카테고리 제목+첫 상품을 한 단위로 두고, 이후 상품은 다음 열로 이어질 수 있다. 카테고리 제목은 한 번만 표시한다. 연속 단위의 최대 열 높이를 최소화하여 균형을 잡는다. 등록된 카테고리·상품·위젯 순서를 바꾸지 않는다.
3. **묶음형**은 카테고리 전체를 한 단위로 두어 분리하지 않는다. 긴 카테고리는 그대로 스크롤로 이어진다. 채움형의 간격 확장은 하지 않는다.
4. 빈 열을 배제한다. 채움형은 한 화면에 들어가는 후보 중 평균 자연 높이 점유율 80% 이상을 우선하고, 같은 조건에서는 더 많은 읽기 열을 쓴다. 희박하면 더 적은 열을 사용한다. 단, 다른 안전 후보보다 글자를 8% 넘게 줄여야 하는 열 수는 여백 개선만을 위해 선택하지 않는다. 한 화면에 들어가는 후보가 있으면 점유율만을 이유로 넘치는 후보를 선택하지 않는다.

## 상하 균형과 하단 영역

- 호출·주문 버튼의 실제 높이와 버튼 위 간격을 제외한 **메뉴 viewport 전체 높이**를 사용한다. 안내 높이를 모든 열에서 일괄 차감하지 않는다.
- 안내 1/2/3은 마지막 실제 메뉴 열에서만 높이를 사용한다. 안내만 남은 빈 열을 만들지 않으며 마지막 위젯보다 아래에 표시한다.
- 채움형은 글자와 내부 문구 간격을 늘리지 않고 기존 외부 리듬을 최대 1.6배까지 균등하게 확장할 수 있다. 열 마지막의 불필요한 간격은 제거한다. 안내 직전 기본 간격은 확장하지 않는다.
- 제한된 확장 후에도 전체가 짧으면 같은 상단선을 유지한 **메뉴 열 전체**를 메뉴 viewport 안에서 세로 가운데 정렬한다. 상단 페이지 여백을 일괄 추가하거나 열별로 따로 가운데 정렬하지 않는다. 내용이 넘치면 상단 inset은 0이다.
- 마지막 bottom 위젯 묶음의 첫 위젯만 유연한 공간을 받고, 뒤의 위젯과 안내는 붙어 이어진다. 모든 위젯 각각에 auto margin을 주지 않는다.
- 더 읽을 내용이 실제로 2px 넘게 남을 때만 배경색 페이드를 표시한다. 마지막에 도달하거나 내용이 적으면 숨긴다. 페이드는 터치를 가로채지 않는다. 빈 메뉴를 채우거나 스크롤을 암시하려고 가짜 높이를 만들지 않는다.

## 재측정과 회귀

내용/가격/옵션/이미지/위젯/안내/서체/기기/화면 폭·높이/기능 변화마다 새 후보를 측정한다. ID나 개수가 같아도 문구 변경을 반영한다. 할인 카운트다운 초 단위 갱신은 측정 원인이 아니다. 폰트 로딩과 방향 전환 후에도 측정 폭·칩 위치·최종 렌더링이 같아야 한다.

`lib/basic-menu-scroll.test.ts`, `scripts/qa-real-matcha-fill.mjs`는 순서·제목 중복·열 수·간격 상한·실제 viewport·읽기 크기·고정영역·페이드·희박/빈/밀집/긴 문구·안내·위젯·텍스트 확대·상태 안정성을 검사한다. 기존 주문/모바일/다이닝 회귀도 통과해야 한다.
