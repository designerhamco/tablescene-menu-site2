# 아티메뉴 베이직 PC·태블릿 읽기 배치 규칙

적용: `cafe_design_a`의 단일 페이지 PC·태블릿과 호환 테스트 `cafe_real_matcha_paged_test`. 여섯 기존 Basic 스킨도 `NativeBasicScroll`에서 같은 열 선택 함수를 재사용한다. 모바일, 다이닝 멀티페이지와 Display는 독립 엔진을 유지한다.

## 읽기 크기를 유지하고 넘침 허용

### 상단행 배치의 전체 스크롤 — 2026-11-13 현재 규칙

“상단행 고정형”은 대표 정보를 상단 행에 배치한다는 구조 이름이며, 상단을 화면에 고정한다는 의미가 아니다. PC·태블릿의 일반형과 왼쪽 로고형, 네이티브·기본 리스트/앨범 모두 가게 설명·가게명/로고·안내와 메뉴가 하나의 바깥 스크롤 안에서 함께 이동한다. 상단만 남겨두는 메뉴 전용 내부 스크롤을 사용하지 않는다. 열 선택의 높이 기준은 실제 viewport에서 상단/여백/액션 높이를 뺀 값으로 유지하고, 늘어난 콘텐츠 높이를 다시 배치 기준으로 삼지 않는다. 대표 사진의 기존 크기, 호출/주문 액션 접근, 말줄임·정렬·상단 여백과 메뉴 사이 간격을 보존한다. 다른 배치 형식과 모바일의 기존 스크롤은 독립적이다. 아래의 메뉴 전용 스크롤 설명은 이 상단행 예외를 제외한 기존 형식에 적용한다.

원페이지는 여러 페이지로 분할하지 않는다는 뜻이다. 대표열과 하단 액션은 고정하고, 메뉴만 하나의 공통 세로 스크롤 영역을 사용한다. 묶음형과 채움형은 동일한 기기별 읽기 상한 크기와 기본 간격을 사용한다. 내용이 넘치면 두 방식 모두 메뉴 안에서 스크롤한다. 배치 전환을 이유로 글자를 축소하거나 확대하지 않는다.

- 기존 공통 상품명/가격 하한 `1rem`, PC 상한 `1.35rem`, 태블릿 상한 `1.30rem`을 재사용한다. 각 실제 열 폭에서 같은 기기별 읽기 크기를 측정한다. 큰 화면에서도 상한을 넘지 않는다.
- 기존 세 의미 필드 참조와 실제 전체 문장을 모두 검사한다. 참조는 측정 중에만 켜고 실제 화면에 빈 줄을 만들지 않는다. 실제 긴 문장·가격·이미지·칩이 참조보다 크면 그 높이도 우선한다.
- 카테고리 = 상품명 × 1.6 × 저장 역할 배율, 설명/대표 설명/가게 설명/안내는 기존 지원 문구 토큰, 보조명은 기존 역할 비율을 공유한다. 저장된 서체·색상·굵기·두 필드 5% 예외는 공유 컴포넌트에서 유지한다. 안내의 모든 문자는 저장한 한글 서체를 사용한다.
- 기존 공통 ordered gap mapper와 0.74 계수, 상품의 1/1.10/1.20 리듬, REAL MATCHA 카테고리 경계 2.9를 사용한다. 카테고리 경계가 상품 간격에 중복 가산되지 않는다. 가격옵션명 간격과 상품 내부 문구 간격은 기존 컴포넌트가 관리한다.

## 열 수와 두 가지 배치

카테고리 제목(설명이 있으면 설명 포함)부터 첫 상품까지는 기존 제목 비율과 상품 기본 간격 × 1.25 중 큰 값을 사용한다. 상품 간 최대 리듬 1.20보다 아주 조금 넓게 두되, 카테고리·위젯·안내 경계 2.9와 상품 내부 간격은 유지한다. 모바일 위임 경로는 사용자 요청으로 제목 아래만 24→26px로 바꾸며 상품 20px/섹션 48px는 유지한다.

대표열을 제외한 메뉴 영역에서 **상품명·카테고리명 가독성을 기준으로 허용된 1·2·3열을 비교**한다. 자동 4열은 사용하지 않는다. 자동 메뉴 열의 공통 최소 안쪽 폭은 `SCROLL_MIN_COLUMN_WIDTH_REM = 16`(기본 루트에서 256px)이며, 대표열·패널 안쪽 여백·열 간격·분리선·스크롤바를 제외한 실제 공간으로 후보를 만든다. 이전 12rem는 좁은 세로 화면에 지나치게 많은 열을 허용하므로 대체한다. 최소 폭 통과가 가독성 통과를 뜻하지는 않는다. 넓은 1열 후보가 실제 상품명/카테고리명의 과한 줄바꿈이나 잘림을 개선하면 2·3열보다 먼저 선택하고 넘치는 내용은 스크롤한다. CSS grid의 소수점 내부 폭과 안정된 스크롤바 공간을 사용한다. 중앙 대표열의 기존 양쪽 두 트랙은 등록 구조 예외를 유지한다.

- 각 후보를 **동일한 기기별 읽기 상한 크기**에서 먼저 렌더링하고 썸네일·가격 열·간격·칩 배치 후 남은 상품명 폭과 실제 텍스트 줄 수를 측정한다. 3열 글자를 먼저 줄여 좁은 이름 공간을 감추지 않는다. 한국어/영어 등 실제 서체·단어 줄바꿈을 사용하며 글자 수나 가격 옵션 개수만으로 열을 강제하지 않는다.
- 넓은 후보에서 이름 폭이 15% 이상 늘고 실제 줄바꿈/가로 잘림이 개선되는지 확인한다. 3줄 이상 이름 또는 가로 잘림 하나가 개선되면 넓은 후보를 우선한다. 2줄 이름은 자연 너비와 8em 중 작은 폭을 기준으로 여러 상품(최소 2개)이 좁아진 경우에만 우선한다. 정상적인 한 상품의 2줄 제목이나 열을 넓혀도 개선되지 않는 긴 이름은 단독 전환 사유가 아니다. 3→2열뿐 아니라 2→1열과 선택된 3열→1열 후보에도 같은 판정을 적용한다.
- 카테고리명도 가격옵션 헤더를 제외한 실제 너비와 줄 수를 측정한다. 두 개 이상 카테고리의 줄바꿈이 넓은 후보에서 줄면 그 넓은 후보를 우선한다. 보통 2줄 상품명도 최소 3개·전체 상품 30% 이상에서 반복되며 넓은 후보가 최소 3줄 및 원래 줄바꿈 상품 수의 35% 이상을 해소할 때 전환할 수 있다. 기존 8em의 심한 좁음 판단은 유지한다.
- 이 가독성 판단은 한 화면 맞춤·점유율보다 우선한다. 3열이 한 화면에 들어가더라도 2열에서 상품명을 훨씬 잘 읽을 수 있으면 2열을 선택하고 넘치는 내용은 스크롤한다. 양쪽 모두 읽기 좋은 경우 아래의 기존 내용량/높이 기준을 사용한다.

1. 채움형은 각 열 수를 같은 기기별 읽기 크기로 실측한다. 가독성 기준을 충족하는 후보 중 한 화면에 들어가는 배치를 우선하고, 모두 넘치면 실제 스크롤 길이가 가장 짧은 배치를 고른다. 묶음형도 같은 기기별 읽기 크기를 사용하고 카테고리를 통째로 배치한다. 한 화면에 맞추기 위한 별도 이진 탐색/축소는 사용하지 않는다.
2. **채움형**은 카테고리 제목+첫 상품을 한 단위로 두고, 이후 상품은 다음 열로 이어질 수 있다. 카테고리 제목은 한 번만 표시한다. 연속 단위의 최대 열 높이를 최소화하여 균형을 잡는다. 등록된 카테고리·상품·위젯 순서를 바꾸지 않는다.
3. **묶음형**은 카테고리 전체를 한 단위로 두어 분리하지 않는다. 긴 카테고리는 그대로 스크롤로 이어진다. 채움형의 간격 확장은 하지 않는다.
4. 빈 열을 배제한다. 채움형은 한 화면에 들어가는 후보 중 평균 자연 높이 점유율 80% 이상을 우선하고, 같은 조건에서는 더 많은 읽기 열을 쓴다. 희박하면 더 적은 열을 사용한다. 묶음형은 다른 안전 후보보다 글자를 8% 넘게 줄여야 하는 열 수를 여백 개선만을 위해 선택하지 않는다. 한 화면에 들어가는 후보가 있으면 점유율만을 이유로 넘치는 후보를 선택하지 않는다. 상품명 가독성을 위한 더 넓은 열 선택은 이 여백 순위와 별개의 상위 기준이다.

### 실제 열 끝 높이 비교 — 2026-10-20

상품명 가독성 우선 판단 뒤에 3열이 선택되면, 같은 서체·크기에서 측정한 2열과 끝 높이를 비교한다. 3열의 최대/최소 높이 차이가 viewport의 40% 이상이면서 최대 열 높이의 45% 이상인 심한 불균형에만 적용한다. 2열은 그 차이를 40% 이상 줄이고, 각 열 최대 높이 기준 미사용 면적 비율을 8%p 이상 줄여야 한다. 추가 스크롤은 viewport의 35% 이하여야 한다. 3열이 한 화면에 들어가는데 2열만 넘치면 여백 개선으로 전환하지 않는다. 읽기 크기를 8% 넘게 줄이는 후보도 제외한다.

등록 순서·묶음/채움 의미·상품명 측정 우선순위는 유지한다. 중앙 대표열은 기존 양쪽 두 트랙을 유지한다. 특정 템플릿 이름이나 아이템 개수로 열을 강제하지 않는다. 일반적인 높이 차이나 원래 균형이 좋은 채움형은 그대로 두며, 모바일에는 적용하지 않는다.

## 좁은 화면의 전체 열 수 — 2026-11-11

위 ‘메뉴 열 수’에는 고정 대표열이 포함되지 않는다. 대표열 1 + 메뉴 2는 전체 3열이고, 대표열 1 + 메뉴 1은 전체 2열이다. 폭 820px·768px에서 대표열까지 빼면 메뉴 열이 약 225–241px였던 리얼맛차 사례는 16rem 최소 폭에 못 미치므로 전체 2열로 내려간다. 캡처와 같은 옵션에서 820px의 대표/메뉴 실제 안쪽 너비는 각각 약 373px이다. 화면 방향이나 템플릿명으로 고정하지 않으며, 넓어진 실제 공간에서 후보를 다시 평가한다.

같은 글자 크기·역할 비율에서 열 수만 바꾼다. 이 기준을 통과시키려고 글자/보조명/설명을 축소하거나 대표영역을 상단으로 옮기지 않는다. 묶음형의 카테고리 보존·채움형의 이어붙이기·등록 순서·모바일의 독립 읽기 규칙과 다이닝의 별도 페이지 구조를 유지한다. `lib/basic-menu-scroll.ts`의 같은 상수를 정식 기본 디자인과 네이티브 베이직 측정기가 함께 사용한다.

## 대표열과 메뉴 열의 동일 너비 — 2026-11-11

리스트·앨범형의 **별도 왼쪽 대표열**과 선택된 각 메뉴 열은 같은 실제 사용 너비를 갖는다. 1열 고정형뿐 아니라 상단행 고정형의 본문(가운데 로고형·로고 왼쪽형 모두)에 적용한다. 리얼맛차·루프베이글·선데이·반고흐·MELLOW와 해당 기본 디자인은 같은 `lib/representative-rail-geometry.ts`를 사용한다. 대표 1 + 메뉴 1은 5:5, 대표 1 + 메뉴 2는 1:1:1, 대표 1 + 메뉴 3은 1:1:1:1이며 메뉴 수는 기존 실제 폭·읽기·배치 계산으로 결정한다.

본문에서 페이지 안쪽 여백과 실제 외부 margin을 뺀 너비를 W, 대표 패널의 내부 좌우 padding 합을 P, 대표→메뉴 간격을 G, 메뉴→메뉴 간격을 D, 메뉴 스크롤바를 S, 메뉴 열 수를 N이라 하면 각 열의 사용 너비는 `(W − P − G − (N − 1) × D − S) ÷ (N + 1)`이다. 대표 패널의 색칠된 폭은 이 너비에 P를 더한 값이다. 색이 있는 상단행의 전체 폭 헤더와 달리 본문에는 좌우 margin이 남으므로 W에서 이를 반드시 제외한다. 분리선 없는 G는 페이지 안쪽 여백 한 개, 선이 있는 D는 여백 두 개와 선 두께를 합한 값이다. 선이 없으면 D=G다.

숨김 측정 후보와 최종 grid가 같은 계산을 사용한다. 리스트는 같은 글자 크기에서 1·2·3열 후보의 가독성·배치 결과를 비교한다. 앨범은 16rem 최소 폭을 통과하는 최대 1·2·3열을 명시적으로 렌더링하고, 왼쪽 가게명/설명 넘침 검사가 실패하면 더 넓은 열로 재시도한다. CSS auto-fill이 대표열 계산과 다른 카드 수를 만들지 않도록 한다. 같은 문서의 폭 변경·폰트 로딩·대표영역 ON/OFF에도 다시 측정한다.

상단행에서 대표영역 OFF이면 본문의 이미지 열을 제거하고 메뉴가 전체 본문 너비를 사용한다. 상단행의 헤더 세 칸과 가게명 크기/정렬/안내 위치는 별도 규칙을 유지한다. 중앙열형은 등록된 중앙 슬롯과 양쪽 메뉴 구조, 좌상단형은 첫 메뉴 패널 안의 대표영역과 동일 패널 폭을 유지한다. 기존 기기별 이미지 비율·색·폰트·묶음/채움 의미·순서·호출/주문, 모바일과 다이닝은 변경하지 않는다.

## 상하 균형과 하단 영역

- 페이지 네 면의 여백은 원본 적응형 보드와 같은 PC `clamp(2rem, 4.2vmin, 4.25rem)`, 세로 태블릿(768–1023px 폭) `clamp(1.25rem, 3vmin, 2rem)`이다. 가로 태블릿은 원본처럼 PC 폭 구간을 따른다. 분리선이 없는 대표열→메뉴, 메뉴 열→메뉴 열, 숨김 측정 폭의 gutter는 이 페이지 여백과 같다. 세로 분리선이 있는 메뉴 열 경계는 선 양쪽에 각각 페이지 안쪽 여백을 확보한다(전체 gutter = 여백 × 2 + 선 두께). 실제 DOM 소수점 폭과 이 gutter로 후보를 다시 계산한다.
- 버튼 위의 실제 빈 안전여백은 페이지 여백의 75%를 사용하되 `clamp(.875rem, 페이지 여백 × .75, 1.25rem)`으로 14–20px에 묶는다(기본 16px 루트). 큰 바깥 여백이 버튼 위에 그대로 추가되지 않도록 한 작은 예외다. 내용이 페이드에 가려지는 영역과 별도로 확보하며 버튼이 없을 때는 공간을 만들지 않는다.

- 호출·주문 버튼의 실제 높이와 버튼 위 간격을 제외한 **메뉴 viewport 전체 높이**를 사용한다. 안내 높이를 모든 열에서 일괄 차감하지 않는다.
- 안내 1/2/3은 마지막 실제 콘텐츠 뒤에 자연스럽게 표시한다. 안내만 남은 빈 열을 만들지 않는다. 일반 상단행 고정형은 상단 오른쪽 안내를 유지하고, 로고 왼쪽형과 중앙열/1열/좌상단형은 콘텐츠 뒤에 표시한다. 화면/열 바닥으로 밀어내는 auto 간격은 사용하지 않는다.
- 채움형은 기존 상품·카테고리·위젯·안내 간격의 의미 비율을 그대로 유지한다. 남은 높이를 메우려고 간격을 늘리거나 메뉴 열 전체를 아래로 내리지 않는다. 열 마지막의 불필요한 간격은 제거하되 실제 안내가 있는 마지막 열은 그 경계를 유지한다.
- 채움형의 마지막 실제 메뉴/안내 뒤에는 페이지 바깥 여백과 동일한 하단 안전여백을 **스크롤 영역 안에만** 둔다. 스크롤을 허용하되 이 빈 여백만 남았을 때는 페이드로 추가 메뉴를 암시하지 않는다. 묶음형에는 이 여백을 추가하지 않는다.
- 모든 위젯은 카테고리 단위의 순서형 흐름이다. 맨 위/카테고리 사이/맨 아래로 자유롭게 이동하며 별도 배치 선택과 이동 잠금을 제거한다. 기존 bottom도 원래 순서를 유지한 flow로 읽고 새 저장값은 flow다. 모바일도 같은 순서를 따르되 독립 읽기 간격을 유지한다.
- 실제 메뉴/안내 내용이 viewport 아래에 2px 넘게 남을 때만 배경색 페이드를 표시한다. 마지막에 도달하거나 내용이 적으면 숨긴다. 페이드는 터치를 가로채지 않는다. 하단 안전여백만으로 페이드를 켜지 않는다.

### 검수 실행과 결과의 범위

`ORDER_QA_BASE=http://localhost:3027 npm run qa:basic-equal-tracks`로 실행한다. `ORDER_QA_BASE`는 확인할 실제 서버, `ORDER_QA_OUTPUT`은 결과 폴더(기본 `/private/tmp/basic-equal-tracks`)다. 실제 선택된 iframe/DOM 크기와 렌더링이 안정된 뒤 대표/메뉴/카드·숨김 후보 폭, 왕복 크기 변경, 순서, 읽기 글자 크기, 색 패널/분리선, 대표영역 OFF와 모바일 독립성을 검사한다. `EQUAL_QA_PC_ONLY=1`은 실제 PC 모드만 확인하는 후속 실행이다.
