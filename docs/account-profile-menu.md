# 아티메뉴 계정 프로필과 헤더 메뉴

2026-11-25. 공식 사이트의 본인 계정 표시이며 실제 메뉴판의 로고·이미지·계정 권한과 독립한다.

## 표시와 이동

- PC 전체 헤더(1280px 이상)는 만들기 오른쪽의 44px 프로필을 누르면 공통 Popover로 계정 레이어를 연다. 이름·이메일·역할, 접근 가능한 내 메뉴판 수, 사장 계정의 AI 잔액·직원 수와 기존 충전/관리/구독 화면 링크, 로그아웃을 제공한다. Escape·바깥 클릭과 포커스 복귀는 공유 Popover가 담당한다.
- 모바일/태블릿 전체 메뉴에는 이름 옆 프로필을 둔다. 누르면 레이어를 중첩하지 않고 `/mypage?tab=account`로 이동한다. 모바일 마이페이지 계정 요약에도 같은 프로필 링크를 둔다.
- 사진이 없거나 이미지 로드에 실패하면 계정 ID로 결정되는 여섯 가지 기본 색 중 하나를 보여준다. 글자·임의 외부 소셜 사진을 넣지 않는다. 색상은 역할이나 권한을 뜻하지 않는다.
- 계정 요약 API는 로그인 세션 본인만 조회한다. 메뉴 접근/소유 관계는 기존 서버 접근 서비스로 확인하며, 직원만인 계정에는 결제·AI 구매·직원 관리 항목을 제공하지 않는다. 읽기 실패는 임의의 0으로 대체하지 않는다. 화면 표시용 메타데이터를 권한 판정에 사용하지 않는다.

## 사진 저장

- 회원정보 화면에서 파일 선택·변경 또는 기본 이미지 선택은 로컬 초안이며 **저장**을 눌러 확정한다. PNG/JPG/WebP 1장, 최대 3MB. 서버에서 실제 형식/디코딩/정지 이미지 여부와 요청 스트림 크기를 검사한다. 방향 보정 후 중앙 512×512 WebP로 변환하고 EXIF를 제거한다.
- 기존 공개 `menu-images` 버킷의 `account-avatars/<session-user-id>/<random-uuid>.webp`를 사용한다. 기존 공지 이미지와 마찬가지로 서버 전용 Storage client만 쓴다. 사진 URL은 공개 이미지 주소이며 계정·이메일 등의 문자열을 파일명에 넣지 않는다. 새 버킷·DB 스키마·Storage 정책·인증 설정 변경은 없다.
- `POST/DELETE /api/account/avatar`는 같은 출처·실제 인증 사용자·탈퇴 상태를 확인한다. 클라이언트의 대상 user ID·기존 경로·외부 URL을 받지 않는다. 본인의 `profile_avatar_path` 메타데이터만 갱신하며 직원도 자기 사진만 바꾼다.
- 불변 새 파일 업로드 → 본인 메타데이터 저장 → 이전 본인 파일 정리 순서다. 저장 실패 시 새 파일만 정리를 시도하고 이전 사진을 유지한다. 기본 이미지 복원도 참조 해제 후 파일을 정리한다. 성공한 화면은 헤더에 갱신 이벤트를 보내고 서버 화면을 새로 읽는다.
- 회원탈퇴 신청이 기존 계정 차단 단계에 도달하면 사진 참조를 해제하고 본인의 해당 파일만 정리를 시도한다. 파일 정리 실패는 서버 경고로 남기며 계정 차단이나 이미 성공한 사진 저장을 취소하지 않는다. 실패 파일의 자동 재정리 작업이나 전체 계정 데이터의 물리 삭제 완료를 보장하지 않는다.

## 검증 경계

기본 색 안정성, 소속 경로 검증, 이미지 디코딩/크기/메타데이터 제거, 업로드·저장 실패 보상과 정리 순서는 `lib/account-profile.test.ts`에서 확인한다. 반응형 헤더·모바일 이동·직원 표시·키보드/포커스와 사진 선택 UI는 별도 브라우저 검수 대상이다. 운영 계정 사진이나 결제 데이터는 검수 목적으로 변경하지 않는다.

검증 명령: `npm run test:account-profile`는 Node의 모듈 모의 기능을 사용해 실제 라우트의 같은 출처·인증/탈퇴·사장/직원 본인 범위·저장 실패 보상까지 확인한다. 네트워크·운영 Storage를 호출하지 않는다.
