# 아티메뉴 컴포넌트 크기·간격 기준

2026-11-11 사용자 피드백 반영. 이전의 더 큰 조작 글자·필드·탭·선택 목록 수치보다 이 문서가 우선한다. 우선 범위는 해당 컴포넌트 내부이며 사이트 탐색·제목·본문은 포함하지 않는다. 기준 데이터는 `lib/site-spacing.ts`의 `SITE_CONTROL_DENSITY`, 실제 스타일은 `styles/ui-system.css`, `styles/site-design.css`, `styles/typography.css`다. `/design-system`의 ‘컴포넌트 내부 밀도’ 표가 같은 데이터를 사용한다.

## 공통 원칙

- 조작 요소는 본문·사이트 탐색과 다른 밀도를 사용한다. 일반 버튼·필드 라벨·드롭다운 옵션은 기본14px, 주요 lg 탭과 룸 선택은16px이다. 기존 와이드 보정은 유지하며14px은 최대15.75px에서 제한된다. GNB·헤더 계정 링크·사이드바 탐색·페이지/섹션/콘텐츠 제목·설명·본문·고객 메뉴판의 글자 크기는 이 변경으로 축소하지 않는다.
- 입력은 기본14px, 터치 포인터 환경은16px이다. 입력 높이는 sm32 / md40 / lg44 / 큰 검색48px, 터치에서는 sm40 / md44px를 유지한다. 지우기·실행 같은32px 보조 행동이 들어간 복합 입력은 최소 md40px를 사용해32px 필드 안에32px 버튼과 테두리를 억지로 넣지 않는다. 버튼은 기존32 / 40 / 44 / 48px 역할을 유지하고 글자와 좌우 여백을 줄인다.
- 내부 간격은4 / 8 / 12px 역할로 구분한다. 버튼·아이콘과 글자는8px, 일반 버튼·입력 좌우12px, 큰 실행 좌우16px이다. 작업 박스·페이지의16 / 24px 간격을 선택 항목 사이에 재사용하지 않는다.
- 옵션은 기본32px, 터치40px 이상이며 긴 문구에 맞춰 커질 수 있다. 항목 사이 gap은0, 팝업 안쪽8px, 전체 선택·구분선·목록 사이4px, 필요한 하단 행동 앞8px이다. 행 높이와 큰 행간을 동시에 더하지 않는다.
- 체크박스·라디오 시각 크기는16px, 클릭은 라벨 행 전체에서 받는다. 한 항목의 키보드 포커스는 한 곳에만 표시한다. 색상 스와치는 자체 포커스 표현을 유지한다. 스위치의44px 조작 영역은 보존한다.
- 일반 탭은 sm32 / md36 / lg40px, 영역형·문서형·룸 선택은40 / 44 / 48px이다. 룸 선택 글자는16px이며 일반 조작 글자14px와 구분한다. 기존 밑줄·연결형·룸 사각형 등 역할과 배치·기능은 유지한다. 탭에 행 높이보다 큰 자체 padding을 중복 적용하지 않는다.
- 같은 작업 묶음에서 나란한 추가·선택 버튼은 같은 높이와 수직 중심을 사용한다. 작은 버튼에 맞춰 전체를 축소하지 않고 해당 역할의 표준 크기를 함께 따른다. 아이콘 버튼은 높이와 같은 정사각형, 텍스트 버튼은 내용에 맞는 너비를 유지한다. 서로 다른 작업이나 독립된 툴바까지 일괄 확대하지 않는다.
- 밑줄형 선택선은 주요 화면·분류·알림 모두 `--site-tab-indicator-width: 3px`을 공유한다. 1px rail과 포커스 표시·다른 컨트롤 경계는 각각의 역할을 유지한다.
- 알림 분류 탭은 공통 `NotificationPanel`에서 글자14px·최소 높이48px·상하8px(`--ui-control-height-lg`, `--site-space-copy`)를 사용한다. 팝업·알림 이력·디자인 시스템 예시가 동일하며, 일반 md 탭36px에 눌리지 않도록 한다. 전체/읽지 않음의 밑줄·동일 폭·방향키·건수·읽음 처리는 유지한다.
- 룸 도구는 `TabsList size`를 `.site-room-tabs-header`가 소유해 고정 추가와 스크롤 선택 목록에 `--site-room-control-height`를 함께 전달한다. 실제 테이블·키오스크/주문/호출의 sm은40px, 일반 md는44px, lg는48px이고 모든 룸 이름은16px·좌우12px(lg16px)다. 일반 sm 탭32px/14px 규칙을 룸 선택에 재사용하지 않는다. 모서리8px·선택/포커스·로딩·비활성·위치·가로 스크롤은 유지한다.

## 필드 모서리·선택 내부 간격·대표 검색

사용자 후속 지시에 따라 라운드는 변경 전으로 복구한다. 일반 입력·비밀번호·텍스트 영역·셀렉트·복합 입력은 기존 `--ui-radius-field=12px`, `SearchField`는 크기에 관계없이 `--ui-radius-control`의 캡슐형을 유지한다. 기본·포커스·오류·비활성·읽기 전용에서도 각 역할의 모양을 유지한다. 일반 필드의 라운드 변경을 검색창에 일괄 적용하지 않는다. 기존 미리보기 선택기의 전용 모서리도 원래 값으로 복구한다. 카테고리 캡슐·상태 칩·아이콘 버튼·스위치·페이지네이션·미디어의 전용 모양은 해당 역할을 유지한다.

PC·태블릿(768px 이상)의 셀렉트는 라벨→선택 개수8px, 개수→화살표 최소8px를 사용한다. 화살표16px·오른쪽 inset12px를 유지해 trailing space는36px이다. 좁은 화면의 기존 label/count gap16px·trailing40px(최소 여유12px), 모바일 아코디언의8px 간격은 그대로다. 동일한 필터 너비 때문에 짧은 라벨 뒤에 남는 여유는 허용하되 라벨과 개수를 양 끝으로 벌리지 않는다. 개수 X의32px 클릭 영역·키보드 초점·전체 선택 동작과 공통 필드 높이는 유지한다.

대표 검색은 `SearchField fieldSize="search"`의48px 높이에 모바일16px·PC/태블릿18px 글자를 사용한다. 작은 도구 입력의14px·터치16px와 구분하며 공통 와이드 보정을 따른다. FAQ 카테고리는 `CategoryFilter size="lg"`의16px, 질문 행의 분류명은 `type-body`16px이다. 질문·답변·페이지 제목·GNB의 크기는 이 요청으로 변경하지 않는다.

## 사이트 탐색·읽기 글자의 보호 경계

컴포넌트 크기·내부 여백을 줄이는 요청은 사이트 탐색과 읽는 글자를 줄이라는 허가가 아니다. `type-nav`는 `type-control` 및 입력 글자 토큰과 독립적으로 유지한다. GNB와 헤더 계정 링크의 기본 크기는 모바일·태블릿15px, PC16px이며 관리 화면 작업 영역의 기존 탐색은15px을 유지한다. 페이지 제목은28/32/36px, 페이지 설명·일반 본문은16px이다. 기존 섹션·콘텐츠 제목 역할과 모든 공통 와이드 보정도 유지한다.

사이트 탐색·읽기 역할이나 기초 `--site-type-*`를 컴포넌트 밀도에 맞춰 일괄 축소하지 않는다. 탐색·제목·본문 크기를 바꾸려면 해당 글자 역할에 대한 사용자 요청이 있어야 하며 `lib/site-typography.ts`, 공통 CSS와 `lib/site-typography-contract.test.ts`의 보호 계약을 함께 변경한다. 검수는 작은 컨트롤과 원래 크기의 GNB·페이지 제목·본문이 같은 화면에 공존하는지 확인한다.

## 컨트롤 너비

반응형은 컨트롤이 남은 폭을 무조건 채운다는 뜻이 아니다. 입력할 내용이 긴 폼은 기존 fill을 유지하며, 목록 검색·필터는 공통 `FilterToolbar`로 구분한다. 검색은 `--ui-filter-search-width=18rem`(288px)에서 멈추고, 같은 그룹의 필터는 가장 넓은 라벨·아이콘·선택 개수·해제 행동·화살표에 맞춘 동일한 너비를 사용한다. 옵션 개수 표시가 생겨도 문구와 행동을 겹치거나 숨기지 않는다. `width:max-content`와 같은 비율의 intrinsic 그리드로 묶어 빈 가로폭까지 늘리지 않는다.

넓은 화면은 검색·네 필터를 한 행에 두며, 실제 공간이 부족하면 그룹을 다음 행으로 넘긴다. 768–1023px는 필터를2열로, 1024px 이상은4열로 묶는다. 보기 전환은 오른쪽, 결과 개수는 다음 행을 유지한다. 모바일은 검색 행과 무배경·무테 필터 아이콘을 유지하며 클릭 영역과 초점은 보존한다. 중앙의 FAQ 대형 검색이나 기존 결제·계정 폼을 이 도구 너비로 일괄 축소하지 않는다.

## 검색과 보기 전환

검색은 `SearchField`의 캡슐형 박스로 구성한다. 실시간 필터는 앞쪽 돋보기와 입력값 지우기, 전용 검색은 오른쪽의 검정 원형 실행 버튼과 지우기를 사용한다. 실행 아이콘을 입력 밖에 따로 띄우거나 두 개의 돋보기를 중복 표시하지 않는다. 원형 실행 크기는 일반 입력32px, 큰 검색40px이며 안쪽 여백은 필드 높이에서 계산한다.

전용 검색 버튼은 type=submit, 지우기는 type=button이다. 기존 Enter·IME 보호, 실시간 검색/제출 검색, native form 이름·GET 필터와 초기화 동작을 유지한다. 여러 조건을 함께 적용하는 ‘조회’ 버튼은 기존 위치를 유지한다. 결과 없음은 빈 결과이며 입력 오류로 표시하지 않는다.

같은 값의 보기 전환은 `ToggleGroup appearance="segmented"`로 묶고, 기존 회색 바탕 안 검정 선택 면과 흰 아이콘으로 표시한다. 포커스 파란색을 선택 상태색으로 재사용하지 않는다. 고객 메뉴판·미리보기·썸네일 화살표·페이지네이션의 기존 전용 외형을 이 규칙으로 일괄 변경하지 않는다.

## FAQ 목록

질문 행은 투명한 목록으로 유지한다. 질문은 읽기 본문16px·600, 기본 상하 여백16px로 맞추고 기존24px padding과18·20px 질문 글자를 중복 적용하지 않는다. hover·열림·누름에 회색 둥근 박스를 추가하지 않는다. 질문 글자 밑줄과 아이콘 색으로 상호작용을 표시하고, 키보드 포커스와 펼침/접힘·답변·구분선은 유지한다.

## 적용과 검증 범위

템플릿 검색, 고객센터 FAQ 검색·질문 목록, 공지 검색, 호출 검색, 문의 제목 검색, 결제 필터와 라이브러리가 같은 검색 구조와 밀도 토큰을 사용한다. 실제 저장·결제·계정·매장 데이터 동작은 변경하지 않는다. 삭제한 고객센터 전용 검색 CSS의 레거시 예외만 제거했으며 예외를 추가하지 않았다.

자동 동작 검사에서는 검색 지우기·포커스 복귀·제출, 보기 전환의 단일 선택과 검정/흰 선택 면, FAQ의 투명 hover·Enter 펼침/답변 연결, 기본값 검색의 native form 값·초기화가 통과했고 런타임 오류는0개였다. 터치 환경은 입력16px·필드44px·옵션40px를 확인했다. 실제 계정·결제·매장 데이터를 바꾸지 않았다.

운영 반영은 릴리스 리비전의 배포 성공과 실제 운영 HTTP/CSS 응답을 확인한 뒤 보고한다. 자동 검증을 시각 검수나 모든 인증 화면 실사용을 완료한 것으로 확대하지 않는다.
