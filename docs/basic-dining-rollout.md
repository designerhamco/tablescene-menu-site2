# 베이직·다이닝과 공통 테이블 주문 전환

기준: 2026-10-18, 시작 기준선 `626f752`. 사용자가 전체 구현과 QA 대상 선택을 위임했고, 코스 가격만 있는 다이닝은 코스 전체를 한 상품으로 주문하기로 확정했다.

## 구현

- 헤더: 베이직 / 다이닝 / 디스플레이 / 디자인 템플릿 / 고객센터. 표시 명칭을 원페이지 베이직/스페셜 다이닝으로 변경하고 기존 상품 키·가격·구독 계약은 유지한다. Display는 준비 중이며 신규 신청을 막는다. 홈 Hero 구조·PSD v3·슬라이드·타이포는 유지한다.
- 원본 REAL MATCHA와 고객 데이터는 보존한다. 별도 숨김 템플릿 `cafe_real_matcha_paged_test`와 `/qa/table-order`에서 실험한다. 판매/교체 갤러리에는 실험 템플릿을 노출하지 않는다.
- 복사본의 PC·태블릿은 왼쪽 브랜드/대표 이미지와 하단 페이지 이동·호출·장바구니를 고정한다. 마지막 페이지도 동일한 열 슬롯이다. 읽기 크기를 줄여 강제로 채우지 않고 카테고리 묶음/연속 배치를 구분한다. 원자적인 콘텐츠 자체가 크면 준비 완료로 표시하지 않는다.
- 위젯의 저장 순서와 flow/bottom을 유지한다. 마지막 하단 위젯은 안내사항 1/2/3 위다. 모바일은 기존 자연 스크롤과 20/24/48 정책을 유지한다.
- 베이직 7종·다이닝 A/B에 공통 담기·필수 옵션·수량·수정·삭제·장바구니·후불 주문을 연결한다. 기존 맞춤형 PC·태블릿은 담기를 가격 아래에 두고 호출/장바구니는 측정된 하단에 원형으로 나란히 둔다. 실제 너비가 넘치는 칩은 다음 줄로 보낸다. 글자 하한과 fit 공식은 완화하지 않는다.
- 호출/주문 미리보기 체크는 독립적이고 기본 OFF다. 새 창·기기 전환에 보존한다. 모의 주문/상태는 테스트 화면 메모리에서만 변경하며 실제 API·DB·PG로 보내지 않는다.
- 모바일: 언어 왼쪽, 테이블 중앙, 호출/장바구니 오른쪽. QR의 customer 채널은 폴더블 포함 모바일 표현을 선택한다. terminal 링크는 실제 기기 표현과 후불만 제공한다. URL만으로 테이블 세션이나 권한이 생기지 않는다.
- 사장 전용 설정: 주문/호출/모바일 선결제 노출, 상품 주문 가능 여부·기본 금액·필수/복수 옵션·추가 금액, 코스 전체 주문. 디자인 가격 열과 주문 옵션은 별도이므로 활성화 전에 주문 금액을 맞춰 확인한다.
- 선결제는 ON이어도 `선결제 · 준비 중` 비활성 버튼이다. 실제 주문은 미결제 후불만 사용한다. PG 호출을 추가하지 않았다.
- 기존 주문관리의 테이블·상품/옵션 snapshot·시각·상태 전환을 재사용한다. 실제 접수는 runtime·site allowlist·사업자 이용권·사장 설정·서명된 방문 세션을 모두 요구한다. 직원 초대/Display 대기번호/선결제는 복구하지 않는다.

## DB 준비 — 미적용

신규 함수만 추가한다. 기존 V1·주문 이력·결제·구독·사용자 데이터는 변경하지 않는다.

1. `20261018085245_add_menu_order_configuration.sql`: 소유권/메뉴판 범위/updated_at 충돌 검사 후 상품·주문 옵션을 원자 저장하는 `replace_menu_item_order_options`. 삭제 옵션은 archive, 주문 snapshot 보존.
2. `20261018090357_add_course_postpay_orders.sql`: V1을 유지하는 `submit_postpay_order_v2`. 개별 상품/선택된 코스를 서버 가격으로 snapshot하고 할인·필수 옵션·수량·중복·세션을 검사. 두 함수 모두 service_role만 실행한다.

승인된 운영 적용 후 generated Supabase types를 재생성하고 신규 RPC의 임시 타입 단언을 제거한다. 과거 Dashboard 적용 이력과 원격 ledger가 정리되지 않아 `db push` 일괄 실행은 하지 않는다. 검토한 두 파일만 적용한다.

## 실제 주문 검증 대상과 남은 승인

기존 오브 테이블 QA는 만료됐고 현재 로그인한 QA 계정과 소유자가 달라 재사용하지 않는다. 현재 로그인한 확인된 QA 계정 아래 다음 두 메뉴판을 신규 생성하는 dry-run을 완료했다. 두 slug 모두 미존재이며 실제 생성/권한/이용기간 변경은 하지 않았다.

- `basic-paged-order-qa-20261018`: 숨김 REAL MATCHA 페이지형 복사본, 베이직 QA.
- `dining-course-order-qa-20261018`: 오브 테이블 A, 코스 전체 주문 QA.

기존 `scripts/seed-aube-smart-call-qa.ts`를 두 플랜에 맞게 확장했다. 기본은 dry-run이며 명시적 `--apply`가 있어야 생성한다. 실제 고객 메뉴판·이용권·구독·결제는 변경하지 않고 새 QA 이용권만 14일로 만든다.

이전에 정한 별도 승인 범위인 운영 DB/환경 변경은 다음 묶음으로 진행한다. 승인 전에는 실주문 검증을 완료로 보고하지 않는다.

1. 위 함수 두 개 적용·권한 확인.
2. 위 두 QA 메뉴판과 승인 시점부터 14일짜리 QA 이용권만 생성. 실제 결제·구독 레코드는 만들지 않는다. 각 QA에 주문/호출·옵션 또는 코스 전체·모바일 선결제 준비 중을 설정.
3. POSTPAY_ORDER/ORDER_DASHBOARD 및 필요한 Call/Table gate의 allowlist를 새 QA 두 UUID에만 한정해 배포. 기존 allowlist는 승인 범위 밖에서 임의 변경하지 않는다.
4. 테이블 QR customer/terminal, QA별 미결제 후불 테스트 주문 1건과 관리자 상태 전환 검증. 선결제·실결제·환불·다른 고객 메뉴판에는 쓰지 않는다.

2026-10-18 Vercel 변수 이름 읽기 감사에서 POSTPAY/ORDER_DASHBOARD는 미등록이다. 코드 배포만으로 실제 주문이 켜지지 않는다. `docs/runbooks/vercel-production-runtime-audit.md` 참조.
