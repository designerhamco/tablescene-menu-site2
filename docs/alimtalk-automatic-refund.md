# 알림톡 충전금 관리자 승인 카드 환불

2026-11-25. 사용자 요청은 **자동 환불 구현 준비와 모의 검수**이며 실제 취소는 PG 계약 후 별도로 검수한다. 이 변경에서 실제 결제·취소·발송, 운영 DB 적용, 운영 환경변수 변경은 하지 않는다.

## 관리자와 점주의 흐름

1. 점주는 기존 주문 설정 또는 구독/결제 내역에서 미사용 유상 잔액 전체의 환불을 신청한다. 결과 확인 중인 발송을 먼저 정산하며, 신청 금액은 보류된다.
2. 관리자 → 알림톡 환불 관리에서 신청을 열고 **환불 승인**을 누른다. 확인창의 남은 금액과 원 결제 건수를 확인한다. 수수료는 0원이며 원래 결제한 카드로만 취소한다.
3. 실제 로그인 관리자와 승인 시각을 DB에 기록하고 모든 원 결제를 작업으로 만든다. 표의 현재 페이지에만 한정하지 않는다. 원 결제가 여러 개라면 각각 정해진 금액을 부분/전체 취소한다.
4. 서버가 PortOne에서 원 결제의 매장·채널·소유자·상품 목적·통화·결제/취소 금액과 카드 수단을 다시 조회한다. 기존 결제에 저장된 store/channel을 사용하므로 현재 테스트 PG 설정이 바뀌어도 임의로 다른 거래를 취소하지 않는다.
5. 한 작업은 DB에서 제출 시작을 먼저 기록한 뒤 한 번만 취소 요청을 보낸다. 다시 조회한 실제 취소 금액만 기존 환불 원장에 반영하며 전액이 확인돼야 환불 완료다.

## 중복과 장애

- 동일 승인과 동시 실행은 같은 승인/작업으로 합쳐진다. 원 결제·대상 금액·작업 ID는 고정된다.
- PortOne 요청에는 고정된 따옴표 포함 `Idempotency-Key`와 `currentCancellableAmount`를 보낸다. 공식 보장 기간은 3시간이므로 이 키만으로 영구 중복 방지를 주장하지 않는다. DB 제출 기록이 별도로 재전송을 막는다.
- 요청 시간 초과·응답 유실은 실패 확정이 아니다. 결과 확인 중으로 유지하고 GET 조회만 반복한다. 같은 취소 POST를 자동 재시도하거나 새 ID로 재생성하지 않는다.
- 제출 직후 프로세스가 종료되어 실제 전송 여부를 모르면 같은 원 결제를 조회하고 관리자 확인으로 해결한다. 근거 없이 잔액을 돌려주거나 취소를 다시 보내지 않는다.
- 일부 금액만 취소된 경우 확인된 금액만 정산하고 나머지는 보류한다. 모순되는 원 결제/취소 금액·비카드 결제는 관리자 확인 대상으로 멈춘다.
- 관리자 자격을 회수하면 승인된 미제출 작업도 새로 실행할 수 없다. 이미 제출한 거래의 조회/정산은 계속 가능하다.

## 실행 게이트와 계약 후 작업

- `ALIMTALK_REFUND_EXECUTION_ENABLED=true`와 DB `alimtalk_billing_policy.refund_execution_enabled=true`가 모두 필요하다. 기본은 OFF다. DB는 PG 검토일과 승인 store/channel이 없으면 ON을 거부한다.
- 새 마이그레이션 `20261125114235_add_alimtalk_refund_approval_jobs.sql`을 적용해야 한다. 운영에는 아직 적용하지 않았다.
- 승인 응답 뒤 서버가 한 번에 4건씩 처리하고 약 150초 안에 다음 배치를 시작하며 최대 20배치로 제한한다. 보통의 다건 환불은 브라우저를 닫아도 이 백그라운드 작업에서 이어진다. 더 오래 걸리거나 중단된 작업은 DB 큐에 남는다. 관리자 상세가 열려 있으면 15초 간격으로 다음 작업을 확인한다. 이미 제출한 작업의 조회 간격은 최소 90초다.
- 장시간·다건·화면을 닫은 뒤의 복구용 `POST /api/cron/process-alimtalk-refunds`도 준비했다. `CRON_SECRET` 인증과 동일한 이중 실행 게이트가 필요하다. **아직 스케줄 등록하지 않았다. 계약 후 실제 운영을 켜기 전에 이 엔드포인트의 정기 실행·실패 모니터링을 함께 연결해야 한다.** GET 방문은 환불을 실행하지 않는다.
- PG가 확정되면 해당 실계약에서 충전금 취급·부분 취소·취소 가능 기간을 확인하고, 승인된 소액 실결제/환불로 원장과 카드사 결과를 대조한다. 테스트 채널은 운영 충전금으로 인정하지 않는다.
- 이번 변경은 고객 발송/충전 결제/구독 환불/식당 손님 주문 환불을 활성화하거나 변경하지 않는다.
