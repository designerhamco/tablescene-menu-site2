## Menu layout boundaries

- Before changing templates, read `docs/template-spacing-contract.md`. PC/tablet single-page fit is one policy; mobile single-page reading is a separate policy with its own numeric tokens. Never let a PC/tablet fit, density, fill or semantic-ratio change alter mobile sizing/spacing.
- The seven active single-page mobile templates share the approved 20px item / 24px heading / 48px section defaults (rem-based). Measure colored upper boxes and separator stroke edges, not just text bounds. Preserve menu order, price/name alignment and desktop notice anchors.
- Display and multi-page engines are excluded from this mobile rollout. All seven mobile templates use 14px notices, 26px category titles and a shared text-brand fit with a hard 44px minimum. Prefer a single line up to 100% width but stop at the width-relative visual ceiling (56px at 342px inner width); balanced multiple lines use a 75% soft target and a 44px ceiling at that inner width. Minimum size, whole-text preservation and visual ceiling take priority over an impossible coverage percentage. No old template-specific title/category/notice size corrections may override these values. Notice rows use normal supporting-copy line-height with zero paragraph gap. Logos bypass text fitting. PC/tablet starts from the three-semantic-field reference; only materially excessive actual whitespace with a safe size gain, or actual wrapped-copy clipping, may switch to actual-content measurement. Fit cache keys include the measurement basis and content/viewport changes restore the reference. Keep readable rem floors (name/price 1rem, supporting copy 0.75rem, secondary name 0.75rem). Store description, product description, featured description, all notices and language UI labels share one supporting-size token. Featured product name, chip and price must match the corresponding menu name, chip and price size on PC/tablet/mobile; featured names no longer use the supporting-copy size. Keep 1/1.10/1.20 between-item rhythm, template role ratios, insets, category gaps and notice anchors. Prefer registered contiguous category order. Only poor original packing with material improvement may use related-category order, then conventional menu order, then bounded deterministic free packing; search a later tier only if the prior tier has no qualifying improvement. Unknown families, page boundaries and widgets are order barriers. Prefer up to three menu columns; a fourth is a readability rescue only when its actual inner width is at least 12rem. PC/tablet single-page content NEVER falls back to scrolling, including portrait tablets (768px and wider) and header cells. Attempt safe packing and ordered flow; do not mark clipping, extra offscreen columns or failed fit as ready. Mobile alone retains the independent reading-scroll policy.
- Mobile internal copy gaps are also shared: item title/secondary/description boundaries 2px, category title/description 8px, brand/description 12px, upper content blocks 24px. All supporting copy uses line-height 1.5. Language controls must use script-aware text with the saved/starter Korean and English font variables, never hardcoded font names. Decorative stroke offsets remain distinct from whitespace measured after a stroke.
- PC/tablet text brands compare one/two-line candidates for all seven templates. Horizontal headers target 65% of the actual central title cell's inner width with width-relative 8%/22% font limits and root text scaling. The three equal-width header cells use a base 8% and maximum 14% of board inner height after the row gap; grow only for measured title/supporting-copy height within this bound. Vertical brand columns keep their 75% target, 10% width floor and 18% frame-height budget. Balanced two-line candidates require a 15% size gain. Do not add template-name-specific title sizes. Mobile language UI-to-brand and brand-to-description share the 12px token, with independent 56px/44px ceilings at 342px inner width. PC/tablet one-page text chips move below when they force a one-line name to wrap or add lines to an already long name; remeasure with fit/viewport changes. Mobile and multi-page keep their prior chip flow.
- Verify all affected mobile templates, narrow/wide phone widths and relevant locales, plus PC/tablet and excluded-engine regressions. Record actual DOM viewport dimensions, not just requested sizes; wait for the rendered layout/fonts to settle before claiming success.

- Customer content edits must invalidate fit caches even when IDs/counts stay the same. Recompute after visible copy, prices, images, widgets, fonts or viewport changes. Sale countdown ticks must not invalidate this content signature.

- Renderer responsibilities and extracted modules are documented in `docs/menu-template-architecture.md`. PC/tablet fit geometry and packing live in `one-page/pc-tablet/cafe-fit-engine.ts`; reusable types, pricing and content helpers live in `shared/cafe-template-*.ts` / `shared/cafe-menu-pricing.ts`. Keep existing mobile title/reading policy, multi-page engines and display engine independent. The user subsequently approved unifying Van Gogh/Sunday top-row outer padding and header-to-menu gap. Both inherit the shared responsive formula; do not reintroduce per-template PC inset or row-gap overrides.

- PC-only top-row rule: confirmed single-line text brands use 75% of the common header-to-menu base gap. Two/multiple lines, natural-wrap fallbacks, logos and all tablet/mobile devices keep the full gap. Compute title candidates from the unscaled gap to prevent feedback; restore the gap on text-brand unmount. Do not use template-name branches or change outer padding/header-height limits.

- ROSY ORANGE adaptive PC/tablet price leaders remain visible on every item, including chip-below rows. Reserve their readable minimum width when measuring chips; remove the old PC auto-start margin/short cap. Chips also move below if they add lines to an already long name. Four-menu-column rescue in a central-brand layout must account for all five actual columns and their gaps before checking the 12rem minimum. Leave mobile leader/chip flow and other engines unchanged.

- All seven one-page presentations link notice 1/2/3 and language trigger/menu label text to the menu-description size. Notice Korean and English runs both use saved --menu-font-ko. Language UI retains saved --menu-font-ko / --menu-font-en by script; legacy fixed notice fonts must not override them. PC text-brand candidate ceilings use 0.875 of the prior slot/height/width-derived ceiling, respecting the existing floor. Tablet brand ceilings are unchanged.

- If an adaptive fourth-column rescue fails final actual crop at the safety limit, reject that rescue for the current content/viewport and retry preferred columns. Also reject an actual failed partition before trying another ordered/related partition; never reuse it through the fit cache. Cached fit states must belong to the current permitted column candidates. Clear rejection on content changes; viewport changes use a fresh rescue session.

- Category descriptions and time-sale supporting text share the product-description size in all seven one-page devices. Keep category emphasis weight/color and discount price/chip roles separate from description sizing.
- One-page time-sale messages, deadlines and countdown digits use saved --menu-font-ko for Korean and English, just like notices. Apply to all PC/tablet/mobile presentations; do not change discount price fonts, language UI or excluded engines.
- All one-page text chips, including menu/featured badges, sale badges, sold-out and trait chips, use saved --menu-font-ko for Korean and --menu-font-en for English. Mixed-script labels split by script; legacy fixed chip fonts and role-font overrides must not win. Keep chip sizes, colors and placement rules unchanged.

- Two-field one-page items are an explicit per-item exception: secondary-only meta or description-only description grows 5%; three-field and title-only rows do not. A description-only item's time-sale explanation and linked featured description follow its 5% description increase. Category/store descriptions, notices and language UI retain the shared base size. Keep mobile 20/24/48 rhythm independent and remeasure PC/tablet with these actual sizes.

- The optional 5% emphasis must yield to single-page fit: when actual crop fails at the name reading floor, disable only that emphasis for the current content/viewport and remeasure. Restore the attempt after content/viewport changes; include the mode in fit/cache keys. Mobile keeps its independent 5% reading rule.
- Portrait tablet canvas grids must not inherit KOHI's legacy mobile one-column/margin rules. Dense menus still use two columns when the actual menu region is below 640px. Inner adaptive wrappers fit the root content-box height, excluding decorative outer padding. Check both tablet orientations for actual column geometry, category/item overlap and complete featured-frame boundaries; viewport overflow alone is insufficient.
- Optional one-page Call UI: PC/tablet Bell + label circle selects a readable accent from the rendered menu palette (brand when it contrasts with the surrounding panel, otherwise a category/menu accent), with contrasting foreground and occupies the measured lower-right footer after widgets, before lower-right notices (or the bottom content edge when absent). Preserve top-row/center-brand notice anchors. Mobile uses a transparent Bell / centered table label / globe-only row in rendered store-name color; both icons are 24px. Table label uses the saved Korean font for every script/numeral and the base product-description size token. Retain 48px row, 44px controls and 12px brand gap. Only mobile adds a fixed bottom Call button in the same selected readable menu accent, sharing the same action and reserving 5rem plus safe-area inset after existing content padding. The dialog appears above it. OFF adds no slots. Include Call mode/table context in fit signatures; never overlap content or scroll. Preview toggle defaults OFF, uses Table 1 and a simulated dialog; actual reception remains separately gated. Display/multi-page are excluded.
